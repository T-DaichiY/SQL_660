🔤 文字データ型 — CHAR・VARCHAR・TEXT

データ型を選ぶときに何を基準にすべきか、そして3つの文字データ型（CHAR・VARCHAR・TEXT）の違いを、実例を通して身につける。

①

データ型を選ぶときに考えること

ドキュメント化の重要性と、型選びの3つの基準

テーブルの列にどのデータ型を使うかを決める前提として、データディクショナリ（data dictionary）——列ごとにどんなデータ型を使い、それがどう使われるかをまとめた仕様書——の存在があります。これは地味に見えますが、実務では非常に重要です。

💡 ドキュメント化の重要性：コードやデータベース設計は、変更・修正のたびに「何をしたか」「なぜそうしたか」を記録しておくべきです。列名やデータ型の選び方が直感的であれば、コメントを読まなくても意図が伝わります。機械学習やAI開発のように、複数人・複数チームで同じデータ構造を再利用する場面ではなおさら重要です。

データ型を選ぶ3つの基準

基準考えること
①データに最適か数値だけか？負の数や小数を含むか？文字だけか？長さは？——列の中の最長値・最短値を確認する
②用途に合っているかその値に対して足し算・掛け算などの計算を行うか？必要な精度（小数点以下の桁数）は？
③速度とストレージ読み書きの速さ、そして保存に必要な容量。1レコードあたり数バイトの差でも、数百万〜数十億レコードになれば大きなコストになる
📌 金額の丸め誤差に注意：小数点以下の桁数（precision）が足りないと、丸め誤差が積み重なって大きな損失につながることがあります。映画『オフィス・スペース』では、取引ごとに端数（1セント未満）を切り捨てて別口座に貯め込むプログラムが登場します——精度の設計ミスがどれほど実害を生むかの好例です。
🍎 かんたん説明

データ型選びは「そのデータの中身は何か」「計算に使うか」「どれくらいの量になるか」の3点で決まります。適当に大きい型を選べばいいわけではなく、無駄なストレージ・処理コストを避けることも大切です。

②

CHAR・VARCHAR・TEXTの違い

固定長パディング vs 可変長 vs 無制限

SQLには主に3つの文字データ型があります。CHARとVARCHARは丸括弧の中に数値（パラメータ）を指定しますが、TEXTにはそれがありません。

CHAR(n) — 固定長、余りは空白で埋める

丸括弧の中の数値は「必ずその長さになる」という意味です。指定より短い値は右側に空白でパディング（穴埋め）されます。指定より長い値は——もし超過分がすべて空白なら自動的に切り詰められますが、そうでなければエラーになります（後述のCASTで明示的に変換した場合のみ、超過分は黙って切り捨てられます）。

CREATE TABLE demo_char (
    code char(4)
);
入力した値char(4)への結果
'AB''AB '（後ろに空白2つでパディング）
'ABCD''ABCD'（ちょうど4文字）
'ABCDEFGH'❌ エラー：value too long for type character(4)

すべてのレコードに常に同じバイト数を割り当てるため、値の長さがバラバラなデータに使うと無駄なストレージが発生します。そのためVARCHARほど頻繁には使われません。

VARCHAR(n) — 可変長、最大値のみ制限

VARCHARも丸括弧に最大長を指定しますが、実際に使うストレージは入力された値の長さぶんだけです。短い値は短いまま保存されるので無駄がありません。

CREATE TABLE demo_varchar (
    email varchar(255)
);

例えばメールアドレスの列にvarchar(255)を使うのはよくあるパターンです。0文字〜255文字まで、実際の長さに応じたストレージしか使いません。3つの文字データ型の中で、VARCHARが最もよく使われます。

TEXT — 上限なし、段落のような長文向け

TEXTには長さの指定がありません。コメントや説明文など、想定される長さがVARCHARの範囲を超えるかもしれない、あるいは長さを一切制限したくない場合に使います。ストレージの使われ方はVARCHARと同様、実際の文字数ぶんだけです。

⚠️ TEXTは便利だが要注意：長さの上限がないため、悪意あるユーザーが極端に長い文字列を送り込んでくるようなセキュリティリスクにもつながります。何でもTEXTにすればいいわけではありません。
🍎 かんたん説明

CHARは「常に同じ長さ」、VARCHARは「最大◯文字まで、実際の長さぶんだけ保存」、TEXTは「上限なしの長文向け」。実務で一番よく使われるのはVARCHARです。

③

実例で考える — どの列にどの型を使う？

用途に応じた判断基準を身につける
データおすすめの型理由
メールアドレスvarchar(255)比較的短い単一の値。長さにばらつきがあるのでVARCHARが適する
姓・名varchar(短めの上限)255文字も要らない。上限を短く絞ることで、SQLインジェクションのような攻撃を狙った過剰な長さの入力を防ぎ、データ整合性も保てる
説明文・コメントtext単一の値ではなく複数の文で構成されうる。長さの上限を決めにくい
ツイート（旧140字制限）varchar(140)上限がはっきり決まっている用途にはVARCHARで長さを強制できる。（280字に拡張された後も、実際に140字を超える投稿は全体の約12%、190字を超えるのはわずか約5%だったという話もある）
州コード（例：GA, TN, NY）char(2)常にちょうど2文字と分かっているので、CHARを使うことでデータ検証（バリデーション）の役割も果たせる
ZIPコードvarchar(5)数字だけに見えるが、足し算・引き算・掛け算をする対象ではなく地理的な「名前」に近い。数値型にすると先頭の0が消える問題も起きるため文字型が適切
商品コード桁数が一定ならchar(n)、バラバラならvarchar(n)識別子・ラベルであり計算対象ではないので数値型ではなく文字型。桁数が揃っているかどうかでCHARかVARCHARかを決める
📌 ZIPコードが数値型でない理由：郵便番号同士を足したり引いたりすることはありません。郵便番号は「ある地域を指し示すラベル」であり、県名や市区町村名を数値にしないのと同じ理屈です。数字で構成されていても、計算に使わないデータは文字型で持つのが適切です。
🍎 かんたん説明

「その値で計算をするか？」「長さは一定か、ばらつくか？」の2つの問いに答えるだけで、CHAR・VARCHAR・TEXTのどれを選ぶべきかはほぼ決まります。

📖 用語集

data dictionary
データディクショナリ
各列のデータ型や用途をまとめたドキュメント。チーム開発での意思疎通に役立つ。
CHAR(n)
固定長文字列
常にn文字になるよう空白でパディングされる文字データ型。
VARCHAR(n)
可変長文字列
最大n文字まで、実際の長さぶんのストレージだけを使う文字データ型。
TEXT
無制限文字列
長さの上限がない文字データ型。長文の説明・コメントなどに使う。
padding
パディング
CHAR型で、指定長に満たない値の余白を空白で埋めること。
SQL injection
SQLインジェクション
悪意あるSQL文を入力欄経由でデータベースに注入する攻撃。入力長の制限が対策の一つになる。
