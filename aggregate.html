M4 · Aggregate function

📊 集計関数（Aggregate function）

1行ずつの計算から、複数行をまとめて1つの値にする計算へ。AVG・SUMと、セットで必要になるGROUP BY。

① 集計関数とは② GROUP BYが必須③ AVGとSUMの実例④ 別名とWHEREの制約📝 Quiz
①

集計関数とは

前のレッスンの手計算を、自動化する

前のレッスンでは、(s_close - s_open) / s_open のように1行の中で列同士を計算しました。しかしこれでは求められないものがあります——たとえば平均です。

🤔 なぜ平均は手計算できないのか：平均を出すには「全部でいくつのレコードがあるか」を知る必要があります。しかし1行ずつの計算では、その行の値しか見えていません。複数の行をまたいでまとめるには、専用の道具が要ります。それが集計関数（aggregate function）です。
関数意味例
AVG()平均AVG(s_close)
SUM()合計SUM(volume)
COUNT()件数COUNT(order_num)
MAX() / MIN()最大 / 最小MAX(grade)

構文はこれまでと同じ形です。SELECTで始まり、列の代わりに関数で包んだ列を書きます。

SELECT AVG(s_close)
FROM stocks;
✍️ 関数名はAVGのように大文字で書くのが良いスタイルです（小文字でも動作します）。
🍎 かんたん説明

集計関数は「たくさんの行を1つの値にまとめる」関数。平均・合計・件数・最大・最小がその代表です。

②

GROUP BY が必須になる理由

「何ごとに」まとめるのかを指定する

知りたいのは「全銘柄をひっくるめた平均」ではなく、「銘柄ごとの平均終値」のはずです。では、その「銘柄ごと」をSQLにどう伝えるのか——それがGROUP BYです。

SELECT s_index, AVG(s_close)
FROM stocks
GROUP BY s_index
ORDER BY s_index;
s_index | avg --------+--------------------- AAPL | 128.4327... AMZN | 1702.9981... （14銘柄それぞれの平均）

やっていることは「s_indexの値ごとにデータを小分けし、その小分けごとに平均を取り、結果として報告する」です。

⚠️ GROUP BYを忘れるとエラーになります。集計関数と、集計していない普通の列を並べて書いた場合、その列は必ずGROUP BYに書かなければなりません。
-- GROUP BY を書かないと…
SELECT s_index, AVG(s_close) FROM stocks;
ERROR: column "stocks.s_index" must appear in the GROUP BY clause or be used in an aggregate function

エラーメッセージが解決策そのものを教えてくれています——「その列をGROUP BYに入れるか、それ自体も集計関数で包むか、どちらかにせよ」。s_indexは文字列なので数学的な計算はできません。したがってGROUP BYに入れるのが正解です。

Excelの平均と比べてみる

ExcelSQL
書き方=AVERAGE(A1:A58)AVG(s_close)
範囲の指定自分でセル範囲を選ぶGROUP BYで「まとめる基準」を指定
銘柄が14個あったら14個の数式を作るクエリは1本のまま
📌 GROUP BYは「範囲指定」の代わりです。Excelでは自分でデータを並べ替えて範囲を切り出す必要がありますが、データベースは膨大な行を扱うのでそれは非現実的です。代わりに「この列の値ごとにまとめて」と指示すれば、SQLが裏側で全部やってくれます。同じ値を見つけるたびに、その仲間だけで平均を計算してくれるわけです。

GROUP BYには複数の列を指定することもできます（詳しくは Group by のレッスンで扱います）。

🍎 かんたん説明

集計関数を使ったらGROUP BYもセットで書く。「何ごとに集計するのか」を伝えるためです。

③

AVG と SUM の実例

stocksテーブルで試す

例1：銘柄ごとの平均終値

SELECT s_index, AVG(s_close)
FROM stocks
GROUP BY s_index
ORDER BY s_index;

14銘柄それぞれの平均株価が並びます。安い銘柄と高い銘柄がひと目で分かり、前レッスンで見たパーセント変化がどこから来ているのかも掴めます。

例2：銘柄ごとの出来高の合計

SELECT s_index, SUM(volume)
FROM stocks
GROUP BY s_index;
s_index | sum --------+------------- AAPL | 9823456700 XYZ | 0 （取引が記録されなかった銘柄は0）

AVGをSUMに、s_closeをvolumeに変えただけです。集計関数はどれも同じ形で使えます。期間中に何件の取引が処理されたかが分かります。

📌 覚え方：集計（aggregate）とはデータをまとめる（grouping）ことです。だからこそ「どうまとめるか」を必ず指定しなければなりません。

例3：合計の大きい順に並べる

SELECT s_index, SUM(volume) AS total_volume
FROM stocks
GROUP BY s_index
ORDER BY total_volume DESC;

集計結果に別名を付ければ、その別名で並べ替えられます。ORDER BY SUM(volume) DESCと書いても動きますが、別名のほうが読みやすくなります。

🍎 かんたん説明

AVGもSUMも使い方は同じ。関数(列) … GROUP BY まとめる列の形を覚えれば応用できます。

④

別名は使える、WHEREでは使えない

集計とフィルタの順序
⚠️ 集計関数はWHERE句では使えません。SELECTで集計した結果をWHEREの条件にすることはできません。WHEREは集計より前に実行されるからです（行を集める前に、その集計結果は存在しません）。集計結果で絞り込みたい場合はHAVINGを使います——これは後のレッスンで扱います。

複雑なクエリの組み立て例

「銘柄ごとの平均パーセント変化を、小数2桁で見たい」——これまで学んだ道具を全部使います。

SELECT s_index,
       CAST(AVG(((s_close - s_open) / s_open) * 100)
            AS numeric(10,2)) AS percent_change
FROM stocks
WHERE s_close IS NOT NULL
GROUP BY s_index
ORDER BY s_index;
s_index | percent_change --------+---------------- AAPL | 0.12 AMZN | -0.03
このクエリで起きていること
1️⃣
WHERE でNULLを除く集計の前に不要な行を落とす
↓
2️⃣
GROUP BY で銘柄ごとに小分けs_index の値ごとにグループを作る
↓
3️⃣
AVG で平均を計算グループごとに1つの値へ
↓
4️⃣
CAST で整形 → ORDER BY で並べる読みやすい形に仕上げる
WHEREは集計の前、HAVING（後述）は集計の後。この順序が要点。
📌 なぜ先にNULLを除くのか：取引がなかった日など、値の無い行が混ざったまま平均を取ると、結果が不当に引っ張られてしまいます。集計の前にデータを掃除しておく——これが正確な統計値を得るコツです。
🍎 かんたん説明

集計結果には別名を付けてORDER BYで使える。ただしWHEREには書けません（集計より前に走るため）。
