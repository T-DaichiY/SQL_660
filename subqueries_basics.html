M6 · Subqueries Part 1

🎯 サブクエリ①：スカラー・列・テーブルサブクエリ

サブクエリ（subquery）とは、あるクエリの中にさらに別のクエリが入れ子になったものです。「まず先に値、または値のリストを計算しておかないと、外側のクエリでそれと比較・フィルタ・JOINできない」というときに使います。ロシアの入れ子人形（マトリョーシカ）のように、1つ開けるとまた中に別のクエリが入っているイメージです。

① サブクエリとは② スカラー③ 列サブクエリ④ テーブルサブクエリ⑤ 相関サブクエリ📝 Quiz
①

サブクエリとは何か

JOINとの使い分け

サブクエリは、欲しい結果を出すのにクエリが1本では足りないときに使います。それぞれのサブクエリは、外側のクエリが使うテーブルの一部（値・値のリスト・行のかたまり）を先に用意する役割を持ちます。いわば「もう一段階、精密なフィルタリング」です。集計関数を別テーブルの基準として使ったり、あるテーブルの列がまるごと別テーブルに存在するかどうかを調べたり、複数テーブルの複雑なデータアクセスを1本のクエリにまとめたりできます。

ただし注意点があります。一般的に、サブクエリはJOINよりも計算コストが高くなりがちです。例外はありますが、JOINで書けるならJOINの方が好まれることが多いです。それでもサブクエリには独自の使いどころがあり、特に「スカラー値で絞り込みたい」「複数テーブルをまたいだ複雑なJOINを整理したい」ときに威力を発揮します。

いつJOINを使うかいつサブクエリを使うか
複数テーブルの列を横に並べて1つの結果セットとして表示したい先に計算した1つの値・値のリストで、外側のクエリを絞り込みたい
単純に「テーブルAとテーブルBを繋ぐ」だけで表現できる集計関数（AVGなど）の結果を、ハードコードせずに条件として使いたい
パフォーマンスを優先したい（一般にJOINの方が効率的）3つ以上のテーブルをまたぐ複雑なJOINを、論理的に整理したい
結果に複数テーブルの列をそのまま表示する必要がある「このテーブルに存在するかどうか」だけを判定したい（表示は不要）

サブクエリには4つの種類があります——スカラー（単一の値）、列（1列・複数行のリスト）、テーブル（複数列・複数行のかたまり）、そして相関（外側の各行ごとに再実行される）です。このページではスカラー・列・テーブルを扱い、相関サブクエリは⑤で扱います。

🍎 かんたん説明

サブクエリ＝クエリの中に入ったもう1つのクエリ。JOINで書ける単純な結合ならJOINの方が速い。でも「先に値を計算してから絞り込みたい」ときはサブクエリの出番です。

②

スカラーサブクエリ

1つの値を返す — WHEREでよく使う

スカラーサブクエリ（scalar subquery）は、ただ1つの値を返すサブクエリです。WHERE句の中でよく使われ、片方の値と比較する場面で活躍します。AVG・MAX・MINのような集計関数を使って、「あるテーブルの集計値を、別の比較の基準にする」というのが典型的な使い方です。

例えば「平均より単位数（tot_cred）が多い学生を知りたい」としましょう。平均値をあらかじめ計算して数字をハードコードしてしまうと、後でデータが増えて平均が変わったときにクエリを書き直す必要が出てきます。そこでスカラーサブクエリを使い、平均を毎回その場で計算させます。

SELECT name, tot_cred
FROM student
WHERE tot_cred > (SELECT AVG(tot_cred) FROM student);
name | tot_cred ------------+---------- Zhang | 102 Shankar | 105 Brandt | 96 Bourikas | 98 (4 rows)

ポイントは、カッコの中の(SELECT AVG(tot_cred) FROM student)が完全に独立したもう1本のクエリだということです。SELECTがあり、FROMがあり——最低限これだけあれば成立します。実行されると単一の数値（例えば平均が94.4だったとする）に置き換わり、結果としてWHERE tot_cred > 94.4のように動きます。返すのが単一の値なので、エイリアス（別名）を付ける必要はありません——列や表としてではなく、そのまま比較値として使われるからです。

📌 スカラーサブクエリは「変数のようなもの」——データが変わるたびに、比較の基準となる値も自動的に更新されます。数字を決め打ちしないことで、クエリが正しさを保ち続けます。
🍎 かんたん説明

スカラーサブクエリはカッコの中で1つの数字を計算し、その数字をWHEREでの比較に使う。AVGなど集計関数と組み合わせるのが定番です。

③

列サブクエリ

WHERE x IN (SELECT ...) — 値のリストと比較

列サブクエリ（column subquery）は、1つの列・複数行——つまり値のリストを返すサブクエリです。横に伸ばせば単なるリストと同じなので、WHERE 列 IN (SELECT ...)という形でよく使われます。「このテーブルの値が、あの別テーブルの列に存在するかどうか」を調べるのに向いています。これはINNER JOINとかなり似た働きをしますが、JOINで書くと問題が起きるケースでは列サブクエリが便利です。

例：「CS-101を履修したことのある学生の名前を知りたい」場合、まずtakesテーブルからCS-101を履修したstudent_idのリストを作り、それをstudentテーブルのstudent_idと比較します。

SELECT name
FROM student
WHERE student_id IN (SELECT student_id FROM takes WHERE course_id = 'CS-101');
name ----------- Zhang Shankar Levy (3 rows)

カッコの中のSELECT student_id FROM takes WHERE course_id = 'CS-101'は1列だけを返します。だからWHERE ... IN (...)の形でそのまま「このリストに含まれるか」を判定できます。列は1つだけなので、こちらもテーブルとしてのエイリアスは不要です——結合するテーブルではなく、比較用の値リストとして扱われるからです。

📌 列サブクエリはINNER JOINに似ていますが、常に置き換えられるわけではありません。「存在するかどうかだけ知りたくて、相手のテーブルの列は表示に使わない」場合は、JOINよりも列サブクエリの方がシンプルに書けることがあります。
🍎 かんたん説明

列サブクエリはリストを返す。WHERE 列 IN (SELECT 列 FROM ... WHERE ...)の形で、「このリストに入っているか」を調べるのに使います。

④

テーブルサブクエリ

導出テーブル（derived table）としてJOINする

テーブルサブクエリ（table subquery）は、複数列・複数行——つまり丸ごと1つの「テーブルのようなもの」を返すサブクエリです。実在しない一時的なテーブルをその場で組み立てて、それをFROM句やJOIN句で使う、というのが基本の使い方です。これは導出テーブル（derived table）と呼ばれます。列や値のリストとは違い、複数列を持つ「テーブル」として扱われるため、必ずテーブルエイリアスが必要です。

特に便利なのは、3つ以上のテーブルをまたいで複雑にJOINしなければならない場面です。「テーブルAとテーブルCを直接つなぐ共通列が無いが、テーブルBを経由すればつながる」というようなとき、先にテーブルB相当の導出テーブルを作ってから結合する、という使い方ができます。また、テーブルサブクエリの中では通常のクエリと同じようにWHERE・集計関数・GROUP BYなどを自由に使えます——これは単なるJOINにはできないことです。

例：学科ごとの平均単位数を先に導出テーブルとして作り、それに学生本人の単位数を比較したいとします。

SELECT s.name, s.dept_name, s.tot_cred, d.avg_credits
FROM student AS s
JOIN (
    SELECT dept_name, AVG(tot_cred) AS avg_credits
    FROM student
    GROUP BY dept_name
) AS d
ON s.dept_name = d.dept_name;
name | dept_name | tot_cred | avg_credits ----------+------------+----------+------------- Zhang | Comp. Sci. | 102 | 92.50 Shankar | Comp. Sci. | 105 | 92.50 Brandt | History | 96 | 88.00 (3 rows)

カッコの中のSELECT dept_name, AVG(tot_cred) AS avg_credits FROM student GROUP BY dept_nameは、それ自体が完結したクエリで、学科ごとの平均単位数という複数行のテーブルを作り出します。それにAS dというエイリアスを付けて、まるで実在のテーブルであるかのようにstudentとJOINしています。

📌 テーブルサブクエリは「その場限りの一時テーブル」を作ってJOINするイメージです。普通のテーブルと同様に必ずエイリアスを付け、結合条件（ON）で共通の列を指定します。
🍎 かんたん説明

テーブルサブクエリは複数列・複数行を返す。(SELECT ... ) AS 別名の形でJOIN句の中に置き、あたかも本物のテーブルのように使います。

⑤

相関サブクエリ

correlated subquery — 外側の行ごとに毎回実行される

相関サブクエリ（correlated subquery）は、外側のクエリと内側のクエリの間に依存関係があるサブクエリです。これまで見た3種類は「サブクエリを1回だけ実行して、その結果を外側が使う」という流れでしたが、相関サブクエリは違います。内側のクエリが、外側のクエリの「今見ている行」を参照するため、外側の行が変わるたびに内側が再計算されます。いわば、外側のクエリを完成させる前に必ず通らなければならない「内側の関所」です。

例：「各教員が何人の学生を指導しているか」を知りたいとします。instructorテーブルには学生数の列がないので、advisorテーブルから数える必要がありますが、それを別テーブルから直接SELECTすることはできません。そこで相関サブクエリを使い、instructorの各行のinstructor_idをadvisor側の条件に埋め込みます。

SELECT name, dept_name,
    (SELECT COUNT(*) FROM advisor WHERE advisor.instructor_id = instructor.instructor_id) AS num_advisees
FROM instructor
ORDER BY dept_name, name;
name | dept_name | num_advisees ------------+------------+-------------- Brandt | Comp. Sci. | 3 Katz | Comp. Sci. | 1 Kim | Elec. Eng. | 0 Srinivasan | Finance | 2 (4 rows)

ここでのinstructor.instructor_idは外側のクエリの、今処理している行を指しています。GROUP BYを使わなくても、この書き方だけで「教員1人につき1つのカウント」が自動的に得られます。

通常のサブクエリ vs 相関サブクエリ：実行される回数の違い
1️⃣
通常のサブクエリ（スカラー・列・テーブル）内側のクエリは最初に1回だけ実行され、その結果を外側が使い回す
↓
🔁
相関サブクエリ外側の行が1件処理されるたびに、内側のクエリがその行の値を使って毎回再実行される
↓
👨‍🏫
例：instructorが4人いれば内側のSELECT COUNT(*) FROM advisor WHERE ...が4回——教員ごとに1回ずつ実行される
外側の1行 → 内側を1回実行、を行数分くり返すのが相関サブクエリの動き方。
⚠️ 複合主キー（composite primary key）を持つテーブルをJOINやサブクエリで経由すると、行が重複・増殖することがあります。例えばtakesテーブルの主キーはstudent_id, course_id, section_id, semester, yearの組み合わせ全体です。同じcourse_idでも学期やセクションが違えば「別の行」として扱われるため、DISTINCTを付けたつもりでも意図した列だけで重複が消えないことがあります。相関サブクエリで外側の1行ごとに計算させる、あるいはSELECT DISTINCTで本当に消したい列を明示するなど、複合主キーの構造を理解した上で重複を防ぐ工夫が必要です。
🍎 かんたん説明

相関サブクエリは、外側の行1つにつき内側のクエリを1回ずつ実行する「行ごとの再計算」です。GROUP BYなしで「行ごとの集計値」を1列として追加できます。複合主キーのテーブルを扱うときは、行の重複に注意しましょう。
