M8 · Common Table Expressions — Part 1 🍎

🍎 超やさしい版：CTE①（WITH句）

問題を解くときに使う「下書きメモ」を作る方法です。まずCTEとは何かを知り、例題で動かして、サブクエリとの違いを見ます。

CTEって何例題 20,000ドル超サブクエリとの違い🧱 本編はこちら
①

CTEって何？

途中の答えに名前を付ける

🎯 これだけ覚えればOK

CTE＝問題を解く間だけ使える「下書きメモ」。WITH 名前 AS ( ... )で作って、あとで表のように使う。

📝
宿題を解くとき、先に途中の計算を紙に書いておくと、最後がラクですよね。CTEはそのSQL版です。

CTE（シーティーイー）は、途中の答えに名前を付けておくしくみです。サブクエリのように式の中に埋めこまず、文のいちばん上に書きます。そのため、あとから読んでもよく分かります。

▶ いちばん小さいCTE（金額15,000以上の融資）

WITH big_loans AS (
    SELECT loan_number, amount
    FROM loan
    WHERE amount >= 15000
)
SELECT * FROM big_loans;
loan_number | amount ------------+------- L-201 | 15000 L-203 | 22000
🧹
CTEはその1回のSQLが終わると消えます。テーブルとして保存されるわけではありません。
🍎 ひとことで

WITHで名前を付けたメモを作り、そのあとのSELECTでFROM 名前と書けば、普通のテーブルのように使えます。

🤔 答えられるかな？（クリックで答えが開く）

Q1. CTEはどのキーワードで始める？A. WITH。WITH 名前 AS ( ... )の形。
Q2. 文が終わったらCTEはどうなる？A. 消える。次の文では、もう一度書かないと使えない。
②

例題：20,000ドル超のお客さん

2段階で考える

🎯 これだけ覚えればOK

お客さんごとの合計をloan_totalsというCTEにして、あとから「20,000を超えた人」を選ぶ。

お題：融資の合計が20,000ドルを超えたお客さんは？（Bankingデータベース）

「合計が20,000を超えた」と言うには、まずお客さんごとの合計が必要です。だから、第1段階をloan_totalsにします。

▶ 全体のSQL

WITH loan_totals AS (
    SELECT b.customer_id, SUM(l.amount) AS total_loans
    FROM borrower b
    JOIN loan l ON b.loan_number = l.loan_number
    GROUP BY b.customer_id
)
SELECT c.customer_name, lt.total_loans
FROM loan_totals lt
JOIN customer c ON lt.customer_id = c.customer_id
WHERE lt.total_loans > 20000
ORDER BY lt.total_loans DESC;
customer_name | total_loans --------------+------------ Hank Irwin | 24000 Omar Diaz | 22000
✂️
2段階に分けるのがコツ。①かっこの中：合計を出す　②かっこの外：20,000超の人を選び、名前を付ける。

かっこの中のSELECTだけを単独で実行すると、10002が24000、10003が15000、10006が22000と出ます。これで、部品が正しく動いているか確かめられます。

🍎 ひとことで

名前（customer_name）はcustomerテーブルにあるので、メインのクエリでJOINして付け足します。1つ1つの部品はとても簡単です。

🤔 答えられるかな？（クリックで答えが開く）

Q1. なぜ最初に「お客さんごとの合計」を作るの？A. 「20,000を超えたか」を判断するには、先にお客さんごとの合計が必要だから。
Q2. customerをJOINするのはなぜ？A. CTEにはcustomer_idしかなく、名前はcustomerテーブルにあるから。
③

サブクエリとの違い

結果は同じ、読みやすさがちがう

🎯 これだけ覚えればOK

基本はサブクエリよりCTE（読みやすい）。ただしCTEが巨大だとメモリを食うので注意。

サブクエリCTE
書く場所式の中文の先頭
読みやすさ内側から読む上から順に読める
同じ式を何回も使うもう一度書く名前を呼ぶだけ
🧠
PostgreSQLは、CTEの結果をメモリに作って持っておきます。小さければ問題なし。巨大だとメモリを使いすぎて遅くなることがあります。
🍎 ひとことで

迷ったらCTE。結果はサブクエリと同じです。大きすぎる下書きだけ要注意。再帰CTE（自分を呼ぶCTE）という上級技もありますが、この授業の課題では使いません。

🤔 答えられるかな？（クリックで答えが開く）

Q1. CTEとサブクエリ、基本的にどっちを使う？A. 読みやすさのためにCTE（性能が心配なときを除く）。
Q2. CTEが巨大だとなぜ困る？A. 結果がメモリに置かれ続けて、メモリを使いすぎて遅くなることがあるから。

💡 まとめ

• CTE＝文の間だけ使える下書き

• WITH 名前 AS ( ... ) SELECT ...

• 小さい部品に分けて、1つずつ確かめる

• 基本はサブクエリよりCTE。巨大なCTEは注意
