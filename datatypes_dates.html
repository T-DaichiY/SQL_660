📅 日付・時刻データ型 — TIMESTAMP・DATE・TIME・INTERVAL

4つの日付/時刻データ型の違いと、INTERVALを使った日付の計算方法、そしてどの場面でどの型を選ぶべきかを学ぶ。

① 4つのデータ型② INTERVALで日付を計算する③ どの型をいつ使うか📝 Quiz
①

4つの日付・時刻データ型

TIMESTAMP・DATE・TIME・INTERVAL
型サイズ内容
timestamp8バイト日付＋時刻の両方。最もよく使われる。フォームの送信記録や取引記録など、精密な記録が必要な場面で多用される
date4バイト日付のみ（時刻を含まない）
time8バイト時刻のみ（日付を含まない）。00:00:00〜24:00:00の24時間制（軍隊式時間）で、AM/PMの概念はない
interval—「長さ」を表す時間の値（日数・月数・年数など）。特定の日時ではなく期間を表す

タイムゾーンを扱う — timestamptz

データを異なる地域・国から収集する場合、タイムゾーンの違いを考慮する必要があります。例えば東海岸標準時（EST）で入力されたフォームと、別のタイムゾーンで入力されたフォームでは、同じ「送信時刻」でも実際には数時間のズレが生じます。

CREATE TABLE form_submissions (
    submitted_at timestamp with time zone
);

timestampにはtimestamp with time zone（略してtimestamptz）という拡張があり、タイムゾーン情報を保持・調整できます。複数の地域からデータを集める場合はこちらを検討しましょう。

🍎 かんたん説明

timestamp＝日付＋時刻、date＝日付だけ、time＝時刻だけ、interval＝期間の長さ。複数タイムゾーンのデータを扱うならtimestamptzを使いましょう。

②

INTERVALで日付を計算する

「30日後」のような期日をタイムスタンプに足し引きする

INTERVALは、開始点・終了点ではなく「長さ」だけを表す値です。「90日」「1週間」「7時間」のように指定でき、他の日付・時刻型と組み合わせて計算に使うのが一般的な使い方です。

実例：請求書の支払期日を30日後に設定する

2022年12月1日に発生した取引について、そこから30日後の期日を自動で求めたいとします。

SELECT invoice_date,
       invoice_date + interval '30 days' AS due_date
FROM invoices
WHERE invoice_date = '2022-12-01';
invoice_date | due_date -------------+------------ 2022-12-01 | 2022-12-31

タイムスタンプにinterval '30 days'を足すだけで、30日後の日付が自動的に計算されます。60日後・90日後の期日を同様に計算すれば、期日ごとに未払いの請求書を抽出してリマインダーを送るような処理も組み立てられます。過去の日付を求めたい場合は、足し算(+)を引き算(−)に変えるだけです。

もう1つの例：24時間の変更猶予

SELECT order_time,
       order_time + interval '24 hours' AS can_cancel_until
FROM orders;

注文が確定してから24時間はキャンセル可能、という業務ルールも、order_time（timestamp）にinterval '24 hours'を足した値と現在時刻を比較することで実装できます。24時間が経過した時点で処理を確定させる、といったトリガーの発想にもつながります。

📌 INTERVALは日数・時間・分などを表す「変数のような値」と考えると分かりやすいです。timestampなど別の日付型と組み合わせて、未来・過去のある地点を計算するのが主な使い方です。エイリアス（AS）を使った計算方法は、別のレッスンでさらに詳しく扱います。
🍎 かんたん説明

INTERVALは「期間の長さ」を表す値。timestampに足せば未来の日付、引けば過去の日付が求められます。期日管理やキャンセル猶予の実装によく使われます。

③

どの型をいつ使うか

用途に応じた使い分け
場面おすすめの型理由
フォーム送信・オンライン注文・金銭取引timestamp（複数地域ならtimestamptz）正確な日時が必要。キャンセル猶予期間の計算や後からの追跡照会に日時両方が必須
過去の出来事・歴史的な記録date古いデータには時刻情報が記録されていない、または重要でないことが多い
イベントへの出席記録date「その日に来場したか」が重要で、正確な時刻までは必要ないケースが多い
繰り返し発生する特定の時刻のパターン（例：交通事故が多発する時間帯）time日付は無関係で、時刻のパターンだけを分析したい場合
💡 車の購入のように「その日に契約した」ことが重要な取引はdateで十分ですが、ローンの申し込みや決済のように正確な日時の記録が必要な取引はtimestampを使うべきです。用途によって同じ「取引」でも適した型が変わります。
🍎 かんたん説明

「正確な時刻まで必要か？」を自問しましょう。必要ならtimestamp、日付だけで十分ならdate、時刻のパターンだけを見たいならtimeを選びます。
