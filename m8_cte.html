M8 · Common Table Expressions — Part 1 (Lecture 4)

🧱 CTE①：WITH句で「下書き」を作る

サブクエリが何重にも入った式は、書くのも読むのも大変です。CTE（共通テーブル式）は、途中の答えに名前を付けて文の先頭に取り出し、あとから普通のテーブルのように使える仕組みです。この単元では、CTEとは何か、WITH ... ASの書き方、Bankingの例題、そしてサブクエリとの違いと性能の注意を学びます。

🎥 講義動画4「CTE part 1」 ・ 📖 Practical SQL 第2版 第13章「Advanced Query Techniques」（サブクエリ・CTE）。教科書だけの追加内容はM8+にあります。

①

CTE（共通テーブル式）とは？

一時的な結果セットに名前を付けて使う

講義の言葉でいうと、CTE（Common Table Expression、共通テーブル式）は「SQL文の中で使う一時的な結果セット」です。一時的なテーブル、変数、リストのようなもので、操作をしている間だけデータを手元に置いておくための入れ物だと考えてください。

CTEのイメージ
🧩
① 部品を作る（WITH ... AS）複雑な問題の「第1段階の答え」に名前を付けて、小さな一時テーブルとして用意する
↓
🔧
② 部品を使う（メインのSELECT）名前を呼ぶだけで、普通のテーブルと同じように列を選んだりJOINしたりできる
↓
🧹
③ 文が終わると消えるCTEはそのSQL文の間だけ存在する。テーブルとして保存されるわけではない
M6のサブクエリでは、こうした部品をFROM (...)やWHERE (...)の中に埋め込みました。CTEは、それを文の先頭に名前付きで取り出す書き方です。

講師が強調していたCTEの利点は次の4つです。

  • 読みやすさ・保守しやすさ：直したい部分を見つけて、そこだけ直せばよい。入り組んだサブクエリをたどる必要がない。
  • モジュール化：大きな問題を小さな部品に分けられる。
  • 単体テストがしやすい：部品ごとに単独で実行して、結果を確かめてから全体を組み立てられる。
  • 再利用：一度定義すれば、同じ文の中で何回でも参照できる。しかもテーブルのように列も値も参照できる。
📌 講師の強調：CTEの目的は、速さよりも「複雑なクエリを書きやすく、読みやすくすること」です。サブクエリを詰め込んで、順番をあれこれ確認する必要がなくなります。

もう1つ、講義で名前だけ紹介された機能に再帰CTE（recursive CTE）があります。再帰とは「自分自身を呼び出して、同じ処理を繰り返す」ことで、社長 → 副社長 → 部長 → …のような親子関係（階層データ）をたどるときに使います。普通なら何度もJOINが必要な場面を、「次へ、次へ」と順に進める形で書けます。この授業の課題では使いませんが、m8_plusで詳しく扱います。

🍎 かんたん説明

CTEは「問題を解くための下書きメモ」です。いきなり1つの巨大な式を書かず、途中の答えに名前を付けてメモしておき、最後にそのメモを組み合わせます。メモはその問題を解いている間だけ使えます。

💻 ミニ練習：CTEを1つ作ってみる

branchテーブルから、assetsが4,000,000より大きい支店を取り出すbig_branchesというCTEを作り、メインのSELECTでそのCTEの全列を表示してください。

WITH big_branches AS (
    SELECT branch_name, branch_city, assets
    FROM branch
    WHERE assets > 4000000
)
SELECT * FROM big_branches;

結果は3行（Brooklyn Bank、Midtown Bank、Downtown Bank）。CTEの中身は普通のSELECT文で、メインのSELECTからは普通のテーブルのように呼び出せます。

②

CTEの書き方：WITH ... AS

かっこの中で一時テーブルを作り、外で使う

CTEはWITH句で作ります。基本の形は次のとおりです（講義のスライドと同じ構造です）。

WITH cte_name AS (
    SELECT col1, col2        -- CTEの中身：普通のSELECT
    FROM some_table
    WHERE ...
)
SELECT *                     -- メインのクエリ：CTEを表のように使う
FROM cte_name;

読み方の順番は、(1) WITHで始める → (2) 名前を付ける → (3) AS → (4) かっこの中に、その一時テーブルを作るクエリを書く → (5) かっこの外で使うです。ASはM4のエイリアス（別名）で見慣れた形で、「この結果セットを〇〇と呼ぶ」という意味です。

覚えておきたいルールを整理します。

ルール内容
名前は自由cte_nameはemployee_salariesでもloan_totalsでもよい。中身が分かる名前にするのが良い。
テーブルと同じに使える列を選ぶ、WHEREで絞る、他のテーブルとJOINする、GROUP BYする、エイリアスを付ける、など全部できる。
何回でも参照できる同じ文の中なら、メインのクエリで複数回呼んでも、他のCTEから呼んでもよい。
中身に集計もJOINも書けるSUMやGROUP BYを含むSELECTでも、複数テーブルのJOINでもよい。CTEが別のCTEを参照することもできる（次のページ）。
その文の間だけセミコロンで文が終わると消える。次の文では使えない（保存されない）。

教科書（Listing 13-13、p.335–336）のCTEは、名前のあとに列名リストを書く形でした。WITH 名前 (列名1, 列名2) AS (...)です。列名リストの要点は次のとおりです。

  • CREATE TABLEのようなデータ型の指定は不要。型は中のSELECTから引き継がれます。
  • 中のSELECTは、リストと同じ数の列を返す必要があります（列名は一致しなくてよい）。
  • 列名を付け替えないなら、列名リストは省略可能です（講義の書き方）。
WITH big_loans (loan_no, amt) AS (
    SELECT loan_number, amount
    FROM loan
    WHERE amount >= 15000
)
SELECT loan_no, amt
FROM big_loans
ORDER BY amt DESC;
loan_no | amt --------+------ L-203 | 22000 L-201 | 15000

教科書は、CTEを「1つ以上のSELECTで一時テーブルをあらかじめ定義し、メインのクエリで必要なだけ参照する」もので、非公式にはWITH queryとも呼ばれる、と説明しています。

⚠️ CTEは「テーブルを作る」わけではありません。WITH ... SELECT ...;を実行して、結果を取り出したら、CTEは役目を終えて消えます。あとで同じ名前を使いたければ、その文の先頭にもう一度WITHを書く必要があります。

まず、いちばん簡単な例で動きを確かめましょう。Bankingデータベースのloanテーブル（融資）から、金額が15,000以上のものだけをCTEに入れます。

WITH big_loans AS (
    SELECT loan_number, branch_name, amount
    FROM loan
    WHERE amount >= 15000
)
SELECT loan_number, amount
FROM big_loans
ORDER BY amount DESC;
loan_number | amount ------------+------- L-203 | 22000 L-201 | 15000 (2 rows)

この例ではbig_loansを1回しか使っていないので、CTEにする必要はあまりありません（ただWHEREを書けば済みます）。CTEの本当の力は、集計した結果をもう一度絞ったり、他のテーブルとJOINしたりするときに出てきます。次の単元で見ましょう。

🍎 かんたん説明

WITH 名前 AS ( ... )で「下書きメモ」を作り、そのあとのSELECTでFROM 名前と書けば、普通のテーブルのように使えます。メモはその文が終わると消えます。

💻 ミニ練習：CTEからORDER BYで取り出す

loanテーブルからamountが10,000以上の融資を取り出すmid_loansというCTEを作り、メインのSELECTでloan_numberとamountをamountの小さい順に表示してください。

WITH mid_loans AS (
    SELECT loan_number, amount
    FROM loan
    WHERE amount >= 10000
)
SELECT loan_number, amount
FROM mid_loans
ORDER BY amount;

結果は2行（L-201の15000、L-203の22000）。ORDER BYはCTEの中ではなく、メインのクエリ側に書いています。

③

例題：loan_totals CTE（Banking）

お客さんごとの融資合計 → 20,000ドル超を選ぶ

講義の例題です。「すべての支店をあわせた融資の合計額が20,000ドルを超えるお客さんの一覧を出す」。使うのはBankingデータベースのcustomer、borrower、loanです（講義のDDLと全く同じではありませんが、似た構造です）。

  • customer：お客さん（customer_id、customer_nameなど）
  • borrower：誰がどの融資を借りているか（customer_id、loan_number）
  • loan：融資そのもの（loan_number、branch_name、amount）

課題文を見て、論理的な第1歩を探します。「お客さんごとの融資の合計額」が分からないと、20,000ドルを超えたかどうか判断できません。つまり第1段階＝お客さんごとの合計融資額で、これを最初のCTEにします。

▶ ステップ1：CTEだけを単独で動かして確かめる（単体テスト）

SELECT b.customer_id, SUM(l.amount) AS total_loans
FROM borrower b
JOIN loan l ON b.loan_number = l.loan_number
GROUP BY b.customer_id;
customer_id | total_loans ------------+------------ 10002 | 24000 10003 | 15000 10006 | 22000 (3 rows)

customer_idはborrowerから、amountはloanから来るので、loan_numberでJOINして、customer_idごとにGROUP BYで合計しています。融資を借りているのは3人だけです。これがloan_totalsというCTEの中身になります。

▶ ステップ2：CTEにして、メインのクエリで20,000ドル超を選ぶ

WITH loan_totals AS (
    SELECT b.customer_id, SUM(l.amount) AS total_loans
    FROM borrower b
    JOIN loan l ON b.loan_number = l.loan_number
    GROUP BY b.customer_id
)
SELECT c.customer_id, c.customer_name, lt.total_loans
FROM loan_totals lt
JOIN customer c ON lt.customer_id = c.customer_id
WHERE lt.total_loans > 20000
ORDER BY lt.total_loans DESC;
customer_id | customer_name | total_loans ------------+---------------+------------ 10002 | Hank Irwin | 24000 10006 | Omar Diaz | 22000 (2 rows)

メインのクエリが何をしているかを順に見ます。

  • loan_totalsにltという短いエイリアスを付けています（講師も「短くするため」と説明）。
  • 課題は「お客さんの一覧」なので、名前が必要です。ところがloan_totalsにはcustomer_idしかなく、customer_nameはcustomerテーブルにあります。そこでcustomer_idでJOINします。
  • 集計の結果を絞る条件total_loans > 20000は、メイン側のWHEREに書けます。CTEが集計を終わらせているので、HAVINGは要りません。
  • 最後に金額の大きい順に並べて完成です。
📌 講師のポイント：CTEの側は「単一のJOIN＋集計」、メインの側は「単一のJOIN＋WHERE」と、どちらも単純なクエリです。これを1つの文に押し込むと、「リストに入っているか」というようなややこしい書き方が必要になります。分けて書くから簡単になるのです。
⚠️ 融資を借りていないお客さん（10001、10004など）はborrowerに出てこないので、loan_totalsにも載りません。この例題は「20,000超」を探すので問題になりませんが、「融資のない人も0として載せたい」場面ではLEFT JOINが必要になります。
🍎 かんたん説明

① まず「お客さんごとの合計」をloan_totalsとしてメモ → ② そのメモから「20,000を超えた人」を選び、名前をcustomerから付け足す。2回に分けるだけで、1つ1つはとても簡単になります。

💻 ミニ練習：合計が15,000以下の人を探す

loan_totalsというCTE（上の例と同じ定義）を作り、メインのクエリで合計が15,000以下のお客さんのcustomer_nameとtotal_loansを表示してください。

WITH loan_totals AS (
    SELECT b.customer_id, SUM(l.amount) AS total_loans
    FROM borrower b
    JOIN loan l ON b.loan_number = l.loan_number
    GROUP BY b.customer_id
)
SELECT c.customer_name, lt.total_loans
FROM loan_totals lt
JOIN customer c ON lt.customer_id = c.customer_id
WHERE lt.total_loans <= 15000;

結果は1行（Maria Chen、15000）。CTEの定義は同じで、メイン側の条件だけを変えました。CTEは部品なので、条件の変更がとても簡単です。

④

CTE と サブクエリ、そして性能の注意

基本はCTE、ただし巨大なCTEには注意

講師は「一般的には、性能の問題が出そうな場合を除いて、サブクエリよりCTEを使う」と言っています。まず、同じ結果になるサブクエリ版（M6の書き方）と比べてみましょう。

▶ サブクエリ版（FROMの中に集計を埋め込む）

SELECT c.customer_id, c.customer_name, t.total_loans
FROM customer c
JOIN (
    SELECT b.customer_id, SUM(l.amount) AS total_loans
    FROM borrower b
    JOIN loan l ON b.loan_number = l.loan_number
    GROUP BY b.customer_id
) t ON t.customer_id = c.customer_id
WHERE t.total_loans > 20000
ORDER BY t.total_loans DESC;
customer_id | customer_name | total_loans ------------+---------------+------------ 10002 | Hank Irwin | 24000 10006 | Omar Diaz | 22000 (2 rows)

結果はCTE版とまったく同じ（Hank Irwin 24000、Omar Diaz 22000）です。違いは書き方だけです。

📖 教科書では：FROMの中に置いたサブクエリを派生テーブル（derived table）と呼びます（p.323）。上のtがまさにそれです。教科書のListing 13-4（p.325）は、2つの派生テーブルをJOINして州ごとの比率を出しますが、Listing 13-14（p.337）は同じ処理を2つのCTEで書き直し、「結果はまったく同じだが、CTEの方が理解しやすい」と述べています。つまり派生テーブルとCTEは結果が同じで、違いは読みやすさです。
サブクエリCTE（WITH）
置き場所FROM／WHEREの中に埋め込む文の先頭に取り出す
名前エイリアス（tなど）が必要な場合がある最初から意味のある名前が付く（loan_totals）
読み方内側から外側へたどる上から下へ、書いた順に読める
再利用同じ式をもう一度書く必要がある名前を呼ぶだけで何回でも使える
テスト切り出して単独で動かす作業が必要かっこの中をそのまま単独で実行できる
向いている場面短い・1回しか使わない部品複雑・複数回使う・手順を分けたいとき

教科書がCTEを使う理由としてあげるのは、① 読みやすいコード、② 重複の削減、③ 修正のしやすさです。②の例（Listing 13-15、p.337–338）では、中央値を出すサブクエリを2か所に書いていたものを、CTE（us_median）として1回だけ書き、CROSS JOINで全行に使えるようにしています。1行1列のCTEをCROSS JOINする形は、このページの練習④の形と同じです。

では、CTEに弱点はないのでしょうか。講師が挙げた性能（パフォーマンス）の注意点があります。

  • PostgreSQLでは、CTEは既定でマテリアライズ（materialized）されます。つまり、CTEを作ると、その結果がハードディスクではなく、一時的なメモリに実際に作られて保持されます。
  • CTEが小さい（1つの値、短いリスト）なら、メモリに置いても負担は軽く、後続の処理がむしろ効率的になることもあります。
  • CTEが巨大（テーブルの大部分を丸ごと入れるなど）だと、メモリを大量に使い、かえって遅くなることがあります。CTEの中身はクエリが終わるまでメモリに残ります。
  • PostgreSQL 12以降にはインライン化（NOT MATERIALIZED）という最適化があります。CTEを別のテーブルとして作らず、メインのクエリに埋め込んで実行する仕組みです。講師は「この課題では使わない」と言っているので、「そういうものがある」と知っていれば十分です。
📌 選び方の目安：① 読みやすさ・分かりやすさを重視するならCTE。② 部品が巨大でメモリが心配なら、サブクエリやJOINに戻すことも考える。③ 迷ったらCTEで書いて、遅いと分かったときに見直す。
⚠️ 💡 PostgreSQLでは上の「メモリに保持」の動きが重要ですが、この演習アリーナのSQLite（実行エンジン）は内部で独自に最適化します。学習のうえでは、結果が同じになること、書き方の違いを押さえてください。性能の違いを体感するための環境ではありません。
🍎 かんたん説明

サブクエリは「式の中に埋めた下書き」、CTEは「式の前に置いた下書き」。結果は同じですが、CTEの方が読みやすく、名前も付きます。ただし、大きすぎる下書きはメモリを食うので気をつけましょう。

💻 ミニ練習：サブクエリをCTEに書き直す

次のサブクエリ版を、avg_salaryというCTEを使う形に書き直してください：
SELECT employee_name, salary FROM employees WHERE salary > (SELECT AVG(salary) FROM employees);
CTEにはAVG(salary)をavg_salという列名で入れ、メインではemployeesとCTEをカンマ区切りで結び（CROSS JOIN）ます。

WITH avg_salary AS (
    SELECT AVG(salary) AS avg_sal
    FROM employees
)
SELECT e.employee_name, e.salary
FROM employees e, avg_salary a
WHERE e.salary > a.avg_sal
ORDER BY e.salary DESC, e.employee_name;

平均給与は57,800で、それを超える9人が出ます。1行1列のCTEは「定数」のように使えて、メインのクエリのWHEREが読みやすくなります。

PostgreSQL 12以降の最適化。CTEを別に実体化せず、メインのクエリへ埋め込んで実行する（NOT MATERIALIZED）。

再帰CTE
自分自身を参照して繰り返し処理するCTE。親子関係などの階層データをたどるときに使う。
