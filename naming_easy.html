テーブル・列の名前は、全部小文字＋アンダースコア（snake_case）でそろえるのが基本です。

3つの書き方

同じ言葉でも書き方は色々

🎯 これだけ覚えればOK

PostgreSQLではsnake_case（全部小文字＋アンダースコア）を使う。他の書き方もあるが、これが業界標準。

書き方例よく使われる場所
camelCaseberrySmoothieプログラミング言語の変数名
PascalCaseBerrySmoothieT-SQL・Microsoft系
snake_caseberry_smoothiePostgreSQL（このコースの標準）
🐍
良い名前は3つのC——specific・concise・consistent。具体的で、簡潔で、一貫している名前を選びましょう。
🍎 ひとことで

迷ったら全部小文字＋アンダースコア。それがsnake_case。

①

小文字化される・引用符は例外

Customers = customers

▶ 大文字で作ったつもりが…

CREATE TABLE customers (...);   -- 1回目：OK
CREATE TABLE Customers (...);   -- 2回目：同じ名前とみなされる
ERROR: relation "customers" already exists
🔡
クォートなしの名前は、PostgreSQLが自動で全部小文字にします。だからCustomersとcustomersは同じテーブルです。
書き方結果
CREATE TABLE Customers小文字化されて customers になる
CREATE TABLE "Customers"大文字小文字を区別する別テーブルになる（要：毎回引用符）

🤔 答えられるかな？（クリックで答えが開く）

Q1. なぜ2回目のCREATE TABLEでエラーになる？A. Customersが小文字化されてcustomersと同じ名前になるから。
Q2. 引用識別子を使うとどうなる？A. 大文字小文字が区別されるが、参照のたびに引用符が必要になる。
🍎 ひとことで

引用符は「例外」。普段はクォートなしのsnake_caseで統一しよう。

②

命名の指針5か条

これを守れば迷わない
指針例
① snake_casearrival_time
② 分かりやすくarv_tm ✗ → arrival_time ○
③ テーブル名は複数形teachers（例外：course）
④ 長さ制限PostgreSQLは63バイトまで
⑤ コピーには日付vehicle_parts_2021_04_08
🆔
全テーブルにidという列があると、どのテーブルのidか分からなくなる。student_idのようにテーブル名を付けよう。

🤔 答えられるかな？（クリックで答えが開く）

Q1. テーブル名は単数形と複数形どちらが基本？A. 複数形（1行=1件のデータの集まりだから）。
Q2. PostgreSQLの識別子の長さ上限は？A. 63バイト。
Q3. すべてのテーブルにidという列があると何が困る？A. どのテーブルのidか名前だけでは分からなくなる。

💡 まとめ

• テーブル・列名はsnake_case

• クォートなしは自動で小文字化される

• 引用識別子は例外的に使う

• テーブル名は複数形＋idにはテーブル名を付ける
