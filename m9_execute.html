①

テーブルを作って、データを入れる

execute を2回呼ぶ

Part 3では、前のPartで作った接続を使って、実際にコマンドを実行します。講師の例は「testというテーブルを作り、値を入れる」です。使うデータベースは M9 用のもの（講義では「module 9 database」）です。

テーブルの中身は、serial型のID、整数のnum列、varcharのdata列。1つ目のexecuteがCREATE TABLE、2つ目がINSERTです。どちらもSQLそのもので、特別なことはありません。

import psycopg2

conn = psycopg2.connect(dbname="module9", user="postgres", password="your_password")
cur = conn.cursor()

cur.execute("""
    CREATE TABLE test (
        id SERIAL PRIMARY KEY,
        num INTEGER,
        data VARCHAR(50)
    );
""")

cur.execute("INSERT INTO test (num, data) VALUES (100, 'abc');")

conn.commit()
cur.close()
conn.close()
  • id SERIALは自動で番号が振られる列。PRIMARY KEYを付けるのが一般的です（講義では「serial型のID」と説明）。
  • INSERTの値（100と'abc'）は、説明用の例です。
  • 最後にcommit → カーソルを閉じる → 接続を閉じる。これで完了です。
⚠️ 引用符に注意。Pythonの文字列を"（ダブルクォート）で囲むと、中のSQLの文字列値は'（シングルクォート）にします。講師によれば、エスケープ文字のトラブルを避けるため三重引用符 """を使う人もいます（上のCREATE TABLEがその書き方）。
🍎 かんたん説明

executeは「SQLの文を、そのまま引用符の中に入れて渡す」だけです。M5・M1で覚えたCREATE TABLEとINSERTが、そのまま使えます。

💻 ミニ練習：INSERTを実行する

既に作ったtestテーブルに、num = 200、data = 'xyz'の行を追加するcur.execute(...)を1行で書いてください。

cur.execute("INSERT INTO test (num, data) VALUES (200, 'xyz');")

Python側は"…"、SQLの文字列値は'…'。末尾の;はSQLの終わりです。

②

ファイルを実行する

コマンドラインで python ファイル名.py

書いたファイルは、実行してはじめて動きます。講師はVS Codeでの実行（Ctrl+F5、またはメニューの「Run」→「Run without debugging」）と、コマンドラインでの実行の両方を見せます。メモ帳派の人はコマンドラインが必要です。

手順（Windows）：

  1. Pythonファイルを保存したフォルダ（講師は Documents の中に PySQL フォルダを作成）に移動する。
  2. コマンドプロンプトで cd documents\PySQL と入力する。
  3. 近道：エクスプローラーでそのフォルダを右クリックして「ターミナルで開く」。cdが要りません。
  4. python ファイル名.py と入力して Enter。
cd documents\PySQL
python full_file.py
⚠️ ファイル名だけを入力して Enter すると、「どのアプリで開きますか？」と聞かれます（講師もここで間違えました）。必ず先頭にpythonを付けること。ファイル名は自分のものに置き換えます（講義では「full file」のようなファイル）。
🍎 かんたん説明

pythonは「このPythonで動かして」という合図です。ファイル名だけでは、Windowsが「どのアプリで開く？」と迷ってしまいます。

③

動いたかどうか確かめる

何も表示されないのは、成功のしるし

実行しても何も表示されません。講師は「それは良いこと」と言います。理由は、今回のファイルにprint（「接続できた」などの出力）を入れていないからです。出したければprintを足せます。

確認は pgAdmin で行います。

  1. pgAdminで該当のデータベースを選び、SELECT * FROM test;を実行する。
  2. 行が入っていれば成功。左のツリーで「Tables」をリフレッシュすると、testテーブルも見えます。
SELECT * FROM test;
id | num | data ----+-----+------ 1 | 100 | abc
📌 テーブルがpgAdminに出てこないときは、まずツリーのリフレッシュを。それでもなければ、commitが書かれているか、データベース名が正しいかを確認します（下の補足）。
💻 ミニ練習：確認のSQL

pgAdminでtestテーブルの全行を確認するSQLを書いてください。

SELECT * FROM test;

Pythonで変更したデータは、pgAdminの通常のSELECTでそのまま確認できます。

補足：よくあるエラーと、次の講義

講義外の内容（参考）

以下は講義の内容ではなく、つまずきやすい点の補足です。

症状よくある原因
password authentication faileduserかpasswordが違う
database "..." does not existdbnameの綴り違い、または別のデータベースに作った

講師は、最後に「次の講義ではクエリを実行して結果を保存する方法を見る」と予告しています（その録音はまだありません）。講義の冒頭の説明では、検索のときはカーソルではなくpandasでDataFrameに保存します。参考に、標準的な書き方の例です。

import pandas as pd
import psycopg2

conn = psycopg2.connect(dbname="module9", user="postgres", password="your_password")
df = pd.read_sql_query("SELECT * FROM test;", conn)
print(df)
conn.close()
📝 講義外の補足：psycopg2の接続をpandasに渡すと、バージョンによって警告が出ることがあります（SQLAlchemyの利用が推奨されるため）。結果は取得できます。講義の公式の書き方が出たら、そちらに合わせてください。
