M7 · Data Wrangling — Transactions, Splitting & Dropping

🔒 データ整形③：トランザクション・分割・削除

データを書き換える作業は、間違えると元に戻せません。そこでトランザクションで「お試し」しながら作業する方法を学び、その総まとめとして、salary_estimate（例：'$110K-$163K (Glassdoor est.)'）を数値の下限・上限の2列に分割する実践例に取り組みます。最後は不要になった列・テーブルの削除（DROP）です。

①

トランザクションとは（COMMITとROLLBACK）

変更を「確定する前」に試して、確認して、取り消せる

これまで UPDATE や ALTER TABLE を1本ずつ実行してきました。しかし、データ整形では「まとめて何本も実行してから、結果を確かめたい」場面が増えます。そこで登場するのがトランザクション（transaction）です。複数のコマンドを1つの作業のまとまりとして囲み、結果を確認してから「確定（COMMIT）」するか「取り消し（ROLLBACK）」するかを選べる仕組みです。ゲームの「セーブ前のお試しプレイ」や、文書編集の「元に戻す」に近いイメージです。

📝 この教材の練習用データ（30行）は講義で使ったKaggleのデータを模した架空のサンプルです。講義のデータは672行でしたが、ここでは ds_jobs テーブルの30行を使います。

使う3つのキーワード

コマンド役割
START TRANSACTION（または BEGIN）トランザクションを開始する。ここから先の変更は「仮」の状態になる
COMMITここまでの変更をすべて確定（永続化）する
ROLLBACK開始時点までの変更をすべて取り消し、元の状態に戻す

この3つはそれぞれ別のコマンドで、pgAdminなどでは1つずつ選択して順番に実行します。途中のコマンドが1つでもエラーになったら、必ず ROLLBACK して最初からやり直します。エラーのまま放置すると、トランザクションが中途半端な状態で残ってしまいます。

いつ使うか

教科書（10章）とレクチャーでは、次のような場面が挙げられています。

  • 複数のステップで表を変更するとき（次のUnitの給与レンジ分割のように、列追加→更新→型変換と続く作業）
  • 初めて使う関数や、自信のない書き方を試すとき（結果が想定と違えば取り消せる）
  • 「全部成功するか、全部失敗するか」でなければならない、関連するコマンド群。教科書の例は、ネット通販の注文処理です。「在庫を減らす」「注文を記録する」「クレジットカードに請求する」のうち、カードが拒否されたのに在庫だけ減っていたら困ります。そこで全部を1つのトランザクションにまとめ、カード決済が失敗したら ROLLBACK ですべてを元に戻します。
トランザクションの流れ
▶️
START TRANSACTIONここから「お試しモード」。変更はまだ確定していない
↓
✏️
UPDATE / ALTER TABLE ... を実行何本でもOK。同じトランザクション内の変更はすぐ確認できる
↓
🔍
SELECT で結果を確認想定どおりの値になっているか、行数や型は正しいかを見る
↓
✅❌
COMMIT か ROLLBACKOKなら COMMIT で確定、おかしければ ROLLBACK で全部なかったことにする
「実行 → 確認 → 確定か取り消し」の順番が、トランザクションの基本形。

実際に試す：UPDATEしてROLLBACKする

まず、変更前の平均評価（rating）を見ておきます。

SELECT ROUND(AVG(rating), 2) AS avg_rating FROM ds_jobs;
avg_rating 3.05 (1 rows)

次に、トランザクションの中で WHERE句のない UPDATE（＝全30行が対象）を実行してみます。本番のテーブルなら大事故ですが、トランザクションの中なら取り消せます。

START TRANSACTION;
UPDATE ds_jobs SET rating = 0;
SELECT ROUND(AVG(rating), 2) AS avg_rating FROM ds_jobs;  -- トランザクション内では変更が見える
ROLLBACK;
SELECT ROUND(AVG(rating), 2) AS avg_rating FROM ds_jobs;  -- 元に戻っている
-- ROLLBACK前（トランザクションの中） avg_rating 0 (1 rows) -- ROLLBACK後 avg_rating 3.05 (1 rows)

トランザクションの中では全行の rating が0になり、平均も0になりました。しかし ROLLBACK のあとは、平均が元の 3.05 に戻っています。もし ROLLBACK の代わりに COMMIT を実行していたら、この変更は永久に確定していました。

📌 トランザクションはバックアップの代わりではありません。トランザクションが守ってくれるのは「COMMITする前」だけです。一度 COMMIT したら元に戻せません。だからバックアップ（CREATE TABLE ... AS SELECT によるコピー）とセットで使うのが基本です。バックアップは「確定後の保険」、トランザクションは「確定前の安全確認」と覚えましょう。
⚠️ 実務のヒント：①スクリプトはこまめに保存しておく（途中で接続が切れると、未COMMITの作業は失われます）。②ROLLBACK を何度も繰り返すと、pgAdminが不安定になったりクラッシュしたりすることがあります。慣れないうちは、変更を小さな単位に分けて、1つずつ確認しながら進めましょう。
💡 PostgreSQLの START TRANSACTION や x::int は、この演習アリーナでも自動変換されてそのまま動きます。
🍎 かんたん説明

トランザクションは「お試しモード」です。START TRANSACTIONで始め、結果を確認して、良ければCOMMIT（確定）、ダメならROLLBACK（取り消し）。バックアップとセットで使うと安心です。

💻 ミニ練習：更新してから取り消す

トランザクションを開始し、ds_jobsの全行のratingを0に更新してから、ROLLBACKで取り消すSQLを書いてください（COMMITは使いません）。

START TRANSACTION;
UPDATE ds_jobs SET rating = 0;
ROLLBACK;

ROLLBACKを実行したので、ratingは元のままです。START TRANSACTIONの代わりにBEGINでも同じ意味になります。

②

トランザクションで給与レンジを分割する

salary_estimate → low_range・high_range（INT）

この単元の主役は、Unit①のトランザクションを使った給与レンジの分割です。ds_jobs.salary_estimate には、たとえば '$110K-$163K (Glassdoor est.)' のような文字列が入っています。これでは「下限が10万ドル以上の求人」のような検索も、平均の計算もできません。1つのテキスト列を、数値の low_range（下限）と high_range（上限）の2列に分けるのがゴールです。

作業は「列追加→分割→記号の除去→桁の復元→型変換」と手順が多く、1つでも間違えるとデータを壊します。まさにトランザクションの出番です。全体像を先に見ておきましょう。

給与レンジ分割の8ステップ
1️⃣
START TRANSACTION作業開始（お試しモード）
↓
2️⃣
ALTER TABLE ... ADD COLUMNlow_range / high_range をTEXTで追加
↓
3️⃣
UPDATE ... SPLIT_PART(salary_estimate, '-', n)「-」の前後で2つに分ける（RETURNINGで確認）
↓
4️⃣
REPLACE で「$」を除く'$110K' → '110K'
↓
5️⃣
「K」以降を除くSPLIT_PART(…,'K',1) か LEFT + POSITION で '110K (Glassdoor est.)' → '110'
↓
6️⃣
|| '000' を付ける'110' → '110000'（K＝千を戻す）
↓
7️⃣
ALTER COLUMN ... TYPE INT USING x::INTTEXT → INT に型変換。数字以外が残っているとエラー
↓
8️⃣
SELECT で確認 → COMMIT / ROLLBACKOKなら確定、おかしければ取り消し
'$110K-$163K (Glassdoor est.)' → low_range = 110000, high_range = 163000

以下、ステップごとに実際に動かした結果を見ていきます（注目する行は post_id 1 '$110K-$163K (Glassdoor est.)'、2桁の下限を持つ post_id 3 '$45K-$79K (Glassdoor est.)'、そして Employer est. の post_id 8 '$52K-$87K (Employer est.)' の3行です）。

ステップ①②　トランザクション開始と列の追加

まず変更前の安全策として、バックアップがなければ CREATE TABLE ds_jobs_backup AS SELECT * FROM ds_jobs; でコピーを作っておきます。そのうえでトランザクションを開始し、列を追加します。分割した直後の値はまだ '$110K' のような文字列なので、最初はTEXT型で作ります。

START TRANSACTION;

ALTER TABLE ds_jobs
    ADD COLUMN low_range TEXT,
    ADD COLUMN high_range TEXT;

ステップ③　SPLIT_PART で「-」の前後に分ける

SPLIT_PART(文字列, 区切り文字, n) は、文字列を区切り文字で分けてn番目の部分を返します（nは1から始まる）。'-' で区切ると、1番目が下限側、2番目が上限側になります。UPDATE ... RETURNING を付けると、更新した行をその場で表示できるので、更新結果のプレビューに便利です。

UPDATE ds_jobs
SET low_range  = SPLIT_PART(salary_estimate, '-', 1),
    high_range = SPLIT_PART(salary_estimate, '-', 2)
RETURNING post_id, salary_estimate, low_range, high_range;
post_id | salary_estimate | low_range | high_range 1 | $110K-$163K (Glassdoor est.) | $110K | $163K (Glassdoor est.) 2 | $137K-$171K (Glassdoor est.) | $137K | $171K (Glassdoor est.) 3 | $45K-$79K (Glassdoor est.) | $45K | $79K (Glassdoor est.) ... 8 | $52K-$87K (Employer est.) | $52K | $87K (Employer est.) ... (30 rows)

下限側は $110K、上限側は $163K (Glassdoor est.) になりました。上限側には注釈の (Glassdoor est.) や (Employer est.) がくっついたままです。これから不要な「$」「K」「注釈」を除いて、数字だけにします。

ステップ④⑤　「$」と「K」以降を取り除く

やり方は2通りあります。講義では文字位置を使う方法が紹介されました。

A. 講義のやり方（SUBSTRING / LEFT ＋ POSITION）：先頭の「$」を SUBSTRING(列, 2) で（2文字目以降を取って）除き、次に'K'の位置を POSITION('K' IN 列) で探して、その直前までを LEFT で切り出します。WHERE POSITION('K' IN 列) > 0 は「Kを含む行だけ」を対象にする安全策です（Kが無い行に LEFT(列, -1) をかけると意図しない結果になるため）。

UPDATE ds_jobs
SET low_range  = SUBSTRING(low_range, 2),
    high_range = SUBSTRING(high_range, 2);

UPDATE ds_jobs
SET low_range = LEFT(low_range, POSITION('K' IN low_range) - 1)
WHERE POSITION('K' IN low_range) > 0;

UPDATE ds_jobs
SET high_range = LEFT(high_range, POSITION('K' IN high_range) - 1)
WHERE POSITION('K' IN high_range) > 0;

B. もっと簡単なやり方（REPLACE ＋ SPLIT_PART）：「$」は REPLACE(列, '$', '') で空文字に置き換え、「K」より前だけが欲しいので、SPLIT_PART(…, 'K', 1) でK区切りの1番目を取ります。1本のUPDATEで済みます。

UPDATE ds_jobs
SET low_range  = SPLIT_PART(REPLACE(low_range, '$', ''), 'K', 1),
    high_range = SPLIT_PART(REPLACE(high_range, '$', ''), 'K', 1);
post_id | low_range | high_range 1 | 110 | 163 3 | 45 | 79 8 | 52 | 87 (3 rows)

AとBはどちらも同じ結果になります（実際に両方を実行して確認済み）。'$45K' のような2桁の下限も、'$52K-$87K (Employer est.)' のように注釈の文字が違う行も、同じ式で正しく処理されています。Bは短くて読みやすい反面、Aは「文字位置を探して切り出す」という文字列処理の基本が身につきます。

ステップ⑥　「000」を付けて千ドル単位を戻す

元の K は「千（thousand）」の意味でした。110 を 110000 にするため、文字列連結演算子 || で末尾に '000' を付けます。

UPDATE ds_jobs
SET low_range  = low_range || '000',
    high_range = high_range || '000';
post_id | low_range | high_range 1 | 110000 | 163000 3 | 45000 | 79000 8 | 52000 | 87000 (3 rows)

見た目は数値ですが、この時点ではまだTEXT型です。文字列のままでは AVG() も大小比較も正しく動きません（'9' > '10' のように文字の辞書順になる）。

ステップ⑦　TEXT から INT に型変換する

ALTER TABLE ds_jobs
    ALTER COLUMN low_range SET DATA TYPE INT USING low_range::INT;

ALTER TABLE ds_jobs
    ALTER COLUMN high_range SET DATA TYPE INT USING high_range::INT;
  • ALTER COLUMN 列名 SET DATA TYPE 型：列のデータ型を変更する。
  • USING 式：既存の値をどのように新しい型へ変換するかを指定する。TEXTからINTへは自動では変換されないので、変換式が必要になる。
  • low_range::INT：PostgreSQL独自のキャスト演算子 ::。CAST(low_range AS INT) と同じ意味（M2のCASTで学んだものの短縮形）。
⚠️ 変換できない文字が1つでも残っているとエラーになります。たとえばステップ⑤を飛ばして、'$110K' のまま型変換すると次のエラーになります。 
ALTER TABLE ds_jobs
    ALTER COLUMN low_range SET DATA TYPE INT USING low_range::INT;
ERROR: invalid input syntax for type int: "$110K"
「K」だけ残して「$」だけ除いた場合や、'000'を付けたあとに「K」が残っている '110K000' でも、invalid input syntax for type int: "110K000" と同様にエラーです。エラーになったらトランザクションの中で ROLLBACK し、原因の手順（ステップ④⑤）を直して最初からやり直します。トランザクションで囲んでおいたおかげで、途中まで進んだ変更がテーブルに残る心配はありません。

ステップ⑧　確認して COMMIT

SELECT post_id, salary_estimate, low_range, high_range
FROM ds_jobs
WHERE post_id IN (1, 3, 8)
ORDER BY post_id;
post_id | salary_estimate | low_range | high_range 1 | $110K-$163K (Glassdoor est.) | 110000 | 163000 3 | $45K-$79K (Glassdoor est.) | 45000 | 79000 8 | $52K-$87K (Employer est.) | 52000 | 87000 (3 rows)

元の salary_estimate と見比べて、値が正しく分かれていることを確認します。型が本当にINTになったかは、SELECT name, type FROM pragma_table_info('ds_jobs')（PostgreSQLでは information_schema.columns）で調べられます。問題なければ確定します。

COMMIT;   -- 確定。おかしければ代わりに ROLLBACK;

型がINTになったので、平均や最大・最小も計算できます。

SELECT ROUND(AVG(low_range)) AS avg_low, ROUND(AVG(high_range)) AS avg_high,
       MIN(low_range) AS min_low, MAX(high_range) AS max_high
FROM ds_jobs;
avg_low | avg_high | min_low | max_high 90933 | 140600 | 45000 | 198000 (1 rows)
📌 データ整形の定石：「新しい列を作る（TEXT）→ 元の列から値を取り出す → 不要な文字を除く → 目的の型に変換する」。元の salary_estimate 列は消さずに残しているので、いつでもやり直せます。
🍎 かんたん説明

1つの列に2つの情報（下限と上限）が入っていたら、まず新しい列を2つ作り、SPLIT_PARTで分け、REPLACEやSPLIT_PART(…,'K',1)で数字だけにして、'000'を付け、最後にUSING x::INTで数値型に変えます。全体をSTART TRANSACTIONで囲んでおけば、失敗してもROLLBACKでやり直せます。

💻 ミニ練習：下限だけを分割する

ds_jobsにlow_range列（TEXT型）を追加し、salary_estimateを'-'で分けた1番目の部分をUPDATEで入れてください（ここでは「$」や「K」の除去はしなくて構いません）。

ALTER TABLE ds_jobs ADD COLUMN low_range TEXT;

UPDATE ds_jobs
SET low_range = SPLIT_PART(salary_estimate, '-', 1);

SPLIT_PART(…, '-', 1)は「-」で分けた1番目を返します。post_id 1のlow_rangeは'$110K'になります。ここから先の「$」「K」の除去とINTへの変換は、本文のステップ④以降と同じです。

③

列とテーブルを削除する

DROP COLUMN と DROP TABLE、そして DELETE とのちがい

整形の途中で、不要になった列やテーブルを消したくなることがあります。たとえば、Unit②の作業をバックアップのコピーで練習したあと、不要になったコピーを片づける場面です。ここでは「列を消す」と「テーブルごと消す」の2つを学びます。どちらも取り消しがきかない（トランザクション外なら即時確定）強力なコマンドなので、必ずバックアップを取ってから実行します。

準備：2つ目のバックアップ表

本番の ds_jobs を直接いじらず、練習用のコピー ds_jobs_backup2 を作り、そこに給与レンジの列を足してみます。

CREATE TABLE ds_jobs_backup2 AS SELECT * FROM ds_jobs;

ALTER TABLE ds_jobs_backup2
    ADD COLUMN low_range INT,
    ADD COLUMN high_range INT;

SELECT name, type FROM pragma_table_info('ds_jobs_backup2') WHERE cid >= 12 ORDER BY cid;
name | type sector | TEXT revenue | TEXT competitors| TEXT low_range | INT high_range | INT (5 rows)

（pragma_table_info はこのアリーナで列の一覧を調べる方法です。PostgreSQLでは information_schema.columns を使います。）

列を削除する：ALTER TABLE ... DROP COLUMN

ALTER TABLE ds_jobs_backup2 DROP COLUMN low_range;
ALTER TABLE ds_jobs_backup2 DROP COLUMN high_range;

SELECT name, type FROM pragma_table_info('ds_jobs_backup2') WHERE cid >= 12 ORDER BY cid;
name | type sector | TEXT revenue | TEXT competitors| TEXT (3 rows)

low_range と high_range が消え、列数が元の15列に戻りました。PostgreSQLでは DROP COLUMN low_range, DROP COLUMN high_range のようにカンマで並べて1本にまとめることもできます。列を消すとその列のデータもすべて失われるので注意してください。

テーブルを削除する：DROP TABLE

DROP TABLE ds_jobs_backup2;

テーブルの中身（行）も構造（列の定義）も、丸ごと消えます。存在しないテーブルに DROP TABLE を実行すると ERROR: no such table（PostgreSQLでは table "..." does not exist）になりますが、DROP TABLE IF EXISTS ds_jobs_backup2; と書けば、無ければ何もせず正常終了します。スクリプトを何度も再実行するときに便利です。列の削除にも DROP COLUMN IF EXISTS が使えます。

📌 まとめ：列を消す ＝ ALTER TABLE ... DROP COLUMN、テーブルごと消す ＝ DROP TABLE。

DROP と DELETE のちがい

コマンド消えるものテーブル自体例
DELETE FROM t WHERE ...条件に合う行残る（空になっても構造は残る）DELETE FROM ds_jobs WHERE rating = -1; → 5行が消えて25行になる
ALTER TABLE t DROP COLUMN c1つの列（全行のその列の値）残る（列が減る）ALTER TABLE ds_jobs_backup2 DROP COLUMN low_range;
DROP TABLE tテーブルそのもの（行も列も）なくなるDROP TABLE ds_jobs_backup2;
⚠️ WHERE句のない DELETE FROM t; は全行を削除します（UPDATE のWHERE忘れと同じ罠）。実行前に、同じ条件で SELECT COUNT(*) ... WHERE ... を実行して対象行数を確認する習慣をつけましょう。これらの削除系コマンドも、Unit①のSTART TRANSACTIONで囲めば、ROLLBACKで取り消せます（PostgreSQLの場合）。
🍎 かんたん説明

列を消すときはALTER TABLE 表 DROP COLUMN 列、表ごと消すときはDROP TABLE 表。行だけ消すのはDELETEです。どれも元に戻せないので、先にバックアップを取りましょう。

💻 ミニ練習：バックアップ表から列を消す

ds_jobsのコピーds_jobs_backup2を作り、そのコピーからrevenue列を削除するSQLを書いてください。

CREATE TABLE ds_jobs_backup2 AS SELECT * FROM ds_jobs;

ALTER TABLE ds_jobs_backup2 DROP COLUMN revenue;

ALTER TABLE 表 DROP COLUMN 列で列を削除します。元のds_jobsには触れていないので、revenue列は残っています。

📖 用語集

transaction
トランザクション
複数のコマンドをひとまとまりにし、全部確定（COMMIT）か全部取り消し（ROLLBACK）かを選べる仕組み。
COMMIT / ROLLBACK
確定／取り消し
COMMITでトランザクション内の変更を永続化し、ROLLBACKで開始時点に戻す。
SPLIT_PART()
文字列の分割
SPLIT_PART(文字列, 区切り, n) で、区切り文字で分けたn番目の部分を返す関数。
USING x::INT
型変換の式
ALTER COLUMN ... TYPE で、既存値を新しい型にどう変換するかを指定する句。::はキャスト演算子。
DROP COLUMN / DROP TABLE
列／テーブルの削除
列を消すALTER TABLE ... DROP COLUMN と、表ごと消すDROP TABLE。行だけ消すDELETEとは別物。

💡 学習のヒント

整形は「バックアップ → START TRANSACTION → 変更 → SELECTで確認 → COMMIT（ダメならROLLBACK）」の型で進めましょう。エラーが出たら慌てずROLLBACKです。
