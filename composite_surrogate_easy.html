⚡

複合キー

2列のペアで一意にする

🎯 これだけ覚えればOK

複合キーは「テーブル制約」でしか書けません。CONSTRAINT 名 PRIMARY KEY (列1, 列2)のように、2列をまとめて1つの主キーにします。

▶ 105号室はScienceとArtsで別扱い

CONSTRAINT room_key PRIMARY KEY (room_number, building)
room_numberbuilding結果
105Science✅ OK（初登場）
105Arts✅ OK（buildingが違う）
105Science❌ エラー（同じペアが重複）
ERROR: duplicate key value violates unique constraint "room_key" DETAIL: Key (room_number, building)=(105, Science) already exists.
🍎 ひとことで

チェックされるのは2列のペア全体。片方だけ同じなら問題ありません。

①

代理キー：IDENTITY

DBが自動で番号を振る
🔢
GENERATED ALWAYS AS IDENTITYを付けた列は、INSERT時に列名を省くだけで自動採番されます。

▶ IDを省いてINSERT

INSERT INTO students (first_name, last_name, email)
VALUES ('Jim', 'Harbaugh', 'jharbaugh@example.edu');
student_id | first_name -----------+------------ 1 | Jim （自動で1番が割り当てられた）
📌 bigintを使う理由：integerは約21億で上限に達しますが、bigintは約922京まで安全。IDENTITYは古いserialの標準版です。
🍎 ひとことで

番号を書かない＝自動採番。これだけ覚えればOKです。

②

代理キーの弱点

重複人物を防げない
長所短所
自然キー追加列が不要・意味がある前提が崩れると重複しうる
代理キー常に一意が保証される同一人物の二重登録を防げない
🛡️
対策：emailなどにUNIQUE制約を追加。主キー（一意な行識別）とUNIQUE（現実の重複防止）は別の役割です。

▶ 発展：手動で番号を入れる／振り直す

INSERT INTO surrogate_key_example OVERRIDING SYSTEM VALUE
VALUES (4, 'Chicken Coop', '2021-09-03 10:33-07');
ALTER TABLE surrogate_key_example
ALTER COLUMN order_number RESTART WITH 5;

Q1. 複合キーはどこに書く？A. テーブル制約としてのみ。列制約では書けない。
Q2. IDENTITY列にINSERTするときは？A. 列名を書き、その列だけ値を省略する。
Q3. 代理キーの弱点を防ぐには？A. email等にUNIQUE制約を追加する。
