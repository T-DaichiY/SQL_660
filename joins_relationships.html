🧬 テーブルの関係とJOINの応用

ここでは、テーブル同士がどんな「関係（relationship）」で結びついているかを整理し、それを踏まえてエイリアスや3つ以上のテーブルのJOIN、JOIN結果に対する計算まで一気に見ていきます。

① テーブルの関係② 多対多と中間テーブル③ エイリアスで短く④ 3つ以上のJOIN⑤ ON句とWHERE句の違い📝 Quiz
①

テーブルの関係（1対1・1対多・多対多）

JOINの結果を理解するための土台

2つのテーブルの間には、大きく分けて3種類の関係（relationship）があります。どの関係かによって、JOINしたときに何行返ってくるかがまったく変わるので、JOINを書く前に必ず意識しておきたいポイントです。

関係の種類意味頻度
1対1（one-to-one）片方のテーブルの1レコードが、もう片方のちょうど1レコードとだけ対応するまれ
1対多（one-to-many）片方の1レコードが、もう片方の複数レコードと対応する最もよく見る
多対多（many-to-many）両方のテーブルが、互いに複数レコードと対応し合うよくある（中間テーブルが必要）

例えば本と著者の関係を考えると、トルストイが書いた作品は『戦争と平和』だけ、シェイクスピアが書いたのは『マクベス』だけ、というような場合は1対1です。しかし実際には1人の著者が複数の本を書くことの方が多いので、「著者→本」は1対多になりやすいのです（1人の著者が複数の本を書くが、各本の著者は1人だけ、という設定の場合）。逆に共著が当たり前の教科書のように、1冊の本に複数の著者がいて、その著者たちも他の本を書いている場合は多対多になります。

University DBには、この3種類すべての例があります。

📌 なぜ関係を意識するのか？ 1対1なら結果件数は絞られ、1対多や多対多ではJOINした瞬間に行が増殖します。「なぜこんなに行数が増えたんだろう？」と思ったら、まず関係の種類を確認するクセをつけましょう。
🍎 かんたん説明

テーブル同士の関係は1対1・1対多・多対多の3種類。University DBでは、department↔instructorとinstructor↔studentは1対多です。

💻 ミニ練習：1対多の関係をJOINで確認する

department（学部）テーブルとinstructor（教員）テーブルを、共通の列dept_nameで結合し、学部名（dept_name）と教員名（name）を表示するSQLを書いてください。1つの学部に複数の教員が対応する「1対多」の関係を確認しましょう。

SELECT department.dept_name, instructor.name
FROM department
JOIN instructor ON department.dept_name = instructor.dept_name;

同じdept_nameが結果に何度も現れれば、それが「1つの学部に複数の教員」という1対多の証拠です。

②

多対多と中間テーブル（junction table）

student ↔ course は takes 経由の多対多

studentとcourseの関係を考えてみましょう。1人の学生は複数の科目を履修できるし、1つの科目（の複数セクション）は複数の学生に履修されます。つまりstudent ↔ course は多対多です。

しかし、多対多の関係はテーブル2つだけでは直接表現できません。そこで中間テーブル（junction table／連結テーブル）を間に挟みます。University DBでは、その役割をtakesテーブルが担っています。takesはstudent_idとcourse_id（とsection_idなど）を両方持っていて、studentとcourseそれぞれに対しては1対多の関係になっています。

student ↔ takes ↔ course（多対多 ＝ 1対多が2本つながったもの）
student
1
N
takes
N
1

1人のstudentは複数のtakes行を持てる（1対多）。1つのcourseも複数のtakes行から参照される（多対1）。この2つの1対多を合わせると、studentとcourseは実質「多対多」になる。
📌 中間テーブルは、多対多を2つの1対多に分解する仕組みです。studentとcourseを直接つなぐ列は存在しませんが、takesが両方の主キーを外部キーとして持つことで、間接的に多対多の関係を表現できます。
🍎 かんたん説明

student↔courseは多対多。直接はつなげないので、両方のIDを持つtakesという中間テーブルを介して結びつけます。

💻 ミニ練習：中間テーブル経由で「多」の側を確認する

studentとtakesをstudent_idでJOINし、student_idが128の学生が履修している科目コード（course_id）をすべて表示するSQLを書いてください。結果が複数行になれば、それが「1人の学生が複数の科目を履修できる」という多対多の一端です。

SELECT student.name, takes.course_id
FROM student
JOIN takes ON student.student_id = takes.student_id
WHERE student.student_id = 128;

同じ学生に対して複数のcourse_idが返ってくるのは、takesが中間テーブルとして両方のIDを保持しているからです。

③

エイリアスでJOINを短く書く

student S, takes T のように短縮する

JOINするテーブルが増えてくると、テーブル名をそのまま書き続けるクエリはどんどん長くなります。そこで使うのがエイリアス（alias／別名）です。FROM テーブル名 別名のように、テーブル名の後にスペースで別名を書くだけで、以降はその短い名前で列を指定できます。

▶ エイリアス無し（冗長）

SELECT student.student_id, takes.course_id, takes.section_id
FROM student
JOIN takes USING (student_id);

▶ エイリアス有り（S, T に短縮）

SELECT S.student_id, T.course_id, T.section_id
FROM student S
JOIN takes T USING (student_id);
📌 エイリアスの書き方は「テーブル名 スペース 別名」。ASを挟んでstudent AS Sと書いても同じ意味になりますが、ASを省略してもエラーにはなりません。列名の前のS.やT.も省略可能な場合がありますが（列名が全テーブルの中で一意なとき）、どのテーブルの列か分かりやすくするために付けておくのがおすすめです。短いクエリでは1文字のエイリアス（S, T, Cなど）がよく使われます。
🍎 かんたん説明

テーブル名の後にスペースと短い名前を書けば、それがエイリアスになります。student S, takes Tのように書けば、S.やT.でずっと短く書けます。

💻 ミニ練習：USING句でJOINする

studentとtakesを、ONではなくUSING(student_id)を使って結合し、学生IDと履修科目IDを表示するSQLを書いてください。

SELECT student.student_id, takes.course_id
FROM student
JOIN takes USING (student_id);

両テーブルの列名が同じ（student_id）ときはUSING(列名)で短く書けます。

④

3つ以上のテーブルをJOINする

student → takes → course の連鎖

studentの氏名、履修しているcourseのタイトル（title）、そしてsection_idを一度に見たいとします。しかしtitle列はcourseテーブルにしかなく、studentにもtakesにもありません。studentテーブルはcourse_idすら持っていないので、courseに直接JOINすることもできません。

そこで、間に立つテーブルを経由して連鎖的にJOINします。studentは直接course_idを持っていませんが、takesはstudent_idとcourse_idの両方を持っています。まずstudentとtakesをstudent_idでJOINし、その結果にcourseをcourse_idでJOINすれば、titleにたどり着けます。

student
student_id
USING(student_id) →
takes
student_id, course_id
takes
course_id
USING(course_id) →
course
course_id, title

▶ 3テーブルJOIN：student → takes → course

SELECT S.student_id, S.name, C.title, T.section_id
FROM student S
JOIN takes T USING (student_id)
JOIN course C USING (course_id);
📌 JOINは上から順に処理されます。まずstudentとtakesがstudent_idで結合され、その中間結果に対して次にcourseがcourse_idで結合されます。すべてを一度にごちゃまぜに結合しているわけではありません。だからこそ、studentが直接持っていないcourse_idも、takesを経由すれば橋渡しできるのです。「欲しい列があるテーブルまで、共通の列を持つテーブルを辿ってつなぐ」というイメージで考えると分かりやすいです。
🍎 かんたん説明

studentにない列（title）は、student→takes→courseと順番にJOINして辿り着きます。JOINは書いた順に処理され、前のJOIN結果に次のテーブルが結合されます。

💻 ミニ練習：student → takes → course の3テーブルJOIN

student・takes・courseをエイリアス（S, T, C）を使ってつなぎ、学生が履修している科目のタイトル（title）を表示するSQLを書いてください。

SELECT S.name, C.title
FROM student S
JOIN takes T ON S.student_id = T.student_id
JOIN course C ON T.course_id = C.course_id;

studentはcourse_idを直接持たないので、takesを経由して橋渡しします。JOINは上から順に処理されます。

⑤

JOIN結果に対する計算（ON句とWHERE句の違い）

enrollment ÷ 平均クラスサイズ ＝ 必要セクション数

JOINした結果の列に対して、さらに集計や算術計算を行うこともよくあります。例えば「各courseの履修者数（enrollment）から、必要なセクション数を求めたい」というケースを見てみましょう。

▶ 履修者数を数え、平均クラスサイズ45人で割って必要セクション数を出す

SELECT T.course_id, S.room_number,
       COUNT(T.student_id) AS enrolled,
       COUNT(T.student_id) / 45 AS sections_needed
FROM takes T
JOIN section S
  ON T.course_id = S.course_id
 AND T.semester = 'Spring' AND T.year = 2002
GROUP BY T.course_id, S.room_number
ORDER BY T.course_id, S.room_number;

ここではcourse_idでJOINしています（section_idは科目をまたいで番号が重複するため、正確な集計にならない）。COUNT(T.student_id)で「その科目・その部屋に何人が履修しているか」を数え、それを平均クラスサイズ（45人）で割ることで、必要なセクション数を計算しています。GROUP BYがあるからこそCOUNTという集計関数が使えることも覚えておきましょう。

注目してほしいのが、semesterとyearの条件をON句の中に書いている点です。これはWHERE句に書くのとは意味が違います。

⚠️ ON句の条件は「結合そのものが起きる前」にかかり、WHERE句の条件は「結合が終わった後」にかかります。INNER JOINでは結果的に同じ行が残ることが多いですが、LEFT JOINなど外部結合では結果が変わります。

▶ 条件をON句に入れる（LEFT JOIN・一致しないtakes側の行はNULLで残る）

SELECT S.student_id, T.course_id
FROM student S
LEFT JOIN takes T
  ON S.student_id = T.student_id AND T.year = 2002;

▶ 条件をWHERE句に入れる（LEFT JOINが実質INNER JOINと同じ結果になる）

SELECT S.student_id, T.course_id
FROM student S
LEFT JOIN takes T
  ON S.student_id = T.student_id
WHERE T.year = 2002;

ON句に入れた場合、2002年以外に履修していない学生でもstudentの行自体はLEFT JOINで残り、takes側の列がNULLになるだけです。一方WHERE句に条件を入れると、結合の後でT.year = 2002を満たさない行（NULLも含む）がすべて削られてしまい、結果的にLEFT JOINなのにINNER JOINと同じような挙動になってしまいます。

🍎 かんたん説明

ON句の条件は結合中に効き、WHERE句の条件は結合後に効きます。INNER JOINなら差が出にくいですが、LEFT JOINなど外部結合では結果が変わるので要注意です。

💻 ミニ練習：（応用）GROUP BYで科目ごとの履修者数

takesをcourseとJOINし、course_idごとに履修している学生数を数えるSQLを書いてください（GROUP BYとCOUNTを使用）。

SELECT T.course_id, COUNT(T.student_id) AS num_students
FROM takes T
JOIN course C ON T.course_id = C.course_id
GROUP BY T.course_id;

JOINした結果に対しても、通常のクエリと同じようにGROUP BYと集計関数が使えます。

📖 用語集

one-to-many
1対多
片方の1レコードが、もう片方の複数レコードと対応する関係。例：department↔instructor。
many-to-many
多対多
両方のテーブルが互いに複数レコードと対応し合う関係。例：student↔course。
junction table
中間テーブル
多対多の関係を2つの1対多に分解するために間に挟むテーブル。例：takes。
alias
エイリアス（別名）
テーブル名の後にスペースを入れて付ける短い別名。クエリを短く書ける。
USING clause
USING句
両テーブルで列名が一致するときに使えるJOIN条件の書き方。USING(列名)。
cardinality
カーディナリティ（多重度）
関係における「いくつ対いくつ」を表す度合い。1・N（多）などで表される。
