①

ERDとは何か・なぜ見るのか

DBAだけのものではない

ERD（Entity Relationship Diagram：実体関連図）とは、データベースの中にあるテーブル（実体）と、それらの間のつながり（関連）を1枚の図にまとめたものです。各テーブルにどんな列があり、どのテーブルがどのテーブルを参照しているのかが、SQLを書かなくても一目で分かります。

ここまでのモジュールで、私たちは主キー・外部キー・制約を使って、テーブル同士を丁寧につなげてきました。しかし、テーブルの数が増えてくると、頭の中だけで全体の構造を把握するのはだんだん難しくなります。そこで役に立つのがERDです。

📌 ERDはデータベース管理者だけのものではありません。データサイエンティストがすでにあるデータベースを引き継いだとき、あるいは他の人が作ったテーブル群を分析に使うとき、まず最初にERDを開いて「このテーブルはどれと繋がっているか」を確認するのが近道です。特に、これから学ぶJOINは複数テーブルを繋げて1つの結果にする操作なので、その直前にERDで全体像を掴んでおくと理解がぐっと早くなります。

🍎 かんたん説明

ERDはデータベースの「地図」。どのテーブルがどのテーブルと繋がっているかを絵で見せてくれます。

②

pgAdminでERDを描く手順

クリックだけで生成できる

pgAdminには、既存のデータベースからERDを自動生成する機能が組み込まれています。SQLは一切書きません。

pgAdminでの操作手順
1️⃣
データベースを右クリックツリーで対象のデータベースを選び、右クリックメニューから「ERD For Database」を選ぶ
↓
2️⃣
テーブルをドラッグして整理する自動配置は重なることが多いので、見やすい位置までドラッグして散らす
↓
3️⃣
Show/Hide details で詳細を切り替えるテーブルをクリックし、列の表示・非表示、PK🔑・FKマークの表示を切り替える
↓
4️⃣
プロジェクトファイル（.pgerd）として保存整理した配置を保存できる。ただし再度開くときはERDツールの中から開く必要があり、ファイルをダブルクリックしても開けない
↓
5️⃣
ズーム・色分けで見やすくする拡大縮小、「Zoom to fit」で画面に全体を収める、テーブルごとの色分けも可能
右クリック1回で自動生成 → あとは見やすく整えるだけ。
⚠️ .pgerdファイルはただの保存形式であって、開き方が特殊です。エクスプローラーやFinderから直接ダブルクリックしても開けません。必ずpgAdminのERDツールを開いてから、そこで対象のファイルを読み込む必要があります。
💡 逆方向もできる：pgAdminは、まっさらな状態からERDを先に描いて、そこから実際のテーブル（CREATE TABLE文一式）を生成することもできます。これは設計を先に固めてから実装する「トップダウン設計」に相当しますが、本レッスンの範囲外です。
🍎 かんたん説明

DBを右クリック→ERD For Databaseで一発生成。保存は.pgerdだが、開くときは必ずERDツールの中から。

③

図の読み方

線の向きが外部キーの方向を示す

ERDの線は、テーブル同士の関係（relationship）を表します。多くのツールはcrow's foot（カラスの足）記法と呼ばれる書き方を使い、線の片方の端が「一（1）」、もう片方の端が枝分かれした「多（many）」を表します。

📌 読み方のルールはひとつだけ：枝分かれした「多」側の端は、外部キー（FK）を持つテーブルを指します。線がシンプルな1本のまま終わる側が、参照される主キー（PK）側のテーブルです。矢印は「FKからPKへ向かう」と考えれば迷いません。

sectionテーブルは特に線が多いテーブルです。教室を表すclassroom (room_number, building)という2列セットを1つの複合FKとして参照し、さらにcourseとtime_slotにもそれぞれ別のFKで繋がっています。ERD上ではこの1つのテーブルから3方向に線が伸びる形になり、「sectionは他の多くのテーブルの情報を束ねる、いわば交差点のようなテーブルだ」ということが視覚的にすぐ分かります。

-- ERDに現れる複合FKの例（section → classroom）
CREATE TABLE section (
    course_id varchar(8) REFERENCES course (course_id),
    room_number varchar(7),
    building varchar(15),
    FOREIGN KEY (room_number, building)
        REFERENCES classroom (room_number, building)
);
CREATE TABLE Query returned successfully.
⚠️ ERDを見て「線がおかしい」と感じたら、それは設計を見直すサインかもしれません。逆に、あるテーブルへ矢印が集中している場合は、そのテーブルが多くのテーブルから参照される中心的な存在だと分かります。
🍎 かんたん説明

枝分かれした端＝FKを持つテーブル、シンプルな端＝PKを持つテーブル。矢印は「多」から「一」へ。

📖 用語集

ERD
実体関連図
Entity Relationship Diagram。テーブルとその関係を図示したもの。
entity
実体
ERD上ではテーブル1つに相当する箱。列（属性）の一覧を持つ。
relationship
関連
2つのテーブルを結ぶ線。多くはPKとFKの参照関係を表す。
cardinality
多重度
1対1・1対多・多対多など、関係の「数」の性質。
crow's foot
カラスの足記法
枝分かれした線で「多」側を表す記法。枝分かれ側＝FKを持つテーブル。

💡 学習のヒント

ERDを開いたら、まず矢印が集中しているテーブルを探しましょう。それが多くの他テーブルから参照される「中心」であることが多く、JOINで頻繁に使うテーブルの目星がつきます。
