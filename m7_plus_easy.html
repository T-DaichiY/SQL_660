🍎 超やさしい版：重複検出・length診断・安全な修復

ここは教科書『Practical SQL 完全ガイド』第10章だけに載っている内容で、講義動画では扱っていません。教材のデータは架空の30行サンプル（ds_jobs）です。

①

重複と表記ゆれを探す

GROUP BY ... HAVING count(*) > 1

🎯 これだけ覚えればOK

同じ値ごとに山を作って（GROUP BY）、山の高さ（count）が2以上（HAVING）なら重複。1列だけで山を作ると、綴り違いが別々の山になって見つかります。

🧦
たとえば靴下の引き出し。同じ柄ごとに山を作れば、「同じ柄が2足以上ある」も「似ているけど微妙に違う柄がある」もすぐ分かります。

▶ company と loc の重複を調べる

SELECT company, loc, count(*) AS n
FROM ds_jobs
GROUP BY company, loc
HAVING count(*) > 1;
(0 rows)

0行は「重複なし」という立派な答えです。

▶ job_title の綴りを見てみる

SELECT job_title, count(*) AS n
FROM ds_jobs
GROUP BY job_title
ORDER BY job_title;
job_title | n ... Senior Data Scientist | 3 Senior. Data Scientist - | 2 Sr Data Scientist | 2 Sr. Data Scientist | 2 (全部で10行)

同じ職種のはずなのに、綴りが4通りに分かれています。

🍎 ひとことで

「山の高さ」で絞るときはWHEREではなくHAVINGを使います。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 重複を探すとき、HAVINGに何と書く？A. HAVING count(*) > 1。2行以上あるグループだけが残る。
Q2. 重複を探して0行だったら？A. エラーではなく「重複なし」という正しい結果。

length() で形式の異常を見つける

文字数を数えて、仲間はずれを探す

🎯 これだけ覚えればOK

GROUP BY length(列)で長さの分布を見て、少数派の長さをWHEREで取り出す。

📏
たとえば同じ長さのはずの鉛筆を並べて、1本だけ極端に短いものを探す作業です。

▶ 説明文が短すぎる行を探す

SELECT post_id, job_desc, LENGTH(job_desc) AS len
FROM ds_jobs
WHERE LENGTH(job_desc) < 5
ORDER BY post_id;
post_id | job_desc | len 11 | TBD | 3 18 | n/a | 3 29 | | 0 (3 rows)

▶ 設立年の桁数を調べる（数値はTEXTにしてから）

SELECT LENGTH(CAST(founded AS TEXT)) AS len, count(*) AS n
FROM ds_jobs
GROUP BY LENGTH(CAST(founded AS TEXT));
len | n 2 | 2 4 | 28 (2 rows)
⚠️
長さ2の2件は-1（「不明」のダミー値）です。空文字列''はNULLではなく長さ0の値なので、IS NULLでは見つかりません。
🍎 ひとことで

length()は「本来は同じ長さのはず」の列で大活躍します。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 空文字列は IS NULL で見つかる？A. 見つからない。空文字列は長さ0の「値」で、NULLとは別物。
Q2. 数値列の桁数を数えるには？A. CAST(列 AS TEXT)で文字列にしてからLENGTH()。
③

列単位のバックアップと安全な修復

コピーを取ってから、狭く直す

🎯 これだけ覚えればOK

直す前に、その列をコピーしておく。直すときはWHEREで対象を絞り、RETURNINGで結果を確認。

↩️
たとえば宿題を書き直す前にコピーを取っておくこと。失敗しても、コピーから元に戻せます。

▶ 列をバックアップして、1行だけ直す

ALTER TABLE ds_jobs ADD COLUMN job_title_copy TEXT;
UPDATE ds_jobs SET job_title_copy = job_title;

UPDATE ds_jobs
SET job_title = 'Senior Data Scientist'
WHERE post_id = 15
RETURNING post_id, job_title, job_title_copy;
post_id | job_title | job_title_copy 15 | Senior Data Scientist | Senior. Data Scientist - (1 rows)

▶ 元に戻したくなったら

UPDATE ds_jobs SET job_title = job_title_copy;

▶ 先頭に0を足して3桁にそろえる（1桁の行だけ）

UPDATE ds_jobs SET job_code = '00' || job_code
WHERE LENGTH(job_code) = 1;
⚠️
WHEREが無いUPDATEは全行に効きます。直したい行だけを指名しましょう。
🍎 ひとことで

||は文字をくっつける記号。WHERE LENGTH(...)で、足りない行だけに足します。

🤔 答えられるかな？（クリックで答えが開く）

Q1. RETURNINGは何をする？A. UPDATEした行を、その場で表示する（PostgreSQL独自の句）。
Q2. WHEREなしでUPDATEすると？A. テーブルの全行が書き換わる。
④

テーブルをまたぐ UPDATE

対応表を見ながら書き換える

🎯 これだけ覚えればOK

対応表（ownership_map）から新しい値を引いて更新する。表にない行はWHERE EXISTSで守る。

📖
たとえば辞書を引きながら書き換える作業。辞書に載っていない言葉は、そのまま残しておきます。

▶ 相関サブクエリ＋EXISTS

UPDATE ds_jobs
SET owner_type = (
    SELECT clean_label FROM ownership_map
    WHERE ownership_map.raw_label = ds_jobs.owner_type
)
WHERE EXISTS (
    SELECT 1 FROM ownership_map
    WHERE ownership_map.raw_label = ds_jobs.owner_type
);

30行のうち27行に対応があり、更新されます。残り3行（Unknownと-1が2件）はそのままです。

⚠️
WHERE EXISTSを付け忘れると、対応がない3行がNULLに上書きされてしまいます。

▶ PostgreSQLのUPDATE ... FROM

UPDATE ds_jobs
SET owner_type = ownership_map.clean_label
FROM ownership_map
WHERE ownership_map.raw_label = ds_jobs.owner_type;
🍎 ひとことで

UPDATE ... FROMなら、条件に合う行だけが更新されるので、ガードを書かなくて済みます。

🤔 答えられるかな？（クリックで答えが開く）

Q1. WHERE EXISTSが必要な理由は？A. 対応表にない行が、サブクエリの結果NULLで上書きされるのを防ぐため。
Q2. 実際に何行が更新される？A. 27行（対応がない3行は更新されない）。
⑤

DELETE・TRUNCATE・DROP の違い

消す範囲は4段階

🎯 これだけ覚えればOK

DELETE＝行だけ、TRUNCATE＝全行、DROP COLUMN＝列、DROP TABLE＝テーブルごと。迷ったらまずSELECTで確認、次にトランザクション。

🧹
たとえば部屋の片づけ。「ゴミを1つ捨てる」（DELETE）から「部屋ごと壊す」（DROP TABLE）まで、強さが全然違います。

▶ トランザクションで試して、取り消す

START TRANSACTION;
DELETE FROM ds_jobs WHERE rating = -1;
SELECT count(*) AS remaining FROM ds_jobs;
ROLLBACK;
remaining 25

rating = -1の5行が消えて30行→25行になりましたが、ROLLBACKで30行に戻ります。

↩️
確定したいときはCOMMIT、取り消したいときはROLLBACK。COMMITの後はUndoできません。
🍎 ひとことで

TRUNCATE ... RESTART IDENTITYはPostgreSQLだけの機能です。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 行だけを条件付きで消すのは？A. DELETE FROM ... WHERE ...。
Q2. ROLLBACKすると？A. トランザクション中の変更が全部なかったことになる。
Q3. DROP TABLEと TRUNCATE の違いは？A. DROP TABLEは表ごと消える。TRUNCATEは全行が消えるが、表の構造は残る。
