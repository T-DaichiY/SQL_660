M8 · Common Table Expressions — Part 2 (Lecture 5)

🧱 CTE②：複数のCTEをつなぐ

CTEは1つだけでなく、カンマでつないで何個でも作れます。この単元では、複数のCTEの文法とルール、講義の2つのCTEの例題（部署名と給与合計）、そして3つ目のCTEや前のCTEを使うCTEまでを学びます。

🎥 講義動画5「CTE part 2（multiple CTEs）」 ・ 📖 Practical SQL 第2版 第13章「Advanced Query Techniques」。会社のデータ（departments／employees／employee_projects）は、教材用の架空のデータです。

①

複数のCTEの書き方

WITHは1回、CTEの間はカンマ

複雑な問題では、CTEが1つでは足りません。講師は動画の冒頭で「複数のCTEの文法は意外と簡単」と言っています。ポイントは、CTEとCTEの間をカンマでつなぐことだけです。

WITH first_cte AS (
    SELECT ...
    FROM ...
),                                -- ← 1つ目の終わりにカンマ
second_cte AS (                   -- ← 2つ目には WITH を付けない
    SELECT ...
    FROM ...
)                                 -- ← 最後のCTEの後ろにカンマは付けない
SELECT ...                        -- ← メインのクエリ（両方を表のように使える）
FROM first_cte
JOIN second_cte ON ...;

講師の説明を整理します。

  • WITHは最初に1回だけ書きます。2つ目以降の前にWITHは不要です。
  • 「テーブルのリストを作っている」と考えると分かりやすいです。WITHは「ここから表の宣言が始まる」という合図で、あとはカンマで区切って名前 AS (...)を並べるだけです。
  • 最後のCTEの後ろにはカンマを付けません。その次に来るのは、次のCTEではなくメインのクエリだからです。
  • それぞれのCTEは、普通のテーブルと同じようにメインのクエリで呼び出せます。

教科書の例（Listing 13-14、p.337）も同じ形です。WITHのあとに「counties (st, pop_est_2018) AS (...)」「establishments (st, establishment_count) AS (...)」をカンマで区切って並べ、最後の閉じかっこの後ろ（メインのSELECTの前）にはカンマがありません。各CTEには、前の単元で紹介した列名リストを付けることもできます。この教材のデータで同じ形を書くとこうなります。

WITH ds (dept, total) AS (
    SELECT department_id, SUM(salary) FROM employees GROUP BY department_id
),
hc (dept, n) AS (
    SELECT department_id, COUNT(*) FROM employees GROUP BY department_id
)
SELECT ds.dept, ds.total, hc.n
FROM ds JOIN hc ON ds.dept = hc.dept
ORDER BY ds.dept;
dept | total | n -----+--------+--- 1 | 355000 | 5 2 | 245000 | 4 3 | 263000 | 5 4 | 143000 | 3 5 | 150000 | 3
📌 カンマの法則：CTEがN個あれば、カンマはN-1個です。2個ならカンマ1個、3個ならカンマ2個。
🍎 かんたん説明

お買いものリストと同じです。「牛乳、卵、パン」とカンマで区切って、最後の「パン」の後ろにはカンマを付けません。CTEもリストのように並べます。

💻 ミニ練習：2つのCTEをカンマでつなぐ

Bankingのloanテーブルから、small_loans（amountが10,000未満）とbig_loans（amountが10,000以上）の2つのCTEを作り、メインのクエリで(SELECT COUNT(*) FROM small_loans)と(SELECT COUNT(*) FROM big_loans)の2つを1行で表示してください。

WITH small_loans AS (
    SELECT loan_number FROM loan WHERE amount < 10000
),
big_loans AS (
    SELECT loan_number FROM loan WHERE amount >= 10000
)
SELECT (SELECT COUNT(*) FROM small_loans) AS n_small,
       (SELECT COUNT(*) FROM big_loans)   AS n_big;

結果は2と2（9,000と5,000が小さい融資、15,000と22,000が大きい融資）。1つ目のCTEの後ろにカンマ、2つ目の後ろにはカンマなしです。

②

ルールとよくある間違い

構文エラーの原因は、ほぼここ

講義と、よくある間違いをまとめます。間違えると構文エラーになる点ばかりです。

ルール間違えると…
① WITHは文頭に1回だけ2つ目の前にもWITHを書くと、構文エラーになる。
② CTEの間はカンマでつなぐカンマを忘れると、次の名前のところで構文エラーになる。
③ 最後のCTEの後ろにカンマは付けない付けると、メインのSELECTの前でエラーになる（「カンマの後ろに何が続くの？」状態）。
④ CTEの名前はユニーク同じ名前を2つ使うことはできない。エラーになる。

よくある間違いの形を、NG例（実行しない）で見ておきましょう。

▶ NG①：2つ目にもWITHを付けてしまった

WITH a AS (SELECT 1 AS x)
WITH b AS (SELECT 2 AS y)      -- ← NG：WITHは1回だけ
SELECT * FROM a, b;

▶ NG②：最後のCTEの後ろにカンマ

WITH a AS (SELECT 1 AS x),
     b AS (SELECT 2 AS y),     -- ← NG：この後ろはメインのSELECT
SELECT * FROM a, b;
⚠️ 名前のかぶりに注意。講師は「同じ名前のCTEを2つ作ることはできない」と強調しています。たとえばdept_totalsという名前を別々の用途で2回使うと、PostgreSQLは「どちらのことか分からない」としてエラー（WITH query name "dept_totals" specified more than onceのような内容）を返します。名前は中身が分かる、重ならないものにしましょう（例：top_project_workers、high_salary_departments）。

名前は、メインのクエリや他のCTEの中からは通常のテーブル名と同じように呼ばれます。そのため、実在するテーブル（employeesやloan）と同じ名前を付けると混乱のもとになります。CTEにはテーブルと違う名前を付けるのが無難です。

🍎 かんたん説明

覚えるのは3つ。WITHは1回、間はカンマ、最後はカンマなし。そして名前はぜんぶ別々です。

💻 ミニ練習：間違いを直す

次のSQLには間違いが2つあります。直して、3つのCTE a、b、c をすべて正しくつないでください。
WITH a AS (SELECT 1 AS x)
WITH b AS (SELECT 2 AS y),
c AS (SELECT 3 AS z),
SELECT * FROM a, b, c;

WITH a AS (SELECT 1 AS x),
     b AS (SELECT 2 AS y),
     c AS (SELECT 3 AS z)
SELECT * FROM a, b, c;

直したのは2か所：①2つ目のWITHを消し、a の後ろにカンマを付ける　②最後の c の後ろのカンマを消す。結果は1 | 2 | 3の1行です。

③

例題：条件ごとにCTEを作る

最長時間の社員がいる部署 かつ 給与合計200,000超

講義の練習問題です（課題で出る形とそっくりだと言っています）。会社のデータは架空の教材用データで、departments（5部署）、employees（20人）、employee_projects（18行）を使います。

📌 課題文：2つのCTEを使って、次の両方を満たす部署の「部署名と部署の給与合計」を出す。
(1) どの社員よりも長い時間、1つのプロジェクトで働いた社員（最長時間）が、少なくとも1人いる。
(2) 部署全員の給与合計が200,000を超える。

課題文の読み方のコツ（講師より）：箇条書きのように条件が複数並んでいるときは、CTEを使う合図です。さらに「合計」という集計も求められているので、条件ごとにCTEに分けると、GROUP BYやHAVINGの置き場所で悩まずに済みます。

条件担当するCTE何を出す？
(1) 最長時間の社員がいるtop_project_workers最長時間の社員のemployee_idとdepartment_id
(2) 給与合計が200,000超high_salary_departments部署ごとのdepartment_idとtotal_salary（200,000超のみ）

▶ CTE① top_project_workers（条件1）

SELECT ep.employee_id, e.department_id
FROM employee_projects ep
JOIN employees e ON ep.employee_id = e.employee_id
WHERE ep.hours_worked = (SELECT MAX(hours_worked) FROM employee_projects);
employee_id | department_id ------------+-------------- 5 | 2 14 | 4 (2 rows)

employee_projectsには部署IDがないので、employeesとemployee_idでJOINしてdepartment_idを付け足しています。WHEREの中の(SELECT MAX(hours_worked) ...)は、「全体の最長時間」＝160を返すサブクエリです。講師も「ここはサブクエリになる」と述べ、「小さいのでこのままにする」と言っています。最長の160時間は、Eva Park（Marketing、プロジェクトP2）と、Noah Fox（HR、P4）の2人です。

▶ CTE② high_salary_departments（条件2）

SELECT department_id, SUM(salary) AS total_salary
FROM employees
GROUP BY department_id
HAVING SUM(salary) > 200000;
department_id | total_salary --------------+------------- 1 | 355000 2 | 245000 3 | 263000 (3 rows)

こちらはとても簡単です。講師は「200,000の条件をメインではなくこのCTEの中に置く」理由を、「メインのクエリで集計を扱うことになるので、給与の話はまとめて給与のCTEに入れた方が混乱しない」と説明しています。

⚠️ 単体テストを忘れずに。それぞれのSELECTを単独で実行して、上のような結果になることを確かめてから、WITHで包みましょう。部品が正しければ、全体も正しく動きます。
💻 ミニ練習：CTE②だけを単独で作る

部署ごとの人数が4人以上の部署を取り出すbig_deptsというCTEを作ってください。CTEの中でdepartment_idとCOUNT(*)（列名はheadcount）を出し、GROUP BYとHAVINGを使います。メインはSELECT * FROM big_deptsです。

WITH big_depts AS (
    SELECT department_id, COUNT(*) AS headcount
    FROM employees
    GROUP BY department_id
    HAVING COUNT(*) >= 4
)
SELECT * FROM big_depts;

結果は3行（部署1が5人、部署2が4人、部署3が5人）。条件と集計をCTEの中に入れ、メインはシンプルなままです。

④

メインのクエリ：結びつけて完成

JOINで「かつ」を作り、部署名を付け足す

2つのCTEが完成したら、メインのクエリで結びつけるだけです。欲しいのは「部署名」と「給与合計」で、給与合計はhigh_salary_departmentsにありますが、部署名はどこにもありません（あるのはdepartment_id）。そこでdepartmentsテーブルにもJOINします。

WITH top_project_workers AS (
    SELECT ep.employee_id, e.department_id
    FROM employee_projects ep
    JOIN employees e ON ep.employee_id = e.employee_id
    WHERE ep.hours_worked = (SELECT MAX(hours_worked) FROM employee_projects)
),
high_salary_departments AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
    HAVING SUM(salary) > 200000
)
SELECT d.department_name, hsd.total_salary
FROM high_salary_departments hsd
JOIN top_project_workers tpw ON hsd.department_id = tpw.department_id
JOIN departments d ON d.department_id = hsd.department_id
GROUP BY d.department_name, hsd.total_salary;
department_name | total_salary ----------------+------------- Marketing | 245000 (1 row)

講義でも結果はMarketing 245,000の1行だけでした。なぜそうなるのかを、JOINの働きで説明します。

2つのCTEのJOINは「かつ（AND）」になる
🅰️
top_project_workers：部署 2、4Marketing（Eva Park）、HR（Noah Fox）
↓
🅱️
high_salary_departments：部署 1、2、3Engineering 355,000／Marketing 245,000／Sales 263,000
↓
🤝
department_id でJOIN → 両方に出る部署 2 だけ残るHR（4）は給与合計143,000で落ち、Engineering（1）とSales（3）は最長時間の社員がいないので落ちる
講師の例：「最長時間の社員がいる部署でも、高給与の部署のリストになければ、JOINで除外される」

最後のGROUP BY d.department_name, hsd.total_salaryは、同じ部署に最長時間の社員が複数いたときに、部署が何行も重複して出てしまうのを防ぐ役目です。この例ではMarketingに該当者が1人（Eva Park）だけですが、一般的な安全策になります。

📌 講師のまとめ：これを1つの巨大なクエリで書いたら「とても複雑になる」ところです。CTEに分けたから、1つ1つは短くて単純なクエリになりました。
🍎 かんたん説明

条件が2つあるときは、条件ごとに「合格リスト」をCTEで作ります。2つのリストをJOINすると、両方のリストに載っている部署だけが残ります。最後に部署名をdepartmentsから付け足して完成です。

💻 ミニ練習：2つのCTEを結びつける

上の2つのCTEを書き、メインのクエリで部署名と給与合計を求めて、Marketing 245000の1行になることを確かめてください（departmentsへのJOINも忘れずに）。

WITH top_project_workers AS (
    SELECT ep.employee_id, e.department_id
    FROM employee_projects ep
    JOIN employees e ON ep.employee_id = e.employee_id
    WHERE ep.hours_worked = (SELECT MAX(hours_worked) FROM employee_projects)
),
high_salary_departments AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
    HAVING SUM(salary) > 200000
)
SELECT d.department_name, hsd.total_salary
FROM high_salary_departments hsd
JOIN top_project_workers tpw ON hsd.department_id = tpw.department_id
JOIN departments d ON d.department_id = hsd.department_id
GROUP BY d.department_name, hsd.total_salary;

結果はMarketing | 245000の1行。もし条件(1)だけなら部署2と4（MarketingとHR）、条件(2)だけなら部署1・2・3が残ります。両方を満たすのはMarketingだけです。

⑤

CTEを増やす・つなげる

3つ以上のCTE、前のCTEを使うCTE

講師は最後に「3つのCTEにもできる」と述べました。CTEの数に上限はなく、あとのCTEは、前に定義したCTEを参照できます。2種類の発展を見ましょう。

▶ ① 「最長時間」を3つ目のCTE（max_hours）に切り出す

講師は「最長時間を求めるサブクエリを、max_hoursのような別のCTEにすることもできる」と説明しました。top_project_workersがmax_hoursをJOINして使う形です。

WITH max_hours AS (
    SELECT MAX(hours_worked) AS mh FROM employee_projects
),
top_project_workers AS (
    SELECT ep.employee_id, e.department_id
    FROM employee_projects ep
    JOIN employees e ON ep.employee_id = e.employee_id
    JOIN max_hours m ON ep.hours_worked = m.mh
),
high_salary_departments AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
    HAVING SUM(salary) > 200000
)
SELECT d.department_name, hsd.total_salary
FROM high_salary_departments hsd
JOIN top_project_workers tpw ON hsd.department_id = tpw.department_id
JOIN departments d ON d.department_id = hsd.department_id
GROUP BY d.department_name, hsd.total_salary;
department_name | total_salary ----------------+------------- Marketing | 245000 (1 row)

結果は同じです。max_hoursは1行1列の「小さなCTE」なので、メモリの心配もありません。カンマはCTEが3つなので2か所です。

▶ ② 前のCTEの結果を使うCTE（CTEの連鎖）

「部署の給与合計が、全部署の合計の平均より大きい部署」を出します。1つ目のCTEで部署ごとの合計を出し、2つ目のCTEが1つ目のCTEを集計します。

WITH dept_salary AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
),
avg_dept AS (
    SELECT AVG(total_salary) AS a      -- ← 前のCTE dept_salary を使っている
    FROM dept_salary
)
SELECT d.department_name, ds.total_salary
FROM dept_salary ds
JOIN departments d ON d.department_id = ds.department_id
CROSS JOIN avg_dept
WHERE ds.total_salary > avg_dept.a
ORDER BY ds.total_salary DESC;
department_name | total_salary ----------------+------------- Engineering | 355000 Sales | 263000 Marketing | 245000 (3 rows)

5部署の合計は355,000／245,000／263,000／143,000／150,000で、その平均は231,200です。これを超えるのがEngineering、Sales、Marketingの3部署です。集計の集計（「合計の平均」）は、CTEがないとサブクエリの入れ子になる典型例です。

教科書（Listing 13-15、p.337–338）も、同じサブクエリを2回書くことを避けるためにCTEを使っています。「1回定義して、何回も参照する」のがCTEの強みで、中央値の割合を.5から.9に変えたいときも、直す場所が1か所で済む、と説明されています。

⚠️ 参照できるのは「前に書いたCTE」だけです（上から下へ）。avg_deptの中でdept_salaryを使えるのは、dept_salaryが先に定義されているからです。順番を逆にすると、PostgreSQLは「その名前の表が見つからない」というエラーを返します。
📌 設計のヒント：(1) まず問題を条件・集計ごとに分ける　(2) 部品を1つずつ単独で実行してテスト　(3) 小さな部品はそのままサブクエリでもよい（講師も、最長時間のサブクエリは小さいのでそのままにしていた）　(4) CTEが多すぎて逆に読みにくくならないよう、ほどほどに。
🍎 かんたん説明

CTEは何個でも作れて、あとのCTEは前のCTEを部品として使えます。「小さな部品を積み上げて、最後に仕上げる」のがCTEの考え方です。

💻 ミニ練習：前のCTEを使うCTE

dept_salary（部署ごとの給与合計）と、それを使って最大の合計額を求めるmax_total（列名はm）の2つのCTEを作り、メインでdept_salaryとmax_totalを結んで、合計額が最大の部署のdepartment_idとtotal_salaryを表示してください。

WITH dept_salary AS (
    SELECT department_id, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department_id
),
max_total AS (
    SELECT MAX(total_salary) AS m
    FROM dept_salary
)
SELECT ds.department_id, ds.total_salary
FROM dept_salary ds
JOIN max_total mt ON ds.total_salary = mt.m;

結果は1行（部署1、355000）。max_totalが前のCTE dept_salaryを使っています。

WITHを1回だけ書き、CTEをカンマで区切って並べる。メインのクエリや後ろのCTEから、どれでも表のように呼べる。
comma rule
カンマの規則
CTEの間にカンマ、最後のCTEの後ろにはカンマなし。N個のCTEならカンマはN-1個。
unique name
ユニークな名前
同じWITH句の中でCTEの名前は重複できない。重複するとエラー。
top_project_workers
最長時間の社員のCTE
講義の例題。全体で最長時間（160）働いた社員と、その所属部署IDを出す。
high_salary_departments
高給与部署のCTE
講義の例題。給与合計が200,000を超える部署を、部署ごとのSUMとHAVINGで出す。
chained CTE
CTEの連鎖
あとのCTEが、前に定義したCTEを参照する書き方。上から下へだけ参照できる。

💡 学習のヒント

CTEが増えたら「まず1つずつ単独で実行して結果を確認」。カンマの数は（CTEの数 − 1）、これで数え間違いを防げます。
