🃏 LIKE と ILIKE — パターンで探す

完全一致でも範囲でもなく「〜で始まる」「〜を含む」で探したいとき。%と_の2つのワイルドカードを使いこなす。

① LIKEとは② % と _③ 実用パターン④ ILIKE📝 Quiz
①

LIKEとは — パターンマッチング

「完全一致」でも「範囲」でもない第3の探し方

ここまで学んできた条件は、完全一致（=、IN）か範囲（>、BETWEEN）のどちらかでした。しかし実務ではこんな要求がよくあります。

  • 「Aで始まる都市名をすべて」
  • 「社名にIncが含まれる顧客を全部」
  • 「@を含む＝メールアドレスらしき値を探したい」

こうしたパターンによる検索を行うのがLIKEです。

SELECT city FROM sales
WHERE city LIKE 'A%';
city ----------- Allentown Aaarhus Auckland ...
📌 ワイルドカード（wildcard）とは、具体的な文字の代わりに置く「なんでもいい」記号のことです。プログラミングの変数のようなもので、そこに何が入ってもよい、という意味のプレースホルダーだと考えてください。SELECT *の*も「全列」を表すワイルドカードでした。
🍎 かんたん説明

LIKEは「〜っぽい文字列」を探す道具。WHERE 列 LIKE 'パターン'と書きます。

②

2つのワイルドカード：% と _

「何文字でもいい」と「ちょうど1文字」
記号意味文字数
%（パーセント）任意の文字が任意の個数0文字でもOK、何文字でもOK
_（アンダースコア）任意の文字がちょうど1つ必ず1文字

% の使い方 — 置く位置で意味が変わる

パターン意味マッチする例
'A%'Aで始まるApple, Atlanta, A
'%A'Aで終わるSofia, Sea, A
'%or%'orを含むOreo, sword, order, or
💡 %は0文字にもマッチします。'%or%'は「前に何文字あってもよく、後ろにも何文字あってもよい」＝「どこかにorがあればよい」という意味です。したがってOreo（先頭がor）も、orという単語そのものもマッチします。

_ の使い方 — 文字数をきっちり指定する

パターン意味マッチする例
'_R%'1文字＋R＋何文字でもaRt, tRee, bRown
'RTX____'RTX＋ちょうど4文字RTX4080, RTX3070
'RTX%'RTXで始まる（後ろは自由）RTX4080, RTX3070 Ti

_は必ず1文字を消費します。4つ並べれば「ちょうど4文字」という意味になり、文字数まで含めて厳密に指定できます。%と_は組み合わせて使えます。

% と _ の違い
'RTX%'
RTX + 何文字でも
RTX4080 ⭕
RTX3070 Ti ⭕
vs
'RTX____'
RTX + ちょうど4文字
RTX4080 ⭕
RTX3070 Ti ❌
%は長さ自由、_は長さを固定する。
🍎 かんたん説明

%＝「あと何文字でもOK」、_＝「ちょうど1文字」。パターンの前後どちらに置くかで「始まる/終わる/含む」が決まります。

③

実用パターン集

現場でよく使う書き方

特殊記号を含むか調べる

-- @ を含む＝メールアドレスらしき値
SELECT contact FROM sales
WHERE contact LIKE '%@%';

@や-のような記号が含まれているかを調べるのにも使えます。データの中身を点検するときに便利です。

製品カテゴリの型番で絞る

-- RTXシリーズのグラフィックボードを全部
SELECT product_code FROM products
WHERE product_code LIKE 'RTX%';

型番や商品コードには「先頭がシリーズ名、後ろが番号」という規則があることが多く、LIKEと相性抜群です。S18_で始まる製品コードだけを取り出す、といった使い方ができます。

WHEREの他の条件と組み合わせる

SELECT customer, sales FROM sales
WHERE customer LIKE '%Inc%'
  AND qtr = 4
ORDER BY sales DESC;

LIKEも普通の条件式なので、AND／ORで他の条件と自由に組み合わせられます。

🍎 かんたん説明

「〜で始まる」なら'ABC%'、「〜を含む」なら'%ABC%'。この2つを覚えれば大半の場面に対応できます。

④

ILIKE — 大文字・小文字を区別しない

LIKEとの唯一の違い
⚠️ LIKEは大文字と小文字を区別します（case-sensitive）。WHERE product_code LIKE 'RTX%'と書いた場合、rtx4080のように小文字で登録されたデータはマッチしません。表記が揺れているデータでは、意図せず取りこぼしが発生します。

ILIKE を使う

-- 大文字小文字を無視してマッチ
SELECT city FROM sales
WHERE city ILIKE 'a%';
city ----------- Allentown auckland AARHUS （Aでも a でも一致する）
LIKEILIKE
大文字小文字区別する区別しない
ワイルドカード% _% _（同じ）
'RTX%'でrtx4080は❌ マッチしない⭕ マッチする
📌 違いはそれだけです。ワイルドカードの使い方も構文もLIKEと完全に同じで、大文字小文字を無視するかどうかだけが異なります。頭のIはinsensitive（区別しない）の I だと覚えましょう。
🧹 表記ゆれのあるデータでは、まずILIKEで幅広く拾って全体像を掴み、その後DISTINCTで実際の表記パターンを確認し、必要ならデータを整える——という進め方が実践的です。
🍎 かんたん説明

ILIKE＝大文字小文字を気にしないLIKE。それ以外はまったく同じです。

📖 用語集

LIKE
パターン一致
ワイルドカードを使って文字列のパターンを検索する演算子。大文字小文字を区別する。
ILIKE
大小文字を無視する一致
LIKEと同じだが大文字小文字を区別しない。PostgreSQLの機能。
%
任意の文字列
0文字以上の任意の文字にマッチするワイルドカード。
_
任意の1文字
ちょうど1文字にマッチするワイルドカード。文字数を固定できる。
case-sensitive
大文字小文字を区別する
LIKEの性質。RTXとrtxは別物として扱われる。
