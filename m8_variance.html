M8 · Statistical Operations — Variance & Standard Deviation

📏 統計③：分散と標準偏差（ばらつき）

平均が「真ん中」を教えてくれるなら、分散と標準偏差は「データがその真ん中のまわりにどれだけ散らばっているか」を教えてくれます。この単元ではvar_samp・stddev_samp（標本）とvar_pop・stddev_pop（母集団）の使い分けと、「±1標準偏差」の読み方を学びます。

📺 講義動画（分散と標準偏差）＋ 教科書 Practical SQL 2nd ed. 第11章「Finding Variance and Standard Deviation」をもとにしています

① ばらつきとは② SQLで計算③ ±1標準偏差の読み方④ 橋どうしを比べる📝 Quiz
①

分散と標準偏差とは

平均のまわりの「散らばり」を測る

データの「中心」を表すのが平均なら、「ばらつき（dispersion）」を表すのが分散（variance）と標準偏差（standard deviation, SD）です。どちらも「データが平均からどれだけ離れているか」を測りますが、役割が少し違います。

分散 (variance)標準偏差 (standard deviation)
定義各値と平均との距離を2乗して、その平均をとったもの分散の平方根
単位元の単位の2乗（大きな数になり、元の値と同じ尺度では読めない）元のデータと同じ単位（気温なら°F）
使いどころデータが全体としてどれくらい変動するかを知りたいとき釣り鐘型（正規分布）と比べて「平均から何SD離れているか」を読みたいとき

2乗する理由は、平均より大きい値（＋）と小さい値（−）が打ち消し合わないようにするためです。ごく小さな例で確かめてみましょう。8個の数 2, 4, 4, 4, 5, 5, 7, 9 は、平均が5です。平均からの距離は −3, −1, −1, −1, 0, 0, 2, 4、その2乗は 9, 1, 1, 1, 0, 0, 4, 16、合計は32。

  • 母集団の分散 ＝ 32 ÷ 8 ＝ 4、標準偏差 ＝ √4 ＝ 2
  • 標本の分散 ＝ 32 ÷ (8 − 1) ＝ 4.571…、標準偏差 ＝ √4.571… ＝ 2.138…

SQLでも同じ数が出ます。

SELECT round(var_pop(x)::numeric, 3)    AS var_pop,
       round(var_samp(x)::numeric, 3)   AS var_samp,
       round(stddev_pop(x)::numeric, 3)  AS sd_pop,
       round(stddev_samp(x)::numeric, 3) AS sd_samp
FROM (SELECT 2 AS x UNION ALL SELECT 4 UNION ALL SELECT 4 UNION ALL SELECT 4
      UNION ALL SELECT 5 UNION ALL SELECT 5 UNION ALL SELECT 7 UNION ALL SELECT 9) AS t;
var_pop | var_samp | sd_pop | sd_samp --------+----------+--------+-------- 4 | 4.571 | 2 | 2.138
📖 講師は「ここは統計の授業ではないので、数式の詳細は統計の授業で学びます。SQLを実行するとこの式が計算されている、という理解で十分です」と言っていました。数式を暗記するより、「平均のまわりの散らばり」というイメージをつかむことが大切です。
🍎 かんたん説明

分散は「平均からの距離の2乗の平均」、標準偏差はその平方根。標準偏差のほうが元のデータと同じ単位なので読みやすいです。値が散らばるほど、どちらも大きくなります。

②

SQLで計算する：var_samp と stddev_samp

標本か母集団かで関数を選ぶ
📋 講義のCSVは4月1〜30日の30日分が7回繰り返されている（210行）ため、同じ値が何度も登場します。講義の数値（125.06・11.18など）はこのデータで再現されます。

ここからはbikesで実際に計算します。講師は、前の単元で独立変数（X）だった最高気温high_tempのばらつきを調べました。使う関数は次の4つです。

関数意味使う場面
var_samp(列)標本分散（n−1で割る）データが大きな母集団の一部（標本）のとき
stddev_samp(列)標本標準偏差同上
var_pop(列)母集団分散（nで割る）データが対象の全部のとき
stddev_pop(列)母集団標準偏差同上

講師は「このデータは、長い期間にわたる自転車の通行量という大きな母集団の標本だから、_sampを使う」と選びました。まず分散です。

SELECT round(var_samp(high_temp)::numeric, 2) AS var_temp
FROM bikes;
var_temp -------- 125.06

125.06。ここで講師の注意が入ります。「この値は気温と同じ尺度ではないので、そのまま『125度』とは読めません」（分散は°Fの2乗の単位だから）。分かるのは「気温にはそれなりのばらつきがある」ということです。1年を通せば気温が大きく変わるのは当然ですね。

標準偏差も並べて出してみましょう。

SELECT round(var_samp(high_temp)::numeric, 2)    AS var_temp,
       round(stddev_samp(high_temp)::numeric, 2) AS sd_temp
FROM bikes;
var_temp | sd_temp ---------+-------- 125.06 | 11.18

11.18。標準偏差は°Fのままなので、「気温は平均から約±11度の範囲で散らばっている」と読めます。実は、stddev_sampはsqrt(var_samp)です（√125.06 ≒ 11.18）。

📌 _samp と _pop の違い：標本版は分母がn − 1、母集団版は分母がn。そのため同じデータでは標本版のほうが少しだけ大きくなります。行数が多いほど差は小さくなります。なお、PostgreSQLのvariance()はvar_sampと、stddev()はstddev_sampと同じです。
SELECT round(var_samp(high_temp)::numeric, 2)    AS var_samp,
       round(var_pop(high_temp)::numeric, 2)     AS var_pop,
       round(stddev_samp(high_temp)::numeric, 2) AS sd_samp,
       round(stddev_pop(high_temp)::numeric, 2)  AS sd_pop
FROM bikes;
var_samp | var_pop | sd_samp | sd_pop ---------+---------+---------+------- 125.06 | 124.47 | 11.18 | 11.16

4つを並べると、標本版（125.06、11.18）は母集団版（124.47、11.16）よりわずかに大きいことが分かります。210行あるので差はほんの少しです。

🍎 かんたん説明

全部のデータなら_pop、一部（サンプル）なら_samp。迷ったら_samp（variance/stddevと同じ）。分散は読みにくく、標準偏差は元の単位で読めます。

💻 ミニ練習：最低気温のばらつきを求める

bikesのlow_tempの標本分散と標本標準偏差を、それぞれround(…::numeric, 2)で丸めて、var_low・sd_lowの2列で求めてください。

SELECT round(var_samp(low_temp)::numeric, 2)    AS var_low,
       round(stddev_samp(low_temp)::numeric, 2) AS sd_low
FROM bikes;

結果は90.68と9.52。最高気温（125.06／11.18）よりばらつきが小さいことが分かります。

③

±1標準偏差の読み方

平均のまわりの「ふつうの範囲」

標準偏差の一番の使い道は、「平均 ± 1 SD」という範囲でデータを眺めることです。データが釣り鐘型（正規分布）なら、約3分の2（約68%）の値が平均±1SDの中に入り、2SD、3SDと離れるほど、値は少なくなります。

📖 講師の例：「平均が65°Fで標準偏差が約11なら、1SDの範囲は54〜76°F。講師の住む地域なら、平均はもっと高く（70〜80°F台）、夏には90°F台に上がり、60°F台後半〜70°F台にもよく留まる。これは標準偏差の大きさに合っていて意外ではない」。

実際にbikesで「平均−1SD」と「平均+1SD」をSQLで計算してみましょう。

SELECT round(avg(high_temp)::numeric, 2)                           AS mean_temp,
       round((avg(high_temp) - stddev_samp(high_temp))::numeric, 2) AS lower_1sd,
       round((avg(high_temp) + stddev_samp(high_temp))::numeric, 2) AS upper_1sd
FROM bikes;
mean_temp | lower_1sd | upper_1sd ----------+-----------+---------- 60.58 | 49.4 | 71.76

平均は60.58°Fで、約49.4〜71.76°Fが1SDの範囲です。では実際に、何日分がこの範囲に入っているでしょうか。サブクエリ（M6）で上限と下限を計算して数えます。

SELECT count(*) AS days_within_1sd,
       round(100.0 * count(*) / (SELECT count(*) FROM bikes), 1) AS pct
FROM bikes
WHERE high_temp BETWEEN
      (SELECT avg(high_temp) - stddev_samp(high_temp) FROM bikes)
  AND (SELECT avg(high_temp) + stddev_samp(high_temp) FROM bikes);
days_within_1sd | pct ----------------+----- 133 | 63.3

210日のうち133日（63.3%）が範囲内でした。「約3分の2」の目安にほぼ合っています。このデータは「ほぼ釣り鐘型」と考えてよさそうです。

講師は最後に、標準偏差の大きさの読み方も紹介しました。

  • 気温のようなデータで標準偏差が20〜30度もあれば、釣り鐘が平らにつぶれている状態。データに大きな問題（異常値や入力ミス）があるかもしれません。
  • 標準偏差がとても小さいなら、釣り鐘はとがっている（ほとんどが平均付近に固まっている）。
⚠️ 標準偏差は「単独」では判断できません。標準偏差11.18が「大きい」か「小さい」かは、平均の大きさや、その列が何を表すかに依存します。次の単元④のように、同じ尺度のもの同士で比べるときに力を発揮します。
🍎 かんたん説明

「平均 ± 1標準偏差」の中に、だいたい3分の2のデータが入ります。広がり（SD）が大きすぎる・小さすぎるときは、データの中身を疑いましょう。

💻 ミニ練習：平均±1SDの範囲を作る

bikesのlow_tempについて、平均mean_lowと、平均−1SDlower_1sd・平均+1SDupper_1sd（stddev_sampを使用）を、すべてround(…::numeric, 2)で丸めて1行で出力してください。

SELECT round(avg(low_temp)::numeric, 2)                           AS mean_low,
       round((avg(low_temp) - stddev_samp(low_temp))::numeric, 2) AS lower_1sd,
       round((avg(low_temp) + stddev_samp(low_temp))::numeric, 2) AS upper_1sd
FROM bikes;

結果は46.41、36.89、55.93。平均46.41°Fのまわり、約±9.5°Fが1SDの範囲です。足し算・引き算した後で::numericにしている（かっこの位置）点に注意。

④

橋どうしのばらつきを比べる

標準偏差と変動係数

標準偏差は「どの列のばらつきが大きいか」を比べるのにも使えます。4つの橋の通行量のばらつきを並べてみましょう。

SELECT round(stddev_samp(brooklyn_bridge)::numeric, 2)    AS brooklyn,
       round(stddev_samp(manhattan_bridge)::numeric, 2)    AS manhattan,
       round(stddev_samp(williamsburg_bridge)::numeric, 2) AS williamsburg,
       round(stddev_samp(queensboro_bridge)::numeric, 2)   AS queensboro
FROM bikes;
brooklyn | manhattan | williamsburg | queensboro ---------+-----------+--------------+----------- 981.24 | 1704.73 | 1814.04 | 1099.25

標準偏差が最も大きいのはWilliamsburg橋（1814）、最も小さいのはBrooklyn橋（981）です。ただし橋ごとに平均の通行量が違う（Williamsburg橋のほうがずっと多い）ので、標準偏差だけの比較は不公平です。そこで「標準偏差 ÷ 平均」（変動係数）という、平均に対する相対的なばらつきも見てみます。

SELECT round(avg(brooklyn_bridge)::numeric, 1)   AS avg_brooklyn,
       round(avg(williamsburg_bridge)::numeric, 1) AS avg_williamsburg,
       round((stddev_samp(brooklyn_bridge)    / avg(brooklyn_bridge))::numeric, 2)    AS cv_brooklyn,
       round((stddev_samp(williamsburg_bridge) / avg(williamsburg_bridge))::numeric, 2) AS cv_williamsburg
FROM bikes;
avg_brooklyn | avg_williamsburg | cv_brooklyn | cv_williamsburg -------------+------------------+-------------+---------------- 2269.6 | 4862.5 | 0.43 | 0.37

平均が大きいWilliamsburg橋は、標準偏差も大きいものの、平均に対する割合で見るとBrooklyn橋のほうがばらつきが大きい（0.43 vs 0.37）ことが分かります。「標準偏差が大きい＝不安定」と決めつけないことが大切です。

💡 PostgreSQLとアリーナの違い：PostgreSQLではstddev_samp(...) / avg(...)は小数のまま割れます。SQLiteでは「整数÷整数」が切り捨てになりますが、ここではstddev_sampが小数を返すので問題ありません。整数同士を割るときは* 1.0を掛けるか、::numericにキャストします。

最後に、分散が「元の単位とは別の尺度」であることをtotalで確かめます。

SELECT round(var_samp(total)::numeric, 0)    AS var_total,
       round(stddev_samp(total)::numeric, 2) AS sd_total
FROM bikes;
var_total | sd_total ----------+--------- 31015693 | 5569.17

分散は約3100万という巨大な数、標準偏差は約5569（人／日）。平均14534.5と並べて読めるのは標準偏差のほうです。

🍎 かんたん説明

ばらつきを比べるときは標準偏差。ただし平均が違うなら「標準偏差÷平均」で相対的に比べると公平です。分散は大きな数になりがちで、直接は読みにくい。

💻 ミニ練習：橋ごとの標準偏差を並べる

bikesでmanhattan_bridgeとqueensboro_bridgeの標本標準偏差を、round(…::numeric, 2)で丸めてmanhattan・queensboroの2列で出力してください。

SELECT round(stddev_samp(manhattan_bridge)::numeric, 2)  AS manhattan,
       round(stddev_samp(queensboro_bridge)::numeric, 2) AS queensboro
FROM bikes;

結果は1704.73と1099.25。Manhattan橋のほうがばらつきが大きいと分かります。
