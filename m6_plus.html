①

アンチ結合 — 「片方にしかない行」を探す

LEFT JOIN + WHERE ... IS NULL

結合で一致しなかった側の列はNULL（不明・存在しない）になります。この性質を逆手に取ると、「一致しなかった行だけ」を取り出せます。これをアンチ結合（anti-join）と呼びます。M6でJOINの種類を学んだとき、LEFT JOINは「左テーブルの全行＋一致すれば右の値も」返すものでした。そこにWHERE 右テーブルの列 IS NULLを足すだけで、「右に一致相手がいない左の行」だけに絞り込めます。

University DBで、一度も履修登録（takes）していない学生を探してみましょう。

SELECT student.student_id, student.name
FROM student
LEFT JOIN takes ON student.student_id = takes.student_id
WHERE takes.student_id IS NULL;
student_id | name 128 | Levy ...（takesに1行も現れない学生だけが残る）
💡 なぜこれで「一致しない行」だけ残るのか：LEFT JOINはstudentの全行を必ず残します。takes側に一致する行があればtakes.student_idには実際の値が入りますが、一致する行が無ければNULLで埋められます。そこをWHERE takes.student_id IS NULLで絞り込めば、「一致相手が無かった行」だけが残るわけです。
📌 INNER JOINでは同じことができません。INNER JOINは最初から一致した行しか返さないので、そもそも「一致しなかった行」がテーブルに存在しないからです。アンチ結合には必ずLEFT（またはRIGHT）JOINが必要です。
🍎 かんたん説明

LEFT JOINしてから「相手側がNULLの行だけ」を選ぶと、「片方にしかいない」行を見つけられます。出席していない学生、注文履歴のない顧客、などを探すときによく使うテクニックです。

②

CTE（共通テーブル式）で読みやすく

WITH ... AS (...) で「一時的な名前付きテーブル」を作る

CTE（Common Table Expression）はWITH 名前 AS (サブクエリ)という形で、サブクエリに一時的な名前を付けて、本体クエリから普通のテーブルのように呼び出せる仕組みです。M6のサブクエリで学んだ「派生テーブル（FROM句のサブクエリ）」と、できることはほぼ同じですが、クエリの先頭にまとめて書けるぶん読みやすくなります。

例えば、「学部の平均取得単位数（tot_cred）より単位数が多い学生」を、これまで学んだ書き方（派生テーブルをFROM句に埋め込む）とCTEの書き方で比べてみます。

-- これまでの書き方：FROM句にサブクエリを直接埋め込む
SELECT student.name, student.tot_cred, dept_avg.avg_cred
FROM student
JOIN (
    SELECT dept_name, avg(tot_cred) AS avg_cred
    FROM student GROUP BY dept_name
) AS dept_avg ON student.dept_name = dept_avg.dept_name
WHERE student.tot_cred > dept_avg.avg_cred;

-- CTEで書き直す：WITHで先に名前を付けておく
WITH dept_avg AS (
    SELECT dept_name, avg(tot_cred) AS avg_cred
    FROM student GROUP BY dept_name
)
SELECT student.name, student.tot_cred, dept_avg.avg_cred
FROM student
JOIN dept_avg ON student.dept_name = dept_avg.dept_name
WHERE student.tot_cred > dept_avg.avg_cred;
name | tot_cred | avg_cred Shankar | 102 | 81.5 ...（本体クエリの構造がすっきりし、dept_avgという名前だけで意味が分かる）

CTEは1回定義すれば、本体クエリの中で何度でも参照できます。同じサブクエリを2箇所にコピペする必要がなくなり、条件を変えたいときもWITHの中の1箇所を直すだけで済みます。

📌 使い分けの目安：サブクエリが短く1回しか使わないならFROM句にそのまま書いてOK。名前を付けたほうが意味が伝わる場合や、同じ計算を複数回使う場合はCTEにまとめましょう。
🍎 かんたん説明

CTEは「クエリの中で使う変数」のようなもの。WITH 名前 AS (...)で計算をあらかじめ名付けておけば、本体のクエリがすっきり読みやすくなります。

③

CASE式で値を分類する

数値を「Freshman」「Senior」のようなカテゴリに変換

CASE WHEN 条件 THEN 結果 ... ELSE 結果 ENDは「もし〜なら」の条件分岐をSELECTの中に書ける式です。数値データをカテゴリ（ラベル）に変換したいときによく使います。

University DBのstudent.tot_cred（取得単位数）から、学年ラベルを作ってみましょう。

SELECT name, tot_cred,
    CASE
        WHEN tot_cred >= 90 THEN 'Senior'
        WHEN tot_cred >= 60 THEN 'Junior'
        WHEN tot_cred >= 30 THEN 'Sophomore'
        ELSE 'Freshman'
    END AS class_year
FROM student
ORDER BY tot_cred DESC;
name | tot_cred | class_year Zhang | 102 | Senior Shankar | 102 | Senior Levy | 46 | Sophomore ...
⚠️ 条件は上から順に評価され、最初にtrueになったものが採用されます。それ以降のWHENは評価されません。もしtot_cred >= 30を一番上に書いてしまうと、単位数90の学生も「Sophomore以上」の最初の条件に引っかかって、意図せずSeniorやJuniorの分岐に届かなくなります。範囲の広い条件ほど後ろに、狭い（厳しい）条件ほど先に書くのが基本です。

CASE式は集計と組み合わせるのにも便利です。例えば、学年ラベルごとの人数を数えることもできます。

SELECT
    CASE WHEN tot_cred >= 90 THEN 'Senior'
         WHEN tot_cred >= 60 THEN 'Junior'
         WHEN tot_cred >= 30 THEN 'Sophomore'
         ELSE 'Freshman' END AS class_year,
    count(*) AS num_students
FROM student
GROUP BY class_year
ORDER BY num_students DESC;
📌 CASE式はSELECTリストのどこでも使えます。普通の列と同じようにGROUP BYやORDER BYのエイリアスとしても参照できるので、集計・分類・並べ替えのどこにでも組み込めます。
🍎 かんたん説明

CASE式は「もしこの値がXXならこのラベル、そうでなければ次の条件…」という変換ルールです。数値をそのまま見せるのではなく、人が読みやすいカテゴリに変えたいときに使います。
