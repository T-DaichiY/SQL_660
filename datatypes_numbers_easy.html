🍎 超やさしい版：数値データ型

整数はinteger、自動採番はserial、小数はnumeric(precision, scale)。計算する数字だけが数値型！

一言でいうと整数とserialprecisionとscale🔢 本編はこちら
⚡

一言でいうと

計算するなら数値型、計算しないなら文字型

🎯 これだけ覚えればOK

数字に見えても「足し算・掛け算をしないなら」文字型（ZIPコードなど）。「計算するなら」数値型。整数はinteger、自動採番はserial、小数はnumeric(precision, scale)。

🍎 ひとことで

「この数字で計算するか？」——YESなら数値型、NOなら文字型を検討。

①

整数とSERIAL（自動採番）

smallint・integer・bigint / serialは主キーの定番
🔹
smallint
2バイト・小さい値向け
🔷
integer
4バイト・一番よく使う
🔶
bigint
8バイト・超大量データ向け

▶ 主キーによく使うserial（自動採番）

CREATE TABLE orders (
    order_id bigserial PRIMARY KEY,
    customer_name varchar(100)
);
CREATE TABLE -- order_idは1, 2, 3... と自動的に増えていく
🆔
SERIALは自動採番の主キー：1から自動で増えていく正の整数。同姓同名の人がいても、一意なIDがあれば正確にレコードを見分けられます。
🍎 ひとことで

迷ったらinteger。膨大な件数になりそうならbigint / bigserialを検討。

②

小数：precisionとscale

precision＝全体の桁数、scale＝小数点以下の桁数

▶ 最大$9,999.99を格納する場合

CREATE TABLE mortgage (
    monthly_payment numeric(6, 2)
);
CREATE TABLE -- 9999.99 → 全体6桁(precision)、小数点以下2桁(scale)

🔢 precision

数字全体の桁数
（整数部分＋小数部分）

🎯 scale

小数点以下だけの桁数

💰
金額はnumeric（固定小数点）で：丸め誤差が積み重なると大きな損失につながることがあります。正確さが命の値には固定小数点を使いましょう。

Q1. 数値型を使うべきかどうかを判断する一番の基準は？A. その値に対して計算（足し算・掛け算など）を行うかどうか。
Q2. SERIALとINTEGERの一番の違いは？A. SERIALは1から自動で増える正の整数で、主キーとしてよく使われる。
Q3. numeric(6,2)で表せる最大の値は？A. 9999.99（全体6桁、小数点以下2桁）。

💡 まとめ

• 計算するなら数値型、しないなら文字型

• 迷ったらinteger、大量データはbigint

• 主キーにはserial系が定番

• precision＝全体桁数、scale＝小数点以下桁数
