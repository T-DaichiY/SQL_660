M1 · INSERT INTO 🍎

🍎 超やさしい版：INSERT INTOでレコードを追加

テーブルに新しい行を足す方法。丸括弧の中に、順番どおりに値を並べるだけ！

一言でいうと順番が命一部だけ入れる✏️ 本編はこちら
⚡

一言でいうと

INSERT INTO テーブル名 VALUES (値, 値, ...);

🎯 これだけ覚えればOK

テーブルに1行足すには INSERT INTO テーブル名 VALUES (値1, 値2, ...);。丸括弧1つ＝1行、カンマ区切りで列から列へ。値の並び順はテーブルの列の並び順と同じにする！

▶ 1件だけ追加する

INSERT INTO students
VALUES (1, 'John', 'Smith', 'jsmith@email.com', 425);
INSERT 0 1

▶ 複数件をまとめて追加する

INSERT INTO students
VALUES
    (1, 'John', 'Smith', 'jsmith@email.com', 425),
    (2, 'Mary', 'Lee', 'mlee@email.com', 310);
INSERT 0 2
🍎 ひとことで

丸括弧のまとまりが1行。カンマでつなげば何行でも一気に追加できる。最後の1組だけセミコロンで締める。

①

列の順番を間違えると危険

型が同じだとエラーにならない！

列名を書かなかったら、値はテーブルを作ったときの列の順番どおりに並べる必要があります。

▶ 姓と名を入れ違えてしまった例

INSERT INTO students
VALUES (1, 'Smith', 'John', 'jsmith@email.com', 425);
INSERT 0 1 -- エラーは出ない！でも first_name に 'Smith'、last_name に 'John' が入ってしまう
🚨
これが一番こわいパターン：first_nameもlast_nameも同じ「文字列（varchar）」なので、入れ違えてもデータベースはエラーを出しません。中身が正しいかまでは見てくれないのです。

✅ 型が違う場合

文字列を数値の列に入れる→
エラーで止まる

⚠️ 型が同じ場合

姓と名を入れ違える→
気づかず成功してしまう

🍎 ひとことで

チェックされるのは「型」だけ。「意味」までは見てくれないから、列の順番は自分の目で必ず確認！

②

列を指定して一部だけ入れる

自動採番されるID列などは飛ばせる

▶ IDは自動なので指定しない

INSERT INTO students (first_name, last_name, email)
VALUES ('John', 'Smith', 'jsmith@email.com');
INSERT 0 1

INTOの後ろに使いたい列名だけを書けば、bigserial型のID列のように自動で番号が振られる列を飛ばせます。

🎯
列リストを書く
(first_name, last_name, ...)
📋
同じ順でVALUES
列リストの並びと値の並びを一致
🆔
ID列は飛ばせる
自動採番なので指定不要
🛡️
合言葉：「列リストの順番」と「VALUESの順番」はワンセット。片方だけ変えると、データが違う列に入ってしまいます。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 列名を書かずにINSERTすると、値はどの順番で並べる？A. CREATE TABLEで定義した列の順番どおりに並べる。
Q2. 姓と名（どちらもvarchar）を入れ違えて挿入すると何が起きる？A. 型は合っているのでエラーにならず、そのまま間違ったデータが入ってしまう。
Q3. 列リストを指定するメリットは？A. 自動採番の列など、指定不要な列を飛ばして必要な列だけ値を入れられる。

💡 まとめ

• 丸括弧1つ＝1行、カンマで複数行

• 列名を省略すると定義順が絶対ルール

• 同じ型どうしの入れ違いはエラーにならない

• 列リストを書けば自動採番の列を飛ばせる
