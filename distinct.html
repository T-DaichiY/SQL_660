M3 · Unique values with Distinct

✨ DISTINCT — 重複を消す

列に含まれる「値の種類」を一覧する。複数列を指定すると組み合わせのユニークになる——ここが最大のポイント。

① DISTINCTとは② 複数列の落とし穴③ 使いどころ④ 実例📝 Quiz
①

DISTINCTとは

重複を取り除き、値の「種類」だけを返す

DISTINCTは、重複した値を取り除いて、その列に存在する値の一覧（ユニークな値の集合）を返すキーワードです。書き方はSELECTの直後に置くだけです。

SELECT DISTINCT qtr
FROM sales;
qtr ---- 3 1 4 2 (4 rows)

salesテーブルには2,823行ありますが、四半期の値は1〜4しかありません。DISTINCTを付けると、その4種類だけが返ってきます。

📌 DISTINCTの結果は並び順が保証されません。上の例でも1,2,3,4の順には出てきません。整った一覧が欲しいときはORDER BYを組み合わせます：SELECT DISTINCT qtr FROM sales ORDER BY qtr;

「何回出てきたか」は分からない

顧客の名前（first_name）で考えてみましょう。Johnという顧客が2人いても、DISTINCT first_nameが返すのはJohnという1件だけです。「Johnという名前が存在する」ことだけを教えてくれ、何人いるかは教えてくれません。件数を知りたい場合は、後のレッスンで学ぶ集計関数（aggregate functions）を使います。

⚠️ NULLもユニークな値の1つとして扱われます。対象の列にNULLが含まれていれば、DISTINCTの結果に空欄が1行分現れます。「値が入っていない」ことも1つの種類としてカウントされる、と覚えておきましょう。
🍎 かんたん説明

DISTINCTは「値の種類リスト」を作る道具。SELECT DISTINCT 列名 FROM テーブル;と書くだけです。

②

複数列を指定したときの落とし穴

列ごとではなく「行（組み合わせ）」がユニークになる

ここがDISTINCTで最も誤解されやすいポイントです。列を2つ以上書いたとき、DISTINCTはそれぞれの列を個別にユニーク化するのではなく、その列の組み合わせ（レコード全体）がユニークかどうかで判定します。

例：first_name と last_name

SELECT DISTINCT first_name, last_name
FROM client;
first_name | last_name -----------+---------- John | Smith John | Jackson Mary | Smith

John SmithとJohn Jacksonは別人なので、両方とも結果に残ります。「Johnが2回出てくるのは重複では？」と感じるかもしれませんが、そうではありません。組み合わせとしては違うため、どちらもユニークな行なのです。

1列のDISTINCT vs 2列のDISTINCT
DISTINCT first_name
John
Mary
2行
≠
DISTINCT first_name, last_name
John Smith / John Jackson
Mary Smith
3行
列を足すほど「組み合わせ（permutation）」が増え、結果の行数も増えていく。

salesテーブルでの実例

-- 製品ラインは7種類しかない
SELECT DISTINCT product_line FROM sales;   -- 7 rows

-- 製品コードは109種類ある
SELECT DISTINCT product_code FROM sales;   -- 109 rows

-- 両方を指定すると…？
SELECT DISTINCT product_line, product_code FROM sales;
product_line | product_code -------------+-------------- Classic Cars | S18_4027 Classic Cars | S24_3191 Motorcycles | S10_1678 ... (109 rows)

結果は109行——製品コードの種類数と同じです。「Classic Cars」が何度も繰り返し現れますが、これは重複ではありません。S18_4027とS24_3191は別の製品なので、組み合わせとしては別物だからです。

📌 覚え方：複数列を指定したとき、種類が多い列の数だけ行が出て、種類が少ない列は繰り返し表示される。「片方の列だけを見ると重複しているように見える」のは正常な動作です。
🍎 かんたん説明

2列書いたら「2列セットで重複していないか」を見ます。片方だけ同じでも、もう片方が違えば残ります。

③

DISTINCTの使いどころ

一覧作成・エラー発見・データクリーニングの入口

用途1：ユニークな一覧を作る

顧客の一覧、取扱商品の一覧、顧客が所在する州の一覧、モデル番号の一覧——「うちには何があるのか」を素早く把握したいときの定番です。同じ値が何度も繰り返される列ほど効果を発揮します。

用途2：エラー・欠損の発見

部品番号が1〜10まで存在するはずなのに、DISTINCTの結果に9番だけがない——これはデータが欠けているサインかもしれません。「あるべきものがない」ことに気付ける、非常に手軽な点検方法です。

用途3：データクリーニングの下準備

🧹 DISTINCT statusを実行してResolvedとresolvedの両方が出てきたら、それは表記ゆれです。同様に、顧客名でIncとInc.、LtdとLtd.が混在していないか——DISTINCTはこうした不統一を洗い出す最初の一歩になります。「Mini Gifts Inc の注文を全部取り出したい」というとき、表記が揃っていなければ取りこぼしが発生します。

用途4：サブクエリや集計の前処理

この先のコースでは、サブクエリの中でDISTINCTを使って対象を特定したり、集計関数（aggregate functions）の前後でデータを整理したりする使い方も出てきます。今は「重複を消す道具」として基本を固めておけば十分です。

🍎 かんたん説明

DISTINCTは「どんな値が入っているのか？」を確認する調査ツール。データの品質チェックにもよく使われます。

④

salesテーブルで確かめる

実際に手を動かす4つの例

例1：四半期の確認

SELECT DISTINCT qtr FROM sales
ORDER BY qtr;
qtr ---- 1 2 3 4

4つの四半期がすべて揃っていることを確認できます。ORDER BYを足せば順番も整います。

例2：注文ステータスの種類

SELECT DISTINCT status FROM sales;
status ----------- Shipped Resolved Cancelled On Hold Disputed In Process (6 rows)

注文が取りうる状態は6種類だと分かります。NULLが表示されなければ、この列にはNULLが存在しないという確認にもなります。

例3：製品ラインの一覧

SELECT DISTINCT product_line FROM sales;
product_line ------------------ Classic Cars Motorcycles Trucks and Buses Vintage Cars Planes Ships Trains (7 rows)

例4：顧客の一覧

SELECT DISTINCT customer FROM sales
ORDER BY customer;
customer -------------------------- AV Stores, Co. Alpha Cognac Amica Models & Co. ... (92 rows)

92社の顧客がいることが分かります。ORDER BYで並べれば、似た名前が隣り合うため、表記ゆれも見つけやすくなります。

📌 DISTINCT ＋ ORDER BY はセットで覚えましょう。一覧を作るのがDISTINCT、それを人間が読める形に整えるのがORDER BYです。
🍎 かんたん説明

気になる列を見つけたら、まずSELECT DISTINCT その列 FROM sales;。テーブルの中身を知る一番手軽な方法です。
