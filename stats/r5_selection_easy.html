🍎 超やさしい版：変数選択とモデル評価

「どの変数を使えば、いちばん良いモデルになる？」と「そのモデルは新しいデータでも通用する？」を、やさしく学びます。

変数を選ぶ後退・ステップワイズシンプルが一番テストで確かめる📊 本編はこちら
📖 講義動画との対応：①は「Variable selection: Forward selection」、②は「Backward selection」と「Stepwise and Hierarchal selection」の前半、③は「Stepwise and Hierarchal selection」の後半、④は「Evaluating performance」です。データはワシントンD.C.の自転車シェア bikes（rentals = 1日の貸出台数）です。
①

変数を1つずつ足す（前進選択）

何もない状態から積み上げる

🎯 これだけ覚えればOK

変数選択 = 良い説明変数を選ぶこと。前進選択は「1つずつ足す」。step() は AIC が一番小さくなるように自動で選ぶ。

🏃
前進選択（forward selection）：何もない状態から、いちばん役に立つ変数を1つずつ足していく。

10個の変数の全組み合わせは 2¹⁰ = 1,024通り、20個なら 100万通り超。全部は試せないので、1つずつ足していきます。

手で試すと、まず4つの変数の R² は次のとおりでした。

変数R²
humidity（湿度）0.0083
temperature（気温）0.4448
windspeed（風速）0.0593
season_Summer（夏）0.1344

気温が約44%で一番！ 2つ目は「調整済みR²」で比べ、temperature + humidity は 0.4810（約48%）、temperature + windspeed は 0.4625。だから湿度を足します。

自動でやるなら、step() の出番です。

null_model <- lm(data = bikesCleanEncoded, rentals ~ 1)   # 説明変数なし = 平均を当てるだけ
full_model <- lm(data = bikesCleanEncoded, rentals ~ .)   # 全部入り

forward_model <- step(null_model,
                      scope = list(lower = null_model, upper = full_model),
                      direction = "forward")

最後は AIC = 9367.2 で止まりました（13個の変数、調整済みR² 0.8324）。AIC は小さいほど良く、数字そのものではなく比べるためのものです。

🍎 ひとことで

前進選択は「チームに1人ずつ仲間を入れる」やり方。一番頼りになる人（気温）から入れて、これ以上入れても良くならなくなったら終わり。

🤔 答えられるかな？（クリックで答えが開く）

Q1. なぜ、変数を全部の組み合わせで試さないの？A. 変数が10個で1,024通り、20個で100万通り超と、数が爆発して大変だから。
Q2. step() は何を一番小さくしようとする？A. AIC（赤池情報量規準）。当てはまりの良さと複雑さのバランス。
Q3. rentals ~ 1 は何のモデル？A. null model。説明変数なしで、平均を当てるだけのモデル。
②

全部から外す（後退・ステップワイズ）

引く・足すの両方

🎯 これだけ覚えればOK

後退選択 = 全部入りから1つずつ外す（-）。ステップワイズ = 足す・外すを両方やる（direction = "both"）。

🎒
後退選択（backward selection）：全部入りのモデルから始めて、いらない変数を1つずつ外していく。
initial_model <- lm(rentals ~ ., data = bikesCleanEncoded2)

backward_model <- step(initial_model, direction = "backward")

出発点（全部入り）の AIC は 9160.9、調整済みR² は約 0.88（0.8783）。- の付いた行（引いたときの AIC）を見て、weekday_Saturday → realfeel → weekday_Thursday → windspeed2 → weekday_Wednesday の順に外すと、AIC は 9153.6 まで下がりました。最後の表は先頭が <none>（これ以上外さないのが最良）で終わります。

➕➖
前進は +、後退は -。ステップワイズは、足す候補（+）も外す候補（-）も一緒に表に並ぶ。
model_all <- lm(data = bikesCleanEncoded2, rentals ~ .)
step(model_all, direction = "both")

このデータでは、外した変数を戻したほうが良くなることはなかったので、ステップワイズの最終モデルも後退選択と同じ（調整済みR² 0.8787）でした。

⚠️ lm(rentals ~ . - month4) はエラーです。month は1つの因子の列で、month4 は「4月」のダミー変数の名前にすぎないからです（月を外したいなら、11列にワンホット化）。
🍎 ひとことで

後退選択は「全員集めてから、いらない人を帰す」。ステップワイズは「入れたり帰したり」。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 後退選択はどの状態から始める？A. 全部の説明変数を入れたモデル（~ .）。
Q2. step() の表で、足す行と引く行の記号は？A. 足す = +、引く = -。
Q3. <none> が一番上に来たら？A. これ以上、変数を足しても外しても良くならない = 終了。
③

シンプルなモデルが一番

倹約モデルと注意点

🎯 これだけ覚えればOK

同じくらい説明できるなら、変数が少ないシンプルなモデルを選ぶ（倹約モデル、オッカムの剃刀）。選んだあとは VIF で重複もチェック。

✂️
オッカムの剃刀：ほかが同じなら、いちばんシンプルな説明が良い。

3つの変数のモデルと20個の変数のモデルで AIC が同じくらいなら、3つのほうを選びましょう。

理由意味
効率集めて保存するデータが少なくて済む
解釈しやすさ3つの変数のほうが、20個より分かりやすい
汎化過学習を避けて、新しいデータでも通用しやすい

BIC（k = log(行数)）は AIC より複雑さへのペナルティが重く、前進選択では変数が13個 → 12個に減りました（BIC = 9427.1）。

⚠️ 前進・後退選択は多重共線性を考えません。前進選択の最終モデルでは、VIF が temperature 213.9、temperature2 98.4、realfeel 69.6 と、とても大きくなっていました。気温・体感温度・気温の2乗は、ほとんど同じ情報だからです。
🧭
階層的回帰（hierarchical regression）：データではなく理論の順番で入れる。たとえば仕事の成績なら、①年齢・学歴 → ②経験・スキル → ③年齢×経験（交互作用）。
方法足す外す理論ベース計算コスト過学習リスク
前進選択○××低中
後退選択×○×高低〜中
ステップワイズ○○×中中
階層的回帰○×○低〜中低
⚠️ olsrr の ols_step_both_p(p_enter = 0.2, p_remove = 0.01) は、結果を自動保存しません。使うときは代入し、選ばれた変数を自分で lm() に書き直します。出力の beta も標準化係数ではなく、ふつうの係数です。
🍎 ひとことで

シンプルなモデルは、集めるのも、説明するのも、新しいデータで使うのも楽。迷ったら、少ない変数のほうを選びましょう。

🤔 答えられるかな？（クリックで答えが開く）

Q1. オッカムの剃刀を一言で言うと？A. ほかが同じなら、シンプルなほうを選ぶ。
Q2. なぜ前進選択のあとに VIF を調べる？A. 前進選択は似た変数（多重共線性）を考えず、重複して入れてしまうことがあるから。
Q3. 階層的回帰は、何に基づいて変数を入れる？A. データの数字ではなく、理論や概念の順番。
④

テストデータで確かめる

過学習とデータ漏洩

🎯 これだけ覚えればOK

訓練データでモデルを作り、テストデータで試す。訓練で高くテストで低いなら過学習。テストの情報を訓練に混ぜない（データ漏洩）。

📝
練習問題（訓練データ）で満点でも、本番（テストデータ）で点が取れなければ、丸暗記しただけ。これが過学習（overfitting）。

たとえば訓練データで R² = 0.95、テストデータで R² = 0.40 なら過学習です。この授業は80:20に分けます（validation も使うなら 70-15-15 や 80-10-10。データが小さいときは分けません）。

set.seed(1)                       # 乱数を固定
n <- dim(bikes)[1]                # 731
train_indices <- sample(1:n, size = 0.8 * n)
train_set <- bikes[train_indices, ]    # 訓練
test_set  <- bikes[-train_indices, ]   # テスト
Training set size: 584 Test set size: 147 Training set size (%): 0.7989056 Test set size (%): 0.2010944

731行が、訓練 584行・テスト 147行に分かれました。訓練データで rentals ~ temperature を作ると R² は 0.3947（約40%）。

predictions <- predict(temp_model_training, newdata = test_set)
cor(test_set$rentals, predictions)^2
[1] 0.3921496
👍
テストの R² は 0.392（式で求めると 0.388）。訓練の 0.395 とほぼ同じ → 過学習していない。
⚠️ データ漏洩（data leakage）：欠損値をデータ全体の中央値で埋めてから分割すると、テストデータの情報が訓練に混ざります。列名の修正・重複行の削除・明らかな入力ミスの修正は分割の前でOK。欠損値の補完などは、分割の後に、訓練データで決めた手順をテストデータにも同じように行います。手順はコメント付きで、自動化できればさらに良いです。
🍎 ひとことで

モデルの本当の実力は、見たことのないデータで測る。テストデータは「本番まで見せない問題」です。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 訓練 R² = 0.95、テスト R² = 0.40。何が起きている？A. 過学習。訓練データのノイズまで覚えてしまい、新しいデータで通用しない。
Q2. 731行を80:20に分けると、訓練とテストは何行？A. 訓練584行、テスト147行（sample() は小数点以下を切り捨てるため）。
Q3. 全データの中央値で欠損値を埋めてから分割すると、何が問題？A. テストの情報が訓練に混ざる（データ漏洩）。性能が実際より良く見える。
