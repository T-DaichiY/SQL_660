作業ディレクトリ

R はどこのファイルを見ている？

作業ディレクトリ（working directory）は、R がファイルを読み込むときに探し、保存するときに置くフォルダです。read.csv("donors.csv") が「ファイルが見つからない」と言うとき、原因のほとんどはここです。

"donors.csv" %in% list.files()
[1] TRUE

getwd() を実行すると、今のフォルダのパス（例："/Users/you/Documents/DTSC550"）が表示されます。上のコードは「donors.csv がそのフォルダにあるか」を TRUE/FALSE で確かめています。

関数役割
getwd()今の作業ディレクトリを表示
list.files()そのフォルダにあるファイルの一覧
setwd("パス")作業ディレクトリを変更

RStudio では Tools → Global Options → General → Default working directory で既定のフォルダを決められます。いちばん簡単なのは、.Rmd と CSV を同じフォルダに置くことです（Notebook はそのフォルダを作業ディレクトリとして実行されます）。

📗 R4DS（Wickham & Grolemund, R for Data Science）より：スクリプトの中に setwd("/Users/…") のような絶対パスを書くと、他の人の PC では動かない。分析ごとにフォルダ（RStudio Project）を作り、その中で相対パスを使うのが長く使えるやり方。パスの区切りは Windows でも / を使うのが安全（\\ は R で特別な意味を持つ）。
出典: R4DS Ch.6 Workflow: Projects（内容を要約・日本語で再構成）
⚠️ パスの書き方は Mac（/Users/name/Desktop）と Windows（C:/Users/name/Desktop）で違います。CSV を Excel や Numbers で開いて上書き保存すると形式が変わることがあるので、開かずにそのまま使いましょう。

コメント

未来の自分とチームのために

# から行末までは R が無視します。短いコードでも「何のための計算か」を書いておくと、あとで読むあなたと同僚が助かります。

seeker <- 3.1415          # 1つ目の変数を作る
lover  <- 2.7183          # 2つ目の変数を作る
keeper <- seeker * lover  # 2つを掛けて3つ目を作る
print(keeper)             # keeper の値を表示
[1] 8.539539
✍️ 良いコメントは「何をしているか」より「なぜそうするか」を書きます。例：# 欠損があるので na.rm = TRUE。
📗 R4DS（Wickham & Grolemund, R for Data Science）より：長い目で見れば、Environment に残った結果ではなくスクリプト（とデータ）を「本物の記録」と考えるべき。スクリプトがあれば環境は再現できるが、逆は難しい。だから RStudio の「終了時にワークスペースを保存しない」設定が勧められている。
出典: R4DS Ch.6 Workflow: Projects（内容を要約・日本語で再構成）

パッケージ：インストールと読み込み

2段階を区別する

パッケージは関数・データのまとまりです（Python の NumPy や pandas のような「ライブラリ」）。R に最初から入っているものもありますが、多くはインターネットから入れます。

段階関数頻度電球のたとえ
① インストールinstall.packages("dplyr")PC ごとに1回電球を取り付ける
② 読み込みlibrary(dplyr)セッション（Notebook）ごとに毎回スイッチを入れる

インストールだけして読み込み忘れると、関数が「見つからない」と言われます。インストールしていないパッケージを読み込もうとしても同じくエラーです。

library(notARealPackage)
Error: there is no package called ‘notARealPackage’
⚠️ install.packages() は引用符あり（"dplyr"）、library() は引用符なしでも動く（library(dplyr)）。インストールの行は Notebook に残すと毎回実行されてしまうので、コンソールで1回だけ実行するか # でコメントアウトしておきます。

入っているパッケージの確認・更新は、RStudio の Packages ペインが簡単です（チェックが入っているのが読み込み済み）。Windows で「Rtools が必要」という警告が出ても、この授業では無視して大丈夫です。

環境の整理

rm() とほうきボタン

作業を続けると Environment にオブジェクトがたまります。古い値が残っていると、消したはずの変数が実は生きていて結果が変わるといった事故の原因になります。

a <- 1
b <- 2
ls()
rm(a)
ls()
rm(list = ls())
ls()
[1] "a" "b" "keeper" "lover" "seeker" [1] "b" "keeper" "lover" "seeker" character(0)
  • ls()：今ある名前の一覧
  • rm(名前)：1つ削除
  • rm(list = ls())：全部削除
  • RStudio の Environment／Console にあるほうきアイコンでも削除できる
🔁 提出前のチェック：環境を空にしてから Run All（すべてのチャンクを上から実行）。エラーなく最後まで動けば、他の人の PC でも再現できる可能性が高くなります。
💻 ミニ練習：パッケージを読み込んで環境を空にする

（1）stats パッケージを読み込み、（2）x <- 5 を作ってから、（3）環境のオブジェクトをすべて削除するコードを書いてください。

library(stats)
x <- 5
rm(list = ls())

stats は R に最初から入っているので install は不要。rm(list = ls()) で全オブジェクトを削除。
