多項式回帰：曲がった関係を二乗項でとらえる

Polynomial regression

これまでの重回帰は「説明変数と応答変数は直線的（linear）な関係」という前提（線形性）で作ってきました。でも現実のデータは、いつも直線とは限りません。直線で当てはまりが悪いとき、対処は大きく2つあります。

  • データを変換して直線に近づける（たとえば対数変換 logarithmic transformation。変換の種類はほかにもたくさんあります）。
  • 非線形（nonlinear）な項をモデルに足す——これがこの回の多項式回帰（polynomial regression）です。

自転車レンタル（bikes）データで確認します。講義では、影響点（Cook の距離 > 0.005 の29日）を除いた702日分のデータ bikesNoIP を使います。まず各予測変数を1つずつ rentals と散布図にし、geom_smooth() でなめらかな線を重ねて、直線かどうかを目で見ます。

bikesNoIP <- bikes[-c(infpts), ]   # 影響点の29日を除く
nrow(bikesNoIP)

bikesNoIP |> ggplot() +
  aes(x = temperature, y = rentals) +
  geom_point() +
  geom_smooth()
[1] 702

講師の見立て：humidity（湿度）は少し曲がっている、windspeed（風速）はわずかに曲がる程度、temperature（気温）ははっきり曲がっている。気温は約65°Fまでは直線的に増え、それより暑くなりすぎるとレンタルは減っていきます（暑すぎると誰も乗らない）。つまりどの予測変数も「完全な直線」ではありません。

気温 × レンタル数（bikesNoIP、702日、実データ）
赤い点線＝直線（adj R² = 0.444）、青い実線＝二次式 temperature + temperature²（adj R² = 0.490）。曲がった形を、二次式のほうが追いかけています。

そこでモデルを拡張します。曲がり方は放物線（parabola）に似ているので、二次式（quadratic）を試します：y = b₀ + b₁x + b₂x²。多項式は何次でも試せますが、講義では二乗（x²）までに絞ります。やり方は簡単で、予測変数を2乗した新しい列を mutate() で作るだけです。

bikesNoIP <- bikesNoIP |>
  mutate(humidity2 = humidity^2) |>
  mutate(windspeed2 = windspeed^2) |>
  mutate(temperature2 = temperature^2)

気温や風速を2乗するので、新しい列の値はずっと大きくなります。次に、これまでのモデル（model 1：気温のみ、model 2：気温・湿度・風速）の調整済み決定係数（adjusted R²）を確認しておきます。

多項式回帰の落とし穴は多重共線性（multicollinearity）です。VIF と許容度（tolerance＝1/VIF）を見てみましょう（VIF が 5 または 10 を超えると問題、というのが目安でした）。

library(car)

humidity と humidity²、temperature と temperature² のVIFが非常に大きい（60〜70台）。これは当然で、temperature² は temperature から作った列なので自動的に相関してしまう（temperature がなければ temperature² は計算できない）からです。

⚠️ 講師の注意：VIFが大きくても、モデルがよく当てはまり、見たことのないデータ（テストセット test set）でもうまく予測できる（generalize）なら、この多重共線性は無理に取り除かなくてもよい（テストセットでの確認は後の回で学びます）。取り除くなら、humidity と temperature（元の列）の両方、または片方を外して、adjusted R² が上がるか試します。

試しに humidity（元の列。humidity2 はその2乗）だけを外した model 5 を見ます。

1 / vif(bikes_model5)
[1] 0.6009739 windspeed temperature humidity2 temperature2 0.92953122 0.01335332 0.88949465 0.01340988

adjusted R² は 0.6032 → 0.6010 でほぼ同じ（改善していない）。temperature と temperature² は相変わらず強く相関しています（一方が他方を2乗して作ったので当然）。いっぽう humidity² と windspeed の許容度は高く、他の変数がとらえていない信号を拾っています。

📝 書き方のメモ：列を作らずに、式の中で lm(rentals ~ temperature + I(temperature^2)) と書くこともできます（^ は式の中では別の意味になるので I() で包みます）。気温だけを二次式にした場合、adjusted R² は 0.444（直線）→ 0.490 になります。
🍎 かんたん説明

直線で足りないときは、予測変数を2乗した列を足すだけで「曲がり」を表せます。そのかわり x と x² は仲間どうし（相関）になるので VIF は大きくなりますが、予測がうまくいくなら気にしすぎなくてOK。

💻 ミニ練習：気温の二乗を足す

bikesNoIP に temperature2（temperature の2乗）の列を作り、rentals を temperature と temperature2 の2つで予測する回帰を実行して、summary() で結果を出してください。

bikesNoIP <- bikesNoIP |> mutate(temperature2 = temperature^2)
bikes_quad <- lm(rentals ~ temperature + temperature2, data = bikesNoIP)
summary(bikes_quad)

係数は temperature = 307.73、temperature2 = −1.92（どちらも p < 0.001）、adjusted R² = 0.4904（直線のみでは 0.4440）。二乗項の係数が負なので、グラフは上に凸（山なり）です。

カテゴリ変数の変換：ラベルとダミー変数

case_when() → dummy encoding → n−1

回帰では量的変数（quantitative variable）を予測します。ここまでは気温・風速のような量的な予測変数でしたが、カテゴリ変数（categorical variable）も予測変数にできます。その前に最初の変換：文字（character）データは factor（因子）に変換します。ただし、アンケートの自由回答（「今日の気分は？」→「元気です」）のようなテキストデータは別で、カテゴリとして使えるものだけを factor にします。

では、なぜカテゴリ変数を「変換」するのでしょうか。理由は2つあります。

理由 ①：人間にわかるようにするため。 データの1行目を見てください。

bikesNoIP[1, c("date", "season", "holiday", "weekday", "weather")]
date season holiday weekday weather 1 2011-01-01 1 0 6 2

season = 1、holiday = 0、weekday = 6、weather = 2……これが何を意味するか、コードブック（codebook／データ辞書）を見ないとわかりません。グラフにしても、曜日が数字のままでは読者に「6 は〇曜日です」と説明しなければなりません。

理由 ②：一部のカテゴリだけ外せるようにするため。 数字で入っているだけの season・holiday・weekday・weather は、そのまま回帰に入れてもカテゴリ変数として扱われます。

①　case_when() で意味のある名前に直す

まず、数字が何を表すかをコードブック（データ辞書）で確認します。

列数字 → 意味
season1 = Winter, 2 = Spring, 3 = Summer, 4 = Fall
holiday0 = No, 1 = Yes
weekday0 = Sunday, 1 = Monday, …, 6 = Saturday
weather1 = Clear, 2 = Light precipitation, 3 = Heavy precipitation

mutate() の中で case_when() を使い、同じ列名で上書きします。

bikesClean <- bikesNoIP |>
  mutate(
    season = case_when(
      season == "1" ~ "Winter",
      season == "2" ~ "Spring",
      season == "3" ~ "Summer",
      season == "4" ~ "Fall",
      .default = season          # 当てはまらなければ元の値を残す
    ),
    holiday = case_when(
      holiday == "0" ~ "No",
      holiday == "1" ~ "Yes",
      .default = holiday
    ),
    weekday = case_when(
      weekday == "0" ~ "Sunday",    weekday == "1" ~ "Monday",
      weekday == "2" ~ "Tuesday",   weekday == "3" ~ "Wednesday",
      weekday == "4" ~ "Thursday",  weekday == "5" ~ "Friday",
      weekday == "6" ~ "Saturday",
      .default = weekday
    ),
    weather = case_when(
      weather == "1" ~ "Clear",
      weather == "2" ~ "Light precipitation",
      weather == "3" ~ "Heavy precipitation",
      .default = weather
    )
  )
bikesClean[1, c("date", "season", "holiday", "weekday", "weather")]
date season holiday weekday weather 1 2011-01-01 Winter No Saturday Light precipitation

1行目を説明できるようになりました：「2011年1月1日、冬、祝日ではない、土曜日、小雨（light precipitation）」。

⚠️ 講師の注意：比較には二重のイコール == を使います。= を1つにしてしまうのはよくある間違いです。また、.default = season を付けておけば、書き漏らした値があっても元の値が残ります。変換後に文字になった列は、factor に戻しておくのがおすすめです（mutate(across(c(season, holiday, weekday, weather), as.factor))）。

②　ダミー変数（dummy encoding／one-hot encoding）

次に「季節を1つだけ外す」にはどうするか。1つの列に 1,2,3,4（または Winter…Fall）が入っているのをやめて、「冬か？」「春か？」「夏か？」「秋か？」を1列ずつ、Yes(1)／No(0) の列に分けます。これをダミー変数（dummy variable）、またはワンホットエンコーディング（one-hot encoding）と呼びます。こうすれば summer の列だけを回帰から外し、winter・spring・fall を残す、ということができます。dplyr の if_else() で手作業で作ると、次のとおりです。

bikesClean |>
  mutate(Winter = if_else(season == "Winter", 1, 0)) |>
  mutate(Spring = if_else(season == "Spring", 1, 0)) |>
  mutate(Summer = if_else(season == "Summer", 1, 0)) |>
  mutate(Fall   = if_else(season == "Fall",   1, 0))
（4行を代表して、各季節の最初の日を表示） date season Winter Spring Summer Fall 1 2011-01-01 Winter 1 0 0 0 80 2011-03-21 Spring 0 1 0 0 172 2011-06-21 Summer 0 0 1 0 267 2011-09-24 Fall 0 0 0 1

1行の中で「1」になるのは4つのうち必ず1つだけです。たとえば最後の行は秋の日なので、Fall だけが 1 で、Winter・Spring・Summer は 0。全702行で、4つの合計はすべて 1 になります。

table(rowSums(bikesClean[, c("Winter", "Spring", "Summer", "Fall")]))
1 702

fastDummies パッケージを使えば一度にできます。ただし課題では手作業の方法を使い、fastDummies は使えません（講義内の紹介のみ）。

library(fastDummies)
bikesCleanEncoded <- dummy_cols(bikesClean, remove_first_dummy = TRUE)
bikesCleanEncoded <- bikesCleanEncoded |>
  select(-c(season, holiday, weekday, weather))   # 元の列は重複なので削除

remove_first_dummy = TRUE によって、各変数の最初のダミーが1つ削られます。列名は season_Spring、season_Summer、season_Winter（season_Fall は無い）のようになります。

変数水準の数残るダミー削られる基準カテゴリ
season43列Fall
holiday21列（holiday_Yes）No
weekday76列Friday
weather32列Clear（降水なし）

なぜ削るのか？「春でも夏でも冬でもなければ、自動的に秋」と決まるので、秋の列は情報を何も足さないからです。ダミーを全部入れると、1つの列が他の列から完全に決まってしまい、ダミー変数トラップ（dummy variable trap）という多重共線性に陥ります。実際に4列とも入れてみると：

trap <- lm(rentals ~ Winter + Spring + Summer + Fall, data = bikesClean)
coef(trap)
summary(trap)   # ← 出力の途中に次の1行が出る
(Intercept) Winter Spring Summer Fall 4768.4624 -2159.4511 234.9957 980.4162 NA Coefficients: (1 not defined because of singularities)
⚠️ 講師の注意：回帰の係数に NA が出たり、singularity（特異）というメッセージ（上の not defined because of singularities）が出たら、ダミー変数トラップを疑います。カテゴリがn個なら、ダミーはn−1個（季節4つ→3列、曜日7つ→6列）にします。
🔑 基準カテゴリの意味：季節を Winter・Spring・Summer の3列にして回帰すると、切片は基準（Fall）のときの平均になります。実際、秋のレンタル平均は 4768.46、冬は 2609.01 で、その差が冬の係数（−2159.45）です。tapply(bikesClean$rentals, bikesClean$season, mean) で確かめられます。

④

交互作用：2つの変数の組み合わせ効果

interaction：A * B

ここまでは、応答変数と各予測変数の関係が、ほかの予測変数の値に左右されないことを前提にしてきました。また多重共線性（2つ以上の予測変数が互いに関連している）も学びました。今回は別の現象です：2つの変数が組み合わさると、別々に使ったときとは違う効果を応答変数に与える。これを交互作用（interaction）と呼びます。

多重共線性 multicollinearity交互作用 interaction
何が起きる？予測変数どうしが関連している（独立でない）2つの予測変数が組み合わさって応答に別の効果をもつ
予測変数どうしの関連あるなくてもよい
対処VIFで確認、必要なら変数を外す積の項（A × B）をモデルに加える

身近な例（講義より）：

  • コレステロールを下げたい：運動か、食事か？ それぞれ良いが、両方すればさらに大きな効果が出そう。
  • 血圧を改善したい：薬か、生活習慣の改善か？ 両方が組み合わさると改善が大きいかもしれない。
  • 生産性を上げたい：研修か、経験か？ 人を採用するなら両方ほしい。

どれも「単独の効果の足し算」より組み合わせの効果のほうが大きいかもしれない、という話です。自転車データなら「天気が悪化し、かつ風速が強くなる」と、風だけ・天気だけのときより大きくレンタルが減るのでは？ と考えられます。

出力の係数から、予測式（回帰式）が組み立てられます。Heavy・Light は、それぞれ 重い降水・小雨のとき 1、そうでなければ 0 をとるダミー変数です。

ŷ（rentals）= 5901.67 − 132.20 × windspeed − 1878.13 × Heavy − 685.78 × Light − 58.10 × windspeed × Heavy − 18.04 × windspeed × Light

例：風速10 mph の晴れの日の予測（Heavy = 0、Light = 0 なので、天気と交互作用の項はすべて 0）：5901.67 − 132.20 × 10 = 4,579.7 台（桁をそろえると 4579.707）。

rentals_hat <- function(windspeed, heavy, light) {
  b[1] + b[2]*windspeed + b[3]*heavy + b[4]*light +
    b[5]*windspeed*heavy + b[6]*windspeed*light

傾き（風が1 mph 強くなるごとの変化）は、晴れ −132.2、小雨 −150.2、大雨 −190.3。天気が悪いほど、風の影響が大きくなる向きに直線が傾きます。

傾きを式から読むと、風速の係数は 晴れ：−132.20、小雨：−132.20 − 18.04 = −150.24、大雨：−132.20 − 58.10 = −190.30。交互作用の係数は「天気が悪いとき、風の影響がどれだけ上乗せされるか」を表します。

⚠️ この例で正直に確認しておくこと：交互作用の2つの係数は有意ではありません（p = 0.674、p = 0.696）。交互作用ありとなしのモデルの比較（anova()）も F = 0.148、p = 0.863 で、調整済み R² も 0.1237（なし）→ 0.1216（あり）とむしろ小さくなります。「ありそうな交互作用」は仮説であり、入れたら必ず改善する、というわけではありません。係数の p 値や adjusted R² で確かめましょう。
anova(model_NoInteraction, model_interaction)

さらに学ぶ：交互作用の説明（Jim Frost）、折れ線グラフで交互作用を見分ける方法（講義では扱わない）、ANOVA における交互作用（ANOVAも交互作用を扱います）。

🍎 かんたん説明

交互作用は「AとBがそろったときだけ効果が変わる」ということ。Rでは A * B と書くだけで、A、B、A:B の3つが入ります。予測は predict() で。でも、有意でなければ無理に入れなくてOK。

💻 ミニ練習：交互作用モデルで予測する

model_interaction（rentals ~ windspeed * weather）を使って、風速5 mph・小雨（"Light precipitation"）の日のレンタル数を predict() で予測してください。

predict(model_interaction,
        data.frame(windspeed = 5, weather = "Light precipitation"))

結果は 4464.69（約4,465台）。手計算では 5901.67 − 132.20×5 − 685.78 − 18.04×5 ≒ 4,464.7 です。

💻 ミニ練習：交互作用を式に書く

bikesClean を使い、rentals を windspeed と weather およびその交互作用で予測する回帰を、星（*）を使った近道の書き方で書いてください。

model_interaction <- lm(rentals ~ windspeed * weather, data = bikesClean)
summary(model_interaction)

windspeed * weather は windspeed + weather + windspeed:weather と同じ。出力には windspeed:weatherHeavy precipitation と windspeed:weatherLight precipitation の2行（コロン付き）が出ます。

📖 用語集

polynomial regression
多項式回帰
x², x³ などの項を足して曲がった関係を表す回帰。
quadratic term
二次項
予測変数を2乗した項（例：temperature2）。放物線の曲がりを表す。
backward elimination
後退消去
最も有意でない予測変数を1つずつ外していく方法。
tolerance / VIF
許容度／分散拡大係数
許容度＝1/VIF。VIFが5〜10超なら多重共線性を疑う。
generalize / test set
汎化／テストセット
未知のデータでもうまく予測できること。確認用のデータがテストセット。
dummy variable (one-hot)
ダミー変数
カテゴリの各水準を 0/1 の列にしたもの。
reference category
基準カテゴリ
ダミーを作るとき削る水準。係数は基準との差になる。
dummy variable trap
ダミー変数トラップ
全水準のダミーを入れて起きる完全な多重共線性。NA係数や singularity が出る。
GVIF
一般化VIF
factor 変数にも使えるVIF。GVIF^(1/(2*Df)) が2超なら要調査。
standardization / normalization
標準化／正規化
z スコアにする／最小・最大でそろえるスケーリング。
interaction effect
交互作用
2つの変数が組み合わさったときの別の効果。式では A * B。
~ . (dot)
ドット記法
応答変数以外の全列を予測変数にする書き方。

💡 学習のヒント

曲がる → 二乗項。カテゴリ → n−1 個のダミー。日付 → 年・月（factor）と日（数値）。組み合わせ効果 → A * B。どの場合も、係数の p 値・adjusted R²・VIF で確かめましょう。
