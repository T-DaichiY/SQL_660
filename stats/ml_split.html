①

なぜ訓練とテストに分けるのか

訓練データの成績は「甘い」

同じデータで学習して、同じデータで評価すると、成績が実力より良く見えます。極端な例が、答えを丸暗記するモデルです。ここでは、「特徴が最も近い物件の価格をそのまま答える」（最近傍法の最もかんたんな形、k = 1）モデルで、訓練とテストの成績を比べます。

set.seed(670)
n <- 400
apt <- data.frame(area  = round(runif(n, 25, 120)),
                  rooms = sample(1:4, n, replace = TRUE, prob = c(.2, .4, .3, .1)),
                  age   = round(runif(n, 0, 50)))
apt$price <- round(40 + 2.2 * apt$area + 12 * apt$rooms - 0.8 * apt$age + rnorm(n, 0, 25), 1)  # 1000 USD
set.seed(1)
idx   <- sample(n, size = 0.8 * n)
train <- apt[idx, ]
test  <- apt[-idx, ]
rmse <- function(y, p) sqrt(mean((y - p)^2))
Xs  <- scale(apt[, c("area", "rooms", "age")])           # standardized features
Xtr <- Xs[idx, ]; Xte <- Xs[-idx, ]
nn1 <- function(Xtr, ytr, Xnew) apply(Xnew, 1, function(v) ytr[which.min(colSums((t(Xtr) - v)^2))])
round(c(train = rmse(train$price, nn1(Xtr, train$price, Xtr)),
        test  = rmse(test$price,  nn1(Xtr, train$price, Xte))), 1)
train test 5.3 37.9

訓練の誤差はほぼ 0（自分の答えを丸暗記しているため。約 5）なのに、テストの誤差は約 38。しかも、次の回で作る単純な線形回帰（テストの RMSE は約 28.5）よりも悪い成績です。これが過学習で、訓練データだけの成績は、新しいデータでの実力を教えてくれません。

📐 ルール：学習に使うのは訓練データだけ。テストデータは、モデルを選び終えたあとに一度だけ使って、「新しいデータでの実力」を見積もります。
②

分け方と乱数

sample() と set.seed()

R では sample() で行番号を無作為に選び、80% を訓練、残りをテストにします（Python の train_test_split と同じ）。

set.seed(1)
idx   <- sample(nrow(apt), size = 0.8 * nrow(apt))
train <- apt[idx, ]
test  <- apt[-idx, ]
c(train = nrow(train), test = nrow(test))
train test 320 80

set.seed(1) は「乱数の種」です（Python では random_state=42）。種を決めると、毎回同じ分け方になり、結果を再現できます。種を変えると、分け方が変わり、テストの成績も少し変わります。

fit_rmse <- function(seed) {
  set.seed(seed); i <- sample(nrow(apt), 0.8 * nrow(apt))
  m <- lm(price ~ area + rooms + age, data = apt[i, ])
  sqrt(mean((apt$price[-i] - predict(m, apt[-i, ]))^2))
}
round(sapply(1:6, fit_rmse), 1)
[1] 28.5 23.9 24.1 25.0 23.9 25.5
種を変えると RMSE が 約 24〜28.5 の間で動きます。「小数第1位の差」で優劣を決めないこと。1回の分け方の結果には、偶然のゆれが含まれています（交差検証で対処：「過学習と交差検証」の回）。
💻 ミニ練習：70% / 30% に分ける

set.seed(7) のあと、apt を 70% 訓練・30% テストに分けて、それぞれの行数を表示してください。

set.seed(7)
idx <- sample(nrow(apt), size = 0.7 * nrow(apt))
train <- apt[idx, ]
test  <- apt[-idx, ]
c(train = nrow(train), test = nrow(test))

400 行の 70% は 280 行、残り 120 行。size に小数が来ても sample() は切り捨てて扱う（0.7 × 400 = 280 ちょうど）。

③

層化：クラスの比率を保つ

陽性が少ないデータで特に大事

分類では、クラスの比率が訓練とテストで同じになるよう分けると安心です。これを層化抽出（stratify=y）と呼びます。陽性が少ないデータでは、ふつうの無作為な分け方だと、テストに陽性が 1 つも入らないことがあります。

y <- c(rep(1, 5), rep(0, 95))          # 100 cases, only 5 positives (5%)
set.seed(10)
mean(replicate(5000, sum(y[sample(100, 20)]) == 0))   # share of random 20% test sets with NO positive
[1] 0.3226

約 3 割の分け方で、テストに陽性がゼロになります（陽性がないと Recall が計算できません）。層化では、クラスごとに同じ割合で選びます。

strat_test <- function(y, frac = 0.2) unlist(lapply(split(seq_along(y), y), function(i) sample(i, size = round(frac * length(i)))))
set.seed(10)
i <- strat_test(y)
table(y[i])                                  # the test set keeps 1 positive and 19 negatives
0 1 19 1
④

データ漏れ（data leakage）

「良すぎる成績」を疑う

データ漏れは、評価の時点では手に入らないはずの情報が、学習に混ざることです。成績が不自然に良くなるのが特徴で、本番では全く使えないモデルになります。代表的な例が、答えから作った列を特徴にしてしまうことです。

set.seed(670)
n <- 400
apt <- data.frame(area  = round(runif(n, 25, 120)),
                  rooms = sample(1:4, n, replace = TRUE, prob = c(.2, .4, .3, .1)),
                  age   = round(runif(n, 0, 50)))
apt$price <- round(40 + 2.2 * apt$area + 12 * apt$rooms - 0.8 * apt$age + rnorm(n, 0, 25), 1)  # 1000 USD
set.seed(1)
idx   <- sample(n, size = 0.8 * n)
train <- apt[idx, ]
test  <- apt[-idx, ]
apt$price_per_area <- apt$price / apt$area          # built FROM the answer (price)!
m <- lm(price ~ area + price_per_area, data = apt[idx, ])
t <- apt[-idx, ]
leak <- 1 - sum((t$price - predict(m, t))^2) / sum((t$price - mean(t$price))^2)
honest <- lm(price ~ area + rooms + age, data = apt[idx, ])
h <- 1 - sum((t$price - predict(honest, t))^2) / sum((t$price - mean(t$price))^2)
round(c(R2_with_leak = leak, R2_honest = h), 3)
R2_with_leak R2_honest 0.947 0.833

漏れのあるモデルは R² が 0.95、漏れのない正直なモデルは 0.83 です。価格から作った「面積あたり価格」を使えば、価格が分かるのは当然です。新しい物件では、価格は予測したい未知の値なので、この列は存在しません。実力以上に良く見えるだけで、本番では使えません。

漏れの例対策
答え（目的変数）から作った列を特徴に使う特徴は「予測する時点で分かる情報」だけにする
テストデータの平均や SD で標準化する訓練データだけで計算して、テストに適用する
分ける前に、全データで欠損を補う分けてから、訓練データの中央値で補う
同じ人・物件の行が訓練とテストに両方ある個人やグループ単位で分ける
