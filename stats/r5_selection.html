変数選択と前進選択（手動）

全部試すのは大変。1つずつ足していこう

モデルを作るときの目標は、データに埋もれている信号（signal）を見つけること（ノイズに惑わされずに）。変数選択（variable selection）とは、モデルにとっていちばん良い説明変数を見つける作業です。「いちばん良い」とは、データをよく説明し、予測に役立つ変数のこと。ただし何をもって「良い」とするかは、組織の定義や使う指標（R²、調整済みR²、p値、AIC など）によって変わります。

全部分集合回帰（all subset regression）

いちばん確実なのは、変数の組み合わせを全部試す方法です。ただし計算量がとても大きく、大きなデータには現実的ではありません。説明変数が k 個あると、各変数が「入る／入らない」の2通りなので、モデルは 2k 通りになります。

説明変数の数試すモデルの数メモ
3 個2³ = 83個だけなら全部試せる（空のモデルを含む）
10 個2¹⁰ = 1,024講義の例
20 個2²⁰ = 1,048,576列数としては「ビッグデータ」ではないのに 100 万超

そこで使うのが前進選択（forward selection）です。「前に進む」ように、変数を1つずつ足していく方法です。

  1. 説明変数を 1 つだけ使った単回帰をいくつも作り、最も良い 1 つを選ぶ（候補は相関行列を見て「関係が強そう」なものから試すとよい）。
  2. 選んだ変数にもう 1 つ足した重回帰を、候補ごとに作って比べ、最も良い組み合わせを選ぶ。
  3. これを繰り返し、停止ルール（stopping rule）を満たしたらやめる。
📌 これまでの準備：この回のデータは、前の動画で整えたものです。コードの流れだけ確認しておきましょう。
bikes <- read_csv("bikes.csv", col_types = "Dffffddddd")

infpts <- unique(which(cooks.distance(bikes_model1) > 0.005))   # 影響点 29 日

手でやってみる：1 回目（R² で比べる）

候補は humidity・temperature・windspeed・season_Summer（夏かどうか）の 4 つ。それぞれ単回帰を作り、R² を比べます。

# First round：単回帰 4 本の R²
summary(lm(data = bikesCleanEncoded, rentals ~ humidity))$r.squared
summary(lm(data = bikesCleanEncoded, rentals ~ temperature))$r.squared
summary(lm(data = bikesCleanEncoded, rentals ~ windspeed))$r.squared
summary(lm(data = bikesCleanEncoded, rentals ~ season_Summer))$r.squared
[1] 0.008311977 [1] 0.4448094 [1] 0.05926697 [1] 0.1343517

上から順に humidity 0.0083、temperature 0.4448、windspeed 0.0593、season_Summer 0.1344。temperature が約 44% を説明して一番です。気温が高い日ほど借りる人が多いはず、というドメイン知識（領域知識）とも合います。

2 回目（調整済み R² で比べる）

temperature を残して、2 つ目の変数を humidity と windspeed で比べます（season_Summer を試してもかまいません）。説明変数が 2 つ以上になったので、比べるのは「調整済みR²（adjusted R²）」です。

# Second round：temperature に何を足す？
summary(lm(data = bikesCleanEncoded, rentals ~ temperature))$adj.r.squared             # 足す前
summary(lm(data = bikesCleanEncoded, rentals ~ temperature + humidity))$adj.r.squared
summary(lm(data = bikesCleanEncoded, rentals ~ temperature + windspeed))$adj.r.squared
[1] 0.4440163 [1] 0.4809831 [1] 0.4625476

temperature だけの 0.444（約 44%）から、humidity を足すと 0.481（約 48%）に改善、windspeed なら 0.463。よって temperature と humidity をモデルに入れます。この作業を、停止ルールを満たすまで繰り返します。

⚠️ R² は変数を足すだけで必ず増えます。説明変数が 2 つ以上のモデルを比べるときは、変数の数でペナルティをかけた調整済みR²（や次に学ぶ AIC）を使いましょう。
🍎 かんたん説明

前進選択は「1人ずつチームに入れていく」やり方。まず一番頼りになる人（temperature）を選び、次に一番相性の良い人（humidity）を足していきます。全員の組み合わせを試すと数が爆発するので、1人ずつ決めていくのです。

💻 ミニ練習：windspeed だけの R² を求める

手動の前進選択の 1 回目と同じ形で、bikesCleanEncoded を使い、windspeed だけで rentals を説明する単回帰の R² を求める R コードを書いてください。

summary(lm(data = bikesCleanEncoded, rentals ~ windspeed))$r.squared

結果は 0.05926697（約 6%）。temperature（0.4448）よりずっと小さいので、1 回目の候補としては選ばれません。

step() で自動化：AIC と BIC

null model から full model まで

手作業は大変なので、R の step() 関数に任せます。step() は既定では R² ではなく AIC を最小にするように変数を選びます。AIC（赤池情報量規準）は「当てはまりの良さ」と「モデルの複雑さ」のバランスを見る指標で、同じくらい説明できるなら、よりシンプルなモデルを好みます。AIC は小さいほど良い指標です。

前進選択では、まず説明変数を 1 つも持たない空のモデル（null model）と、全部入りのモデル（full model）を作ります。

null_model <- lm(data = bikesCleanEncoded, rentals ~ 1)   # 切片だけ（= rentals の平均を当てるだけ）
full_model <- lm(data = bikesCleanEncoded, rentals ~ .)   # ~ . は「残り全部の列」

forward_model <- step(null_model,
                      scope = list(lower = null_model, upper = full_model),
                      direction = "forward")
  • null model：rentals ~ 1。説明変数なしで、いわば「平均を当てずっぽうに答える」モデル。どの変数も役に立たないなら、これが最良になり得ます。
  • full model：rentals ~ .。. を使うと、変数がたくさんあっても全部を書かずに済みます。
  • scope：lower（最小の形＝null）から upper（最大の形＝full）までの範囲で動く、という指定。direction = "forward" で「何もない状態から積み上げる」。

停止ルールを変える：BIC

AIC 以外を使うこともできます。BIC（ベイズ情報量規準）は、AIC より複雑さへのペナルティが重い指標です。step() の k に log(行数) を渡すと BIC になります。

bikesN <- nrow(bikesCleanEncoded)    # 行数

forward_model_bic <- step(null_model,
                          scope = list(lower = null_model, upper = full_model),
                          direction = "forward",
                          k = log(bikesN))

出力の見出しは相変わらず AIC= と表示されますが、中身は BIC です（k を指定したため）。最初の null model の値は約 10,613 から始まり、最後は次のようになります。

前進選択・後退選択の落とし穴：多重共線性

⚠️ 前進選択も後退選択も、多重共線性（multicollinearity）を考慮しません。すでにモデルにある変数と似た変数（強く相関する変数）が、さらに足されてしまうことがあり、冗長になります。選んだあとでVIF（分散拡大係数）を調べ、必要ならより倹約的（parsimonious）なモデルに絞りましょう。
library(car)
round(vif(forward_model), 1)

このモデルでは temperature（213.9）・temperature2（98.4）・realfeel（69.6）、さらに windspeed と windspeed2 の VIF がとても大きいことが分かります。気温・体感温度・気温の2乗は、互いにほとんど同じ情報を持っているからです（temperature と realfeel の相関は 0.99）。AIC が下がっても、こうした変数の重複は別途チェックして整理する必要があります。

🍎 かんたん説明

step() は「AIC が一番小さくなるように」自動で変数を足してくれる機械。でも「似た者同士」を一緒に入れてしまうことがあるので、最後に VIF で重複を点検しましょう。

💻 ミニ練習：前進選択を BIC で行う

null model（null_model）と full model（full_model）はすでに作ってあるものとします。step() で前進選択を行い、停止基準を BIC にする R コードを書いてください（行数は nrow(bikesCleanEncoded)）。

bikesN <- nrow(bikesCleanEncoded)
step(null_model,
     scope = list(lower = null_model, upper = full_model),
     direction = "forward",
     k = log(bikesN))

k = log(行数) が BIC の合図です。見出しは「AIC=」のままですが、最終モデルは 12 変数、値は 9427.1 になります。

③

後退選択（backward selection）

全部入りから、1つずつ外していく

後退選択（backward selection）は前進選択の逆です。最初に全部の説明変数を入れたモデルを作り、p値が最も大きい（最も有意でない）変数を 1 つずつ外していく方法で、停止条件を満たすまで繰り返します。

手でやってみる

ここでは日付を month・day・year に分けたデータ bikesCleanEncoded2 を使い、rentals ~ .（全部入り）から始めます。

backward0 <- lm(data = bikesCleanEncoded2, rentals ~ .)   # 全部入りモデル
summary(backward0)$adj.r.squared
[1] 0.8782628

全部入りの調整済みR² は約 0.88（0.8783）とたいへん高い値です。ただし、係数表を見ると有意でない（p値が大きい）ものがたくさんあります。たとえば month4 の p値は 0.600 です。では month4 を外そうとすると…

lm(rentals ~ . - month4, data = bikesCleanEncoded2)
Error in eval(predvars, data, env) : object 'month4' not found

エラーになります。month4 はデータの独立した列ではないからです。month は 1〜12 を水準とする 1 つの因子（factor）の列で、month4 は R が係数表に出す「4月」のダミー変数の名前にすぎません。1 か月ずつ外したいなら、月をワンホット化して、12 列ではなく 11 列（1 か月は基準として外す）の列を自分で作る必要があります（宿題として試してみましょう）。このデータには月の列が month しかないため、この方法では月ごとには外せません。

⚠️ 12 か月分を全部ダミー化すると、1 列が他の 11 列から決まってしまい（ダミー変数の罠）、モデルが組めなくなります。基準になる 1 水準を除いた n−1 列にするのがルールです。

step() で自動化

後退選択は step() に全部入りモデルを渡し、direction = "backward" を指定します（前進選択の ~ 1 から積み上げる形とは逆です）。

initial_model <- lm(rentals ~ ., data = bikesCleanEncoded2)

backward_model <- step(initial_model, direction = "backward")
summary(backward_model)

後退選択でも多重共線性は扱わない

前進選択と同じく、後退選択も多重共線性を処理しません。たとえば 月は気温と交絡しているかもしれません。夏に貸出が多いのは「月」のせいではなく「気温」のせいかもしれないのです。あるいは、季節（season）の変数がすでにその変動を説明しているなら、season は残して month を外すほうが、AIC も調整済みR² も良くなる可能性があります。

前進選択後退選択
出発点空のモデル（~ 1）全部入り（~ .）
1 ステップの動き変数を 1 つ足す（+）変数を 1 つ引く（-）
step() の指定direction = "forward" と scopedirection = "backward"
停止足しても AIC が下がらない外しても AIC が下がらない（<none>）
多重共線性どちらも考慮しない → 最後に VIF を確認
🍎 かんたん説明

後退選択は「全員集めてから、役に立たない人を1人ずつ帰す」やり方。帰しても成績（AIC）が良くならなくなったら終わりです。前進は＋、後退は−と覚えましょう。

💻 ミニ練習：後退選択を実行する

bikesCleanEncoded2 の全部入りモデルを initial_model として作り、step() で後退選択を行い、結果を backward_model に保存する R コードを書いてください。

initial_model <- lm(rentals ~ ., data = bikesCleanEncoded2)
backward_model <- step(initial_model, direction = "backward")

結果は 5 つの変数（weekday_Saturday・realfeel・weekday_Thursday・windspeed2・weekday_Wednesday）が順に外れ、AIC 9160.9 → 9153.6、調整済みR² 0.8787 になります。

④

ステップワイズ・階層的回帰・倹約モデル

4つの方法の使い分け

前進選択は足すだけ、後退選択は引くだけでした。では両方を同時にやったら？それがステップワイズ選択（stepwise selection／mixed selection）です。前進選択のように変数を足し、後退選択のように変数を外す。いいとこ取りの方法です。

step() で direction = "both"

model_all <- lm(data = bikesCleanEncoded2, rentals ~ .)

step(model_all, direction = "both")

出発は全部入りモデル（AIC 9160.9）なので、最初は外す（-）ことしかできません（すでに全部入っているので足す変数がない）。AIC が下がる weekday_Saturday を外します。2 回目以降の表には、外す候補（-）と、外した変数を戻す候補（+）が一緒に並びます。

olsrr パッケージの ols_step 関数

olsrr パッケージには、ステップワイズ用の関数が用意されています。名前は ols_step_ ＋ 方向（both）＋ 指標です。

関数変数を出し入れする基準
ols_step_both_p()p値
ols_step_both_aic()AIC
ols_step_both_r2()R²
ols_step_both_adj_r2()調整済みR²

引数も確認しておきましょう（詳しくはドキュメントを参照）。

library(olsrr)
modelAll <- lm(data = bikesCleanEncoded, rentals ~ .)

ols_step_both_p(model = modelAll,
                p_enter = 0.2,      # この値以下のp値なら、モデルに入る
                p_remove = 0.01,    # この値より大きいp値なら、モデルから外す
                progress = FALSE,   # TRUE にすると途中経過を表示
                details = FALSE)    # TRUE にすると各ステップの詳細を表示
  • p_enter：変数が入るためのp値の上限（講義では 0.2 以下で入る）。
  • p_remove：p値がこれより大きいと変数が外れる（講義では 0.01 より大きいと外す）。
  • progress・details を TRUE にすると詳しい情報が出ます（時間は少しかかります）。

初期値と違う設定なので、step() とは少し違う結果になります。出力には AIC・BIC・R²・SBIC・調整済みR² が表示され、「real_feel が追加→のちに削除」「windspeed² が追加→windspeed が削除」「Monday が追加→削除」のように、追加と削除（Added/Removed 列）の履歴が見られます。

⚠️ 2つの注意：(1) 出力に出る beta は標準化回帰係数ではなく、ふつうの回帰係数です。(2) olsrr の ols_step_ 関数は更新後のモデルを自動で保存しません。使いたいときは結果を新しいオブジェクトに代入し、選ばれた変数を自分で lm() に書き直します。

階層的回帰（hierarchical regression）

前進・後退・ステップワイズは、機械的に（データの数字だけで）変数を選びます。それに対して階層的回帰は、理論や概念の構造に沿って、変数を段階的に入れる（外す）方法です。「この変数は先に入れるべき」という重要度や理論的な関係を前提にします。

例：会社での仕事のパフォーマンス（job performance）を予測する

  1. ステップ 1：統制変数（control variables）として年齢と学歴を入れる。
  2. ステップ 2：仕事に関係する変数、つまり経験とスキルを足す。
  3. ステップ 3：交互作用（年齢 × 経験：年齢と経験が組み合わさって効くか）を足す。

これは前の3つよりずっと繊細で、ドメイン知識と、組織・状況の理解が必要です。

倹約モデル（parsimonious model）とオッカムの剃刀

倹約モデル（parsimonious model）とは、データを、できるだけシンプルに、しかし十分に説明するモデルのこと。必要最小限の説明変数で、データの背後にある信号をとらえます。ここで出てくるのがオッカムの剃刀（Occam's razor）。中世の哲学者オッカムの考えで、「ほかが同じなら、よりシンプルな説明（モデル）が良い」という原則です。シンプルなモデルが好まれる理由は 3 つあります。

  • 効率（efficiency）：変数が 3 個のモデルと 20 個のモデルで AIC が同じくらいなら、3 個のほうを選ぶ。集めて保存するデータが少なくて済みます。
  • 解釈しやすさ（interpretability）：3 つの変数は 20 個よりずっと理解しやすい。
  • 汎化（generalization）：変数が少ないほうが、過学習を避けて新しいデータにも通用しやすい（過学習は⑤で）。

4 つの方法の比較

方法変数を足す変数を外す理論に基づく？計算コスト過学習のリスク
前進選択するしないいいえ低い中程度
後退選択しないするいいえ高い低〜中程度
ステップワイズするするいいえ中程度中程度
階層的回帰するしないはい低〜中程度低い
🍎 かんたん説明

前進は「足すだけ」、後退は「引くだけ」、ステップワイズは「足したり引いたり」。階層的回帰は、データではなく理論に従って順番に入れていく方法です。どれを使っても、ゴールはできるだけシンプルで十分に説明できるモデルです。

⑤

モデルの性能を評価する

過学習と train/test 分割

ここまでは「どのモデルを選ぶか」でした。次は「選んだモデルが、見たことのない新しいデータでもうまくいくか」です。予測に使う（本番運用する）なら、モデルを作ったときのデータだけでなく、明日・来月届くデータでも通用しなければいけません。

過学習（overfitting）

過学習とは、モデルが手元のデータを丸暗記してしまい、背後にあるパターン（信号）を理解できていない状態です。ノイズを信号だと勘違いします。単回帰・重回帰ではそれほど大きな問題にならないこともありますが、機械学習のモデルは、重回帰より複雑なぶん、過学習しやすいので、先の科目で必ず出てきます。

訓練データとテストデータ（train/test split）

データを 2 つに分けます。

  • 訓練データ（training set）：モデルを作る（パターンと関係を学ぶ）ためのデータ。
  • テストデータ（test set）：取っておいて、未知のデータでの性能を測るためのデータ。「モデルは汎化（generalize）できているか？」に答えます。

ほかに validation set（検証データ）や holdout set もありますが、ここでは扱いません。

📌 たとえば訓練データでは R² = 0.95、テストデータでは R² = 0.40 なら、モデルは過学習です。訓練データのノイズまで学んで高い R² を出しているのに、新しいデータではうまく予測できません。

この授業では 80:20（訓練 80%／テスト 20%）で分けます。validation set も使う場合は 70-15-15 や 80-10-10（訓練-検証-テスト）などがよく使われ、データの大きさで決めます。データが小さいときは分割しません（全部を訓練に使います）。

R で分割する

set.seed(1)                      # 乱数を固定（再現性のため）

n <- dim(bikes)[1]               # 行数（731）

train_indices <- sample(1:n, size = 0.8 * n)   # 1〜731 から 80% をランダムに選ぶ

train_set <- bikes[train_indices, ]    # 選んだ行 = 訓練データ
test_set  <- bikes[-train_indices, ]   # それ以外 = テストデータ

cat("Training set size:", nrow(train_set), "\n")
cat("Test set size:", nrow(test_set), "\n")
cat("Training set size (%):", nrow(train_set) / n, "\n")
cat("Test set size (%):", nrow(test_set) / n, "\n")
Training set size: 584 Test set size: 147 Training set size (%): 0.7989056 Test set size (%): 0.2010944

731 の 80% は 584.8 で、sample() は切り捨てて 584 行を選びます。そのため訓練 584 行・テスト 147 行（0.7989 ≒ 80%、0.2011 ≒ 20%）と、ぴったり 80:20 にはなりません。

ステップ 2〜4：作る → 予測する → 評価する

# 2) 訓練データでモデルを作る
temp_model_training <- lm(data = train_set, rentals ~ temperature)
summary(temp_model_training)$r.squared
[1] 0.3946758

訓練データでの R² は約 0.39（約 40%）。次に、未知のデータ（テストデータ）で予測します。

# 3) テストデータで予測
predictions <- predict(temp_model_training, newdata = test_set)

# 4) テストデータでの R² を、定義の式から計算
ss_total    <- sum((test_set$rentals - mean(test_set$rentals))^2)
ss_residual <- sum((test_set$rentals - predictions)^2)
r_squared <- 1 - (ss_residual / ss_total)
cat("R-squared:", r_squared, "\n")
R-squared: 0.3880397

テストデータでの R² は 0.388 で、訓練データ（0.395）とほぼ同じです。差が小さいので、このモデルは過学習していません（ノイズに惑わされず、信号をつかめている）。予測値の次元（行数）が実測値と同じであることに気をつけましょう。もっと簡単に、予測値と実測値の相関を2乗する方法もあります。

r_squared <- cor(test_set$rentals, predictions)^2
cat("R-squared:", r_squared, "\n")
R-squared: 0.3921496

0.392 と、式から求めた 0.388 は少し違います。相関の2乗は「予測値が実測値にどれだけ直線的に合うか」を測るので、予測値の平均や傾きのずれまでは罰しないためです。どちらも訓練データと近い値で、結論は同じです。

テストデータ 147 日の予測値と実測値（赤の破線は完全に一致する線）
完璧なモデルなら全部の点が破線の上（相関 r = 1）に乗ります。予測値と実測値の相関は r = 0.626（r² = 0.392）で、まずまずの関係です。

R² を計算する関数は yardstick など別のパッケージにもあります（rsq()）。ここでは入門として、チューニングや交差検証（cross validation）などの手順は省いています。

データクリーニングは、分割の「前」か「後」か

これはとても大切な点です。

  • 分割の前にやってよいこと：列名の修正、重複行の削除、明らかな入力ミスの修正（訓練データでもテストデータでも同じになる作業）。
  • 分割の後にやること：それ以外の多くの処理。訓練データでやった処理は、テストデータにも同じようにやります。手順はコメント付きでわかりやすく書き、自動化できればさらに良いです。
⚠️ データ漏洩（data leakage）：分割の前にクリーニングをすると、テストデータの情報が訓練データに影響してしまいます。たとえば欠損値（NA）をデータ全体の中央値で埋めると、テストデータの値が中央値に混ざり、その中央値が訓練データ、ひいてはモデルに影響します。すると性能が実際より良く見えることになります。訓練データとテストデータの間には、きちんと線を引きましょう。欠損値の補完（imputing NAs）などは、分割の後に行います。
🍎 かんたん説明

モデルの「本当の実力」は、見せたことのないデータで測ります。練習問題（訓練データ）で満点でも、本番（テストデータ）で点が取れなければ、丸暗記しただけ。これが過学習です。

💻 ミニ練習：テストデータの R² を求める

predictions（テストデータへの予測値）と test_set がすでにあるとします。予測値と実測値（rentals）の相関を 2 乗する方法で、テストデータの R² を求める R コードを書いてください。

cor(test_set$rentals, predictions)^2

結果は 0.3921496（約 0.39）。訓練データの R²（0.3947）とほぼ同じなので、過学習は見られません。

変数の全組み合わせ（2ᵏ 通り）を試す方法。大きなデータには不向き。
forward selection
前進選択
変数を 1 つずつ足していく。direction = "forward"。
backward selection
後退選択
全部入りから p値の大きい変数を 1 つずつ外す。direction = "backward"。
stepwise selection
ステップワイズ選択
足す・外すを同時に行う（mixed）。direction = "both"。
hierarchical regression
階層的回帰
理論に沿って変数を段階的に入れる方法。ドメイン知識が必要。
AIC / BIC
赤池／ベイズ情報量規準
当てはまりと複雑さのバランス。小さいほど良く、BIC のほうがペナルティが重い。
null model
空のモデル
rentals ~ 1。説明変数なしで平均を当てるだけ。
parsimonious model
倹約モデル
できるだけ少ない変数で信号をとらえるモデル。オッカムの剃刀。
overfitting
過学習
手元のデータ（ノイズ）を丸暗記し、新しいデータで性能が落ちること。
training / test set
訓練／テストデータ
訓練でモデルを作り、テストで未知データへの性能を測る（80:20 など）。
data leakage
データ漏洩
テストデータの情報が訓練に影響してしまうこと。性能が甘く見える。

💡 学習のヒント

前進は＋、後退は−、ステップワイズは両方。step() は既定で AIC を最小化し、k = log(n) で BIC になります。選んだあとは VIF を確認し、最後はテストデータで性能を測りましょう。
