🧱 重回帰・診断・標準化係数・多重共線性(VIF)・影響点

単回帰の「説明変数 1 つ」から、説明変数をいくつも使う重回帰（multiple regression）へ進みます。作ったモデルは「どれがよいモデルか」「どの変数が効いているか」「変数どうしが重なっていないか」「おかしな点が線を引っ張っていないか」を診断（diagnostics）して初めて信頼できます。この回は、その診断道具をまとめて学びます。

📺 講義動画: 「SU1 Data Analytics M5 — Multiple regression」／「Diagnostics」／「Standardize regression coefficients」／「Multicollinearity & VIF」／「Influential point analysis」

📦 データ: 自転車シェアの日次データ bikes（731 日分。目的変数 rentals ＝その日の貸出台数、説明変数は humidity（湿度 0〜1）・temperature（気温 °F）・windspeed（風速 mph））。多重共線性の説明には R で作った模擬データも使います。

①

重回帰モデル：予測変数をいくつも使う

lm() で作り、手計算・fitted・predict で予測する

単回帰（simple linear regression / OLS）は、予測変数（predictor）が 1 つ、たとえば気温 x から貸出台数 y を予測する式でした。

yᵢ = b₀ + b₁xᵢ + eᵢ　（e は誤差。誤差の代わりに ŷ と書いてもよい）

重回帰（multiple regression）は「気温だけでなく、湿度や風速も分かればもっとよく当たるのでは？」という発想で、予測変数を n 個まで増やします（添字を p＝predictor と書くこともあります）。

yᵢ = b₀ + b₁x₁ᵢ + b₂x₂ᵢ + … + bₙxₙᵢ + eᵢ

R での作り方は、単回帰の ~ の右側に + で変数を足すだけです。ここでは湿度・気温・風速の 3 変数でモデルを作り、bikes_model1 と名付けます。

bikes_model1 <- lm(rentals ~ humidity + temperature + windspeed, data = bikes)

係数（coefficients）は summary() の Estimate 列です。b₁ ＝ 湿度、b₂ ＝ 気温、b₃ ＝ 風速の係数にあたり、予測変数が 3 つなので b₃ までです。Std. Error から後ろの列の読み方は、単回帰とほとんど同じです（予測変数の行が増えただけ）。これを回帰式に書き直すと次のとおりです。

rentalŝ ＝ 2706.00 − 3100.12 × humidity ＋ 78.32 × temperature − 115.46 × windspeed

この式があれば、「ある日の湿度・気温・風速」の 3 つが分かるだけで貸出台数を見積もれます。

4 つの変数を 1 枚で見る（講義では plotly の 3D 散布図）

x・y・z 軸に湿度・気温・風速、点の色で貸出台数（応答変数）を表すと、4 変数を 1 つの図に載せられます。マウスで回転でき、点にカーソルを合わせると値が出ます。気温が低い領域に貸出の少ない（暗い色の）点が集まり、気温が高い領域ほど貸出の多い（黄色の）点が増えます。

# install.packages("plotly")  # 初回のみ
library(plotly)
plot_ly(bikes, x = ~humidity, y = ~temperature, z = ~windspeed,
        marker = list(color = ~rentals, showscale = TRUE),
        type = "scatter3d", mode = "markers")

予測①：式に手で代入する（15 行目の日）

講義は、データの 15 行目（講師が適当に選んだ日）を例にしました。実際の値を見てから、式に代入してみます。

bikes[15, c("humidity", "temperature", "windspeed", "rentals")]

2706.00 - 3100.12 * 0.49875 + 78.32 * 37.34 - 115.46 * 6.576
humidity temperature windspeed rentals 15 0.49875 37.33997 6.576293 1248 [1] 3325.019

予測はおよそ 3,300 台。ところが実際は 1,248 台です。差（残差 ＝ 実測 − 予測）は約 −2,000 台で、負の残差（negative residual）は「モデルが実際より多く見積もりすぎた（過大予測）」ことを意味します。この日に限れば、このモデルはあまり役に立っていません。

⚠️ R では掛け算の * を必ず書く。数学では係数が括弧の隣にあるだけで掛け算を表せますが、R では 3100.12(0.49875) のような書き方はエラーです。

もう少しプログラムらしく書くなら、dplyr の pull() で列から値を 1 つ取り出して掛けます。pull() を使うと、余計な列名（humidity など）が結果に付かず、数値だけが出ます。

library(dplyr)
h <- bikes[15, ] |> pull(humidity)
t <- bikes[15, ] |> pull(temperature)
w <- bikes[15, ] |> pull(windspeed)
2706.00 - 3100.12 * h + 78.32 * t - 115.46 * w
[1] 3325.019

予測②：fitted.values ③：predict()

手計算は係数の丸めで少しずれます（3325.019）。モデルが覚えているあてはめ値（fitted values）を使えば、丸めなしの予測が取り出せます。

bikes_model1$fitted.values[15]
residuals(bikes_model1)[15]
15 3324.815 15 -2076.815

ただし fitted.values は、その湿度・気温・風速の組が実際にデータの中にある行にしか使えません。どんな組でも予測できる、より汎用的な道具が predict() です。モデルを作った後に、予測したい値をデータフレーム（data frame）で渡します。ルールは単回帰のときと同じで、次の 2 つです。

  • 新しいデータはデータフレームであること。
  • 列名はモデルで使った変数名と同じにして、予測したい値を入れること。
new.data <- data.frame(humidity = 0.65, temperature = 38, windspeed = 7)
predict(bikes_model1, newdata = new.data)
1 2858.69

湿度 0.65・気温 38°F・風速 7 mph の日は、約 2,859 台と予測されます。この組がデータにあるとは限らないため、実測がなく、残差は計算できません（predict() は「手計算を代わりにやってくれる」関数です）。

複数の日を一度に予測するには、c()（concatenate）で値を並べます。1 つ目は今の日、2 つ目は湿度が高く・気温が高く・風が弱い日です。

new.data <- data.frame(humidity    = c(0.65, 0.85),
                       temperature = c(38, 80),
                       windspeed   = c(7, 2))
predict(bikes_model1, newdata = new.data)
1 2 2858.690 6105.251

2 日目は約 6,105 台と、予測がずっと大きくなります。暖かく風が弱いので貸出が増える一方、湿度が高い（係数は負）ことは少し押し下げる、という複数の変数の効果が合わさっています。

🔑 重回帰の係数の読み方：たとえば風速の係数 −115.46 は、「湿度と気温が同じなら、風速が 1 mph 強いと貸出が約 115 台少ない」と予測する、という意味です（他の変数を一定にしたときの効果）。
🍎 かんたん説明

重回帰は「材料をいくつも使う予測」。lm() の ~ の右に + で並べるだけ。fitted は「データにある日」、predict は「好きな日」の予測。残差がマイナスなら予測しすぎです。

💻 ミニ練習：3 変数のモデルと予測

bikes データで、rentals を humidity・temperature・windspeed で予測するモデルを bikes_model1 として作り、湿度 0.65・気温 38・風速 7 の日の貸出台数を予測する R コードを書いてください。

bikes_model1 <- lm(rentals ~ humidity + temperature + windspeed, data = bikes)
new.data <- data.frame(humidity = 0.65, temperature = 38, windspeed = 7)
predict(bikes_model1, newdata = new.data)

結果は約 2858.69。列名は変数名と完全に一致させ、値は data.frame() で渡します。

②

モデルの診断指標：どちらのモデルがよいか

調整済み R²・AIC・BIC・S・RMSE・F・Cp

説明変数がたくさんあるとき、4 変数のモデルが 2 変数のモデルより悪いこともあります。では、どのモデルを選び、予測がどれくらい当たっているかをどう判断するのでしょうか。講義の方針は総合的（holistic）に判断することです。統計では長い間、予測変数の行末の星（*, **, ***）が付いた p 値だけを見て「有意だから OK」とする人が多くいましたが、1 つの指標に頼りすぎないことが大切です。

診断の道具は他にもあります（残差分析は plot(model) で行えます。VIF（多重共線性）は④、影響点の分析は⑤で扱います）。この単元では、モデル A とモデル B のどちらがよいかを比べる指標を見ます。比べるのは次の 2 つです。

  • temp_model：気温だけの単回帰 lm(rentals ~ temperature, data = bikes)
  • bikes_model1：気温・湿度・風速の重回帰（①のモデル）
temp_model <- lm(rentals ~ temperature, data = bikes)
bikes_model1 <- lm(rentals ~ humidity + temperature + windspeed, data = bikes)

1) 調整済み R²（adjusted R²）：高いほどよい

通常の R² は、予測変数を増やせば（役に立たない変数でも）必ず上がってしまうので、重回帰では使いにくい指標です。たとえば家の価格を予測するのに「ドアノブの数」や「ドアノブの直径」を入れても、価値とはほとんど関係ないのに R² は上がります。調整済み R² は、役に立たない予測変数を入れたモデルにペナルティを課して、膨らんだ R² を下げます。20 個の変数を手当たり次第に投げ込んでも見抜かれます。高い値がよい指標です。

summary(temp_model)$adj.r.squared
summary(bikes_model1)$adj.r.squared
[1] 0.3929171 [1] 0.4586704

気温だけのモデルは 0.393、3 変数のモデルは 0.459。大きく増えたわけではありませんが、湿度と風速を知ることで貸出の予測が改善したと言えます。

2) AIC（赤池情報量規準）：低いほどよい

AIC（Akaike Information Criterion）は、データへの当てはまり（fit）とモデルの複雑さ（complexity）のバランスを取る指標です。データによく合わせたいが、複雑すぎる過剰適合（overfit）モデルは避けたい、という両立を狙います。覚えておくことは 2 つです。

  1. 当てはまりと複雑さのバランスを取る指標である。
  2. 低い値がよい。そして相対的な指標で、値そのものの大きさ（絶対値）に意味はなく、別のモデルと比べてどちらが低いかを見る。

3) BIC（ベイズ情報量規準）：低いほどよい

BIC（Bayesian Information Criterion）は AIC と同じ発想ですが、モデルの複雑さへのペナルティがより強く、単純さ（parsimony）を好みます。別名 SBC とも呼ばれます。

AIC(temp_model, bikes_model1)
BIC(temp_model, bikes_model1)
bic(temp_model, bikes_model1)   # 小文字はエラー
df AIC temp_model 3 12779.54 bikes_model1 5 12697.73 df BIC temp_model 3 12793.32 bikes_model1 5 12720.70 Error in bic(temp_model, bikes_model1) : could not find function "bic"
⚠️ BIC() は大文字で書きます。bic() と小文字にすると上のようにエラーになります。AIC・BIC のどちらも、3 変数のモデルのほうが低いので、重回帰モデルがよいという結論になります（差は AIC で約 82、BIC で約 73）。

4) 残差標準誤差 S と RMSE：小さいほどよい

残差標準誤差（residual standard error, S）は、点が回帰直線からどれだけ離れているか（残差）のばらつきです。点が線の近くに集まっていれば S は小さく、よい線だと言えます。S を最小にしたいので、小さい値がよい指標です。summary() に Residual standard error として出ており、$sigma でも取り出せます。

RMSE（root mean squared error）は、名前のとおり「誤差を二乗し（squared）、平均し（mean）、平方根（root）を取る」計算です。R には RMSE の関数がないので、実測値（actual）と予測値（predicted）を渡す関数を自分で作ります：残差（actual − predicted）→ 二乗 → 平均 → 平方根（二乗した分の単位を戻す）。

summary(temp_model)$sigma
summary(bikes_model1)$sigma

calculate_rmse <- function(actual, predicted) {
  sqrt(mean((actual - predicted)^2))
}
calculate_rmse(bikes$rentals, temp_model$fitted.values)
calculate_rmse(bikes$rentals, bikes_model1$fitted.values)
[1] 1509.388 [1] 1425.305 [1] 1507.322 [1] 1421.4

S も RMSE も重回帰モデルのほうが小さく、こちらも重回帰が優れています。またデータが大きくなるほど S は RMSE に近づきます（気温モデルでは S = 1509.388 と RMSE = 1507.322、ほぼ同じ）。

5) F 統計量：モデル全体の検定（omnibus test）

summary() の最終行にある F 統計量（F-statistic）は、モデル全体の当てはまりを検定します。ANOVA と同じ考え方で、omnibus test（全体検定）と呼ばれます。

  • H₀：すべての係数が 0（β₁ = β₂ = … = 0）。つまり、どの予測変数も応答変数と有意な関係がない。
  • H₁：少なくとも 1 つの係数は 0 ではない。

F が大きいほど、予測変数のあるモデルは予測変数のないモデルよりよく当てはまります。「大きい」の基準は有意水準 α で、p 値が α より小さければ H₀ を棄却し、少なくとも 1 つの予測変数に関係がある証拠が得られます。

⚠️ F が有意でも、すべての予測変数が有意とは限りません。F 検定は「全体として少なくとも 1 つは効いている」ことしか言えません。どの予測変数が効いているかは、係数の t 検定など追加の分析で見ます。
summary(bikes_model1)$fstatistic
value numdf dendf 207.1771 3.0000 727.0000

F = 207.18、分子の自由度（numerator df）は 3、分母の自由度（denominator df）は 727。p 値は 2.2e-16 より小さく、H₀ を棄却できます（気温だけのモデルは F = 473.47、自由度 1 と 729）。

6) Mallows の Cp

Mallows の Cpは、計算した Cp をモデルのパラメータ数 p（切片を含めて数える）と比べます。講義の整理は次のとおりです。

  • Cp ≈ p：よいモデル。過度に複雑にならず、データをよく説明している。
  • Cp > p：過剰適合（overfitting）、不要な予測変数を含んでいる可能性。
  • Cp < p：過小適合（underfitting）、データの重要なばらつきを捉えられていない。

R に標準の関数はないので、データとモデルを渡す関数を自作します（残差平方和 RSS、平均二乗誤差 MSE、行数 n、パラメータ数 p を使って Cp ＝ RSS / MSE − (n − 2p) を計算）。

calculate_MallowsC <- function(dataset, model) {
  rss <- sum(residuals(model)^2)
  mse <- summary(model)$sigma^2
  n   <- nrow(dataset)
  p   <- length(coef(model))      # 切片 + 予測変数
  cp  <- (rss / mse) - (n - 2 * p)
  cat("Mallows' C: ", cp, "\n")
  cat("Number of predictors (including intercept): ", p, "\n")
}
calculate_MallowsC(bikes, temp_model)
calculate_MallowsC(bikes, bikes_model1)
Mallows' C: 2 Number of predictors (including intercept): 2 Mallows' C: 4 Number of predictors (including intercept): 4

気温モデルは Cp = 2、p = 2（切片＋気温）。重回帰モデルは Cp = 4、p = 4（切片＋ 3 変数）。どちらも Cp = p で、Cp から見ればどちらもよいモデルです。Cp ≈ p となるのは、モデルが適切に設定され、残差がおおよそ正規分布に従い、過剰適合・過小適合の大きな問題がないときです。

💡 補足：この自作関数はそのモデル自身の MSE で計算するため、どのモデルでも Cp ＝ p になります。本来の Cp は、全予測変数を入れた大きいモデルの MSE を基準に使い、候補モデルを比べます。Cp は他の指標と合わせて総合的に見る補助的な指標だと考えましょう。

🍎 かんたん説明

モデルの「通信簿」は 1 つではなく何種類もあります。調整済み R² は高いほどよい、AIC・BIC・S・RMSE は低い（小さい）ほどよい。F は「全体として役に立つか」のチェック。1 つの指標だけで決めず、みんなで話し合うように総合判断しましょう。

標準化回帰係数：どの予測変数がいちばん効くか

単位の違う変数を同じ土俵で比べる

①のモデルの係数を見ると、湿度は −3100、気温は 78、風速は −115 です。−3100 が最大だから「湿度がいちばん重要」と言えるでしょうか。答えはいいえ。湿度は 0〜1、気温は °F、風速は mph と単位（スケール）が違うので、係数の大きさをそのまま比べられません。しかも 3 変数とも p 値は極めて小さく、p 値でも差がつきません。

そこでデータを標準化（standardize）します。標準化とはz スコアを求めること、つまり「観測値 − 平均」を「標準偏差」で割ることです。講義は 3 つの方法を示し、3 番目（lm.beta）を推奨しました。

方法 1：手動で z スコアを作る（mutate）

新しいデータセット bikes_for_beta に、必要な 4 列を選び、それぞれ z_ で始まる標準化した列を作ります。

library(dplyr)
bikes_for_beta <- bikes |>
  select(rentals, humidity, temperature, windspeed) |>
  mutate(z_rentals     = (rentals     - mean(rentals))     / sd(rentals),
         z_humidity    = (humidity    - mean(humidity))    / sd(humidity),
         z_temperature = (temperature - mean(temperature)) / sd(temperature),
         z_windspeed   = (windspeed   - mean(windspeed))   / sd(windspeed))
head(bikes_for_beta[, c("rentals", "z_rentals")], 3)
rentals z_rentals 1 985 -1.817 2 801 -1.912 3 1349 -1.629

1 行目の貸出 985 台は z = −1.8。「平均より約 2 標準偏差低い」日という意味です（rentals の平均は 4504.3、標準偏差は 1937.2）。この z 変数でモデルを作り直します。

z_model <- lm(z_rentals ~ z_humidity + z_temperature + z_windspeed, data = bikes_for_beta)
coef(z_model)
(Intercept) z_humidity z_temperature z_windspeed 6.657435e-16 -2.279295e-01 6.260599e-01 -1.923005e-01

切片はほぼ 0（6.66e-16）。注目は絶対値（符号を無視した大きさ）が最大の係数：気温 0.626。つまり気温が貸出台数にいちばん大きな影響を与える予測変数です。次いで湿度（−0.228）、風速（−0.192）の順です。

元の係数と標準化係数の比較
元の係数は 湿度 −3100.12／気温 78.32／風速 −115.46 と単位がバラバラ。標準化すると気温 0.626 が最大。符号は向き、大きさは影響の強さ。

同じことは、他の見方でも確かめられます。相関行列では、貸出と最も強く相関するのは気温（0.63）。また、summary() の第 3 列の t 値も、気温が絶対値最大（22.6、湿度 −8.1、風速 −6.8）です。

方法 2：scale() で一気に標準化

方法 1 は丁寧でよい復習ですが、scale() を使えば z スコアが自動で作れて、とても簡潔です。scale() の結果は行列なので、as.data.frame() でデータフレームにしてから lm() に渡します（列名は元のまま）。

bikes_for_beta2 <- bikes |>
  select(rentals, humidity, temperature, windspeed) |>
  scale() |>
  as.data.frame()
z_model2 <- lm(rentals ~ humidity + temperature + windspeed, data = bikes_for_beta2)
round(coef(z_model2), 4)
(Intercept) humidity temperature windspeed 0.0000 -0.2279 0.6261 -0.1923

方法 1 とまったく同じ係数になります。

データそのものを標準化せず、モデルを渡すだけで標準化係数が出ます。初回は install.packages("lm.beta") が必要です。summary() に包むと、元の Estimate と並んで Standardized 列が出ます。

💻 課題でよく出る書き方（code grade alert）：最も効く予測変数の標準化係数だけを取り出すには、summary(lm.beta(model))$coefficients[3, 2]。3 行目（temperature）、2 列目（Standardized 列）を指定します。値は 0.626 です。
⚠️ "beta" の意味に注意。パッケージ名が lm.beta なのは、教科書によっては β を「標準化回帰係数」の記号として使うからです。しかし別の人は 標準化していない（unstandardized）係数を β₀, β₁, …, βₖ と書き、母集団の回帰直線の未知の傾きも β、さらに検出力（statistical power）の文脈でも β が出てきます。課題では「standardized regression coefficient」または「lm.beta」と明記して区別します。

解釈と注意点

回帰式の β が標準化係数で、β₁ = 0.5、β₂ = 1 なら「x₂ は x₁ の 2 倍重要」と結論できます。ただし両方がおおよそ同じ分布で、標準偏差が大きくは違わないという仮定のもとでの話です。

メリット注意点
単位が違う予測変数の相対的な重要度を直接比べられる単位がなくなり、実用上の意味が見えにくい（例：「1 件あたり $100」vs「1 件あたり 0.2 標準偏差」。$100 のほうが非専門家には分かりやすい）
データを探索するとき、変数の重要度をすばやく把握できる予測には向かない。標準化を元に戻す（unstandardize）か、元の係数を使う
同じスケールなので非専門家への説明に使いやすい予測変数が同じような分布・似た標準偏差という仮定が強い
標本のばらつきに左右され、別のデータセットへの一般化がしにくい
🔑 講義の推奨：報告するときは元の係数と標準化係数の両方を載せる。読み手に応じてどちらも必要になります。
🍎 かんたん説明

単位がバラバラの定規（円・°F・mph）を、みんな「標準偏差」という同じ定規にそろえたのが標準化係数。符号は無視して、絶対値が大きいほど影響が大きい。このデータでは気温が1位（0.626）、湿度が2位、風速が3位です。

多重共線性と VIF

予測変数どうしが似すぎていないか

多重共線性（multicollinearity）とは、2 つ以上の予測変数が互いに強く相関し、強い線形関係をもっている状態です（multi ＝複数、collinear ＝同じ直線上、つまり複数の変数が互いに関連している）。何が困るのでしょうか。

  • 回帰係数がうまく推定できない／膨らむ（inflated）。
  • 係数の符号が直感に合わない（正のはずが負、など）。
  • 標準誤差が膨らみ、それに頼る t 統計量と p 値が信頼できなくなる。
🔑 このクラスの基準：予測変数どうしの相関が絶対値で 0.5 未満なら共線性は低い。絶対値が 0.5 より大きければ、2 つの変数は相関していて多重共線性があるとみなします（相関の符号は無視し、大きさだけを見る）。

例①：血圧を体重・身長・体格指数（BMI）で予測する。BMI は体重と身長から計算されるので、BMI は両者と相関します。そのまま回帰すると「体重が増えると血圧が上がるのに、BMI が下がると血圧が上がる」といった奇妙な向きや、膨らんだ標準誤差が出ます。
例②：家の価格を寝室数・築年数・階数・床面積で予測する。寝室数が多いほど床面積も広いはずなので、この 2 つは相関しており、予測のよくないモデルになります。

模擬データで体験する

講義では、わざと多重共線性をもたせた模擬データ（100 行）を R で作りました。y を 4 つの予測変数 x1〜x4 で予測します。

set.seed(1)
n  <- 100
x1 <- rnorm(n, mean = 50, sd = 10)
x2 <- x1 + rnorm(n, mean = 0, sd = 2)        # x1 にとても近い
x3 <- rnorm(n, mean = 50, sd = 5)            # 無関係
x4 <- x1 + -x2 + rnorm(n, mean = 0, sd = 1)  # x1 と x2 の差
y  <- 5 + 2 * x1 - 1 * x2 + rnorm(n, mean = 0, sd = 5)
data <- data.frame(y, x1, x2, x3, x4)
round(cor(data), 3)
y x1 x2 x3 x4 y 1.000 0.860 0.821 0.038 0.078 x1 0.860 1.000 0.978 0.018 -0.022 x2 0.821 0.978 1.000 0.008 -0.208 x3 0.038 0.018 0.008 1.000 0.093 x4 0.078 -0.022 -0.208 0.093 1.000

目的変数 y と x1（0.860）、x2（0.821）が強く相関しているのを見て、思わず「よい予測変数だ！」と喜びたくなります。ところが x1 と x2 の相関が 0.978。基準の 0.5 を大きく超えており、典型的な多重共線性です。x1 と x2 の散布図を見ると、互いにほぼ一直線に並んでいます。

x1 と x2 は一直線上に並ぶ（相関 0.978）
y を予測するのに x1 も x2 も強いが、予測変数どうしが同じ情報をもっている。

検出法 1：相関行列

cor() の相関行列で、予測変数どうしのセルが絶対値 0.5 を超えていないかを確認します。ただしこの方法は2 つの変数の相関しか見えず、3 つ以上が一緒に相関している場合は見つけられません。bikes のモデル（realfeel を除いた数値変数）では、予測変数間の相関は最大でも −0.25（湿度と風速）で、0.5 を超えるものはなく、多重共線性の問題はなさそうです（③の相関行列を参照。貸出と気温だけが 0.63 と強い）。

検出法 2：VIF（分散拡大係数）と許容度

VIF（variance inflation factor, 分散拡大係数）は多重共線性の量を測る指標で、相関行列では見えない 3 変数以上の関係も検出できます。

VIF ＝ 1 / (1 − R²ₖ)　＝　1 / 許容度（Tolerance）

ここでの R²ₖ は、ある予測変数（例：気温）を目的変数に見立て、他の予測変数（湿度・風速）で予測したときの R² です。逆数（1 / VIF）が許容度（tolerance）で、「他の予測変数では説明されない分散の割合」を表します。

状態VIF許容度
問題なし5 以下0.2 以上
多重共線性あり（対処が必要）5 より大きい0.2 より小さい
深刻（huge problem）10 より大きい0.1 より小さい

許容度のほうが解釈しやすい場合があります。たとえば許容度 0.88 はよいことです（その変数は、他の変数がすでに説明していない情報をたくさんもっている）。逆に許容度がとても低い変数は、他の変数がすでに説明している分散ばかりなので、「この変数は要らない」と言えます。

library(car)
vif(bikes_model1)
1 / vif(bikes_model1)        # 許容度（tolerance）
humidity temperature windspeed 1.074850 1.034283 1.084580 humidity temperature windspeed 0.9303623 0.9668533 0.9220157

bikes_model1 は 3 変数とも VIF が 5 よりずっと小さい（1.03〜1.08）ので、多重共線性はありません。olsrr パッケージの ols_vif_tol(model) でも VIF と許容度を一緒に出せ、許容度はどれも 0.2 より大きい（湿度 0.930、気温 0.967、風速 0.922）ので、湿度は他の変数が説明していない情報を十分もっており、モデルに残すべきです。

次に、模擬データのモデルです。

fake_model <- lm(y ~ x1 + x2 + x3 + x4)
vif(fake_model)
x1 x2 x3 x4 110.221767 115.181353 1.014920 5.047766

x1 と x2 の VIF は 5 を大きく超え（x2 は 約 115）、同じ分散を二重に説明しています。さらに相関行列では見えなかったこと：x4 も（VIF 5.05 ＞ 5）、x1・x2 と絡んだ多重共線性の問題をもっています（x4 ＝ x1 − x2 ＋ ノイズ、と 3 変数が関係している）。相関行列は 2 変数しか見えないので x4 の問題を見逃しますが、VIF なら検出できます。

VIF の比較（点線は基準の 5）
赤＝基準超え、橙＝ぎりぎり超え、緑＝問題なし。

VIF が高いときの対処

  1. 問題の変数を 1 つ削除する（例：床面積・寝室数・階数のうち、相関する 3 つから 1 つだけ残す）。模擬データでは VIF が最大（115）の x2 を除いたところ、残りの VIF がすべて 5 未満になり、x4 と x1 の問題も解消しました。
  2. 相関する予測変数を 1 つの変数に合体する。たとえば階数と床面積を「1 階あたりの床面積（square footage per story）」という 1 つの変数にまとめる（割り算）。講義の宿題：このモデルで x1 と x2 から新しい変数 x5（積や商など）を作り、うまくいくか試してみる。
  3. 主成分分析（PCA）や、LASSO などの正則化（regularization）という方法もあるが、このコースの範囲外。
fake_model2 <- lm(y ~ x1 + x3 + x4)    # x2 を除く
vif(fake_model2)
x1 x3 x4 1.000895 1.009098 1.009236
🍎 かんたん説明

2 人の友だちがまったく同じことを言っているなら、1 人の意見で十分。似すぎている予測変数は 1 つにするか、まとめます。VIF が 5 を超えたら要注意（許容度 0.2 未満）、10 を超えたら大問題です。

影響点分析：回帰線を引っ張る点を探す

外れ値・高レバレッジ・Cook の距離

影響点（influential point）とは、順序対 (x, y) のうち、回帰直線の係数、その標準誤差、調整済み R²、その他の統計量に大きな影響を与える点のことです。大切なのは すべての外れ値が影響点とは限らないことです。外れ値の現れ方には 3 つのタイプがあります。

外れ値の 3 タイプ（橙の大きな点が問題の点、赤線＝その点を含む回帰線、灰色の点線＝含まない回帰線）
① Y方向の外れ値
xは平均的、残差だけ大きい
傾き：点なし 0.95 → 点あり 1.00
② X方向の外れ値（高レバレッジ）
yは平均的、線を強く引っ張る
傾き：点なし 0.95 → 点あり 0.52
③ x・yとも極端だが傾向に沿う
線はほぼ動かない
傾き：点なし 0.95 → 点あり 0.98
R で作った例（20 点＋橙の 1 点）。① は残差が大きいが線はあまり動かない。② は線を大きく引っ張る。③ は x・y とも極端でも傾向に沿うので影響が小さい。
  1. Y 方向の外れ値：y が極端に大きい（残差が非常に大きい）が、x は他と変わらない。
  2. X 方向の外れ値＝高レバレッジ点（high leverage point）：y は平均的だが、x が他の x（たとえば 0〜10）から遠く離れている。最小二乗法の回帰直線をその点が強く引っ張り、本来あるべき傾向から大きくずれる。
  3. x・y とも極端だが、傾向の線に沿っている点：外れ値ではあるが、その点を除いても傾き・切片はほぼ同じ。影響点ではない。

つまり影響点とは、回帰直線の式や、R・R² などの要約統計量を大きく変える点です。

見つけ方：手動 vs 自動（Cook の距離）

手動：その点を入れた回帰と除いた回帰を比べる。候補が 100 個あると大変です。自動（推奨）：Cook の距離（Cook's distance, D）は、その観測値を取り除いたときモデルがどれだけ変わるかを測ります。点を抜いて全部を再計算し、しきい値と比べて影響の大きさを判断してくれます。D が大きいほど、係数や統計量への影響が大きい点です。

🔑 このクラスのしきい値：D > 4 / (n − k − 1) なら影響点。n ＝データの行数、k ＝モデルの予測変数の数。
他の目安：D > 0.5 で影響点の可能性あり、D > 1 ならほぼ確実に影響点。また k を入れない簡易版の 4 / n を使う人もいます（公式を覚えなくてよい利点）。

bikes は 731 行 × 10 列。重回帰の予測変数は 3 つなので k = 3、n = 731 で 4 / (731 − 3 − 1) ＝ 4 / 727 ≈ 0.0055。講義のコードでは切りのよい 0.005 を使いました。

olsrr パッケージには関数がそろっています：ols_plot_cooksd_bar(model)（全点の棒グラフ。しきい値を超えた点が赤、普通の点が青）、ols_plot_cooksd_chart(model)（もう少しすっきりした図だが赤と青の区別はない）。以下は cooks.distance() の値から描いた同様の図です。

この点は回帰直線の係数を大きく動かします。まず疑うべきはデータ入力ミス（湿度 0 や貸出台数の誤り）。もしこの会社のデータなら、「2011 年 3 月 10 日について他に情報はないか、なぜそんなに影響が大きいのか」を確認しましょう。

しきい値を超えた点を一覧にして、除く

上位 10 個だけでなく、しきい値を超えた全部の行を調べます。cooks_d に保存し、0.005 を超える行番号を取ります。unique() は、cooks.distance でなぜか起きる重複を除くために付けます。

cooks_d <- cooks.distance(bikes_model1)
influential_points <- unique(which(cooks_d > 0.005))
length(influential_points)
bikes_clean <- bikes[-influential_points, ]     # c(...) の前のマイナスで「除く」
nrow(bikes_clean)
nrow(bikes_clean) / nrow(bikes)
[1] 29 [1] 702 [1] 0.9603283

しきい値を超えた影響点は 29 行。除くと 702 行が残ります。元のデータの約 96% を残し、約 4% を除いたことになります（どれだけ捨てたかを確認する習慣をつけましょう）。分析者の仕事は、この 29 行を見て、データ入力ミスがないか・パターンがないかを検討することです。

係数が確かに変わり、調整済み R² は上がりました。モデルがノイズを無視して信号（signal）をよく捉えていることを示します。Cook の距離に照らして「除く価値があるほどの変化」だった、というのが講義の結論です。

分布も変わります。要約統計量（全データ → 影響点を除く）：貸出の最小値 22 → 431、湿度の最小値 0 → 0.2758、風速の最大値 21.13 → 17.58、気温の最大値 90.50 → 88.17。平均値と中央値はほぼ同じ（貸出の平均 4504 → 4526）。

最後に、モデルのプロット plot(model) の 4 枚目の図、Residuals vs Leverage（残差 対 レバレッジ）を比べます。

plot(bikes_model1, which = 5)    # 除く前：赤い線が大きく傾く
plot(bikes_model2, which = 5)    # 除いた後：線がずっと平ら

除く前は Cook の距離の領域の近くで線が大きく下に傾いていますが、除いた後は線がずっと平らです。標準化残差が、元のデータよりも安定していることを示す視覚的な確認です。

⚠️ 講師の注意：データを除くのは重大なことです。
  • 理由なく除かない、そして除いた事実を隠さない。
  • 元のデータと新しいデータの両方を保存し、どう・なぜ・何を除いたかを記録（justification）として残す。
  • 3 月 10 日のような怪しい点は掘り下げて調べる（データ入力ミスの可能性）。
  • データを失いすぎたと感じたら、理由を添えて別のしきい値を使う選択肢もある。ちなみに 4 / (n − k − 1) ＝ 0.0055 まで厳しくすると 24 行、0.005 だと 29 行で、しきい値で数は変わります。
🍎 かんたん説明

外れ値でも、線を動かさない点は「影響点」ではありません。線を引っ張る点（高レバレッジなど）を、Cook の距離という「影響力の点数」で探します。除くときは、理由を書いて、元データも必ず取っておきましょう。

💻 ミニ練習：Cook の距離で影響点を探す

bikes_model1 の Cook の距離を cooks_d に保存し、しきい値 0.005 を超える行番号を重複なしで influential_points に入れ、それらを除いたデータ bikes_clean を作ってください。

cooks_d <- cooks.distance(bikes_model1)
influential_points <- unique(which(cooks_d > 0.005))
bikes_clean <- bikes[-influential_points, ]
nrow(bikes_clean)

影響点は 29 行、残りは 702 行（約 96%）。[-influential_points, ] のマイナスが「除く」の意味です。
