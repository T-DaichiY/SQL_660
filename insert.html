✏️ INSERT INTO文 — テーブルにレコードを追加する

データベース → テーブル → レコードという階層を理解し、1件の挿入・複数件の挿入・列を指定した部分挿入の3つのやり方を学ぶ。

①

データベース → テーブル → レコードという階層

INSERT INTOの基本構文と、なぜ「ADD」ではなく「INSERT」なのか

データベースは一番上位の存在で、その中にテーブルがあり、テーブルの中に個々のレコード（行）があります。Excelで例えるなら、テーブルはシート、レコードはその中の1行にあたります。CREATE TABLEで列（列見出し）を定義したら、次はその見出しに合うデータを1行ずつ埋めていく作業——それがINSERTです。

💡 データベース全体からは色々なテーブルの情報を検索できますが、実際のレコードは常にテーブルの中に存在します。「データベースは高レベル、テーブルはもう少し具体的、レコードはさらに具体的」という階層を意識しましょう。

基本のキーワード：INSERT INTO ... VALUES ...

INSERT文は3つのパーツからできています。①何をする（INSERT）、②どこに入れる（INTO テーブル名）、③何を入れる（VALUES 値のリスト）。

INSERT INTO table_name
VALUES (value1, value2, value3, ...);

VALUESの後ろの丸括弧の中に、カンマ区切りで値を並べます。1つの丸括弧のまとまりが、テーブルの1行（1レコード）に対応します。カンマの位置が、そのままテーブルの列から列への移動を表しています。

📌 なぜ「ADD」ではなく「INSERT」？ ADD（足す）は算数・数学的な計算をイメージさせる言葉です。私たちはここで計算をしているのではなく、テーブルに新しい情報を「挿し込んで」いるだけ。だから言語的に自然な「INSERT」が使われています。

複数行を一度に挿入する

丸括弧のまとまりをカンマで区切って複数並べると、一度のINSERT文で複数行をまとめて挿入できます。

INSERT INTO students
VALUES
    (1, 'John', 'Smith', 'jsmith@email.com', 425),
    (2, 'Mary', 'Lee', 'mlee@email.com', 310);
INSERT 0 2

最後の行だけ文末をセミコロン(;)で終え、それ以外の行はカンマ(,)で続けます。これは、スプレッドシートに1行ずつ入力していくのと同じ感覚です。

🍎 かんたん説明

INSERT INTOはテーブルに新しい行を足すための命令。丸括弧1つ＝1行、カンマで列から列へ、複数の丸括弧をカンマでつなげば複数行を一気に追加できます。

②

列を指定しないと「定義順」が絶対ルール

同じデータ型ならエラーにならない——だからこそ危険な入れ違い

先ほどの構文には、どの列に何を入れるかという指定がありませんでした。列名を書かなかった場合、PostgreSQLはCREATE TABLEで定義した列の並び順どおりに値が来ると仮定します。

ここでは id・first_name・last_name・email・amount（注文金額）という5つの列を持つテーブルを例に考えます。

正しい順番の場合

INSERT INTO orders
VALUES (1, 'John', 'Smith', 'jsmith@email.com', 425);
INSERT 0 1

id・first_name・last_name・email・amountの順で値を並べているので、問題なく成功します。

同じデータ型どうしを入れ違えた場合 — エラーにならない罠

INSERT INTO orders
VALUES (1, 'Smith', 'John', 'jsmith@email.com', 425);
INSERT 0 1 -- 成功してしまう！ first_name列に 'Smith'、last_name列に 'John' が入る

first_nameとlast_nameを入れ違えても、両方ともvarchar型の文字列なので、データベースはエラーを出しません。「文字数の上限内に収まる文字列か？」というチェックしか行われないからです。データベースは"Smith"が姓なのか名なのか意味までは理解しません。これが転記ミス（transposition error）と呼ばれる、見つけにくいバグの正体です。

データ型そのものが違う場合 — ここでようやくエラー

INSERT INTO orders
VALUES (1, 'jsmith@email.com', 'John', 425, 'Smith');
ERROR: invalid input syntax for type numeric: "Smith"

今度はemail（varchar）をfirst_name列の位置に、数値のamount列の位置に文字列'Smith'を置いてしまいました。amount列は数値型を期待しているため、今度こそ明確なデータ型エラーで止まります。

ケース結果理由
正しい順番✅ 成功列の定義順と値の順が一致
同じ型どうしの入れ違い（姓・名）⚠️ 成功してしまう（データが誤り）型チェックは通るが、内容の意味までは検証されない
型そのものが不一致（文字列 → 数値列）❌ エラーデータ型が根本的に一致しない
⚠️ 一番怖いのは「エラーにならないミス」。型は合っているのに中身が入れ違っている転記ミスは、実行時には何も警告してくれません。INSERT文を書くときは、必ず列の定義順を確認してから値を並べましょう。スプレッドシートからコピーする場合も、列の並びをテーブル定義に合わせてから貼り付けるのが安全です。
🍎 かんたん説明

チェックされているのは「型が合っているか」だけで、「内容が正しいか」ではありません。同じ型どうしを入れ違えてもエラーは出ないので、列の順番は自分の目でしっかり確認するクセをつけましょう。

③

列を指定して一部だけ挿入する

INSERT INTO table (列名, ...) VALUES (...) — 自動採番の列はスキップ

すべての列に自分で値を入れなくてよいケースもあります。例えばbigserial型のID列は、データベース側が自動的に連番を割り振ってくれるので、こちらから値を渡す必要がありません。そんなときは、INTOの後ろに使う列名だけを丸括弧で指定します。

INSERT INTO students (first_name, last_name, email, credits)
VALUES
    ('John', 'Smith', 'jsmith@email.com', 36),
    ('Mary', 'Lee', 'mlee@email.com', 42);
INSERT 0 2

id列とgpa列（GPAは後で計算する想定）には触れず、first_name・last_name・email・creditsの4列だけを指定しています。VALUESの中の値は、この列リストで宣言した順番と対応していれば構いません——テーブル本来の定義順である必要はありません。

💡 これはWebサイトの新規登録フォームと同じ発想です。ユーザーは自分でIDを決めず、名前やメールアドレスなど基本情報だけを入力し、IDはシステム側が自動で割り振ります。

それでも列リストと値の順番は一致させる

列リストで順番を自由に変えられるといっても、指定した列リストの並びと、VALUESの並びが食い違えば、当然データは誤った列に入ってしまいます（Unit②で見た問題がここでも起こり得ます）。

⚠️ 列リストを (email, first_name, last_name, credits) にしたのに、VALUESを ('John', 'Smith', 'jsmith@email.com', 36) の順で書けば、emailの列に'John'が入ってしまいます。列リストの並びと値の並びは常にセットで確認しましょう。

実務での活用：テーブル間で列の順番を揃える

students・teachers・adminのように似た構造の複数テーブルがある場合、共通する列（例：last_name, first_name, email）の並び順を全テーブルで統一しておくと、データ入力や自動化の際に迷いがなくなります。テーブル固有の列（salaryやdepartmentなど）はその後ろに追加すればよいだけです。

📌 自動化への発展： Googleフォームなどのオンラインフォームで集めたデータを、関数（ストアドプロシージャ）を使って自動的にINSERTするしくみを作れば、手作業での入力を減らせます。
🍎 かんたん説明

列リストを指定すれば、自動採番される列などを飛ばして必要な列だけ埋められます。ルールは1つだけ——「列リストの順番」と「VALUESの順番」を必ず一致させること。

INSERT INTO
Insert Statement
テーブルに新しい行（レコード）を追加するSQL文。
VALUES
Values Clause
挿入する実際の値を、丸括弧・カンマ区切りで指定する部分。
column list
列リスト
INTOの後ろに指定する、挿入対象の列名の並び。省略時はテーブル定義順が使われる。
bigserial
自動採番
値を指定しなくてもデータベースが自動的に連番を割り振ってくれる整数型。
data type mismatch
データ型の不一致

transposition error
転記ミス
同じデータ型の値同士を入れ違えてしまうミス。エラーにならないため気づきにくい。

💡 学習のヒント

INSERT文を書くときは、まずテーブル定義（またはINTOの後ろの列リスト）を確認し、その並び順にそって値を1つずつ数えながら書くクセをつけると、転記ミスを大きく減らせます。
