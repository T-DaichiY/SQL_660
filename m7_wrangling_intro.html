M7 · Data Wrangling — Review, Import & Explore

🔎 データ整形①：準備・取込・探索

現実のデータは、きれいな状態では届きません。データ整形（データラングリング）は、生のデータを分析できる形に整える作業で、データサイエンティストは仕事の時間の大半をここに使うと言われます。この単元では、整形の全体の流れ、データの見直しと取り込み、そしてGROUP BYを使った「汚れ探し」までを学びます。

📦 この教材の練習用データ（30行）は、講義で使ったKaggle／Glassdoorの実データ（Uncleaned_DS_jobs.csv、672行）から取り出した30行のサンプルです

①

データ整形（ラングリング）とは？

なぜ汚れたデータが生まれ、どう進めるのか

データ整形（data wrangling）とは、集めたデータの間違い・欠け・表記ゆれを直し、分析やレポートに使える状態にする作業のことです。データクリーニング、データ修復（remediation）、データマンジング（munging）とほぼ同じ意味で使われます。データサイエンティストは、モデルを作る時間よりも、この下ごしらえに多くの時間を使うと言われます。

ではなぜデータは汚れるのでしょうか。主な原因は3つです。

  • 入力フォームの制限がゆるい：自由入力欄に人が打ち込むと、Sr.・Sr・Seniorのように同じ意味が別の書き方で入る。
  • 外部業者（サードパーティ）から届く：他社のCSVは、こちらのルールとは無関係に作られている。
  • データベース側に制約がない：型・NOT NULL・CHECKなどの制約（M5）がなければ、変な値も素通りする。

M7を通して使う練習用テーブルはds_jobs（Glassdoorのデータサイエンス系求人。練習用は実データから抜き出した30件）です。求人サイトのデータなので、まさに上の3つが全部当てはまります。

M7 の各単元は、この流れの順番にそって進みます（この単元は 1〜5）。
📌 課題のイメージ：M7の最終課題では、自分で選んだデータセット（たとえばKaggleの公開データ）を整形します。形式は自由ですが、なぜそう直したのかをコメントで説明しながら、1つの.sqlファイルにまとめて提出します。

そこで大事になるのがSQLのコメントです。コメントは実行されず、人間への説明として読まれます。

-- 1行コメント：ハイフン2つから行末まで
SELECT COUNT(*) FROM ds_jobs;  -- 行の後ろにも書ける

/* ブロックコメント：
   複数行にわたって説明を書ける。
   取り込み後に行数を確かめる理由：取りこぼしを見つけるため */
SELECT COUNT(*) FROM ds_jobs;
⚠️ /*を閉じ忘れると、その後ろが全部コメントになります。閉じる*/がないと、それ以降のSQLは1行も実行されません。「書いたのに何も起きない」ときは、まず閉じ忘れを疑いましょう。

コツは、各コマンドの上にブロックコメントを置き、「何をするか」ではなく「なぜそうするか」を書くことです。「何をするか」はSQLを読めば分かりますが、理由は書かないと消えてしまいます。半年後の自分（や採点者）が読んだときに、判断の根拠が分かるようにしておきます。

🍎 かんたん説明

データ整形は「汚れたデータの大掃除」です。いきなり掃除を始めず、まずメモを取り、状態を確かめ、バックアップを取ってから、簡単なところから少しずつ直します。理由はコメントに残しましょう。

💻 ミニ練習：ブロックコメント付きで行数を数える

まず/* ... */のブロックコメントで「取り込み後に行数を確認する理由」を書き、そのあとにds_jobsテーブルの全行数を数えるSQLを書いてください。

/* 取り込みの取りこぼしがないか、行数で確かめる */
SELECT COUNT(*) FROM ds_jobs;

結果は30。コメントは実行されないので、SQLの結果には影響しません。

②

データを見直して取り込む（Review & Import）

型を決めてからCREATE TABLE、取り込んだら件数を検証

取り込む前に、CSVの15列を1つずつ眺めて「この列は何型にするか」「どこが汚れていそうか」「どう直すか」をメモします。ds_jobsでは次のようになります。

列予定の型汚れている点直す方針
post_idinteger特になし（主キー）そのまま
job_titletextSr/Sr./(Sr.)/Seniorなど表記ゆれ統一する
salary_esttext$137K-$171K (Glassdoor est.)と文字列下限・上限の数値列に分ける
job_desctextTBD・n/a・空文字が混在NULLに揃える
ratingnumeric未評価が-1（番兵値）NULLに置き換える
companytext末尾に改行と評価がくっつく（Healthfirst＋改行＋3.1）評価部分を取り除く
loctextNew York, NYと市と州が1列（Utahのように州だけの行も）市・州に分割
headquartertext不明が-1（文字列）NULLに置き換える
org_sizetext不明が-1（文字列）NULLに置き換える
foundedinteger不明が-1（整数）NULLに置き換える
owner_typetext不明が-1、Company - Privateなど長い名前対応表で短いラベルに統一
industry, sectortext不明が-1NULLに置き換える
revenuetextUnknown / Non-Applicableと-1NULLに置き換える
competitorstext競合なしが-1（文字列。30行中22行）NULLに置き換える

型が決まったらCREATE TABLEで作ります。ポイントは、数として使う列だけ数値型にし、それ以外はtextにしておくことです。取り込み時点で無理に整形しようとせず、「まず全部入れて、あとでSQLで直す」方が安全です。

CREATE TABLE ds_jobs (
    post_id integer PRIMARY KEY,
    job_title text,
    salary_est text,
    job_desc text,
    rating numeric,
    company text,
    loc text,
    headquarter text,
    org_size text,
    founded integer,
    owner_type text,
    industry text,
    sector text,
    revenue text,
    competitors text
);

テーブルができたら、CSVファイルをCOPYで一括取り込みします（PostgreSQLの構文）。HEADERは「1行目は見出しなので読み飛ばす」という指定です。

COPY ds_jobs
FROM 'C:\data\ds_jobs.csv'
WITH (FORMAT CSV, HEADER);
⚠️ この練習アリーナにはCSV取り込み機能がありません。COPY ... FROMは説明用のPostgreSQL構文で、ここでは実行できません。ds_jobsはあらかじめ読み込み済みのテーブルとして用意されているので、以降の例と演習はすぐに試せます。

取り込んだら、必ず件数を検証します。元のCSVの行数（この教材の練習データでは30行、講義のファイルでは672行）とテーブルの行数が違えば、取り込みに失敗している証拠です。

SELECT COUNT(*) FROM ds_jobs;
SELECT COUNT(company) FROM ds_jobs;
SELECT COUNT(rating) FROM ds_jobs;
count(*) = 30 count(company) = 30 count(rating) = 30

ここで重要な発見があります。評価ratingが-1の行は4行あり、実質の「評価あり」は26行のはずです。それなのにCOUNT(rating)は26ではなく30です。COUNT(列)はNULLを数えない（M4）ので、-1がNULLではなく本物の数値として取り込まれていることが分かります。

📌 番兵値（sentinel value）とは、「不明」「なし」を表すために入れられた特別な値（-1、Unknownなど）です。SQLからは普通の値に見えるので、そのまま平均を取ると-1が混ざって結果が狂います。番兵値はNULLに置き換えるのが基本方針です（次の単元で実際に直します）。
🍎 かんたん説明

取り込む前に「どの列がどんな型か、どこが汚いか」を表にしておき、取り込んだら件数を数えて確かめます。「-1」はNULLではなくただの数字として入るので、COUNTでも数えられてしまいます。

💻 ミニ練習：行数と列の件数を確認する

ds_jobsの全行数をCOUNT(*)で、rating列の件数をCOUNT(rating)で、1つのSELECTにまとめて求めてください。2つの値が同じになることを確かめましょう。

SELECT COUNT(*), COUNT(rating)
FROM ds_jobs;

どちらも30になります。-1がNULLではなく数値として入っているので、4行の「未評価」も数えられてしまっています。

③

データを探索する（Exploring）

GROUP BY + COUNT + ORDER BY で汚れを見つける

汚れを探す最強の道具は、M4で学んだGROUP BYです。1つの列を選び、値ごとに何行あるかを数えます。

SELECT col, COUNT(col)
FROM ds_jobs
GROUP BY col
ORDER BY col;

ORDER BYを付けるのが肝心です。並べ替えると、似た値が隣り合って並び、Sr.・Sr・Seniorのような「繰り返しのパターン」が目に入ります。順番がバラバラだと見逃してしまいます。また、同じ意味なのに別々の行として数えられていれば、それが表記ゆれの証拠です。

まずjob_titleに使ってみます。

SELECT job_title, COUNT(job_title)
FROM ds_jobs GROUP BY job_title ORDER BY job_title;
job_title | count -------------------------------------+------ (Sr.) Data Scientist - | 1 Data Analyst | 3 Data Engineer | 2 Data Scientist | 11 Machine Learning Engineer | 3 Scientist / Group Lead, Cancer Biology | 1 Senior Business Intelligence Analyst | 1 Senior Data Engineer | 1 Senior Data Scientist | 3 Sr Data Analyst | 1 Sr Data Scientist | 2 Sr. Data Scientist | 1 (12 rows)

Data Scientist系の4通り（(Sr.) Data Scientist -、Senior Data Scientist、Sr Data Scientist、Sr. Data Scientist）は、本来すべて同じ「Senior Data Scientist」のはずです（1+3+2+1で合計7行）。SrとSeniorの違い、ピリオドの有無、かっこや末尾の -が原因です。さらにSr Data Analyst（1行）とSenior Data Engineer（1行）も同じSr/Senior系の表記ゆれで、Sr/Seniorを含む行は全部で10行になります。

次にratingです。

SELECT rating, COUNT(rating)
FROM ds_jobs GROUP BY rating ORDER BY rating;
rating | count -------+------ -1 | 4 2.3 | 1 2.6 | 1 2.7 | 1 ...（以下、最大4.9まで。全20行）

並べ替えたので、最小値の-1がいちばん上に来て、4行あることがすぐに分かります。次はowner_typeです。

SELECT owner_type, COUNT(owner_type)
FROM ds_jobs GROUP BY owner_type ORDER BY owner_type;
owner_type | count --------------------------------+------ -1 | 3 Company - Private | 17 Company - Public | 4 Government | 1 Nonprofit Organization | 2 Other Organization | 1 Subsidiary or Business Segment | 2 (7 rows)

-1（3行）は「不明」を表す番兵値です。またCompany - PrivateやSubsidiary or Business Segmentのように長いラベルもあり、Other Organizationのように短い共通ラベル（Other）にまとめられそうな値もあります（後で対応表を使って統一します）。

今度はcompanyです（先頭8行のみ表示）。

SELECT company, COUNT(company)
FROM ds_jobs GROUP BY company ORDER BY company LIMIT 8;
company | count ---------------------------------+------ Allied Solutions⏎3.4 | 1 Better Hire⏎4.0 | 1 Big Huge Games⏎4.9 | 1 Cambridge FX⏎3.5 | 1 Centauri⏎4.6 | 1 Change Healthcare⏎2.7 | 1 Comprehensive Healthcare⏎2.6 | 1 Creative Circle⏎3.6 | 1 ...

社名の末尾に、改行（⏎で表示）に続けて評価（3.4など）がくっついています。実際のデータでは改行（CHAR(10)）が入っているため、画面によっては2行に見えます。ただし全行ではなく、Radical ConvergenceやEvolvincのようにrating = -1の行（4行）にはくっついていません。評価の部分は改行＋3文字（X.X）で合計4文字なので、あとでLEFT(company, LENGTH(company)-4)のように末尾4文字を切り落とせます。ただしrating = -1の行にこれをやると社名が欠けるので、必ずWHERE rating <> -1のような条件が必要です。

⚠️ 社名のようにほぼ全行がユニークな列では、GROUP BYの件数はほとんど1になります。この場合は件数よりも、並べ替えた文字列の見た目を目で確認することが探索の中心です。

最後にsalary_estです（先頭6行のみ表示）。

SELECT salary_est, COUNT(salary_est)
FROM ds_jobs GROUP BY salary_est ORDER BY salary_est;
salary_est | count -----------------------------+------ $101K-$165K (Glassdoor est.) | 2 $112K-$116K (Glassdoor est.) | 2 $124K-$198K (Glassdoor est.) | 1 $128K-$201K (Glassdoor est.) | 2 $137K-$171K (Glassdoor est.) | 1 $141K-$225K (Glassdoor est.) | 1 ...

すべての値が$下限K-$上限Kの形で、末尾に(Glassdoor est.)か(Employer est.)が付いています（後者は2行）。しかも後者は$145K-$225K(Employer est.)のように、かっこの前にスペースがないので、同じ切り方では分解できません。下限は$79Kの2桁も$212Kの3桁もあり、このままでは数値として計算できないので、後で分解する必要があります。

探索で見つけたことは、その場でメモに残します。これが次の単元の設計図になります。

📋 クリーニングのチェックリスト（ここまでの発見）
  • job_title：Sr/Sr./(Sr.)をSeniorに統一、末尾の -も除去（Sr/Seniorを含む10行）
  • rating：-1（4行）→ NULL
  • owner_type：-1（3行）→ NULL、他は短いラベルに
  • company：末尾の改行＋評価（4文字）を除去（rating = -1の行は除く）
  • salary_est：数値2列に分解、末尾の(…est.)を除去（(Employer est.)の2行はスペースなしに注意）

💡 PostgreSQLのx::intのようなキャストは、この演習アリーナでも自動変換されてそのまま動きます（COPYだけは動きません）。

🍎 かんたん説明

「GROUP BYで値ごとに数え、ORDER BYで並べる」だけで、表記ゆれや-1のような不自然な値が浮かび上がります。見つけた汚れは、忘れないようにチェックリストにメモしましょう。

💻 ミニ練習：ratingの値ごとの件数を見る

ratingごとの件数をGROUP BYで数え、ratingの小さい順に並べてください。先頭に-1の行が出て、件数が4になることを確認しましょう。

SELECT rating, COUNT(rating)
FROM ds_jobs
GROUP BY rating
ORDER BY rating;

1行目が-1 | 4になります。最小値が先頭に来るので、番兵値を見つけやすくなります。
