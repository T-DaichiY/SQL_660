🍎 超やさしい版：主キー①

主キーは「重複なし・空欄なし」の目印列。3種類の作り方があります。

⚡

主キーの2ルール

重複なし・空欄なし

🎯 これだけ覚えればOK

主キー＝各行の目印になる列。①同じ値が2つあってはダメ、②空欄（NULL）もダメ。この2つだけ守られていれば主キーになれます。

🔑
制約とは「変な値を入れさせない仕組み」。Googleフォームのシャツサイズや電話番号の入力形式と同じで、データが汚れるのを入り口で防ぎます。
ルール意味
一意（unique）同じ値を持つ行が2つあってはならない
NOT NULL値が空の行があってはならない
🍎 ひとことで

主キーの列を見れば、それだけで「この行は誰か」が必ず分かる——それが主キーの役目です。

①

3種類のキー

自然・代理・複合
種類例
自然キー免許証番号、email、course_id
代理キー自動採番のID、UUID
複合キー免許証番号＋州、room_number＋building
🗺️
複合キーが必要になる理由の例：アメリカの免許証番号は州ごとに発行されるので、driver_idだけでは同じ番号の別人が2人存在してしまいます。driver_id + stateならこの2人を区別できます。
🍎 ひとことで

データにもともと使える値があれば自然キー、なければ自動採番の代理キー、1列で足りなければ複合キー。

②

構文と重複エラー

最短形とエラーメッセージ

▶ 一番短い書き方

course_id varchar(8) PRIMARY KEY

▶ 同じ主キーを2回入れようとすると…

INSERT INTO natural_key_example (license_id, first_name, last_name)
VALUES ('T229901', 'John', 'Mitchell');
ERROR: duplicate key value violates unique constraint "license_key" DETAIL: Key (license_id)=(T229901) already exists.

🤔 答えられるかな？（クリックで答えが開く）

Q1. 主キーの2ルールは？A. 一意であること、NULLでないこと。
Q2. CONSTRAINT名を省略したら？A. PostgreSQLが自動で「テーブル名_pkey」と名付ける。
Q3. 免許証番号だけでは主キーにできない場合があるのはなぜ？A. 州ごとに発行されるため、同じ番号が別人に重複することがあるから。
