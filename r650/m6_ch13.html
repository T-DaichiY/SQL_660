01

なぜ「デプロイ」まで学ぶのか

モデルは使われて初めて価値になる

ここまでの12章で、ロジスティック回帰モデルを作ること・評価すること（逸脱度・AIC・Z値）を学びました。でも現実の仕事では、それだけでは足りません。

データのクリーニング、分析、モデル作成、診断——これらはデータサイエンスの楽しい部分です。しかしそれを組織の価値に変換できなければ、仕事として成立しません。組織が本当に欲しいのは「統計の出力」ではなく、誰でも使えて意思決定に役立つ道具です。

💼 この章のゴール：データセットを取得 → クリーニング → モデル構築 → 診断 → ダッシュボードとしてデプロイ、というエンドツーエンドのプロジェクトを完成させること。ポートフォリオに載せられる「動く成果物」を作ります。

デプロイに使うのは Shiny。Rからそのまま使えるWebアプリのフレームワークです。「Shinyを書いたことがない」——それで大丈夫。この章のもうひとつのテーマは、生成AI（LLM）に助けてもらいながら、書いたことのないコードを完成させるという現代的なワークフローです。

🗺️ エンドツーエンド・プロジェクトの全体像

ステップやること使うもの

02

データの準備

Kaggleのローンデフォルトデータを絞り込む

使うのはCourseraの「Loan Default Prediction」チャレンジのデータセット。255,000行 × 18列という、これまでの例（アバロン・German Credit）よりずっと大きなデータです。「返済不能（Default）になるか否か」という2値の結果を予測する——まさにロジスティック回帰の出番です。

# CSVを読み込む（列型のメッセージは非表示）loans_raw <- read_csv("Loan_default.csv", show_col_types = FALSE)# 訓練を速くするため50,000行をサンプリングset.seed(123) # 再現性のためloan_data <- sample_n(loans_raw, 50000)rm(loans_raw) # 巨大データを環境から削除して軽くする

ここでの3つの実務テクニックに注目してください。

📌 大きなデータを扱う3つの工夫
① sample_n() — 25万行のままだと訓練が遅い。まず5万行で開発し、後で「データを増やすと改善するか？」を検証する。
② set.seed() — 乱数を固定して、誰がやっても同じサンプル・同じ結果を再現できるようにする。
③ rm() — 使い終わった巨大オブジェクトをメモリから消して、RStudioの動作を軽く保つ。

また、モデルを作る前にLoanID（ローンの識別番号）を削除します。IDには予測に役立つ情報がなく、モデルにとってはただのノイズだからです。

03

LLMと組んで開発する

プロンプトは「小さく分割」が鉄則

「Shinyアプリを書いたことがない」状態からどう始めるか。答えはLLM（このプロジェクトではGoogle Gemini）に段階的に依頼することです。最初のプロンプトはこうでした。

# プロンプト①（要約）「このデータセットでローンのデフォルトを予測する　ロジスティック回帰モデルを作りたい。　データのクリーニングとモデル構築のRコードを書いて。　データセットのリンクはこちら：…」

LLMは、ライブラリ読み込み → データ読み込み → クリーニング（欠損値チェック：このデータは欠損ゼロでした）→ 訓練/テスト分割 → glm(…, family = binomial) でのモデル構築 → AUCなどの評価指標、という一連のコメント付きコードを返してくれました。family = binomial になっているか——ここを自分の知識で検証できるのが、この授業を受けたあなたの強みです。

✂️
プロンプトは小さく分割する！
「クリーニング＋モデル＋Shinyアプリ」を一度に頼むと
LLMも人間と同じで、タスクが多すぎると手を抜くことがある。
①クリーニング → ②モデル → ③変数選択 → ④Shinyアプリ、と段階的に積み上げる。
🧑‍🔬 Human in the loop（人間による検証）：LLMの出力を鵜呑みにしない。「family=binomialか？」「有意でない変数はどれか？」「この評価指標は妥当か？」——判断するのは統計を学んだあなたです。LLMはコードを速く書く道具であって、分析の責任者ではありません。
04

予測変数の絞り込み

手動除去 vs ステップワイズ選択（AIC）

summary() を見ると、多くの予測変数は有意（***）でしたが、LoanTerm や LoanPurpose、一部のEducationダミーなどは有意ではありませんでした。「有意でない予測変数をモデルから除去するコードを書いて」と2つ目のプロンプトを投げると、LLMは2つの方法を提案してきます。

# 方法①：手動で有意でない変数を除いて作り直すmod2 <- glm(Default ~ Age + Income + LoanAmount + CreditScore + MonthsEmployed + InterestRate + Education + EmploymentType, data = loan_data, family = binomial)# 方法②：ステップワイズ選択（AICで自動選択）← 第6〜7章の知識！mod_step <- step(mod_full, trace = 0) # trace=0で途中経過を非表示# → 手動と同じモデルに到達

ここで面白い問題が出てきます。Education（学歴）はカテゴリ変数なので、「Masterは有意だがHigh Schoolは有意でない」という状態でも、High Schoolのダミーだけを取り除くことはできません。カテゴリ変数はレベル全体でひとまとまりだからです。

💡 人間がLLMを超える瞬間：この問題への一手はワンホットエンコーディング（例：Education_HighSchool を独立した0/1変数にする）。LLMは最初この方法を提案しませんでした。分析者であるあなたが「ワンホット化して個別に除去できるようにして」と指示できる——これがhuman in the loopの価値です。

なお step() の trace = 0 を外すと、AICが1ステップずつどう改善していくかの長い出力が見られます。第6〜7章で学んだAICが実務でどう働くか、一度確認してみる価値があります。

05

Shinyアプリの構築とデバッグ

UI + Server、エラーはLLMに貼り付けて直す

いよいよ本題。「このモデルをデプロイするShinyアプリを作って」と依頼します。Shinyアプリは大きく2つの部品でできています。

library(shiny)# UI：ユーザーが見る画面（入力フォームと結果表示）ui <- fluidPage( titlePanel("ローンデフォルト リスク診断"), numericInput("age", "年齢", 35), numericInput("income", "年収", 60000), numericInput("credit", "クレジットスコア", 650), actionButton("go", "リスクを診断"), textOutput("result"))# Server：裏側の計算（モデルでpredictして確率を返す）server <- function(input, output) { output$result <- renderText({ p <- predict(mod2, newdata = 入力から作ったdata.frame, type = "response") paste0("デフォルト確率: ", round(p*100), "% → ", if(p < 0.1) "低リスク" else "高リスク") })}shinyApp(ui, server) # アプリ起動！

ただし——最初に実行したら、いきなりエラーが出ました。ここからが現実の開発です。実際のワークフローはこんな往復でした。

🔁 実際のプロンプト往復の記録

往復依頼内容結果
③Shinyアプリを作ってエラー発生
④「このエラーは何？どう直す？」（エラー文を貼る）修正コード → アプリ起動✅
⑤全コードを1チャンクで＋改善提案もまた別のエラー → 再修正
⑥モデルパラメータの表を隠して、確率とリスク判定を前面にUI再設計
⑦新たなエラーを貼って修正依頼完成🎉 確率＋リスク表示
🎨 UIの大原則：使う人は統計を知りません。summary()の係数表やp値を見せても意味がない。「デフォルト確率 8% → 低リスク」のような一目でわかる出力を前面・中央に。リスクの閾値（何%から高リスクか）は銀行ごとの基準に合わせて調整できます。

完成したアプリで遊んでみると、モデルの理解も深まります。「クレジットスコアを最低にして、ローン額を最大にしたら12%……まだ低リスク？」——そんな違和感が出たら、診断（第5〜8章）に立ち返るサインです。データを5万行から増やしたら改善するか？という検証の入口にもなります。

06

公開してポートフォリオへ

shinyapps.io でリンクひとつの共有

ローカルで動くだけでは「Rを持っている人」しか使えません。shinyapps.io（無料枠あり）にデプロイすれば、URLひとつで誰でも使えるWebアプリになります。

# ① shinyapps.io でアカウント作成# ② RStudioからアカウントを接続してデプロイinstall.packages("rsconnect")rsconnect::setAccountInfo(name="あなたのID", token="…", secret="…")rsconnect::deployApp() # → https://あなたのID.shinyapps.io/アプリ名/

これで完成したものは、単なる課題ではありません。

💼 ポートフォリオとしての価値
① GitHubにノートブックを置き、履歴書にリンクを載せられる
② 採用担当者はRを実行しなくても、リンクを開くだけであなたの「動く成果物」を見られる
③ 「クリーニング → モデル → 診断 → デプロイ」というエンドツーエンドの実力証明になる

仕上げのアイデア：LLMに「このダッシュボードをどう改善する？」と聞いてみる。どの予測変数が確率に最も効いているかの表示、レイアウト変更、説明文の追加——改善のループは続きます。ロジスティック回帰に限らず、どんなモデルもShinyでダッシュボード化できる。これがM6の締めくくりです。
