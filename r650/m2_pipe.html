パイプの威力

左の結果を右へ渡す

パイプ |> は「左の結果を、右の関数の第1引数に渡す」記号です。動詞が各行の先頭に並ぶので、4ステップでもスラスラ読めます。

flights |> filter(dest == "IAH") |> mutate(speed = distance / air_time * 60) |> select(year:day, dep_time, carrier, flight, speed) |> arrange(desc(speed))

パイプなしだと2通りの書き方になりますが、どちらも読みにくい。

# ① 入れ子：内側から読まないといけないarrange( select( mutate(filter(flights, dest == "IAH"), speed = distance / air_time * 60), year:day, dep_time, carrier, flight, speed), desc(speed))# ② 途中結果をいちいち保存：名前が増えて邪魔（課題では避ける）flights1 <- filter(flights, dest == "IAH")flights2 <- mutate(flights1, speed = distance / air_time * 60)
種類記号由来
ネイティブパイプ|>base R（R 4.1〜）
magrittr パイプ%>%magrittr（tidyverse）
📌 RStudio：Ctrl/Cmd + Shift + M で入力。Tools → Global Options → Code → 「Use Native Pipe Operator」で |> になります。
②

スタイルの9か条

見た目を整える
#ルール○ 良い例 / × 悪い例
1パイプの前にスペースflights |> ○ ／ flights|> ×
2パイプは行の最後次の行から動詞を書く
3dplyr の動詞は1行に1つgroup_by と summarize を同じ行に詰めない
4引数が多いときは1行に1引数summarize( の中を改行
5最初の行以降は2スペース字下げ引数はさらに 2 スペース
6) は独立した行で関数名と揃える縦位置を合わせる
7縦のスペースは惜しまない後から足しやすい
8パイプは10〜15行まで長すぎたら途中で保存し、わかる名前を付ける
9ggplot2 は +パイプの流れから ggplot に入れたら以降は +
# ○ 良い書き方flights |> group_by(tailnum) |> summarize( delay = mean(arr_delay, na.rm = TRUE), n = n() )# × 悪い書き方flights|>group_by(tailnum) |> summarize(delay = mean(arr_delay, na.rm = TRUE), n = n())
⚠️ ggplot2 は +、データ加工は |>。グラフの層を |> でつなぐとエラーになります。
flights |> group_by(month) |> summarize(delay = mean(arr_delay, na.rm = TRUE)) |> ggplot(aes(x = month, y = delay)) + geom_point() + geom_line()
