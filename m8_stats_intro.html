M8 · Statistical Operations — Correlation

📊 統計①：SQLで相関を調べる corr()

平均・合計・件数・最大／最小…ここまでは「基本の統計値」でした。ここからは一歩進んで、2つの変数の関係の強さと向きを表す相関係数を、たった1つの関数corr(Y, X)で求めます。

📺 講義動画①「Statistical operation」＋ 教科書 Practical SQL 2nd ed. 第11章「Statistical Functions in SQL」（corr(Y, X)）をもとにしています

📦 練習データ bikes は、ニューヨークのイースト川の4つの橋（Brooklyn・Manhattan・Williamsburg・Queensboro）を通った自転車の数を、2016年4月の日ごとにまとめた表です（講義と同じ公開データ。降水量 precip は、痕跡を表す'T'を0に、'0.47 (S)'を0.47にそろえた数値列に整えてあります）

①

なぜSQLで統計をやるのか

基本の集計から、もう一歩先へ

これまでのAVG・SUM・COUNT・MAX・MINも立派な統計値ですが、データをもう少し深く眺めたいときは、相関（correlation）や回帰（regression）、ばらつき（分散・標準偏差）といった道具が役に立ちます。M8の前半（統計編）では、この3つをSQLで扱います。

ただし講師が強調していたように、SQLは統計分析のメインの道具ではありません。本格的なグラフ作成や詳しい分析、モデル作りは、あとで学ぶPythonやRの仕事です。では、なぜSQLで統計をやるのでしょうか。

  • データを動かさずに、その場でざっと傾向をつかめる（別のシステムへ移す手間がない）。
  • PythonやRにデータを渡す前の下調べになる（「この2つ、関係ありそうだな」と当たりをつける）。
  • 統計関数は集計関数なので、GROUP BYやHAVING（M4）とそのまま組み合わせられる。
📌 この単元の道具：PostgreSQLの統計関数はcorr（相関）・regr_slope / regr_intercept / regr_r2（回帰）・var_samp / stddev_samp（ばらつき）など。どれも「列を入れると1つの数が返る」集計関数です。
🍎 かんたん説明

SQLの統計は「データを調べる最初の一歩」。くわしい分析はPython/Rに任せて、SQLでは手早く当たりをつけるのが役目です。

②

相関係数 r と corr(Y, X)

強さと向きを1つの数で表す

相関（correlation）とは、2つの変数の間の「直線的な関係」の強さと向きのことです。たとえば「気温が高い日ほど自転車の通行量が多い」なら、気温と通行量には相関があります。数値で表したものが相関係数 r（ピアソンの積率相関係数）で、SQLでは次のように書きます。

SELECT corr(Y, X) FROM テーブル名;

引数のYとXには意味があります。講師が強調していたポイントです。

  • X ＝ 独立変数（原因っぽい側）：ほかの変数に左右されないと考える変数。
  • Y ＝ 従属変数（結果っぽい側）：Xの値に応じて変わる（Xに従属する）と考える変数。
  • 書く順番は Y が先、X が後。「corr(Y, X)」と覚えましょう。
💡 実は、相関係数の計算そのものは Y と X を入れ替えても同じ値になります（教科書の注意書きにもあります）。それでも「結果（Y）、原因（X）」の順に書く習慣をつけるのは、読む人に意図が伝わるから、そして次の回帰（regr_slope(Y, X)）では順番が結果を変えるからです。

返ってくるr は −1 から +1 の間の数です（講義では「0〜1の目盛りが正と負の両方にある」と説明されていました）。符号が向き、絶対値の大きさが強さを表します。

散布図のイメージ（点は1日1個、赤い点線は当てはまる直線）
強い正の相関
r ≈ 0.95
強い負の相関
r ≈ -0.91
ほぼ相関なし
r ≈ 0.21
相関が強いほど、点が1本の直線にぴったり沿って並びます。ばらけるほど r は0に近づきます（図は説明用に作った人工データです）。
r（＋でも−でも、絶対値で見る）教科書 Table 11-1 の読み方
0No relationship（関係なし）
0.01 〜 0.29Weak relationship（弱い）
0.3 〜 0.59Moderate relationship（中くらい）
0.6 〜 0.99Strong to nearly perfect（強い〜ほぼ完全）
1Perfect relationship（完全な直線）

符号が向き：＋（direct relationship）はXが増えるとYも増える右上がり、−（inverse relationship）はXが増えるとYは減る右下がりです。

※ 表は教科書（Chapter 11、Table 11-1）のもの。教科書も「統計家によって解釈は少し違う」と断っています。

📖 教科書より：corr(Y, X)は2つの入力を取る二変数の集計関数（binary aggregate function）の1つです。教科書は、Yを「値がほかの変数に応じて変わる従属変数」、Xを「値がほかに依存しない独立変数」と説明し、「ただし相関の計算は従属・独立を区別しない（入れ替えても同じ）」と注記しています。また、Pearsonのrは「直線的な関係の強さと向き」を測り、点が1本の直線に沿うほど強い関係です。
🍎 かんたん説明

corr(Y, X)は「2つの列がどれくらい一緒に動くか」を−1〜+1で返します。+に近い＝同じ向きに動く、−に近い＝逆向きに動く、0に近い＝関係なし。

③

bikes データで corr() を使う

最高気温・降水量と通行量の関係

講義で使うbikesテーブルの列は次のとおりです（練習アリーナのスキーマパネルにも出ます）。

列意味
cross_date自転車が橋を渡った日（date型。'2016-04-01'の形）
high_temp / low_tempその日の最高気温／最低気温（°F）
precip降水量（インチ）。'T'（ごく微量）は0、'0.47 (S)'は0.47にそろえてある（numeric列）
brooklyn・manhattan
williamsburg・queensboro		各橋を渡った自転車の数
total4つの橋の合計
📋 講義のCSVは4月1〜30日の30日分が7回繰り返されている（210行）ため、cross_dateは30種類しかありません。

講義のCREATE TABLEでは、列は cross_date date, high_temp numeric, low_temp numeric, precip numeric, brooklyn integer, manhattan integer, williamsburg integer, queensboro integer, total integer の9列で、idや曜日の列はありません。

まず中身を3行だけ見てみましょう（SELECT … FROM bikes LIMIT 3、橋ごとの列を除く）。

cross_date | high_temp | low_temp | precip | total -----------+-----------+----------+--------+------ 2016-04-01 | 78.1 | 66 | 0.01 | 11497 2016-04-02 | 55 | 48.9 | 0.15 | 6922 2016-04-03 | 39.9 | 34 | 0.09 | 4759 (3 rows)

ここで講師は考えます。「通行量の合計（total）は、何かに左右されそうだ。たとえば最高気温では？」。つまり従属変数 Y ＝ total、独立変数 X ＝ high_tempです。

SELECT corr(total, high_temp) AS corr_temp
FROM bikes;
corr_temp ------------------ 0.7433437005618628

1行1列の、1つの数が返りました。約0.74です。桁が長いので、round()で小数第2位に丸めましょう。ここで重要な講師のポイントがあります。

⚠️ PostgreSQLでは、round(値, 桁数)を使うために、先に::numericでキャストします。corr()はdouble precision（浮動小数点）を返し、桁数付きのroundはnumeric型にしか使えないからです。::numericはCAST(… AS numeric)の短縮形です（M2のCAST）。
💡 演習アリーナのSQLiteでは、roundが浮動小数点にもそのまま使えるため、::numericは自動的に変換されます。PostgreSQLの書き方で書けば、どちらでも動きます。
SELECT round(corr(total, high_temp)::numeric, 2) AS corr_temp
FROM bikes;
corr_temp --------- 0.74

r ＝ 0.74。教科書の目安（0.6〜0.99）では「強い正の相関」です。気温が上がるほど、通行量の合計も増える傾向がある、と読めます。夏のほうが冬より走る人が多いはず、という直感とも合いますね。

次に、降水量 precip との相関です。「雨が降ると自転車に乗る人は減るのでは？」という仮説を調べます。

SELECT round(corr(total, precip)::numeric, 2) AS corr_precip
FROM bikes;
corr_precip ----------- -0.59

r ＝ −0.59。符号がマイナスなので逆向きの関係です。講師の言葉では「中程度の負の相関（moderate negative）」。降水量が増えるほど、通行量の合計は減る傾向があります。気温（同じ向きに動く）と降水量（逆向きに動く）で、符号の意味の違いがはっきり分かります。

🔁 引数を入れ替えてみる：corr(high_temp, total)と書いても相関係数は同じ0.74になります。
SELECT round(corr(high_temp, total)::numeric, 2) AS swapped
FROM bikes;
swapped ------- 0.74
📖 教科書の例（国勢調査・3,142郡）：Listing 11-2ではcorr(median_hh_income, pct_bachelors_higher)が0.6999…（0.70の少し手前）で、「大卒以上の割合が高い郡ほど世帯年収も高い」強めの正の相関でした。Listing 11-3でround(…::numeric, 2)を使うと、0.70・0.06（年収と60分以上通勤の割合：ほぼ無関係）・−0.14（大卒割合と長時間通勤：弱い負の相関）になります。教科書は「round()は丸める数と桁数の2つを取り、桁数を省くと整数に丸める」「corr()はデフォルトで浮動小数点（double precision）を返すので::numericに変換する」と説明しています。
🍎 かんたん説明

round(corr(Y, X)::numeric, 2)が基本の形。0.74は「気温が高い日は通行量も多い」、−0.59は「雨が多い日は通行量が少ない」。符号は向き、大きさは強さです。

💻 ミニ練習：気温との相関を求める

bikesテーブルで、total（Y）とlow_temp（X）の相関係数をround(…::numeric, 2)で小数第2位まで丸めて求めてください。最高気温より弱い相関（0.49）になります。

SELECT round(corr(total, low_temp)::numeric, 2) AS corr_low
FROM bikes;

結果は0.49。教科書の目安では「中くらい（moderate）」の正の相関で、最高気温（0.74）より弱いことが分かります。

④

応用：橋ごと・グループごと・注意点

GROUP BY / HAVING との組み合わせ

列を変えれば、いろいろな組み合わせを1つのSELECTで比べられます。橋ごとの気温との相関を一度に並べてみましょう（ASで別名を付けるとスッキリ読めます）。

SELECT
  round(corr(brooklyn,    high_temp)::numeric, 2) AS brooklyn,
  round(corr(manhattan,    high_temp)::numeric, 2) AS manhattan,
  round(corr(williamsburg, high_temp)::numeric, 2) AS williamsburg,
  round(corr(queensboro,   high_temp)::numeric, 2) AS queensboro
FROM bikes;
brooklyn | manhattan | williamsburg | queensboro ---------+-----------+--------------+----------- 0.74 | 0.72 | 0.76 | 0.73

4つの橋すべてで0.7前後の正の相関で、Williamsburg橋がもっとも強く（0.76）、Manhattan橋がもっとも弱い（0.72）という結果です。

統計関数は集計関数なので、GROUP BYと組み合わせて「グループごとの相関」も求められます。最高気温の帯（50°F未満＝cool、65°F未満＝mild、それ以上＝warm）にCASEで分け、帯ごとの気温と通行量の相関を見てみましょう。

SELECT CASE WHEN high_temp < 50 THEN 'cool'
                 WHEN high_temp < 65 THEN 'mild'
                 ELSE 'warm' END AS temp_band,
       round(corr(total, high_temp)::numeric, 2) AS r,
       count(*) AS n
FROM bikes
GROUP BY temp_band
ORDER BY temp_band;
temp_band | r | n ----------+-------+--- cool | 0.56 | 49 mild | 0.65 | 84 warm | -0.06 | 77 (3 rows)
⚠️ データについての注意：この表は4月1〜30日の30日分が7回繰り返されたものです。講義の数値（0.74など）はこのデータで再現されます。帯ごとに見ると、coolは0.56、mildは0.65と正の相関ですが、warmでは−0.06とほぼ無関係になります。全体では強い相関でも、気温の範囲を狭めると見えなくなることがあります（教科書も、相関は「全体の傾向」を表すもので注意して解釈するよう述べています）。

グループごとの相関に条件を付けるには、WHEREではなくHAVINGを使います（M4：集計後の値で絞るのはHAVING）。

SELECT CASE WHEN high_temp < 50 THEN 'cool'
                 WHEN high_temp < 65 THEN 'mild'
                 ELSE 'warm' END AS temp_band,
       round(corr(total, high_temp)::numeric, 2) AS r
FROM bikes
GROUP BY temp_band
HAVING corr(total, high_temp) > 0.6
ORDER BY temp_band;
temp_band | r ----------+----- mild | 0.65

最後に、相関を読むときの注意点を押さえましょう（最初の2つは教科書の注意、あとの2つは補足）。

  • 相関は因果関係ではない。「気温と通行量が一緒に動く」ことは言えても、「気温が上がったから通行量が増えた」とまでは言えません（教科書の1つ目の注意：変化が一緒に動くだけで、原因は証明されない）。
  • 統計的に有意かどうかの検定が別に必要。教科書の2つ目の注意：相関は偶然かもしれないので、統計家は検定で確かめます。その検定は本書（とこの授業）の範囲外です。
  • 直線的な関係しか測れない。点がきれいなU字を描いていても、r は0に近くなることがあります。
  • NULLを含む行は無視される。PostgreSQLのcorr(Y, X)は、YまたはXがNULLの行を計算から外します（AVGと同じ考え方）。
🍎 かんたん説明

corrは集計関数。GROUP BYでグループ別の相関、HAVINGで「相関が〇〇以上のグループだけ」が取り出せます。ただし相関があっても原因とは限りません。

💻 ミニ練習：相関の強いグループだけ残す

bikesを最高気温の帯（CASE：50未満＝'cool'、65未満＝'mild'、それ以外＝'warm'）ごとにグループ化し、totalとhigh_tempの相関が0.55以上の帯だけを、帯の名前temp_bandと丸めた相関r（小数第2位）の2列で、temp_bandの昇順に出力してください。

SELECT CASE WHEN high_temp < 50 THEN 'cool'
                 WHEN high_temp < 65 THEN 'mild'
                 ELSE 'warm' END AS temp_band,
       round(corr(total, high_temp)::numeric, 2) AS r
FROM bikes
GROUP BY temp_band
HAVING corr(total, high_temp) >= 0.55
ORDER BY temp_band;

cool（0.56）とmild（0.65）の2行が残ります（warmは−0.06）。グループ集計後の値で絞るのでWHEREではなくHAVINGです。丸めた値ではなく元のcorr(...)で比べている点にも注意しましょう。
