🍎 超やさしい版：制約

列に付けるルールは4つだけ——NOT NULL・CHECK・UNIQUE・DEFAULT。それぞれ何を守るのかを見ていきます。

4つの制約CHECKUNIQUE vs PK🛡️ 本編はこちら
⚡

4つの制約をまとめて見る

空・範囲・重複・初期値

🎯 これだけ覚えればOK

列の形は属性名 データ型 制約。既定ではNULL（空）OKなので、空にしたくない列にはNOT NULLを付けます。

🚫 NOT NULL

空を禁止する
first_name NOT NULL

✅ CHECK

値の範囲をテストする
CHECK (price > 0)

🆔 UNIQUE

重複だけ禁止（NULLは複数可）
email UNIQUE

🧩 DEFAULT

書かなかったときの初期値
DEFAULT CURRENT_DATE

▶ NOT NULLの基本形

first_name varchar(50) NOT NULL,
middle_name varchar(50) NULL
CREATE TABLE Query returned successfully.
🍎 ひとことで

ミドルネームは無い人もいるからNULL可。名前は必ずあるからNOT NULL。

①

CHECK＝値の見張り番

TRUEになる値しか通さない
🚦
CHECKはTRUE/FALSEの判定です。TRUEになる行だけがテーブルに入れます。価格が0より大きいか、日付が今日以前か、といった条件をチェックします。

▶ 違反するとエラーになる

price numeric CHECK (price > 0)
ERROR: new row for relation "products" violates check constraint "products_price_check"
書き方意味
CHECK (quantity >= 0)在庫は0でもOK
CHECK (price > 0)価格は0だとタダになるのでNG
CHECK (sale_price < retail_price)セール価格は定価より必ず安い
🍎 ひとことで

CHECKは1列だけでなく、2つの列を見比べる条件にも使えます。

②

UNIQUE vs PRIMARY KEY

両方「重複禁止」だけど別物
観点PRIMARY KEYUNIQUE
重複禁止禁止
NULL不可複数OK
変更基本しないしてよい

▶ SNSのusersテーブル

user_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
email text UNIQUE,
username text UNIQUE
ERROR: duplicate key value violates unique constraint "email_unique" DETAIL: Key (email)=(slee@example.org) already exists.
🆔
内部IDは一生変わらない前提でPRIMARY KEYに。emailやusernameは人が変えたくなるのでUNIQUEにします。

🤔 答えられるかな？（クリックで答えが開く）

Q1. 列を書かなかったらNULLは許可される？A. される。既定はNULL許可。NOT NULLを付けて初めて禁止できる。
Q2. price > 0 と price >= 0 の違いは？A. >= 0は価格0（無料）も許してしまうので、価格には> 0を使う。
Q3. UNIQUEとPRIMARY KEYの一番の違いは？A. UNIQUEはNULLを複数許し、値を変更してよい前提。PKはNULL不可・変更しない前提。

💡 まとめ

• 列は既定でNULL可。禁止するにはNOT NULL

• CHECKはTRUE/FALSEで値の範囲を判定

• UNIQUEは重複だけ禁止、PKはNULLも禁止

• DEFAULTは書かなかったときの初期値
