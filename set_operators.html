M6 · Set Operators

➕ 集合演算子（UNION・INTERSECT・EXCEPT）

JOINは別々のテーブルの列を横に並べる操作でした。それに対して集合演算子（set operator）は、形（列数・列の型）が同じ2つのクエリの結果を、行として重ねたり比較したりする操作です。JOINは「テーブル」を参照しますが、集合演算子は「クエリ（SELECT文）」同士を組み合わせる点も大きな違いです。

①

JOINとSET演算子の違い

「横に並べる」か「縦に重ねる」か

たとえばteaches（誰がどの授業を教えているか）とtakes（誰がどの授業を受けているか）から、両方のcourse_idを見たいとします。

JOINを使うと、2つのテーブルのcourse_id列を条件で結び付けて、1行の中に両方の列を並べて表示します。「instructorの列」と「studentの列」が横に並ぶだけで、データそのものが混ざり合うわけではありません。

一方集合演算子を使うと、「teachesのcourse_id」と「takesのcourse_id」を1本の列に統合し、重複を除いたユニークな行のリストとして返します。列を横に増やすのではなく、行を縦に積み重ねる（または比較する）イメージです。

JOIN＝横に並べる／SET演算子＝縦に重ねる
teaches.course_id
＋
takes.course_id

JOIN → 1行に2列として並ぶ（同じ行に instructor 側 course_id と student 側 course_id）

SET演算子（UNIONなど） → 1列にまとめて重複を除いた行のリストになる

JOIN集合演算子（UNION/INTERSECT/EXCEPT）
組み合わせ方列を横に並べる行を縦に重ねる／比較する
対象テーブル（キーで結合）クエリ（SELECT文の結果）
重複行自動では除去しない自動で除去する（ALLを付けない限り）
順序LEFT/RIGHTで結果が変わる基本は順序を問わない（EXCEPTだけ例外）
🍎 かんたん説明

JOINはテーブルの列を横に並べる。集合演算子は2つのクエリの行を縦に重ねたり比べたりする。集合演算子は自動的に重複を消す。

②

UNION（行を結合する）

両方に存在する行をすべて集める

UNIONは、2つのクエリの結果をすべて合体させ、重複を除いたユニークな一覧を作ります。「教えられている、または受講されているコースを全部見たい」というときに使えます。

SELECT course_id FROM teaches
UNION
SELECT course_id FROM takes
ORDER BY course_id;
course_id ---------- CS-101 CS-190 CS-315 ... (85 rows)

teachesが100件、takesが30,000件あっても、UNIONは重複を除いて「教えられている、または受講されているコースの種類」だけを返すので、結果はずっと少なくなります（この例では85種類）。

⚠️ UNIONにWHEREを付けるときは要注意。片方のクエリだけに条件（例：WHERE year = 2009）を付けても、もう片方のクエリは絞り込まれないため、結果がほとんど変わらないことがあります。両方のクエリに同じ条件を書くか、後述のINTERSECTを検討しましょう。
🍎 かんたん説明

UNIONは2つのクエリの結果を1つのリストにまとめ、重複を除きます。「どちらかにあれば含める」という演算子です。

③

INTERSECT（共通する行）

両方のクエリに存在する行だけを残す

INTERSECTは、両方のクエリの結果に共通して存在する行だけを返します。ベン図でいう「重なった部分」だけです。

例えば「前提科目（prereq）を持ち、かつ実際に教えられている（teaches）コース」を調べたいとします。

SELECT course_id FROM prereq
INTERSECT
SELECT course_id FROM teaches
WHERE year = 2009;
course_id ---------- CS-101 CS-190 CS-315 (3 rows)

先ほどのUNIONの例で「WHEREを片方に付けても絞り込めない」という問題がありましたが、INTERSECTなら両方のクエリに存在する行だけが残るため、片方のクエリだけにWHERE year = 2009を付けても正しく絞り込めます——結局「2009年に教えられていたコース」に自然と限定されるからです。

📌 INTERSECTはWHERE句をどちらのクエリに置くかが重要です。ただし列自体が存在しないクエリには置けません——例えばprereq(course_id, prereq_id)にはyear列が無いので、WHERE year = 2009はteaches側のクエリに書く必要があります。
🍎 かんたん説明

INTERSECTは「両方のクエリに存在する行」だけを返します。片方だけにある行は消えます。

④

EXCEPT（差集合・順序に注意）

1番目のクエリから2番目のクエリの行を引く

EXCEPTは、1つ目のクエリの結果から、2つ目のクエリにも存在する行を取り除いた結果を返します。「A EXCEPT B」は「AにあってBに無いもの」で、イメージとしてはA − Bです。

例えば「前提科目が設定されていないコース」を知りたいとき、全コースから前提科目テーブルに登場するコースを引きます。

SELECT course_id FROM course
EXCEPT
SELECT course_id FROM prereq;
course_id ---------- CS-001 CS-002 CS-005 ... (121 rows)

courseテーブルには200件あり、prereqには重複を含めて（同じコースに複数の前提科目があるため）ユニークなcourse_idが約100件ほど登場します。結果として、EXCEPTで残るのは121件——「前提科目が1つも設定されていないコース」です。

⚠️ EXCEPTだけはUNIONやINTERSECTと違い、クエリの順序を入れ替えると結果が変わります。A EXCEPT Bは「Aのうち、Bに無いもの」ですが、B EXCEPT Aは「Bのうち、Aに無いもの」——まったく別の結果です。 
-- 全コースから、前提科目テーブルにあるコースを引く → 121件
SELECT course_id FROM course EXCEPT SELECT course_id FROM prereq;

-- 順序を逆にすると…
SELECT course_id FROM prereq EXCEPT SELECT course_id FROM course;
course_id ---------- (0 rows)
prereqに登場するコースIDは、すべてcourseテーブルにも存在するため（外部キーの制約上当然）、「prereqにあってcourseに無いもの」は0件になります。
🍎 かんたん説明

EXCEPTは「A − B」。1つ目のクエリから2つ目のクエリと重なる行を取り除きます。順番を変えると答えも変わる、UNION/INTERSECTには無い特徴です。

⑤

ルールとALLキーワード

列数・データ型を揃える／重複行の扱い

集合演算子を使うための基本ルールは2つだけです。

  1. 2つのクエリの列数（SELECTする列の数）が一致していること
  2. 対応する列同士のデータ型が互換であること（列名が同じである必要はない）

JOINでは列の型がずれていても「キーが一致するか」さえ分かれば結合できますが、集合演算子は列を1本に統合してしまうため、型が揃っていないと「重複かどうか」「存在するかどうか」を判定できません。例えば1つ目のクエリのcourse_idが整数型、2つ目が文字列型だと、SQLはこの2つを同じ値として比較できず、エラーになります。

-- 基本構文
SELECT col1, col2 FROM table_a
UNION -- または INTERSECT / EXCEPT（+ ALL も可）
SELECT col1, col2 FROM table_b
ORDER BY col1; -- ORDER BYは最後に1回だけ
📌 UNION ALL / INTERSECT ALL / EXCEPT ALLは重複行を残します。通常のUNION・INTERSECT・EXCEPTは結果から重複行を自動で取り除きますが、時系列イベントの繰り返しなど「重複そのものが意味を持つ」データでは、ALLを付けることで元の重複を保持できます。例えばteachesとtakesをUNIONすると重複が除かれた一覧になりますが、UNION ALLにすると片方が30,000件・もう片方が100件なら、合計30,100件がそのまま返ります。
SELECT course_id FROM teaches
UNION ALL
SELECT course_id FROM takes;
course_id ---------- ... (重複を含む) (30100 rows)
演算子重複の扱い順序
UNION除去問わない
UNION ALL保持問わない
INTERSECT除去問わない
EXCEPT除去重要：A EXCEPT B ≠ B EXCEPT A
🍎 かんたん説明

2つのクエリは列数とデータ型を揃える。ALLを付けると重複を消さずに全部残す。EXCEPTだけは順序で結果が変わるので要注意。

SQLを自分で書いて、必要なキーワードが揃っているか確認しましょう。「答え合わせ」はキーワードチェック（本物の実行結果ではありません）、「答えを見る」で模範解答が見られます。実際に合っているかは、ぜひpgAdminでも実行して確かめてください。

Q1. UNIONで2つのクエリを合体する

takesテーブルから、Spring学期に履修されたcourse_idの一覧と、Fall学期に履修されたcourse_idの一覧をUNIONで1つのリストにまとめるSQLを書いてください（重複は自動で除去されます）。

SELECT course_id FROM takes WHERE semester = 'Spring'
UNION
SELECT course_id FROM takes WHERE semester = 'Fall';

UNIONは2つのクエリの行を1つのリストに合体し、重複を除いた結果を返します。

Q2. INTERSECTで両学期に共通する科目を探す

takesテーブルを使い、2009年のSpring学期にも2009年のFall学期にも履修されているcourse_idをINTERSECTで求めるSQLを書いてください。

SELECT course_id FROM takes WHERE semester = 'Spring' AND year = 2009
INTERSECT
SELECT course_id FROM takes WHERE semester = 'Fall' AND year = 2009;

INTERSECTは両方のクエリに共通する行だけを返します——ベン図の「重なった部分」です。

Q3.（応用）EXCEPTで差を求める（順序に注意）

takesテーブルを使い、「2009年のSpring学期に履修されたが、2009年のFall学期には履修されなかった」course_idをEXCEPTで求めるSQLを書いてください。

SELECT course_id FROM takes WHERE semester = 'Spring' AND year = 2009
EXCEPT
SELECT course_id FROM takes WHERE semester = 'Fall' AND year = 2009;

EXCEPTは順序が重要です——A EXCEPT Bは「Aにあって、Bに無いもの」。クエリの順番を入れ替えると結果も変わります（B EXCEPT Aは別物）。
