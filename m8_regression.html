M8 · Statistics in SQL — Regression (Lecture video 2 · Practical SQL Ch.11)

📈 統計②：回帰 regr_slope / regr_intercept / regr_r2

相関が「関係の強さ」なら、回帰は「関係を表す直線」です。y = mx + bの傾き・切片・r²をSQLで取り出し、気温から自転車の通行量を予測します。講義動画②と教科書『Practical SQL 第2版』11章に対応します。

🚲 使うデータは前ページと同じbikes（NYC East River橋の自転車通行量、講義のCSV：4月の30日分が7回繰り返され、210行）です。

① 回帰とは② 傾きと切片③ r²と予測📝 Quiz
📖 教科書対応（Practical SQL 第2版 Ch.11 Statistics、PDFのページ番号）
  • ① 回帰とは → Predicting Values with Regression Analysis（p.274〜275）。相関の背景は Measuring Correlation with corr(Y, X)（p.269〜272）と Checking Additional Correlations（p.272〜274）
  • ② 傾きと切片 → Predicting Values with Regression Analysis（Listing 11-4、p.276〜277）
  • ③ r²と予測 → Finding the Effect of an Independent Variable with r-Squared（Listing 11-5、p.277〜278）

教科書の例は、米国の郡ごとの「学士号以上の割合 pct_bachelors_higher（X）」と「世帯所得の中央値 median_hh_income（Y）」です（r ≒ 0.70、傾き1016.55、切片29651.42、r² ＝ 0.490）。このページではサイクリング（bikes）のデータで同じ手順を行います。

①

回帰とは？ 直線で関係を表す

y = mx + b と、傾き・切片・r²

前のページのcorr()（相関係数）は、2つの変数が「どれくらい一緒に動くか」を-1〜1の1つの数字で教えてくれました。でも、それだけでは「気温が1度上がると、通行量は何人増えるのか？」「気温が80度のとき通行量はいくつ？」には答えられません。そこで登場するのが線形回帰（linear regression）です。

線形回帰とは、従属変数y（説明される側。ここでは通行量）と、1つ以上の独立変数x（説明する側。ここでは気温）の関係を、1本の直線で表すモデルです。データの真ん中を通る直線を引いて、関係を数式にします。もちろんデータは直線の周りに散らばるので完璧ではありませんが、関係をより具体的に説明できます。

相関 corr()回帰 regr_*()
答えること関係の強さと向き関係を表す直線の式
出てくる数字r（-1〜1）の1つ傾き・切片・r²の3つ
できること「強い／弱い」と言える「xがこの値のときyはいくつ」と予測できる

直線の式は、中学で習う y = mx + b そのものです。統計の授業では y = b₀ + b₁x + ε のように書き、最後のε（誤差項）が「直線からのズレ」を表します。SQLで取り出す部品は次の3つです。

教科書では、この直線を最小二乗回帰直線（least squares regression line）、つまり「データにいちばんよく合う直線」と呼び、式を Y = bX + a と書きます（Yは予測値＝従属変数、bは傾き、Xは独立変数の値、aはX＝0のときの高さ＝y切片）。文字は違いますが、y = mx + bと同じ式です。教科書の問いは「学士号を持つ人が30%の郡では、世帯所得の中央値はいくつと予想できるか？ 学士号の割合が1ポイント増えると所得はいくら増えるか？」で、まさにデータにない値を、直線上で予測するために回帰を使います。

直線 y = m·x + b の部品とSQL関数
📐
m ＝ 傾き（slope）regr_slope(Y, X)：xが1増えるとyがいくつ増えるか
＋
📍
b ＝ 切片（intercept）regr_intercept(Y, X)：x＝0のときのyの値
＋
🎯
r² ＝ 決定係数regr_r2(Y, X)：直線がデータのばらつきをどれだけ説明できるか（0〜1）
この3つがそろえば、直線の式と、その直線の「信頼度」が分かります。

講義では「幸福度は収入の関数」というグラフが例に出ました。直線は y = 0.2 + 0.71x で、傾きの0.71が正なので、収入が増えると幸福度も増える傾向があります。ただし傾きが1未満なので「収入が1増えても幸福度は1までは増えない」。しかも点は直線の上下にかなりばらついていて、外れ値も目立ちます。つまり「傾向はあるが、相関は中くらい以下」だというわけです。線を引けることと、その線がデータによく合っていることは別の話で、だから傾きとは別にr²も見る必要があります。

相関の強さの目安は、教科書の Table 11-1（p.270）では次のとおりです：0＝関係なし、0.01〜0.29＝弱い、0.3〜0.59＝中程度、0.6〜0.99＝強い〜ほぼ完全、1＝完全。bikesのcorr = 0.74は「強い」、precipの−0.59は「中程度」の上端です。

📌 この授業の回帰は直線だけを扱います（単回帰）。曲線など別の形の線が合うデータもありますが、それは統計の授業の範囲です。
🍎 かんたん説明

相関は「仲がいいかどうか」、回帰は「仲のよさを式にしたもの」です。式（直線）ができれば、気温を入れるだけで通行量を予想できます。部品は傾き・切片・r²の3つです。

💻 ミニ練習：部品の名前と関数をつなぐ

次の3つに合うPostgreSQL関数名を、コメントで書いてください：①傾き、②切片、③決定係数r²。答え合わせは関数名がそろっているかを見ます。

-- ① 傾き　　 regr_slope(Y, X)
-- ② 切片　　 regr_intercept(Y, X)
-- ③ 決定係数 regr_r2(Y, X)

3つとも名前がregr_で始まり、引数は(Y, X)の2つです（Yが先）。

②

傾きと切片を取り出す

regr_slope(Y, X) と regr_intercept(Y, X)

ここからは、前のページと同じbikesテーブル（NYCのEast River橋を渡った自転車の数。210行）を使います。totalが1日の総通行量、high_tempが最高気温（華氏）です。相関が高かったhigh_tempを使い、totalをhigh_tempで説明する直線を作りましょう。

最初に最重要ルールです。引数の順番は (Y, X)、つまり「説明される側（結果）が先、説明する側（原因）が後」です。

⚠️ 順番を逆にしても、エラーは出ません。ただし答えがまったく別の数字になります。たとえばregr_slope(high_temp, total)と書くと「通行量が1人増えると気温が何度上がるか」という意味になり、結果は0.0015といった意味のない数字になります。corr()と違って、回帰は引数の順番で答えが変わる、と覚えましょう。
SELECT regr_slope(total, high_temp) AS slope,
       regr_intercept(total, high_temp) AS intercept
FROM bikes;
slope | intercept ------------------+------------------- 370.1804037848244 | -7891.028861284664 (1 row)

小数点以下が長すぎて読みにくいので、round(値, 桁数)で丸めます。講義の注意点は「PostgreSQLでは、roundの前に::numericでキャストする」ことです。regr_slopeなどの結果はdouble precision（浮動小数点）で、PostgreSQLのround(値, 桁数)はnumeric型にしか2引数で使えないからです。::numericを付け忘れるとエラーになります。roundは大文字でも小文字でも構いません（講義では小文字で統一）。

SELECT round(regr_slope(total, high_temp)::numeric, 2) AS slope,
       round(regr_intercept(total, high_temp)::numeric, 2) AS intercept
FROM bikes;
slope | intercept -------+---------- 370.18 | -7891.03 (1 row)

これで直線の式が決まりました。y = 370.18·x − 7891.03、つまり通行量 ≒ 370.18 × 最高気温 − 7891.03です。読み方は次のとおりです。

  • 傾き 370.18：最高気温が1度上がるごとに、1日の総通行量が約370人増える。正の傾きなので、気温と通行量は「同じ向きに動く」（前ページのcorr = 0.74の正の相関と一致）。
  • 切片 −7891.03：最高気温が0度のときの予測値。通行量がマイナスになることはありえないので、切片は「直線を延ばしたときの数学上の値」と割り切ります。この教材のデータは最低でも30度台の日しかなく、0度の予測はデータの範囲の外です。講義でも「Excelでグラフにすると、直線が下に大きくずれているのが見える」と説明されました。
📖 教科書の例（Listing 11-4）：regr_slope(median_hh_income, pct_bachelors_higher)は1016.55、regr_intercept(...)は29651.42。「学士号の割合が1ポイント増えるごとに、郡の所得の中央値が約1016.55ドル増える」と読み、切片は「割合が0のときに直線がy軸を切る高さ」と説明されています。ここでも引数は(Y, X)の順です。なお教科書はcorr()について「入れ替えても同じ結果」と注記していますが、regr_slopeなどは入れ替えると別の数字になります。
📌 データの注意：講義のCSVは4月1〜30日の30日分が7回繰り返されている（行数210行のまま使う）。そのため日付は30種類だけで、同じ日付の行が7行ずつあります。傾きやr²の値は、どの繰り返し回数でも変わりません。
📌 このテーブルの注意：precip（降水量）は元のデータに T（trace＝ごく微量）や 0.47 (S)（雪）のような文字が混ざっていたため、T→0、0.47 (S)→0.47に直して数値の列にしてあります（M7のデータ整形と同じ発想です）。

降水量でも同じ形で書けます。precipは「降水量(インチ)」なので、傾きは雨が1インチ増えたときの通行量の変化です。

SELECT round(regr_slope(total, precip)::numeric, 2) AS slope,
       round(regr_intercept(total, precip)::numeric, 2) AS intercept
FROM bikes;
slope | intercept ----------+---------- -32225.98 | 16220.99 (1 row)

傾きが負（−32225.98）なのは、雨が降るほど通行量が減るから（前ページのcorr = −0.59の「中程度の負の相関」と同じ向き）。切片16220.99は「降水量0のときの直線上の通行量」です。なお、このデータの降水量は最大でも0.47インチで、1インチ降る日は1日もありません。「1インチ増えると約32,000人減る」を文字どおりに受け取らず、傾きは「向きと大きさの目安」として読みましょう（0.1インチなら約3,200人減）。

⚠️ PostgreSQLとこの演習アリーナの違い：💡 PostgreSQLでは、round(regr_slope(...), 2)を::numericなしで書くとエラーになります。演習アリーナのSQLiteでは::numericなしでも動きますが、課題や本番のPostgreSQLに備えて、必ず::numericを付ける習慣にしましょう。
🍎 かんたん説明

regr_slope(Y, X)とregr_intercept(Y, X)は「直線の傾き」と「直線がy軸を切る高さ」を返します。Yが先、Xが後。長い小数はround(…::numeric, 2)で整えます。

💻 ミニ練習：気温から通行量への傾きと切片

bikesで、totalをhigh_tempで説明する回帰の傾きと切片を、それぞれ小数第2位に丸めて、1回のSELECTで出力してください。Yが先、::numericを忘れずに。

SELECT round(regr_slope(total, high_temp)::numeric, 2) AS slope,
       round(regr_intercept(total, high_temp)::numeric, 2) AS intercept
FROM bikes;

結果は370.18 | -7891.03です。引数は(total, high_temp)、つまりY（結果）が先です。

③

r²と予測、変数の比較

regr_r2(Y, X) を読み、直線から予測する

3つ目の部品が決定係数 r²（r-squared）、関数はregr_r2(Y, X)です。値は0〜1で、「Yのばらつきのうち、Xで説明できる割合」を表します。0に近ければ直線はほとんど役に立たず、1に近ければ点が直線の上にほぼ乗っています。

SELECT round(regr_slope(total, high_temp)::numeric, 2) AS slope,
       round(regr_intercept(total, high_temp)::numeric, 2) AS intercept,
       round(regr_r2(total, high_temp)::numeric, 2) AS r_squared
FROM bikes;
slope | intercept | r_squared -------+-----------+---------- 370.18 | -7891.03 | 0.55 (1 row)

r_squared = 0.55は、総通行量の変動のおよそ55%が、最高気温で説明できるという意味です。講義では「半分を少し超える、かなり高い数字」と評価しています。残りの約45%は、天気以外（曜日、イベント、風、季節など）が関わっているということです。

📌 相関係数との関係：単回帰では r² ＝ r × r です。前ページで求めたcorr(total, high_temp) = 0.74を2乗すると0.74 × 0.74 ≒ 0.55。実際にregr_r2は0.55を返します（0.5525…）。つまり「相関係数の2乗」が「説明できる割合」です。

教科書(p.277)の定義も同じです。「rを2乗した決定係数（coefficient of determination）＝r²は、独立変数によって説明される変動の割合で、0〜1の値」。たとえばr²が0.1なら「独立変数は従属変数の変動の10%を説明する、つまりほとんど説明していない」。教科書の例ではr² = 0.490で、郡の所得のばらつきの約49%が学士号の割合で説明でき、残りの51%は別の要因（たとえば地域にある仕事の種類）で決まる、と述べています。

直線に気温を代入して「予測」する

回帰の最大の使い道は予測です。関数の戻り値は普通の数値なので、傾き × x ＋ 切片をSELECT内で計算できます。最高気温が70度の日の予想通行量は、次のとおりです。

SELECT round((regr_slope(total, high_temp) * 70 + regr_intercept(total, high_temp))::numeric, 0) AS predicted_70
FROM bikes;
predicted_70 ------------ 18022 (1 row)

計算は 370.18 × 70 − 7891.03 ≒ 18022 です。かっこ全体に::numericを付けている点に注目してください（式全体をnumericにしてからroundします）。80度なら21723、50度なら10618です。

教科書(p.277)も同じ方法で予測しています。Y = 1016.55(30) + 29651.42 = 60147.92、つまり「学士号の割合が30%の郡の所得の中央値は約$60,148と予想できる」。実際の郡はこの値の上にも下にも散らばります。点が直線上に完全には並ばない（r ＝ 0.70は強いが完全ではない）からで、教科書も「他の要因が所得のばらつきに関わっている」と書いています。

ただし、これは平均的な予想であり、実際の日の通行量は直線の上下にばらつきます（r²が1でないぶん）。予測はデータの範囲（このデータでは約40〜81度）の内側で使いましょう。

どの説明変数がよく効くか（r²の比較）

講義の最後のポイントです。r²は「どの変数がYをよく説明するか」を比べる物差しにもなります。気温と降水量を比べてみましょう。

SELECT 'high_temp' AS x, round(regr_r2(total, high_temp)::numeric, 2) AS r_squared FROM bikes
UNION ALL
SELECT 'low_temp', round(regr_r2(total, low_temp)::numeric, 2) FROM bikes
UNION ALL
SELECT 'precip', round(regr_r2(total, precip)::numeric, 2) FROM bikes;
x | r_squared ----------+---------- high_temp | 0.55 low_temp | 0.24 precip | 0.35 (3 rows)

最高気温(0.55)が最強で、降水量(0.35)、最低気温(0.24)の順です。講義では「降水量でも計算すれば、80〜90%くらい説明できるかもしれない」と予想していましたが、実際に計算すると降水量のr²は0.35で、気温より低い結果でした。予想ではなく、SQLで計算して確かめることが大切、という良い例です。

⚠️ 教科書の注意点（p.278）：①相関は因果を証明しない（教科書は「離婚率とマーガリン消費量」のような無意味な相関の例に触れています）。また相関の節（p.274）でも「強い相関があっても、一方が他方の原因とは言えない。一緒に動くだけ」とあります。②統計の専門家は、結果が偶然でないかを調べる有意性検定や、データが正規分布に従うかなどの確認を、回帰の結果を受け入れる前に行います（本書の範囲外）。
この教材の補足（教科書の記述ではありません）：直線以外の形の関係はr²が低く出ること、また直線から離れた範囲（このデータなら気温40〜81度の外）の予測は外挿（extrapolation）で信頼できないことにも注意しましょう。気温が高い日だけで回帰を作るとr²がぐっと下がる点は演習で確かめます。
⚠️ r²が高い ≠ 原因である：r²は「同じ方向にそろって動く割合」を示すだけで、「気温が通行量を引き起こす」と証明するものではありません（相関は因果ではない）。また、直線以外の形（曲線）の関係は、r²が低く出ることもあります。さらに、同じ変数でも暑すぎる日は通行量が頭打ちになるため、気温が高い日だけで回帰を作ると、r²がぐっと下がります（演習で確かめましょう）。
🍎 かんたん説明

regr_r2は「この直線は、どれくらい当たるか」の点数（0〜1）です。0.55なら55点くらい、つまり「半分ちょっと当たる」。点数が高い変数ほど、予想に使いやすい説明役です。

💻 ミニ練習：降水量のr²と、気温70度の予測

bikesから、totalをprecipで説明する回帰のr²を小数第2位で出力してください（0.35になります）。

SELECT round(regr_r2(total, precip)::numeric, 2) AS r_squared
FROM bikes;

結果は0.35です。気温の0.55より低いので、降水量は気温ほど通行量を説明できていません。

least squares regression line
最小二乗回帰直線
教科書の言う「最もよく合う直線」。Y = bX + a。bが傾き、aがy切片。
coefficient of determination
決定係数（r²）
rを2乗した値。独立変数で説明できる従属変数の変動の割合（0〜1）。
::numeric
numericキャスト
double precisionをnumeric型に変換する。round(値, 桁数)の前に必要。
dependent / independent variable
従属変数／独立変数
説明される側(Y)と、説明する側(X)。

💡 学習のヒント

回帰は(Y, X)の順、丸めるときは::numeric。この2つを書く前に毎回声に出して確認しましょう。傾き＝向きと大きさ、r²＝当たり具合、と覚えると読みやすくなります。
