🔢 数値データ型 — INTEGER・SERIAL・NUMERIC

整数系（smallint/integer/bigint）、自動採番のserial系、そして小数を扱うnumericの精度(precision)とスケール(scale)を理解する。

① 文字と数値の違い② 整数系とserial系③ 小数：precisionとscale📝 Quiz
①

文字データ型と数値データ型の違い

「計算に使うかどうか」が最大の分かれ目

文字データ型と数値データ型の一番の違いは、その値に対して数学的な計算を行う意図があるかどうかです。ある列が数字だけで構成されていても、それが計算対象でないなら（郵便番号や商品コードのように）文字型を使うべきです。逆に、加減乗除やその他の計算をしたいなら数値型を選びます。

💡 文字型として保存された数字（例：'123'という文字列）は、そのままでは計算に使えません。計算したい場合はCAST（型変換）が必要です。CASTについては別レッスンで扱います。
🍎 かんたん説明

「この値を足し算・掛け算などの計算に使いたいか？」——YESなら数値型、NOなら（数字に見えても）文字型を検討しましょう。

②

整数系（integer）とserial系

バイト数・範囲、そして自動採番される主キー

整数系：smallint・integer・bigint

整数（小数を含まない、正負両方の値）を扱う代表的な3つの型です。

型サイズ用途の例
smallint2バイト（約±32,000の範囲）社員ID・在籍年数など、比較的小さい値
integer4バイト（最も一般的）あらゆる場面で使われる標準的な整数型
bigint8バイト（非常に広い範囲）暗号化に関わる値など、20億を超える可能性がある値
⚠️ 「とりあえずbigint」は良くない：大は小を兼ねるからと何でもbigintにすると、レコード数が数百万〜数十億に達したときにストレージと処理速度の両方で無駄なコストがかかります。実際に必要な範囲を見積もって選びましょう。

自動採番：smallserial・serial・bigserial

整数系と非常によく似た型にserial系があります。範囲はほぼ同じですが、負の値を含まず、1から自動的にインクリメント（増分）していくという特徴があります。この性質から、レコードを一意に識別する主キー（primary key）として頻繁に使われます。

型範囲の目安用途の例
smallserial〜約32,000社員IDや型番など、件数がそれほど多くならないもの
serial〜約20億社会保障番号や口座番号のような、ある程度永続的な一意識別子
bigserial〜約922京Amazonの注文番号・取引ID・領収書番号など、膨大な件数が発生するもの

なぜ一意な識別子（ID）が必要なのでしょうか。世界には同姓同名の「John Smith」が何千人もいます。FacebookやInstagramのアカウント、銀行口座、社会保障番号のように、一意な値を割り当てることで特定のレコードを素早く正確に検索できるようになります。

📌 主キーはメールアドレスのような値でも代用できますが、整数の一意な値のほうが検索・照合が高速で効率的なため、実務ではserial系がよく使われます。
🍎 かんたん説明

整数はsmallint→integer→bigintの順で扱える範囲が広がります。serial系はそれに「自動採番」機能が付いたバージョンで、主キーの定番です。件数の見込みに応じてサイズを選びましょう。

③

小数を扱う型：precisionとscale

固定小数点(numeric/decimal) vs 浮動小数点(real/double precision)

小数（フラクション）は、整数部分と小数部分を持つ値です。SQLには分数という概念はなく、すべて小数（decimal）として表現されます。小数には固定小数点（fixed point）と浮動小数点（floating point）の2種類があります。

固定小数点：numeric（decimal） — precisionとscale

最もよく使う固定小数点型がnumericです。numeric(precision, scale)という形で指定し、この2つの数値の意味を正しく理解することが重要です。

用語意味
precision（精度）数値全体で使える桁数の合計（整数部分＋小数部分）
scale（スケール）小数点以下に使える桁数
⚠️ よくある誤解：「precisionは小数点の左側の桁数」ではありません。precisionは全体の桁数、scaleが小数点以下の桁数です。precisionから scaleを引いた分が、小数点の左側（整数部分）の桁数になります。

実例：住宅ローンの月々の支払額

月々の住宅ローン返済額が、最大で$9,999.99まで想定されるとします。

CREATE TABLE mortgage (
    monthly_payment numeric(6, 2)
);

$9,999.99は「9999」＋「99」＝合計6桁なので precision = 6、小数点以下は2桁なので scale = 2。つまりnumeric(6, 2)が正解です。もし上限を$999.99までに絞り込むなら、全体の桁数は5になるのでprecisionは5に変わります（scaleは2のまま）。逆にscaleを3に増やせば、小数点以下が1桁増える代わりに整数部分の桁が1つ減り、最大値は$99.999になります。

📌 覚え方：precision＝合計の桁数、scale＝小数点以下の桁数。「precision引くscale」が小数点より左側（整数部分）の桁数になります。

浮動小数点：real・double precision

固定小数点が「桁数を厳密に固定する」のに対し、浮動小数点は柔軟に桁数が変わる代わりに、精度がやや劣る（＝厳密な正確さが必要な金額計算には不向き）という特徴があります。その代わりストレージが小さく済むため、大量の小さな値を保存するような場面で有効です。

用途おすすめの型
金額計算など、厳密な正確さが必要固定小数点（numeric / decimal）
厳密さより省スペースを優先したい大量データ浮動小数点（real / double precision）
💡 迷ったら少し大きめに：データ型は後から縮小するのが難しく、面倒です。想定される最大値に確信が持てないときは、思っているよりも一段階大きいサイズを選んでおく方が安全です（例：社員IDの再利用がないと確信できないならsmallserialではなくserialを検討）。
🍎 かんたん説明

numeric(precision, scale)は「全体の桁数」と「小数点以下の桁数」で決まります。金額のように正確さが命の値は固定小数点、大量の近似値でよいデータは浮動小数点が向いています。

📖 用語集

integer
整数
小数を含まない正負の数値。4バイトで最も一般的な整数型。
bigint
大整数
8バイトで非常に広い範囲を扱える整数型。大規模データや暗号関連の値に使う。
serial
自動採番
1から自動的にインクリメントする正の整数型。主キーとしてよく使われる。
primary key
主キー
テーブル内でレコードを一意に識別する値。
precision
精度
numeric型で許容される桁数の合計（整数部分＋小数部分）。
scale
スケール
numeric型で小数点以下に許容される桁数。
fixed-point / floating-point
固定小数点／浮動小数点
固定小数点(numeric)は桁数が厳密で正確、浮動小数点(real等)は柔軟だが精度がやや劣る。

💡 学習のヒント

precisionは「全体の桁数」、scaleは「小数点以下の桁数」。混同しやすいので、numeric(precision, scale)と書くときは必ずこの順番を意識しましょう。
