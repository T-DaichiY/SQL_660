M3 · Filtering with Where — Part 1

🎯 WHERE① — 条件で行を絞る

条件式は必ずTRUEかFALSEになる。TRUEの行だけが結果に残る——この一点さえ掴めば、WHEREは怖くない。

① 条件式のしくみ② 比較演算子③ WHEREの構文④ データ型の落とし穴📝 Quiz
①

条件式のしくみ — TRUEなら残る、FALSEなら消える

1行ずつ判定していく

ここまでのレッスンで、全体を見る（SELECT *）→ 列を絞る → 並べ替える（ORDER BY）→ 重複を消す（DISTINCT）と進んできました。WHEREはさらに一歩進んで、条件に基づいて行（レコード）を絞り込む句です。

📌 WHEREの核心はこの1文です：条件式がTRUEと評価された行だけがクエリ結果に含まれ、FALSEの行は飛ばされる。ほかは全部この応用にすぎません。

条件式（conditional）とは

条件式は「A 演算子 B」という形をしていて、結果は必ずTRUEかFALSEのどちらかになります。数値そのものが返るわけではありません。

5 < 8   -- TRUE
9 < 8   -- FALSE

SQLは1行ずつ評価している

「注文金額が50,000ドルを超える売上を見たい」という条件を書いたとき、データベースは次のように動きます。

WHERE order_amount > 50000 の評価
1️⃣
1行目：$45,00045000 > 50000 → FALSE → 除外
↓
2️⃣
2行目：$55,00055000 > 50000 → TRUE → 結果に追加 ✅
↓
3️⃣
3行目以降…テーブルの最後まで同じ判定を繰り返す
1行ずつ条件を当てはめ、TRUEの行だけを積み上げていく。それがWHEREの動作。
🍎 かんたん説明

WHEREは「○×クイズ」。1行ずつ条件に当てはめて、○（TRUE）の行だけを残します。

②

比較演算子（comparison operators）

算数で見慣れた記号＋SQL特有の3つ
演算子意味例メモ
=等しいqtr = 1プログラミング言語と違い==ではない
>より大きいsales > 3000算数と同じ
<より小さいsales < 100算数と同じ
>=以上qty >= 10比較記号が先、＝が後
<=以下qty <= 10同上（=<は誤り）
<>等しくないstatus <> 'Shipped'データベース系の伝統的な書き方
!=等しくないstatus != 'Shipped'プログラミング言語由来。!は「否定」

SQL特有の3つに注意

「以上・以下」：数学では≦≧という1文字の記号がありますが、キーボードにはありません。SQLでは比較記号を先に、イコールを後に並べて<= >=と書きます。

「等しくない」には2通りの書き方があります。<>は「より小さい、または、より大きい」＝「その値そのものではない」という発想の記法で、データベース系の言語でよく使われます。!=はPythonなどのプログラミング言語由来で、!が否定（not）を表します。

⚠️ どちらを使っても構いませんが、一貫させること。同じクエリやプロジェクトの中で<>と!=が混ざっていると、読む人が混乱します。チームやコースの慣習に合わせて、どちらかに統一しましょう。
🍎 かんたん説明

算数の記号がほぼそのまま使えます。特殊なのは「以上＝>=」「以下＝<=」「≠＝<>または!=」の3つだけ。

③

WHEREの構文と位置

FROMの後、ORDER BYの前
SELECT column1, column2, column3
FROM table_name
WHERE condition
ORDER BY column1;

順番はSELECT → FROM → WHERE → ORDER BYで固定です。英語として読むと自然に理解できます——「これらの列を、このテーブルから、この条件で、この順に並べて」。

🧠 豆知識：実はSQLの内部処理では、WHEREは列の選択より先に実行されています。ただし学習段階では「列を選んでから、行を絞る」と考えて構いません。書く順番と読む順番が一致しているほうが、クエリを組み立てやすいからです。

例1：第1四半期の売上一覧

「第1四半期の売上について、顧客名・製品ライン・売上額の一覧が欲しい」という依頼を受けたとします。

SELECT customer, product_line, sales
FROM sales
WHERE qtr = 1;
customer | product_line | sales ------------------------+--------------+--------- Land of Toys Inc. | Motorcycles | 2871.00 Cruz & Sons Co. | Classic Cars | 3884.34 ... (665 rows)
📌 絞り込みに使う列を、SELECTに含める必要はありません。上の例ではqtrで絞っているのに、qtr列は表示していません。全行が「第1四半期」だと分かりきっているので、表示してもあまり意味がないからです。もちろん含めても正しく動きます——目的次第で決めましょう。

例2：ORDER BYと組み合わせる

SELECT customer, product_line, sales
FROM sales
WHERE qtr = 1
ORDER BY customer;

絞り込んだ結果を、さらに顧客名のアルファベット順に整理できます。SELECT・WHERE・ORDER BYを組み合わせることで、実務で使えるクエリになっていきます。

文字列を条件にする

SELECT customer, sales FROM sales
WHERE region = 'SW';

文字型の値はシングルクォート'で囲みます。文字列で意味を持つ比較は基本的に=（と<>）だけです。region < 'Southwest'のような大小比較は、書けてもほとんど意味を持ちません。

💡 「北西・南西・南東の3地域を対象にしたい」のように複数の候補から選びたい場合は、次のレッスンで学ぶINを使います。

日付を条件にする

SELECT * FROM sales
WHERE order_date > '2020-01-01';

日付には比較演算子がそのまま使えます（「2020年1月1日より後」という意味になります）。ただしフォーマットが列の定義と一致していることが条件です。形式が違ったり日付として解釈できない文字列を書くと、エラーになります。

🍎 かんたん説明

WHEREはFROMの後ろ。数値はそのまま、文字と日付はシングルクォートで囲む。並べ替えたいときはWHEREの後にORDER BYを足します。

④

データ型の落とし穴 — money型でつまずく

左辺と右辺の型を必ず合わせる

「3,000ドルを超える売上の、顧客名・製品ライン・製品コード・売上額が欲しい」——素直に書くとこうなります。

SELECT customer, product_line, product_code, sales
FROM sales
WHERE sales > 3000;
ERROR: operator does not exist: money > integer HINT: No operator matches the given name and argument types. You might need to add explicit type casts.
⚠️ エラーの意味：「money型 > integer型という比較を行う演算子は存在しない」——つまり左辺と右辺のデータ型が食い違っているということです。

原因を突き止める

pgAdminでテーブルを右クリック →「Properties」→「Definition」で列のデータ型を確認できます。このsales列はmoney型でした。money型は$という数字以外の文字を含むため、文字列と同じようにシングルクォートで囲む必要があります。

⭕ 正しい書き方

SELECT customer, product_line, product_code, sales
FROM sales
WHERE sales > '3000'
ORDER BY sales;
customer | product_line | product_code | sales -----------------------+--------------+--------------+---------- Muscle Machine Inc | Classic Cars | S18_1749 | $3,002.00 Land of Toys Inc. | Vintage Cars | S24_3969 | $3,015.50 ...
📌 覚え方：数字以外の文字を含む型（money、date、text、varchar…）はクォートで囲む。純粋な数値型（integer、numeric）はそのまま書く。

逆のパターン：integer列に小数を渡す

-- qtr は integer 型
WHERE qtr = 1      -- ⭕ 正しい
WHERE qtr = 1.0    -- ❌ 1.0 は整数ではない
⚠️ WHEREを書くときの鉄則：条件の左側（列）のデータ型と、右側（値）のデータ型を必ず一致させること。うまくいかないときは、まず列のデータ型を確認する習慣をつけましょう。「自分が扱っているデータが何型なのか」を意識することが、SQLでは決定的に重要です。
🍎 かんたん説明

エラーが出たら型を疑う。money型は'3000'のようにクォートで囲む必要があります（$記号を含む型だから）。
