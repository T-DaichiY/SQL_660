M6 · Subqueries Part 3 — Problem-Solving Strategy

🧭 サブクエリ③：問題の解き方

このページは新しい構文の話ではありません。どんな複雑なサブクエリの問題にも通用する「解き方の手順」を扱います。いきなり完成形を書こうとせず、まず欲しい値を仮の数字で決め打ちして動作を確認し、それをサブクエリに置き換えていく——この積み上げ方さえ身につければ、初見の問題でも詰まらずに進められます。

① 欲しい値を仮の数字で② 仮の数字をサブクエリに③ 同じ都市の顧客④ 支店の最低残高⑤ ある地域の全支店で融資📝 Quiz
①

まず「欲しい値」を仮の数字で書いてみる

いきなり1本のクエリで完成させようとしない

複雑な問題を見たとき、多くの人はいきなり最終形のSQLを一発で書こうとして混乱します。うまくいく人は逆で、「結局どんな値でこの行を絞り込みたいのか」を先に日本語（英語）で言葉にし、その値を実際の数字や文字列に置き換えてから、外側のクエリを組み立てます。値が合っているかをその都度確認しながら進めるので、途中でどこが間違っているか必ず分かります。

例えば「支店の最小残高より多い口座を探したい」なら、最小残高そのものを先に計算して数字を確認します（38656のような具体的な値）。それを確認できたら、その数字をそのままWHERE句にハードコード（決め打ち）して、外側のクエリ全体が正しく動くかをテストします。

複雑なクエリを組み立てる4ステップ
🗣️
1. 欲しい結果を言葉にする「支店の最小残高より多い口座」のように、何を絞り込みたいかを明確にする
↓
🔢
2. 必要な値を仮の数字でハードコードして試す最小残高を別クエリで先に計算し、その数字（例：38656）をWHEREに直接書いて動かす
↓
🔁
3. その数字を計算するサブクエリに置き換えるハードコードした38656を、それを計算する(SELECT ...)に丸ごと入れ替える
↓
✅
4. 動作確認置き換え後も同じ件数・同じ結果になるかを確認する。件数が大きく変わったら要注意
一気に書かず、1ステップごとに実行して確認する——これがサブクエリを崩さず組み立てるコツ。
📌 一度にすべてを書こうとすると、どこが間違っているか分からなくなります。ハードコードした状態で外側のクエリが正しく動くことを先に確認しておけば、あとはその数字をサブクエリに差し替えるだけの単純作業になります。
🍎 かんたん説明

いきなり完成形を書かない。まず欲しい数字を計算して確認し、それを一旦手で書き込んで（ハードコードして）外側のクエリを動かしてみる。それが第一歩です。

💻 ミニ練習：欲しい値をまず単独で確認する

「支店の最小残高より多い口座」を求める前段階として、ステップ1を実践してみましょう。accountテーブル全体の最小残高（MIN）を、口座の一覧ではなく1つの数値だけとして返すSQLを書いてください。

SELECT MIN(balance) FROM account;

まずこの1件だけの数値を確認するのが第一歩。この数字が分かって初めて、次のステップでWHERE句にハードコードできます。

②

仮の数字をサブクエリに置き換える

動作確認済みの値を(SELECT ...)に差し替えるだけ

ハードコードした状態で外側のクエリが正しく動くことを確認できたら、次はその数字を計算していた小さなクエリを、単独で実行して単一の値（スカラー値）を返すことを確認します。そのうえで、ハードコードしていた数字の位置に、その小さなクエリを丸ごとカッコで囲んで差し込みます。

下の2つを見比べてください。左は「値を先に調べて、数字を直接書いた」バージョン、右は「その数字を計算するサブクエリに置き換えた」最終バージョンです。WHERE句の形はほとんど変わっていません——数字だった部分が(SELECT ...)に変わっただけです。

▶ ステップ2：まず仮の数字でハードコードして試す

-- ① 先に単独で最小残高を調べる → 500だったとする
SELECT account_number, branch_name, balance
FROM account
WHERE balance > 500;

▶ ステップ3：仮の数字をサブクエリに置き換えた最終版

SELECT account_number, branch_name, balance
FROM account
WHERE balance > (
    SELECT MIN(balance) FROM account
);
⚠️ 置き換えたら必ず件数を見比べましょう。サブクエリが1行1列（スカラー値）を返しているつもりでも、条件を間違えると複数行が返り、思わぬ掛け算（デカルト積）のような結果になってしまうことがあります。ハードコード版と同じ件数・同じ行が返ってくることを確認するまでは完成ではありません。
🍎 かんたん説明

ハードコードした数字を消して、代わりにその数字を計算する(SELECT ...)を丸ごと入れる。それだけで「決め打ちのクエリ」が「データが変わっても自動で追従するクエリ」になります。

💻 ミニ練習：平均残高より多い口座の顧客

「まず仮の数字でハードコード→サブクエリに置き換える」手順で、accountテーブルの平均残高（AVG）より多い残高を持つ口座のaccount_number・branch_name・balanceを求めるSQLを書いてください。

SELECT account_number, branch_name, balance
FROM account
WHERE balance > (
    SELECT AVG(balance) FROM account
);

まずSELECT AVG(balance) FROM account;だけを単独で実行して数字を確認し、その値をハードコードしてから(SELECT ...)に置き換えるのがこのページの手順です。

③

実例①：同じ都市に住む別の顧客を探す

customer_cityを自分自身のテーブルから引く

問題：「顧客10001と同じ都市に住んでいる、他の顧客を全員探したい（本人は除く）」。手順どおりに進めます。

▶ ステップ1：まず欲しい値（この顧客の街）だけを単独で確認する

SELECT customer_city
FROM customer
WHERE customer_id = '10001';
-- → 'Bronx' が1件だけ返る（単一値なのでスカラーOK）

▶ ステップ2〜3：'Bronx'でハードコードして確認 → サブクエリに置き換える

SELECT customer_id, customer_name, customer_street
FROM customer
WHERE customer_city = (
    SELECT customer_city FROM customer WHERE customer_id = '10001'
)
AND customer_id <> '10001'
ORDER BY customer_name;
customer_id | customer_name | customer_street ------------+----------------+------------------ 10024 | Hank Irwin | River Ave 10039 | Maria Chen | Grand Concourse 10052 | ... | ...
📌 AND customer_id <> '10001'を忘れると本人も結果に混じります。「自分自身と同じ都市」を探す問題では、自分自身をどこかで除外する条件が必要になることが多いので、要件を読むときに意識しておきましょう。
🍎 かんたん説明

まず対象の顧客が住んでいる街を1件だけ調べ、それを使って「同じ街に住んでいる人」を探す。本人を除くのを忘れないこと。

💻 ミニ練習：Johnsonと同じ都市に住む顧客

customer_name = 'Johnson'の顧客と同じ都市に住んでいる、他の顧客（Johnson本人は除く）のcustomer_id・customer_nameを求めるSQLを書いてください。列サブクエリと本人除外の条件を使います。

SELECT customer_id, customer_name
FROM customer
WHERE customer_city = (
    SELECT customer_city FROM customer WHERE customer_name = 'Johnson'
)
AND customer_name <> 'Johnson';

このユニットの「同じ都市の顧客」と同じパターンです。本人を除外するAND customer_name <> 'Johnson'を忘れないでください。

④

実例②：支店の最低残高を超える預金を探す

JOINとサブクエリを組み合わせる

問題：「Brooklyn Bank支店に口座を持ち、その支店内の最小残高より多い残高を持つ顧客の、口座番号・顧客名・支店名を求めたい」。account・depositor・customerのJOINと、支店の最小残高を求めるスカラーサブクエリの両方が必要です。

▶ ステップ1：欲しい値（Brooklyn Bankの最小残高）を単独で確認

SELECT MIN(balance)
FROM account
WHERE branch_name = 'Brooklyn Bank';
-- → 38656 が1件だけ返る

▶ ステップ2〜3：38656でハードコードして確認 → サブクエリに置き換える

SELECT a.account_number, c.customer_name, a.branch_name
FROM account a
JOIN depositor d ON a.account_number = d.account_number
JOIN customer c ON d.customer_id = c.customer_id
WHERE a.branch_name = 'Brooklyn Bank'
AND a.balance > (
    SELECT MIN(balance) FROM account WHERE branch_name = 'Brooklyn Bank'
);
account_number | customer_name | branch_name ----------------+----------------+--------------- A-217 | Hank Irwin | Brooklyn Bank A-305 | Maria Chen | Brooklyn Bank ...
⚠️ ハードコードだけの段階で件数を必ず確認しましょう。「Brooklyn Bankの全員」を出すクエリより、「最小残高を超える人」に絞ったクエリのほうが必ず件数が少なくなるはずです。もし増えていたら、JOINの条件かWHEREの条件のどこかが間違っています。
📌 この例のように「外側のWHEREと同じ絞り込み条件（branch_name = 'Brooklyn Bank'）」をサブクエリの中にも書く必要があることがあります。そうしないと、サブクエリが「その支店の最小残高」ではなく「全支店の中の最小残高」を返してしまい、意味が変わってしまいます。
🍎 かんたん説明

JOINで必要なテーブルをつなげ、WHEREでその支店に絞り、さらに「その支店の最小残高」をサブクエリで計算して比較する。JOINとサブクエリは同時に使ってよい。

💻 ミニ練習：Midtown Bank支店の最低残高を超える預金者

「Midtown Bank支店に口座を持ち、その支店内の最小残高より多い残高を持つ顧客の、口座番号・顧客名・支店名を求めたい」。account・depositor・customerをJOINし、支店の最小残高を求めるスカラーサブクエリを使うSQLを書いてください。

SELECT a.account_number, c.customer_name, a.branch_name
FROM account a
JOIN depositor d ON a.account_number = d.account_number
JOIN customer c ON d.customer_id = c.customer_id
WHERE a.branch_name = 'Midtown Bank'
AND a.balance > (
    SELECT MIN(balance) FROM account WHERE branch_name = 'Midtown Bank'
);

サブクエリの中にもWHERE branch_name = 'Midtown Bank'を書かないと、「全支店の中の最小残高」になってしまい意味が変わります。

⑤

実例③：ある地域のすべての支店で融資を受けている顧客

HAVING COUNT(DISTINCT ...) = (SELECT COUNT(*) ...)

問題：「Brooklynという都市にあるすべての支店で、少なくとも1件ずつローンを組んでいる顧客を探したい」。branch_city = 'Brooklyn'の支店が何件あるかをまず確認し、それと同じ数だけ異なるBrooklyn支店でローンを持っている顧客を探します。

▶ ステップ1：欲しい値（Brooklynにある支店の数）を単独で確認

SELECT COUNT(*)
FROM branch
WHERE branch_city = 'Brooklyn';
-- → 2 が1件だけ返る（例：Brooklyn Bank, Brooklyn Bridge Bank）

▶ ステップ2〜3：2でハードコードして確認 → サブクエリに置き換える

SELECT br.customer_id
FROM borrower br
JOIN loan l ON br.loan_number = l.loan_number
WHERE l.branch_name IN (
    SELECT branch_name FROM branch WHERE branch_city = 'Brooklyn'
)
GROUP BY br.customer_id
HAVING COUNT(DISTINCT l.branch_name) = (
    SELECT COUNT(*) FROM branch WHERE branch_city = 'Brooklyn'
);
customer_id ------------ 10048 10098
📌 なぜCOUNT(DISTINCT branch_name)で、ただのCOUNT(branch_name)ではダメなのか？同じ顧客が同じBrooklyn支店で2件のローンを組んでいる可能性があります。単純なCOUNTだとそれを2件と数えてしまい、実際には1支店にしか融資がないのに「Brooklynの全支店で融資がある」と誤判定してしまいます。DISTINCTを付けることで「支店の種類の数」を正しく数えられます。
📌 右辺を2と決め打ちせず(SELECT COUNT(*) FROM branch WHERE branch_city = 'Brooklyn')にしておく理由。今後Brooklynに支店が増えたり減ったりしても、このクエリはコードを書き換えることなく正しい件数と自動的に比較してくれます。決め打ちの数字は、データが変わった瞬間に古い基準のままになってしまいます。
🍎 かんたん説明

「ある地域の全支店で」という条件は、HAVING COUNT(DISTINCT 支店名) = その地域の支店数、という形にする。DISTINCTで二重カウントを防ぎ、支店数もサブクエリで計算しておけば、データが変わっても壊れません。

💻 ミニ練習：2支店を超えるローンを持つ顧客

borrowerとloanをJOINし、3つ以上の異なる支店でローンを組んでいる顧客のcustomer_idを求めるSQLを書いてください。このユニットの「Brooklynの全支店で融資」と同じHAVING COUNT(DISTINCT ...)のパターンを使います。

SELECT br.customer_id
FROM borrower br
JOIN loan l ON br.loan_number = l.loan_number
GROUP BY br.customer_id
HAVING COUNT(DISTINCT l.branch_name) > 2;

COUNT(DISTINCT branch_name)を使うことで、同じ支店で複数ローンを組んでいても二重カウントされません。

📖 用語集

incremental query building
段階的なクエリ構築
一気に完成形を書かず、値の確認→ハードコード→サブクエリ化、と一段ずつテストしながら組み立てる進め方。
hardcoding
決め打ち・ハードコード
計算で求めるべき値を、確認のために一時的に具体的な数字や文字列として直接書き込むこと。
scalar subquery
スカラーサブクエリ
1行1列＝単一の値だけを返すサブクエリ。WHEREの比較にそのまま使える。
HAVING
ハビング句
GROUP BYでまとめた後の集約結果（COUNTなど）を条件で絞り込む句。集約値の比較にはWHEREではなくHAVINGを使う。
COUNT(DISTINCT ...)
重複を除いた件数
同じ値の重複を1件として数える集計。同じ支店への複数ローンを二重カウントしないために使う。
self-referencing subquery
自己参照サブクエリ
同じテーブルに対して、別の行の値（例：他の顧客の都市）を調べるために発行するサブクエリ。

💡 学習のヒント

詰まったら、まず外側のクエリを「サブクエリ抜き・仮の数字」で動かしてみましょう。動けば半分終わったも同然。あとはその数字を(SELECT ...)に置き換えるだけです。
