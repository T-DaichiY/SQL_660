M4 · Sum

➕ SUM — 合計を求める

単独で全体の合計、WHEREと組み合わせて条件付きの合計、COUNTと並べればもっと深い情報が見えてくる。

① SUM単独② WHEREと組み合わせる③ 集計関数を並べる📝 Quiz
①

SUM単独 — GROUP BYが要らないケース

全体を1つの数字にまとめる

SUM()は他の集計関数と同じくシンプルです。ordersテーブルの注文金額の総額を求めてみます。

SELECT SUM(ord_amount)
FROM orders;
sum ------- 72600

テーブルにある全注文の合計は72,600でした。

📌 ここではGROUP BYが不要です。集計関数と一緒に非集計の列を書いていないからです。「全体で1つの値」を求めるだけなら、GROUP BYは要りません。GROUP BYが必須になるのは、SELECT customer_code, SUM(...)のようにグループの見出しになる列を並べたときです。
🍎 かんたん説明

SELECT SUM(列) FROM テーブル;だけで全体の合計が出ます。内訳が欲しいときにGROUP BYを足します。

②

WHEREと組み合わせる

条件を満たす行だけを合計する

「1,000ドル未満の注文だけの合計」を知りたい場合は、WHEREを足します。

SELECT SUM(ord_amount)
FROM orders
WHERE ord_amount < 1000;
sum ------ 4700
WHEREは集計の「前」に効く
全34件
合計 72,600
→
WHERE で絞る
1,000未満のみ
→
SUM で合計
4,700
まず行を絞り、残った行だけを合計する。

全体の72,600に対して、小口注文の合計はわずか4,700。売上の大部分が大口注文から来ていることが読み取れます。

💡 WHEREは集計前のフィルタです。ord_amountという普通の列で絞っているので、問題なく動きます。もし「合計が◯◯以上のグループだけ」のように集計結果で絞りたい場合は、WHEREではなくHAVINGを使います（次のレッスン）。
🍎 かんたん説明

SUMにWHEREを足せば「条件付きの合計」。絞ってから足す、という順番です。

③

集計関数は並べて書ける

合計と件数を同時に出す

「1,000ドル未満の注文は、合計いくらで、何件あるのか？」——両方知りたければ、集計関数を並べて書くだけです。

SELECT SUM(ord_amount), COUNT(ord_amount)
FROM orders
WHERE ord_amount < 1000;
sum | count -----+------- 4700 | 8
📌 ここから読み取れること：全34件の注文のうち8件が1,000ドル未満で、その合計が4,700。つまり注文の約4分の1が小口で、金額ベースでは全体の6%程度にすぎない——複数の集計値を並べると、単独では見えない意味が出てきます。

さらに掘り下げるならGROUP BY

-- 顧客ごとの小口注文の合計と件数
SELECT customer_code,
       SUM(ord_amount) AS total,
       COUNT(ord_amount) AS orders
FROM orders
WHERE ord_amount < 1000
GROUP BY customer_code
ORDER BY total DESC;

顧客コード・担当者コード・日付など、どの列でもグループ化できます。組み合わせ次第で、いくらでも細かい分析ができます。

✍️ ここではcustomer_codeという非集計列を書いたので、GROUP BYが必須になっている点に注目してください。Unit①でGROUP BYが不要だった理由と表裏一体です。
🍎 かんたん説明

SUMとCOUNTは同時に書けます。「いくらで、何件か」を並べると、データの意味がぐっと分かりやすくなります。

SUM()
合計

COUNT()
件数
対象となる行の数を数える集計関数。SUMと並べると解釈が深まる。
GROUP BYが不要な場合
全体集計
非集計の列を選んでいないとき。全体を1つの値にまとめる。
WHERE と集計
集計前のフィルタ
WHEREは集計の前に行を絞る。集計結果での絞り込みはHAVING。

💡 学習のヒント

SUMだけでは「多いのか少ないのか」が判断できません。COUNTを並べて「1件あたりいくらか」を掴む癖をつけると、数字の解釈が一段深くなります。
