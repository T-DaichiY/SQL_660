🧹 データ整形②：ALTER・UPDATEでクリーニング

ここからはデータ整形の実践に入ります。前のレッスンで表の状態を調べたら、次は直す番です。ALTERとUPDATEの違いを整理し、バックアップを取ってから職種名の表記ゆれを直し、会社名にくっついた評価を取り除き、-1を本物のNULLに置き換えます。M3〜M4で学んだWHERE・LIKE・GROUP BY・COUNTがそのまま検査の道具になります。

①

ALTER TABLE と UPDATE の違い

構造を変えるのがALTER、データを変えるのがUPDATE

データを整えるときに使う2つの命令は、名前が似ていますが変えるものがまったく違います。ALTER TABLEは表の構造（列の追加・名前変更・データ型・NOT NULL制約）を変え、UPDATEは表に入っているデータ（値そのもの）を変えます。M1〜M2で学んだCREATE TABLEで作った「入れ物」を後から作り替えるのがALTER、入れ物の中身を書き換えるのがUPDATEです。

📝 この教材の練習用データ（30行）は講義で使ったKaggleのデータを模した架空のサンプルです。講義のデータは672行ですが、ここではds_jobsテーブル（30行）を使い、実際に表示される件数で説明します。

ALTER TABLEUPDATE
変えるもの表の構造（列・型・制約）行のデータ（値）
例列を追加する／型を変える／NOT NULLを付ける'Sr.'を'Senior'に直す／-1をNULLにする
影響する行表全体（すべての行が対象）WHEREで選んだ行（省略すると全行）
考えることどの列を、どう変えるか「どんな値にするか（SET）」と「どの行か（WHERE）」

構文の骨組みを並べます。まず構造を変えるALTER TABLEです（列を削除するDROP COLUMNは次のレッスンで扱います）。

ALTER TABLE t ADD COLUMN c type;
ALTER TABLE t ALTER COLUMN c SET DATA TYPE type;
ALTER TABLE t ALTER COLUMN c SET NOT NULL;
ALTER TABLE t ALTER COLUMN c DROP NOT NULL;

次にデータを書き換えるUPDATEです。WHEREは省略できますが、その意味は大きく変わります。

UPDATE t SET c = value;              -- WHEREなし：全行が変わる
UPDATE t SET c = value WHERE cond;   -- 条件に合う行だけが変わる

実例として、まずds_jobsに「整形済みか」を記録するための空の列を追加してみます。追加直後の新しい列は、全30行がNULLです。

ALTER TABLE ds_jobs ADD COLUMN cleaned_at TEXT;
name | type -----------+------ cleaned_at | TEXT (1 row)
UPDATEを書くときに考える2つのこと
🎯
SET：どんな値にするか例：SET job_title = 'Senior Data Scientist'
↓
🔍
WHERE：どの行を変えるか例：WHERE job_title = 'Sr. Data Scientist'
↓
✅
実行前にSELECTで確認同じWHEREでSELECTして、対象の行数をチェックする
SETは「何に」、WHEREは「どこを」。この2つを分けて考えるとミスが減る。
⚠️ WHEREのないUPDATEは、表のすべての行を書き換えます。たとえばUPDATE ds_jobs SET rating = 0;を実行すると、30行すべてのratingが0になります。実際に確認するには、次のようにBEGINで取引を始め、確認したらROLLBACKで取り消します（取引の詳細は次のレッスンで学びます）。
BEGIN;
UPDATE ds_jobs SET rating = 0;
SELECT COUNT(*) AS n, MIN(rating) AS mn, MAX(rating) AS mx FROM ds_jobs;
ROLLBACK;
n | mn | mx ---+----+---- 30 | 0 | 0 (1 row)

30行すべてが0になっているのが分かります。ROLLBACKしたので、実際のデータは元どおり（最小-1・最大4.6）です。この失敗はバックアップなしでは取り返しがつかないので、次の単元でバックアップを先に取る習慣を学びます。

🍎 かんたん説明

ALTERは「入れ物」を作り替える、UPDATEは「中身」を書き換える。UPDATEはSET（何にする）とWHERE（どの行）をセットで考え、WHEREを忘れると全行が変わります。

💻 ミニ練習：列を追加する

ds_jobsテーブルに、TEXT型の新しい列cleaned_noteを追加するSQLを書いてください。

ALTER TABLE ds_jobs ADD COLUMN cleaned_note TEXT;

ALTER TABLE 表名 ADD COLUMN 列名 型が基本形。既存の30行の新しい列はすべてNULLになります。

②

バックアップを取って job_title を整える

CREATE TABLE ... AS SELECT → UPDATE + REPLACE

データを書き換える前に、必ずバックアップ（複製テーブル）を取ります。UPDATEは元に戻す「取り消し」ボタンがありません（COMMIT後は特に）。教科書（第10章）でも、先にコピーを作ってからUPDATEすることが勧められています。CREATE TABLE ... AS SELECTを使うと、1行でコピーできます。

CREATE TABLE ds_jobs_backup AS
SELECT * FROM ds_jobs;

SELECT COUNT(*) AS n FROM ds_jobs_backup;
n ---- 30 (1 row)

30行ちゃんとコピーされました。件数の確認までがバックアップの手順です。次に、直したいjob_titleの状態をGROUP BY（M4）で確認します。

SELECT job_title, COUNT(*) AS n
FROM ds_jobs
GROUP BY job_title
ORDER BY job_title;
job_title | n ------------------------------+--- Business Intelligence Analyst | 3 Data Analyst | 4 Data Engineer | 3 Data Scientist | 6 Machine Learning Engineer | 3 Research Scientist | 2 Senior Data Scientist | 3 Senior. Data Scientist - | 2 Sr Data Scientist | 2 Sr. Data Scientist | 2 (10 rows)

本来同じ「シニア・データサイエンティスト」のはずの職種が、4つの表記に分かれています（3＋2＋2＋2＝9行）。これを1つにまとめます。

手順①：変な表記を完全一致で直す。'Senior. Data Scientist -'（post_id 15, 28の2行）は、ほかのパターンと共通部分がないので、まず完全一致のWHEREで直します。LIKE 'Senior%'のように広く書くと、すでに正しい'Senior Data Scientist'の行まで巻き込むので避けます。

UPDATE ds_jobs
SET job_title = 'Senior Data Scientist'
WHERE job_title = 'Senior. Data Scientist -';
UPDATE 2 post_id | job_title --------+---------------------- 15 | Senior Data Scientist 28 | Senior Data Scientist

手順②：REPLACEで'Sr.'を直す。REPLACE(文字列, 探す文字, 置き換える文字)は、文字列の中の一部だけを置き換える関数です。WHEREなしでも、'Sr.'を含まない行はそのまま変わりません（ただし行としては「更新」扱いになります）。

UPDATE ds_jobs
SET job_title = REPLACE(job_title, 'Sr.', 'Senior');
post_id | job_title --------+---------------------- 5 | Senior Data Scientist (Sr. → Senior) 19 | Senior Data Scientist (Sr. → Senior) 9 | Sr Data Scientist (まだ) 23 | Sr Data Scientist (まだ)

手順③：ピリオドなしの'Sr'を直す。これで残りの2行（post_id 9, 23）が直ります。

UPDATE ds_jobs
SET job_title = REPLACE(job_title, 'Sr', 'Senior');
⚠️ 順番のワナ：必ず'Sr.'（ピリオド付き）を先に置き換えます。もしREPLACE(job_title, 'Sr', 'Senior')を先に実行すると、'Sr. Data Scientist'は'Senior. Data Scientist'になり、ピリオドが残ってしまいます（post_id 5, 19が'Senior. Data Scientist'になる）。長くて具体的なパターンから先に処理する、と覚えましょう。

直したあと、もう一度GROUP BYで確認します。変更前と変更後を同じクエリで比べるのが、クリーニングの基本チェックです。

job_title | n ------------------------------+--- Business Intelligence Analyst | 3 Data Analyst | 4 Data Engineer | 3 Data Scientist | 6 Machine Learning Engineer | 3 Research Scientist | 2 Senior Data Scientist | 9 (7 rows)

10種類あった表記が7種類になり、'Senior Data Scientist'は9行（3＋2＋2＋2）にまとまりました。

📌 失敗したらバックアップから戻せます。たとえばjob_titleだけ元に戻したいときは、UPDATE ds_jobs SET job_title = b.job_title FROM ds_jobs_backup AS b WHERE ds_jobs.post_id = b.post_id;のように、主キー（post_id）で対応させて値をコピーし直します。表ごと戻すならDROP TABLE ds_jobs;してからバックアップをコピーし直す方法もあります。

💡 PostgreSQLのUPDATE ... FROMは、この演習アリーナでもそのまま動きます。

🍎 かんたん説明

まずバックアップ（CREATE TABLE ... AS SELECT）。次に、変な表記→'Sr.'→'Sr'の順で直し、GROUP BYで確認します。最終的に'Senior Data Scientist'は9行になります。

💻 ミニ練習：REPLACEでjob_titleを直す

ds_jobsテーブルで、job_titleに含まれる'Sr.'を'Senior'に置き換えるUPDATE文を書いてください（post_id 5, 19の2行が変わります）。

UPDATE ds_jobs
SET job_title = REPLACE(job_title, 'Sr.', 'Senior');

REPLACE(列, 探す文字, 置き換える文字)をSETの右辺に書きます。'Sr.'が含まれない行は変化しません。

③

会社名の末尾についた評価を取り除く

SUBSTRING・LENGTH・RIGHT と LIKE のワイルドカード

会社名（company）の末尾に、評価が貼り付いています（例：Bluepeak Studios4.4）。これはratingの値が3文字（4.4）として会社名に混ざったものです。ratingが-1でない25行がこの状態で、評価が-1の5行はOpen Door Healthのようにきれいな名前のままです。

取り除くには「末尾3文字を切り落として、残りを取り出す」と考えます。使う関数は3つです。

関数働き例
LENGTH(x)文字数を返すLENGTH('Bluepeak Studios4.4') → 19
SUBSTRING(x, 開始, 長さ)開始位置から指定の長さを取り出す（位置は1から数える）SUBSTRING('Bluepeak Studios4.4', 1, 16) → 'Bluepeak Studios'
RIGHT(x, n)右端からn文字を取り出すRIGHT('Bluepeak Studios4.4', 3) → '4.4'

つまり「先頭から（全体の長さ−3）文字」を取れば評価が消えます：SUBSTRING(company, 1, LENGTH(company) - 3)。プログラミング言語のように0から数えるのではなく、SQLの位置は1始まりな点に注意しましょう。

ただし、5行のきれいな名前まで3文字削ると壊れてしまいます。そこで「どの行に適用するか」をWHEREで絞ります。条件は「右端3文字が数字・ドット・数字の形か」。M3で習ったLIKEのワイルドカードを使います：_は任意の1文字、%は任意の0文字以上です。'_._'は「何か1文字、ドット、何か1文字」の3文字に一致します。

UPDATEの前に、必ず同じWHEREでSELECTしてプレビューします。

SELECT post_id, company,
       SUBSTRING(company, 1, LENGTH(company) - 3) AS cleaned
FROM ds_jobs
WHERE RIGHT(company, 3) LIKE '_._'
ORDER BY post_id
LIMIT 6;
post_id | company | cleaned --------+---------------------------+------------------------ 1 | Bluepeak Studios4.4 | Bluepeak Studios 2 | Ironwood Consulting3.9 | Ironwood Consulting 3 | Novaline Pharma3.6 | Novaline Pharma 5 | Pacific Grid Laboratory4.1| Pacific Grid Laboratory 6 | District 94.2 | District 9 7 | 23Genomics3.8 | 23Genomics (6 rows。WHEREに一致するのは全部で25行)

プレビューは良さそうです。特にDistrict 94.2は、末尾3文字が4.2なのでDistrict 9になります（社名の数字9は残る）。23Genomics3.8も先頭の23は残ります。一致するのは25行です。ではWHEREを付けなかった場合、きれいな5行はどうなるか見てみましょう（SELECTなので安全です）。

post_id | company | wrong --------+---------------------+------------------ 4 | Open Door Health | Open Door Hea 11 | Brightside Labs | Brightside L 18 | Harbor Analytics | Harbor Analyt 25 | Riverbend Institute | Riverbend Instit 29 | Cedar Health | Cedar Hea (5 rows)
⚠️ このWHERE RIGHT(company, 3) LIKE '_._'は省略できません。省略すると、評価が付いていない5行の会社名も末尾3文字が削られてOpen Door Heaのように壊れます。UPDATEの前に、同じWHEREを付けたSELECTで対象行を目で確認する習慣をつけましょう。
UPDATE ds_jobs
SET company = SUBSTRING(company, 1, LENGTH(company) - 3)
WHERE RIGHT(company, 3) LIKE '_._';
UPDATE 25

「UPDATE 25」と表示され、想定どおり25行が更新されました。行数が予想と違ったら、すぐ原因を調べます（バックアップがあるので戻せます）。確認として、GROUP BY companyを実行すると、きれいな社名ごとにまとまって表示されます。

SELECT post_id, company
FROM ds_jobs
WHERE post_id IN (1, 4, 6, 7)
ORDER BY post_id;
post_id | company --------+-------------------- 1 | Bluepeak Studios 4 | Open Door Health 6 | District 9 7 | 23Genomics (4 rows)
📌 このパターン'_._'は「数字・ドット・数字」を想定した簡易な条件です。今回の評価は2.9〜4.6の形なので有効ですが、一般には_は数字以外の文字にも一致します。より厳密にしたいときは、次のレッスンで学ぶ正規表現（~ '\d\.\d$'）を使います。

🎤 講義では、この条件をILIKE（大文字小文字を区別しないLIKE）で書き、右端3文字が「何か・ドット・何か」の形かを確かめていました（%で前後に何が来てもよいことを表す書き方）。ここでは同じ働きのLIKE '_._'を使っています。数字とドットの形だけを見る点は同じです。

💡 PostgreSQLのLIKEは大文字小文字を区別しますが、この演習アリーナ（SQLite）では区別しません。この課題の'_._'には影響しません。

🍎 かんたん説明

会社名の末尾3文字（評価）を切り落とすにはSUBSTRING(名前, 1, LENGTH(名前) - 3)。ただし評価が付いていない行を壊さないよう、WHERE RIGHT(名前, 3) LIKE '_._'で対象の25行だけに絞ります。

💻 ミニ練習：会社名から評価を取り除く

ds_jobsのcompanyから末尾3文字の評価を取り除くUPDATE文を書いてください。ただし末尾3文字が_._の形（例：4.4）の行だけが対象です（25行）。

UPDATE ds_jobs
SET company = SUBSTRING(company, 1, LENGTH(company) - 3)
WHERE RIGHT(company, 3) LIKE '_._';

WHEREを忘れると、評価の付いていない5行の会社名まで3文字削られてしまいます。

④

-1 を本物の NULL に置き換える

番兵値（sentinel）を NULL にして集計を正しくする

CSVから取り込んだデータには、「値がない」ことを-1や'Unknown'のようなふつうの値で表している列があります（番兵値＝sentinel value）。SQLは-1を本物のデータだと思って計算するので、平均や件数がゆがみます。これを本物のNULL（M3・M4で学んだ「値なし」）に置き換えるのが、クリーニングの大事な仕事です。

列番兵値行数書き方
competitors（TEXT）文字列の'-1'13行WHERE competitors = '-1'（引用符あり）
rating（REAL）数値の-15行WHERE rating = -1（引用符なし）
headquarter（TEXT）'-1'2行WHERE headquarter = '-1'
revenue（TEXT）'Unknown / Non-Applicable'5行文字列で比較
⚠️ 列の型に合わせて引用符を使い分けます。competitorsはTEXT列なので、番兵は文字列の'-1'です。PostgreSQLでWHERE competitors = -1と書くと型が合わずエラーになります。逆にratingは数値列なので= -1（引用符なし）と書きます。

まず変更前の状態を、COUNT(*)とCOUNT(列)の違いで確認します。COUNT(列)はNULLを数えないので、番兵値のままだと「-1の行」も数えられてしまいます。

SELECT COUNT(*) AS total, COUNT(rating) AS c_rating,
       COUNT(competitors) AS c_comp, ROUND(AVG(rating), 2) AS avg_rating
FROM ds_jobs;
total | c_rating | c_comp | avg_rating ------+----------+--------+----------- 30 | 30 | 30 | 3.05 (1 row)

-1の行も数えるのでCOUNT(rating)は30、平均評価は3.05に下がってしまっています（-1が5行混ざっているため）。ではNULLに変えます。

UPDATE ds_jobs SET competitors = NULL WHERE competitors = '-1';
UPDATE ds_jobs SET rating = NULL WHERE rating = -1;
UPDATE ds_jobs SET headquarter = NULL WHERE headquarter = '-1';
UPDATE 13 (competitors) UPDATE 5 (rating: post_id 4, 11, 18, 25, 29) UPDATE 2 (headquarter: post_id 11, 18)
SELECT COUNT(*) AS total, COUNT(rating) AS c_rating,
       COUNT(competitors) AS c_comp, ROUND(AVG(rating), 2) AS avg_rating
FROM ds_jobs;
total | c_rating | c_comp | avg_rating ------+----------+--------+----------- 30 | 25 | 17 | 3.86 (1 row)

COUNT(rating)が30→25、COUNT(competitors)が30→17に減り、COUNT(*)は30のままです。この違いこそが、NULLに変わった証拠です。平均評価も3.05から本来の3.86になりました。番兵値をNULLにしないと、AVGやMINなどの集計がゆがむ理由がよく分かります。

別解：NULLIF。NULLIF(列, '-1')は「列が'-1'ならNULL、そうでなければ元の値」を返す関数です。UPDATEをコンパクトに書けます。

UPDATE ds_jobs
SET competitors = NULLIF(competitors, '-1');

WHERE付きのUPDATE ... = NULLと結果は同じです。なおrevenueの'Unknown / Non-Applicable'（5行）も、同じ考え方でNULLIF(revenue, 'Unknown / Non-Applicable')によりNULLにできます。

📌 NULLの判定は= NULLではなくIS NULL。UPDATEで「値をNULLにする」ときはSET col = NULLで正しいのですが、「NULLの行を探す」ときはM3で学んだとおりWHERE col IS NULLを使います。
🍎 かんたん説明

「-1」や「Unknown」は本物のデータではなく「値がない」の代わりです。UPDATE ... SET 列 = NULL WHERE 列 = '-1'で本物のNULLにすると、COUNT(列)やAVGが正しい結果になります。TEXT列は'-1'、数値列は-1です。

💻 ミニ練習：-1をNULLに置き換える

ds_jobsのcompetitors列で、値が文字列'-1'の行（13行）をNULLに更新するUPDATE文を書いてください。

UPDATE ds_jobs
SET competitors = NULL
WHERE competitors = '-1';

competitorsはTEXT列なので'-1'と引用符を付けます。SET competitors = NULLIF(competitors, '-1')でも同じ結果になります。
