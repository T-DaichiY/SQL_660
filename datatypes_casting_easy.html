🍎 超やさしい版：CASTによる型変換

CAST(列 AS 型) か 列::型 で、その場だけ型を付け替える。テーブル自体は変わらない！

一言でいうと2つの書き方失敗するとき🔄 本編はこちら
⚡

一言でいうと

その場限りの型変換

🎯 これだけ覚えればOK

CAST(列 AS 型)で、クエリ結果の値だけを別の型に変換できる。テーブルの実データは変わらない。あくまで応急処置——最初から正しい型を選ぶのがベスト。

▶ 文字列のZIPコードを整数に変換する

SELECT CAST(zip_code AS integer) - 10 AS adjusted
FROM customers;
adjusted -------- 30290
🍎 ひとことで

CASTは「その結果だけ、別の型として見せる」機能。テーブルの中身自体は書き換わりません。

①

2つの書き方

CAST(列 AS 型) と 列::型

📘 標準構文

CAST(zip_code AS integer)

⚡ 短縮構文

zip_code::integer

どちらも結果は全く同じ。会社やチームのルールに従って選べばOKです。

🍎 ひとことで

「CAST(列 AS 型)」でも「列::型」でも同じ結果。書き方が2種類あるだけです。

②

CASTが失敗するとき

「データが型に収まるか」がすべて

▶ 文字が混ざった値をintegerに変換しようとすると…

SELECT CAST(code AS integer) FROM demo;
-- codeの値が 'A105' の場合
ERROR: invalid input syntax for type integer: "A105"
🧦
靴下と足の関係：データが変換先の型に「フィット」しなければCASTは失敗します。'A105'のような文字混じりの値はintegerに入りません。

🤔 答えられるかな？（クリックで答えが開く）

Q1. CASTを実行すると、テーブルの実データはどうなる？A. 変わらない。CASTはクエリ結果だけを一時的に変換する。
Q2. 'A105'をintegerにCASTするとどうなる？A. エラーになる（数字以外の文字が含まれているため）。
Q3. CASTを頻繁に使うのは良い習慣？A. いいえ。最初から正しいデータ型を選ぶべきで、CASTはやむを得ないときの応急処置。

💡 まとめ

• CASTはクエリ時点だけの一時的な型変換

• CAST(列 AS 型) と 列::型 は同じ結果

• データが型に収まらないとエラー

• 多用せず、最初から正しい型を選ぶのが基本
