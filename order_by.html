M3 · Sorting data with Order By

🔽 ORDER BY — 結果を並べ替える

ASC（昇順）とDESC（降順）、文の最後に置くルール、そして複数列で並べ替える「複合ソート」の落とし穴まで。

① ORDER BYとは② ASC と DESC③ 実例で練習④ 複合ソート📝 Quiz
①

ORDER BYとは — 絞り込みの次のステップ

列を選んだら、次は「どう並べるか」

SELECT文で列を絞り込んだら、次のステップは並べ替えです。ORDER BYは、取り出した結果を指定した列の順に整列させる句で、SELECT文の最後に置きます。

SELECT first_name, last_name
FROM student
ORDER BY last_name;
first_name | last_name -----------+---------- Kenji | Abe Mika | Baba ... | ... Yuto | Watanabe

読み方は英語の語順そのままです——「student テーブルから first_name と last_name を選び、last_name の順に並べよ」。SELECTで「何を」、FROMで「どこから」、ORDER BYで「どう並べるか」を答える、という構造になっています。

クエリの組み立ての流れ
SELECT
どの列？
→
FROM
どのテーブル？
→
ORDER BY
どう並べる？
広く選び → 場所を決め → 整理する。ORDER BYは常に最後尾。
📌 このレッスンではsalesテーブルを使います。まだインポートしていない場合は、M3 の最初のレッスン（データセットの取り込み）に戻ってください。この先ずっと使い続けるテーブルです。
🍎 かんたん説明

ORDER BYは「並べ替えの命令」。クエリの一番最後に ORDER BY 列名; と書くだけです。

②

ASC と DESC — 昇順と降順

ASCが既定値。DESCは必ず明示する
キーワード意味並び順指定
ASCascending（昇順）A → Z ／ 小 → 大既定値。省略しても同じ
DESCdescending（降順）Z → A ／ 大 → 小使うときは必ず書く

ascendは「上がる・増える」という意味です。リストを下にたどるほど値が大きくなっていく——それが昇順です。descendはその逆で、大きい値から小さい値へ下がっていきます。

昇順（既定）

SELECT customer FROM sales
ORDER BY customer ASC;
-- ASC は省略可。書いても意味は変わらない
customer ------------------------- Alpha Cognac Alpha Cognac Amica Models & Co. ...

ASCは書いても書かなくても結果は同じです。ただし「意図して昇順にした」ことを読み手に伝えるドキュメント目的で、あえて書くことはよくあります。

降順

SELECT customer FROM sales
ORDER BY customer DESC;
customer ------------------------- Vitachrome Inc. UK Collectables, Ltd. Toys of Finland, Co. ...
📌 日本語で考えてから訳すのがコツです。「アルファベット順に」＝ASC、「金額の高い順に」＝DESC、「item番号の大きいものから」＝DESC、「売れた個数の少ない順に」＝ASC。日本語の指示をASC/DESCに置き換える練習をしましょう。
🍎 かんたん説明

ASC＝小さい順（既定）、DESC＝大きい順。何も書かなければ必ずASCになります。

③

実例で練習する

salesテーブルで手を動かす

例1：MSRPの高い順に並べる

「顧客名・製品ライン・希望小売価格を、価格の高い順に表示せよ」

SELECT customer, product_line, msrp
FROM sales
ORDER BY msrp DESC;
customer | product_line | msrp ----------------------+--------------+------ Euro Shopping Channel | Classic Cars | 214 Mini Gifts Distr. | Classic Cars | 214 ... | ... | ...

DESCを外して実行すれば、逆に安いものから並びます。既定が昇順であることを自分の目で確かめてみてください。

例2：列の順番は「表示の順番」

⚠️ SELECTに列を書いた順番が、そのまま結果の列の並びになります。顧客ごとの購入品と価格を見たいなら、customer, product_line, msrpの順に書くべきで、product_line, customer, msrpでは顧客名が真ん中に埋もれて読みにくくなります。「欲しい情報が出ればいい」ではなく「論理的に読めるクエリ」を書くことを意識しましょう。

例3：* と ORDER BY は併用できる

SELECT * FROM sales
ORDER BY customer;

全列を取り出しながら並べ替えることもできます。ORDER BYで指定する列がSELECTのリストに含まれている必要は、必ずしもありません。

例4：四半期を第4→第1の順に

SELECT customer, sales, qtr
FROM sales
ORDER BY qtr DESC;
customer | sales | qtr --------------------+---------+---- Technics Stores Inc | 5404.6 | 4 Corporate Gift Ideas| 3227.9 | 4 ... (Q4 → Q3 → Q2 → Q1)
✍️ スタイルの話：1行に続けて書いても動きますが、SELECT／FROM／ORDER BYはそれぞれ改行するのが一般的です。読みやすく、句の切れ目もはっきりします。
🍎 かんたん説明

「〜順に」と言われたら、その基準になる列をORDER BYに書く。大きい順ならDESCを足す。それだけです。

④

複合ソート（compound ordering）

複数列で並べる——ASC/DESCは列ごとに指定する

「まず四半期の新しい順、その中で売上の大きい順」のように、複数の列を優先順位を付けて並べることができます。ORDER BYに列をカンマ区切りで並べるだけです。左に書いた列ほど優先度が高くなります。

⚠️ 最大の落とし穴：ORDER BY qtr, sales DESC と書くと、DESCが効くのは直前のsalesだけです。qtrは指定がないので昇順になります。「最後にDESCと書いたから全部降順」ではありません。

❌ 意図どおりに動かない書き方

SELECT customer, sales, qtr FROM sales
ORDER BY qtr, sales DESC;
-- qtr は昇順（既定）、sales だけが降順になる

さらに、ORDER BY DESC qtr, salesのようにDESCを前に置くのは構文エラーです。DESCは必ず対象の列名の直後に書きます。

⭕ 正しい書き方：列ごとに指定する

SELECT customer, sales, qtr
FROM sales
ORDER BY qtr DESC, sales DESC;
customer | sales | qtr -----------------------+----------+---- Euro Shopping Channel | 14082.80 | 4 Mini Gifts Distributors| 12001.00 | 4 Technics Stores Inc | 9064.50 | 4 ... Q4の中で売上が大きい順 → 次にQ3 ...

英語で読むと「salesテーブルから customer, sales, qtr を取り出し、四半期を大きい順に、その中で売上を大きい順に並べよ」。片方だけDESCにしたければ、その列にだけ書けばよいのです。

複合ソートの優先順位
qtr DESC
第1キー
→
同じ四半期の中で
並び順を決める
→
sales DESC
第2キー
第1キーが同点のときだけ、第2キーが効く。
📌 やりすぎに注意：顧客・四半期・売上額…と3つ4つと重ねていくと、コードは長くなるのに得られる情報はほとんど増えません（diminishing returns＝収穫逓減）。データ量と目的に見合った範囲でとどめましょう。
🍎 かんたん説明

複数列で並べるときは、列ごとにASC/DESCを書くのが鉄則。書かなかった列は自動的に昇順になります。

💡 学習のヒント

複合ソートで結果が想定と違うときは、まず「どの列にASC/DESCが付いているか」を1列ずつ確認しましょう。指定のない列は必ず昇順です。
