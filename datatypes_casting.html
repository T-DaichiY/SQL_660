①

CASTとは何か

クエリ時点だけの一時的な型変換——スキーマ設計の代わりではない

CAST（キャスト）とは、列のデータ型を強制的に変換することです。ここで重要なのは、私たちが行っているのはあくまでクエリ（SELECT）であり、データベースやテーブルそのものを変更しているわけではないという点です。テーブルに保存されているデータ自体は変わらず、その場で取り出した結果だけを、目的に合わせて変換して表示・計算するのがCASTです。

CASTが役立つのは、すでに存在するテーブルやデータベースにアクセスしていて、そのデータ型が今やりたいことに合っていない場合です。例えば、本来は日付として扱いたいデータが文字型で保存されている、あるいは数値として計算したいデータが文字型で保存されている、といったケースです。

⚠️ CASTは応急処置であって、正しい設計の代わりではありません。最初から適切なデータ型を選んでおくべきで、CASTは頻繁に使うべきものではありません。すでにあるテーブルの型を作り直すのが難しい・避けたい場合の限定的な手段と考えましょう。何でもかんでもCASTするようになると、処理負荷が増えるだけでなく、他の人がそのデータを扱いにくくなります。
🍎 かんたん説明

CASTは「その場限りの型の付け替え」。テーブルの実データは変わりません。本来は最初から正しい型を選ぶべきで、CASTはやむを得ない場合の最終手段です。

②

CASTの構文 — 2通りの書き方

CAST(列 AS 型) と 列::型

基本構文：CAST(column AS type)

文字型で保存されている数値をinteger型に変換して計算に使いたい場合、次のように書きます。

SELECT CAST(zip_code AS integer) - 10 AS adjusted
FROM customers;
adjusted -------- 30290 30291

CAST(列名 AS 変換したい型)という形で、対象の列を指定した型に変換します。変換後の値に対しては、引き算や掛け算などの計算をそのまま行えます。

日付・タイムスタンプへの変換

SELECT CAST(text_date AS timestamp) AS event_time
FROM events;

文字型の日付をtimestampに変換すれば、日付の計算やINTERVALを使った演算が可能になります。

短縮構文：column::type

PostgreSQLには、CAST() ASを使わずに書ける、より短い専用構文もあります。

SELECT zip_code::integer - 10 AS adjusted
FROM customers;

列名::型名のようにコロン2つ（::）を挟むだけで、CASTと全く同じ動作をします。文字数はほぼ変わりませんが、スペースを省けるぶんやや短く書けます。可読性という点ではCAST() ASのほうが分かりやすいという意見もあり、どちらを使うかは所属するチームや会社の規約に従うのが一般的です。

📌 どちらの構文も結果は同じです。CAST(col AS type)とcol::type、2つの書き方があることを覚えておきましょう。
🍎 かんたん説明

CASTには2つの書き方があります：CAST(列 AS 型)という正式な書き方と、列::型という短縮形。どちらも同じ結果になります。

③

変換が成功するためのルール

「変換先の型に収まるデータ」であることが絶対条件

CASTの一番大切なルールはシンプルです。変換元のデータが、変換先の型として成立する内容でなければならないということです。

失敗する例：文字が混ざったテキストをintegerへ

SELECT CAST(code AS integer) FROM demo;
-- codeの値が 'A105' の場合
ERROR: invalid input syntax for type integer: "A105"

'A105'のように数字以外の文字（特殊文字を含む）が混ざっている場合、integerへの変換はエラーになります。すべて数字だけで構成されている文字列——例えばZIPコードのような値——であれば、integerへの変換は成功します。

📌 覚え方：靴下に足を入れるのと同じイメージです。足に対して靴下が小さすぎたり、そもそも形が合わなければ、無理に押し込んでも入りません。データが変換先の型にきちんと「フィット」する内容でなければ、CASTは失敗します。

失敗する例：フォーマットが合わない日付文字列

text型の日付をtimestampに変換する場合も同様のルールが適用されます。

SELECT CAST(text_date AS timestamp) FROM events;

この変換が成功するには、text_date列の値がSQLで認識される日付形式（例：'2022-12-01'）になっている必要があります。フォーマットが崩れている、あるいは日付として解釈できない文字列が混ざっている場合はエラーになります。

⚠️ 事前チェックが重要：キャストする前に、DISTINCTなどを使って対象列の値を確認し、フォーマットが揃っているか・変換先の型にきちんと収まるかを事前に調べておくことをおすすめします。データが揃っていない場合は、先にクリーニング（修正）してからキャストする必要があります。
🍎 かんたん説明

ルールはただ1つ——「変換先の型にそのデータが本当に収まるか」。数字以外の文字が混ざったテキストをintegerに、不正な形式の文字列をtimestampに変換しようとすると、必ずエラーになります。

CAST
キャスト
クエリ結果の値を、その場だけ別のデータ型に変換すること。元のテーブルは変更されない。
CAST(col AS type)
標準構文
列を指定した型に変換する基本の書き方。
::type
短縮構文
PostgreSQL独自の、CASTと同じ結果を得られるコロン2つの短縮記法。
invalid input syntax
不正な入力エラー
変換元の値の内容が変換先の型として成立しないときに出るエラー。

💡 学習のヒント

キャストする前に、対象列の値をDISTINCTなどで確認しておくと、変換エラーを未然に防げます。「このデータは本当にこの型に収まるか？」を常に自問しましょう。
