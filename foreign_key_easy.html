M5 · Foreign keys 🍎

🍎 超やさしい版：外部キー

外部キーは「よそのテーブルに実在する値しか入れない」というルールです。

FKとはエラーと直し方教科書の例🔗 本編はこちら
⚡

FKとは

よそのPKを指す値

🎯 これだけ覚えればOK

子のFKは、必ず親のPKに実在する値でなければいけません。存在しない親を指すことはできない——これが参照整合性です。

FKとPKの向き
🧑‍🎓
students（親）student_idがPK
↑ FK → PK
📚
takes（子）student_idがFK
矢印はいつも子から親へ。

▶ 書き方

student_id bigint REFERENCES students (student_id)
🍎 ひとことで

同じstudent_idがtakesに何回出てきてもOK。1人の学生は何科目も履修するからです。

①

エラーと直し方

親を先に作る

▶ 存在しない学生4番を履修させると…

INSERT INTO takes VALUES (4, 'B');
ERROR: insert or update on table "takes" violates foreign key constraint "takes_student_id_fkey" DETAIL: Key (student_id)=(4) is not present in table "students".
🛠️
直し方は簡単：先に親（students）にその学生を入れるだけ。その後で同じINSERTをやり直せば成功します。
正しい順番
1️⃣
入学studentsに追加
↓
2️⃣
学籍番号発行student_idが決まる
↓
3️⃣
履修登録takesに追加
親が先、子が後。
操作何が起きるか
親が無いのに子を作るFKエラー（拒否される）
子に参照されたまま親を消すそのままでは削除できない
🍎 ひとことで

削除も同じ問題の裏返し。参照されている親は先に消せません（次のCascadeレッスンで解決します）。

②

教科書の例

licenses と registrations

▶ 1枚の免許証に複数の更新登録

license_id text REFERENCES licenses (license_id)

1枚の免許証（親）に対して、更新の登録（子）が何行あってもOK——これも1対多のFKです。

🤔 答えられるかな？（クリックで答えが開く）

Q1. FKはどこの値と一致していればいい？A. 他テーブルのPK（または一意な列）。
Q2. takesに同じstudent_idが何回も出てきていい？A. いい。1人が複数科目を履修するから。
Q3. FKエラーが出たらまず何をする？A. 参照先の親テーブルに、先にその値を追加する。

💡 まとめ

• FKは他テーブルのPKに一致する値

• 矢印は子（FK）→親（PK）

• 1対多はOK、存在しない親はNG

• エラーが出たら先に親を作る
