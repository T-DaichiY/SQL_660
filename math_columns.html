①

列同士の計算

2 + 2 の「2」を列名に置き換えるだけ
📦 このレッスンからデータセットが変わります。ここでは株価の履歴データ（stocksテーブル）を使います。テーブル作成とインポートの手順に従って準備してください。このデータにはNULLが含まれているため、インポート時の設定に注意が必要です。

SQLは2 + 2のような計算ができます。そして、その数字の部分を列名に置き換えると、行ごとに計算が行われます。

-- 数字同士の計算
SELECT 2 + 2;          -- 4

-- 列同士の計算 ← これが本題
SELECT column_a + column_b FROM some_table;

足し算・引き算・掛け算・割り算のすべてが使えます。列と列、列と定数、どちらの組み合わせでも構いません。

例1：株価の終値 − 始値（1日の変動）

SELECT s_index, s_close - s_open AS change
FROM stocks
ORDER BY s_index;
s_index | change --------+--------- 1 | 43.91 2 | -12.05 3 | 4 | -47.62
📌 なぜ「終値 − 始値」の順番なのか。上がったのか下がったのかを知りたいので、新しい値から古い値を引きます。結果がプラスなら上昇、マイナスなら下落です。逆にすると符号が反転してしまいます。

結果の列はAS changeで名前を付けています（前のレッスンの内容です）。計算元の2列がどちらも数値型なので、結果も数値型になります。

⚠️ NULLがあると結果もNULLになります。上の結果の3行目が空欄なのは、s_closeかs_openのどちらかがNULLだからです。実データにNULLが混ざるのは普通のことで、「0として扱う」「無視する」「その行を除く」など、目的に応じた判断が必要になります。

例2：高値 − 安値（その日の値幅）

SELECT s_index, s_date, s_high - s_low AS diff
FROM stocks
ORDER BY s_index;
s_index | s_date | diff --------+------------+-------- 1 | 2019-01-02 | 113.62 2 | 2019-01-03 | 58.40

計算列で並べ替える

SELECT s_index, s_close - s_open AS change
FROM stocks
ORDER BY change DESC;

これまで並べ替えの対象は既存の列だけでしたが、いまや自分が作った列でも並べ替えられます。「一番値上がりした日は？」「一番下落した日は？」といった問いに答えられるようになりました。

🍎 かんたん説明

数式の数字の部分を列名にするだけ。SELECT 列A - 列B AS 名前 FROM テーブル;で新しい列ができます。

②

演算の順序（order of operations）

カッコを忘れると意味が変わる

「1日の値幅は、株価全体の何％にあたるか」を計算してみましょう。値幅を終値で割ります。

SELECT s_index,
       (s_high - s_low) / s_close AS percent_delta
FROM stocks;
s_index | percent_delta --------+--------------------- 1 | 0.01043210987654321 2 | 0.02871500000000000
⚠️ カッコを外すと全く別の計算になります。s_high - s_low / s_closeと書くと、算数のルール（掛け算・割り算が先）により先にs_low / s_closeが計算されてしまいます。「高値から（安値÷終値）を引く」という、意味のない式になってしまいます。

パーセント表示にする

SELECT s_index,
       ((s_high - s_low) / s_close) * 100 AS percent_delta
FROM stocks;
s_index | percent_delta --------+--------------------- 1 | 1.04321098765432100 2 | 2.87150000000000000

100を掛けるときも全体をカッコで囲みます。カッコを増やすほど式は読みにくくなりますが、意図した順序で計算されることのほうが遥かに重要です。

📌 迷ったらカッコを付ける。不要なカッコがあっても結果は変わりませんが、必要なカッコが無いと結果が変わります。数式を書いたら「どこから計算されるか」を必ず声に出して確認しましょう。
🍎 かんたん説明

算数と同じで掛け算・割り算が先。引き算を先にやりたければ(A - B) / Cのようにカッコで囲みます。

％に変換
「もとの値に対して、どれくらいの割合で変化したか」を測る。

なぜ「差」ではなく「割合」なのか

ある物の値段が500ドル上がったとします。これは大きな変化でしょうか？

もとの値段500ドルの値上がりはパーセント変化
10ドルのものとんでもない高騰+5000%
300ドルのゲーム機誰も買えなくなる約 +167%
50万ドルの家ほぼ誤差+0.1%

同じ「500ドル」でも意味がまったく違います。だから変化量そのものではなく、もとの値に対する割合で見るのです。インフレ率、消費者物価指数（CPI）、生活費の変動など、世の中の多くの指標がこの考え方でできています。

手計算で確かめる

古い値新しい値計算結果
$5$10(10 − 5) ÷ 5 = 1+100%（2倍）
$3$7(7 − 3) ÷ 3 = 1.333+133%
$175$150(150 − 175) ÷ 175 = −0.143−14.3%（値下がり）
$9,500$10,000(10000 − 9500) ÷ 9500 = 0.0526+5.26%
⚠️ 結果は小数で返ります。計算結果が1なら1%ではなく100%です。0.0526なら5.26%。パーセント表示にしたければ100を掛ける必要があります。
📌 符号の意味：新しい値のほうが大きければプラス（増加）、小さければマイナス（減少）。だから「新 − 旧」の順序が重要なのです。

株価データに適用する

始値（s_open）が「古い値」、終値（s_close）が「新しい値」です。

SELECT s_index,
       ((s_close - s_open) / s_open) * 100 AS percent_change
FROM stocks
ORDER BY s_index;
s_index | percent_change --------+--------------------- 1 | 0.5321098765432100 2 | -1.2050000000000000
⚠️ カッコの位置が命です。s_close - s_open / s_openと書くと、s_open / s_open＝常に1が先に計算され、結果は「終値 − 1」というまったく無意味な値になります。しかもエラーにはならないため、間違いに気付きにくいのが厄介です。
🍎 かんたん説明

パーセント変化＝(新 − 旧) ÷ 旧 × 100。カッコを2重に付けるのを忘れずに。

④

CASTで整形し、NULLを除外する

読める結果に仕上げる

小数点以下が長すぎる問題

0.5321098765432100のような値は読みにくいので、CASTを使って小数第2位までに整えます（CASTのレッスンで学んだ内容です）。

SELECT s_index,
       CAST(((s_close - s_open) / s_open) * 100 AS numeric(10,2))
         AS percent_change
FROM stocks
ORDER BY s_index;
s_index | percent_change --------+---------------- 1 | 0.53 2 | -1.21 3 | 4 | -2.07

numeric(10,2)は「全体で10桁、うち小数点以下2桁」という意味です（数値データ型のレッスンの precision と scale ）。ぐっと読みやすくなりました。

計算列で並べ替える

SELECT s_index,
       CAST(((s_close - s_open) / s_open) * 100 AS numeric(10,2)) AS percent_change
FROM stocks
ORDER BY percent_change DESC;

これで「最も上昇率が高かった日」が分かります。しかし——NULLの行が先頭に並んでしまいます。

NULLを除外する

⚠️ 計算列の別名はWHEREでは使えません。WHERE percent_change IS NOT NULLと書きたくなりますが、これはエラーになります。WHEREはSELECTより先に処理されるため、その時点ではpercent_changeという名前がまだ存在しないからです。
-- 元の列でNULLを除く
SELECT s_index,
       CAST(((s_close - s_open) / s_open) * 100 AS numeric(10,2)) AS percent_change
FROM stocks
WHERE s_close IS NOT NULL
ORDER BY percent_change DESC;
s_index | percent_change --------+---------------- 412 | 17.70 287 | 12.04 ... 93 | -12.31
📌 IS NULL と IS NOT NULL：前者はNULLの行だけ、後者はNULL以外の行を返します。計算結果がNULLになるのは元の列がNULLだからなので、元の列に対して条件を書けば目的を達成できます。

この結果から「最大の上昇は+17.70%、最大の下落は−12.31%」といったことが読み取れます。データ全体を眺めると多くの日が±0.5〜2%の範囲に収まっており、比較的安定した銘柄だと分かります。

🚀 次のステップ：ここまでは1行ごとの計算でした。次のレッスンでは、複数行をまとめて集計する集計関数（aggregate functions）——合計・平均・最大・最小・件数——を学びます。
🍎 かんたん説明

桁が多いときはCAST(… AS numeric(10,2))。NULLを除きたいときは、元の列にIS NOT NULLを使います（別名はWHEREで使えません）。

💡 学習のヒント

計算式を書いたら、必ず1行分を手計算して答え合わせをしましょう。カッコの位置ミスはエラーにならず、静かに間違った値を返してくるのが一番怖いパターンです。
